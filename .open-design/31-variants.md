# 轨迹卡精度表达 · 三版对照与推荐

> 需求原话：「5m 的 GPS 点与 400m 的 network 点看起来一样可信 —— 这是不表达不确定」「历史数据里有大量 3 位小数（≈110m）坐标，画出来是网格阶梯」。
> 硬约束：不加按钮 · 画布恒 180px · 不新增锚点 · 颜色只取既有 token · 低精度不许只靠颜色表达。

## 三版差异（差异在表达通道，不在配色）

| | **A · 分段线型**（推荐） | B · 低置信点符号 | C · 误差走廊 |
|---|---|---|---|
| 低精度怎么表达 | 线型：实线 → **虚线** + 55% 不透明度 | 符号：低置信采样点画**空心圆环**，线降为 38% | 宽度：**带宽 = 误差圈**（400m≈13px、15m≈1.5px） |
| 表达粒度 | 段（哪一段不可信） | 点（哪个采样不可信） | 区域（位置可能落在哪条带里） |
| 灰度 / 色盲下 | 虚线 vs 实线，形状差异最强 | 空心圆环是形状，但只占 2.6px | 靠宽窄 + 淡浓，弱于 A |
| 粗坐标日呈现 | 点线（1.5/3.5），阶梯清晰 | 实心小方块标出被量化后的坐标 | 整条只剩一个格子宽，阶梯反而被带宽抹平 |
| Compose 成本 | 低：`PathEffect.dashPathEffect` 分段画 | 中：逐点在线上补画圆 | 中：按精度换算二次描边路径 |
| 主要风险 | 低置信段很长时「花」 | 采样密时圆环糊成一片 | 带宽随画布缩放变化，同一 400m 在不同日子宽窄不同 |

## 推荐 A，理由三条

1. **灰度下最稳**：虚线/实线是形状差异，转灰度、色弱、室外强光都不丢；B 的 2.6px 圆环和 C 的带宽差在灰度下明显弱一档。
2. **不改变现有卡片结构**：只换描边样式，图例三个点、卡尾一行说明、180px 画布全不动；44dp 触达与锚点集合零变化（本次不新增任何可交互元素）。
3. **粗坐标与低精度用同一套语义**：都是「这条线不可全信」，用户只需学一次。

C 的信息量最大（能读出 15m 与 400m 的差别），但**带宽与画布缩放耦合**：自绘模式按当日轨迹范围自适应缩放，同一个 400m 在 2km 的一天里是粗带、在 30km 的一天里是一条线。要修就得给带宽加下限，那就退回成 B 的符号语义。

## 落地方案（推荐 A 的最终形态）

| 项 | 取值 |
|---|---|
| 高置信段 | `accent` 100%、1.5dp 实线（现状不变） |
| 低置信段（accuracy > 100m） | `accent` 55%、1.5dp、`dashPathEffect(4dp, 3dp)` |
| 粗坐标日（≥60% 采样 ≤3 位小数） | 整条 `accent` 55%、1.5dp、`dashPathEffect(1.5dp, 3.5dp)`，且不参与平滑 |
| 阈值来源 | `LocationQuality.HIGH_ACCURACY_METERS`（100m），不写第二份 |
| 卡尾说明（替换既有单行，不新增行） | 低置信「虚线 = 精度 >100m（可能偏几百米）」／粗坐标「历史粗坐标 ≈110m，阶梯是坐标只存 3 位小数造成的」 |
| 图例 | 不动（起点/终点/停留 + 署名） |

## 有意偏离（报备）

| 项 | 偏离 | 原因 |
|---|---|---|
| 显示字体 | 未用 `--font-display`（衬线） | app 全站无衬线（SF 层级），照模版用衬线会误导实现 |
| 12px 文本 | 低于模版「正文 ≥14px」 | 与 app `labelSmall`（12sp，图例/刻度）同源，属既有口径 |
| 卡头 `样本 N · 时间段` | 本例用 12px muted | app 现用 `MetaText`（`meta` #86868b）在 surface 上仅 **3.33:1**，低于 4.5:1；本次只把新增说明行定为 `muted`(4.66:1)，卡头是否一起改由 leader 定 |
