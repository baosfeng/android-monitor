## 关键决策

1. **不新增 Tab**：`s16` 是 push 屏（不在 `TAB_OF_SCREEN` 内），由 `data-goto="s16"` 进入；外壳自动给 appbar 标题与返回键，Tab 下标不变（通知深链依赖）。
2. **行程段模型照调研结论**：`Stay`（地点 + 起止 + 时长 + 期间 Top3 App）/ `Move`（起终点 + 时长 + 距离）/ `Gap`（未记录，不猜内容）。
3. **时间带用纯 CSS**（`--l` / `--w` 百分比定位），不引 Canvas：分片体系下 Canvas 需要额外 JS 与重绘时机，评审价值一样但维护成本更高。
4. **隐私三档做成数据属性 `data-privacy="a|b|c"`**：同一份 DOM 用 `.pv-a/.pv-b/.pv-c` 切换，时间轴与详情抽屉共享同一套口径，避免两处文案漂移。
5. **筛选并组不新增 chip**：页面并入「应用」、通知并入「网络」；组级与行级两条规则都要放行（只改行级会因组级 `data-has` 命中不到而整组消失）。
6. **指纹文案去掉 `#`**：`#a3f2` 会被 `odops verify` 的裸色值检查当成 hex 计入（46 → 66 处）。改成 `页面 a3f2` 后回到 47 处（+1 是新增 PAGE 行的微信品牌绿，与既有行同款）。

| 上一轮 P1：进屏复位、s16 空态 | `s16` 脚本 + `.st-empty` 块 |

## 关键决策

1. **四档复用一套变体类**：名称走 `.pv-a`（标题）/`.pv-b`（指纹）/`.pv-c`（标题，全文与控件级共用）；说明文案另起 `.cap-a…cap-d`，避免「全文/控件级」把两句说明同时显示（第一版就是踩了这个坑，截图里卡头出现两行说明）。
2. **全文用原生 `<details>`**：默认 3 行 + 「展开全文 · 20 行」，展开后 200px 内滚动；不用额外 JS，键盘可达。
3. **控件级 = 全文 + 可操作项**：`本页 12 个可操作项` + 5 个 chip；chip 用 `flex-wrap`（单行 5 个在 297px 内会裁掉第 5 个），chip 为展示用（`pointer-events:none`）。
4. **开关状态纯 CSS 驱动**：`#s16-clicklog` 放在 `.content` 之前，`~` 选择器同时控制卡头提示与三张抽屉的操作记录；JS 只做「点开关 → 改 checked」与文案。
5. **进屏复位**：`MutationObserver` 监听 section 的 `is-active`，进屏时把 `input[id^="s16-s"]` 全部取消勾选（只清抽屉，不清粒度与开关）。
6. **s17 用单张抽屉 + 行内写回**：点 App 行 → 抽屉标题变「微信 · 记录粒度」、4 档勾选态与行一致；选完写回该行 `data-level` 与右侧档位文案并收起。
