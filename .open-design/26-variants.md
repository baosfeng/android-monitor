# 记账详情页（记一笔）· A/B 两版对照与选定

> 日期：2026-10-16 · 原型：`26-a-quan-chouti.html`（定版） · 对照：`26-ab-duizhao.html`
> 需求原话：「我希望一屏就能操作，而不是和现在一样还得来回滑动」

## 起点：原版为什么不行（s05）

| 问题 | 实测 |
|------|------|
| 21 个分类排成 **6 行网格** | 纵向高度是主要来源 |
| 3 个账户是**带余额的大卡片行** | 每行约 64px |
| 日期 / 备注各自独立成段 | 再叠两块 |
| 结果 | 内容远超一屏，必须来回滑 |

用户后续三条反馈：① 分类展开不够选，冷门要划很久，「至少两排」② 账户展开「很丑」③ 时间只能选当前，想记「昨天 10 点」记不了。

## 两版对照（差异只在交互模型）

| | **A · 全抽屉**（选定） | B · 内联展开（落选） |
|---|---|---|
| 点分类 | 弹底部抽屉，**一屏摆出 20 个**（4 列 × 5 行） | 就地展开 **8 个** + 「更多分类」 |
| 主表单高度 | **恒定 738，开抽屉时不动** | 展开后 **850 > 738 → 必须滚** |
| 点账户 | 抽屉列表（带余额：余额宝 ¥4,120.55） | 内联 chips + 浅色底 |
| 字段行模型 | 分类/账户/时间/单据 **同一套** | 内联 + 抽屉 **两套并存** |

实测数据来源：`document.querySelector('.screen.s14X .content')` 的 `scrollHeight` vs `clientHeight`。

## 选定：A

用户原话：**「总体满意 A」**。决定性理由是「一屏不放滚」—— 抽屉开合不影响主表单高度，而 B 展开就会把表单顶下去。

## 定版已落地的交互细节

| 交互 | 行为 |
|------|------|
| 分类 / 账户 | **选中即自动收起抽屉** + 回写行上的值（用户明确要求） |
| 时间 | 抽屉**保持打开**（日期 + 时 + 分要连着选），由「确定」关闭 |
| 时间选择 | 日期快捷 chips + **时/分两个滚轮**（0-23 / 0-59，中间高亮带 + scroll-snap） |
| 点抽屉外空白 | **关闭抽屉**（外壳只绑了关闭按钮，遮罩是另接的） |
| 单据 | 抽屉展示 6 项：商户 / 商品说明 / 付款方式 / 交易时间 / 订单号 / 平台分类 |
