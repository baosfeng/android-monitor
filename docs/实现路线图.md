# 实现路线图

从零开始到可用版本的开发路线图。按阶段划分，每个阶段都有明确的交付物。

**交付模式**：开发者真机测试通过 → Release 签名打包 APK → 交付 APK 文件给用户侧载安装。用户完全不需要接触 Android Studio 或命令行。

---

## 总体规则

| 规则 | 说明 |
|------|------|
| **每次改动必须测试** | 没有测试的代码不允许提交。优先手动真机测试 |
| **测试通过才打包** | 阶段交付物必须经过真机验证，确认所有功能正常才出 APK |
| **用户只收 APK** | 用户完全不碰代码，每次交付给用户的只有一个 `.apk` 文件 |
| **一次打包终身可用** | Release 签名后，后续升级使用同一签名，覆盖安装不丢失数据 |

---

## 阶段一：项目骨架与基础能力（预估 2-3 天）

### 目标
搭建可运行的 Android 项目，实现最基本的无障碍服务监听 + 本地存储 + 上报。

### 任务清单

| # | 任务 | 依赖 |
|---|------|------|
| 1.1 | 创建 Android Kotlin 项目，配置 Gradle（target API 36, compileSdk 36） | 无 |
| 1.2 | 声明所有权限到 AndroidManifest.xml | 1.1 |
| 1.3 | 实现基础 `MonitorAccessibilityService`，监听 `TYPE_WINDOW_STATE_CHANGED` | 1.1 |
| 1.4 | 实现基础的 `ScreenStateReceiver`（亮/灭/解锁） | 1.1 |
| 1.5 | 定义 Room 数据库：`events` 表 + DAO | 1.1 |
| 1.6 | 定义统一的 Event 数据模型 | 1.1 |
| 1.7 | 实现 `EventCollector`：接收事件 → 写入 Room | 1.5, 1.6 |
| 1.8 | 实现 `EventReporter`：定时从 Room 读取未上报事件 → HTTP POST | 1.5, 1.6 |
| 1.9 | 实现设备注册流程（首次启动 POST /devices） | 1.8 |
| 1.10 | 实现前台服务 + 静音通知 | 1.1 |
| 1.11 | 实现简单的引导/状态页面（`MainActivity`） | 1.1 |

### 测试清单（真机）

| # | 测试项 | 预期结果 |
|---|--------|---------|
| T1.1 | 安装 APK，按引导开启无障碍服务 | 无障碍服务状态变为"已开启" |
| T1.2 | 打开微信 → 返回桌面 → 打开抖音 | Logcat 输出正确的包名切换记录 |
| T1.3 | 按电源键关屏 → 再按亮屏 → 解锁 | 依次输出 screen_off → screen_on → unlock_success |
| T1.4 | 2 分钟内无网络 | 事件存入 Room，不丢失 |
| T1.5 | 检查前台服务通知 | 通知栏显示极简图标，无声音无震动 |
| T1.6 | 杀掉 App 进程 | AlarmManager 30 分钟内重新拉起 |

### 交付物
- `app-release.apk` 签名安装包
- 无障碍服务能正常工作，检测到前台 App 切换
- 事件写入本地数据库

## 阶段二：完整事件覆盖（预估 2-3 天）

### 目标
实现所有 20 种事件类型的采集。

### 任务清单

| # | 任务 | 说明 |
|---|------|------|
| 2.1 | 通知监听（通知到达 + 移除） | AccessibilityEvent 已有接口 |
| 2.2 | Activity 级切换（同 App 内） | 在阶段一的 window change 处理中扩展 |
| 2.3 | 充电状态（开始/停止/电量变化） | 新增 BatteryReceiver |
| 2.4 | WiFi 连接/断开（Android 16 使用 `NEARBY_WIFI_DEVICES` 权限） | 新增 WifiReceiver + NetworkCallback |
| 2.5 | 耳机插拔 | 新增 HeadsetReceiver |
| 2.6 | 应用安装/卸载 | 新增 PackageReceiver |
| 2.7 | 情景模式变化 | 监听 AudioManager |
| 2.8 | USB 连接电脑 | 新增 UsbReceiver |

### 测试清单（真机）

| # | 测试项 | 预期结果 |
|---|--------|---------|
| T2.1 | 插拔充电器 | 触发 charging_started / charging_stopped |
| T2.2 | 切换 WiFi（开/关/切换网络） | 触发 wifi_connected / wifi_disconnected，含 SSID |
| T2.3 | 插拔耳机 | 触发 headset_plugged / headset_unplugged |
| T2.4 | 通过应用商店安装/卸载一个 App | 触发 app_installed / app_uninstalled |
| T2.5 | 通知栏收到微信消息 | 触发 notification_received |
| T2.6 | 滑掉通知 | 触发 notification_removed |
| T2.7 | 切换静音/振动/响铃 | 触发 ringer_mode_changed |
| T2.8 | USB 连接电脑 | 触发 connected_to_pc |

### 交付物
- `app-release.apk`
- 全部 20 种事件类型都能被采集和上报
- 每种事件类型的 JSON 结构与 API 定义一致

## 阶段三：健壮性与容错（预估 2 天）

### 目标
确保监控服务 7×24 小时稳定运行。

### 任务清单

| # | 任务 | 说明 |
|---|------|------|
| 3.1 | 服务存活检测与自动重启 | AlarmManager 定时检查 |
| 3.2 | 网络断线重传机制 | 指数退避 + 最多 5 次 |
| 3.3 | 离线缓存容量控制 | 自动清理超过 3 天的数据 |
| 3.4 | 事件去重（同一事件 500ms 内不重复上报） | 防止误报 |
| 3.5 | BootReceiver 开机自启 | 解锁后延迟启动 |
| 3.6 | 电池优化白名单引导 | 跳转系统设置 |
| 3.7 | 故障通知机制 | 仅服务异常时通知 |
| 3.8 | CrashHandler 异常捕获 | 异常退出时记录日志 |

### 测试清单（真机）

| # | 测试项 | 预期结果 |
|---|--------|---------|
| T3.1 | 飞行模式 30 分钟 | 30 分钟后弹出"网络异常"通知 |
| T3.2 | 强制停止 App → 等待 | App 被 AlarmManager 重新拉起 |
| T3.3 | 强制停止无障碍服务 | 30 秒内检测到 → 通知用户 |
| T3.4 | 手机重启 | 解锁后 App 自动启动 |
| T3.5 | 连续使用 24 小时 | 无崩溃、内存无泄漏、日志完整 |

## 技术债与未来迭代

| 项目 | 优先级 | 说明 |
|------|--------|------|
| 多设备统一管理 | 低 | 多台手机数据汇总到一个后端 |
| 后端搭建指南 | 低 | 提供 Docker Compose 一键启动后端 |
| 截图/录屏监控 | 低 | 需要更高级权限，隐私风险大 |
| 地理位置信息 | 低 | 不在此项目范围 |
| 代码混淆/加固 | 低 | V1 暂不需要 |
