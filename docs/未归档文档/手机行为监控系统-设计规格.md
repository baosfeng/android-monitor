# 手机行为监控系统 —— 设计规格文档

> 版本: 1.0  
> 日期: 2026-07-01  
> 状态: 已定稿  
> 目标设备: 小米 14 / HyperOS 3 / Android 16 (API 36)

---

## 1. 项目概述

### 1.1 目标

开发一款 Android 端行为监控 App，通过无障碍服务实时采集用户手机操作行为，通过 HTTP API 实时上报到自建后端。

### 1.2 设计哲学

| 原则 | 要求 |
|------|------|
| **静默无感** | 正常运行无通知、无弹窗、无图标提示 |
| **省电精简** | 日耗电 ≤ 5%，APK ≤ 2MB，常驻内存 ≤ 30MB |
| **仅故障通知** | 仅在服务异常时主动通知用户 |
| **测试先行** | 每次改动真机验证 → 打包 APK 交付 |
| **用户零门槛** | 交付物仅为 APK 文件，用户无需接触开发环境 |
| **全量监控** | 共 **37 种事件类型**，覆盖系统状态、应用行为、App 内界面内容 |

### 1.3 技术栈

| 层级 | 选型 |
|------|------|
| 语言 | Kotlin |
| 构建 | Gradle Kts |
| UI | Jetpack Compose + Navigation Compose |
| 本地存储 | Room (SQLite) |
| 网络 | OkHttp + Retrofit |
| JSON | Kotlinx Serialization |
| 依赖注入 | 手动（不引入 Hilt/Dagger） |
| 异步 | Kotlin Coroutines + Flow |
| 目标 API | 36 (Android 16) |
| 包名 | `com.bsfeng.monitor` |

| `wifi_connected` / `wifi_disconnected` | BroadcastReceiver + NetworkCallback |
| `headset_plugged` / `headset_unplugged` | BroadcastReceiver |
| `app_installed` / `app_uninstalled` | BroadcastReceiver |

| `connected_to_pc` / `disconnected_from_pc` | BroadcastReceiver |
| **`bluetooth_connected` / `bluetooth_disconnected`** | BroadcastReceiver |
| **`airplane_mode_changed`** | BroadcastReceiver |
| **`mobile_data_changed`** | TelephonyCallback + NetworkCallback |
| **`power_save_mode_changed`** | BroadcastReceiver |
| **`screenshot_taken`** | ScreenCaptureCallback + ContentObserver |
| **`vpn_connected` / `vpn_disconnected`** | ConnectivityManager.NetworkCallback |
| **`app_crashed`** | ApplicationExitInfo（定期检查，非实时） |
| **`storage_low` / `storage_ok`** | BroadcastReceiver |
| **`hotspot_changed`** | TetheringManager |
| **`volume_changed`** | ContentObserver on Settings.System |
| **`timezone_changed`** | BroadcastReceiver |
| **`locale_changed`** | BroadcastReceiver |
| **`call_state_changed`** | TelephonyCallback |
| **`screen_content_detected`** | AccessibilityService + UI 树遍历 + 屏幕标题提取 |

### 2.2 通知策略

| 场景 | 通知表现 |
|------|---------|
| **正常监控中** | **完全无通知**。不启动前台服务，通知栏永远不出现任何图标 |
| **无障碍服务被系统关闭** | 弹真实通知："监控服务已停止，请重新开启" |
| **网络中断 > 30 分钟** | 弹通知："网络连接异常，数据将在恢复后上传" |
| **事件积压 > 1000 条** | 弹通知："事件积压过多，请检查网络" |

### 2.3 后端接口

详见 `docs/API接口定义.md`，共 4 个接口：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/events` | POST | 批量上报事件 |
| `/api/v1/events` | GET | 查询事件（可选） |
| `/api/v1/devices` | POST | 设备注册 |
| `/api/v1/heartbeat` | GET | 心跳+获取服务端配置 |

后端地址编译时通过 `BuildConfig.SERVER_BASE_URL` 硬编码。

## 3. Android 端技术方案

### 3.1 权限清单

```xml
<!-- 无障碍服务（需用户手动开启） -->
<uses-permission android:name="android.permission.BIND_ACCESSIBILITY_SERVICE" />
<!-- 屏幕状态 -->
<uses-permission android:name="android.permission.READ_PHONE_STATE" />
<!-- 网络 -->
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
<!-- WiFi（Android 16 使用 NEARBY_WIFI_DEVICES，不需位置） -->
<uses-permission android:name="android.permission.ACCESS_WIFI_STATE" />
<uses-permission android:name="android.permission.NEARBY_WIFI_DEVICES" />
<!-- 电量 -->
<uses-permission android:name="android.permission.BATTERY_STATS" />
<!-- 应用安装/卸载 -->
<uses-permission android:name="android.permission.QUERY_ALL_PACKAGES" />
<!-- 开机自启 -->
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
<!-- USB -->
<uses-permission android:name="android.permission.USB_PERMISSION" />
<!-- 情景模式 -->
<uses-permission android:name="android.permission.ACCESS_NOTIFICATION_POLICY" />
```

### 3.2 无障碍服务（无前台服务）

- `MonitorAccessibilityService` 继承 `AccessibilityService`，是唯一的后台组件
- **不启动前台服务**——通知栏永远不出现 App 图标
- 所有动态注册的 BroadcastReceiver 必须显式声明 `RECEIVER_EXPORTED` / `RECEIVER_NOT_EXPORTED`
- 数据上传使用 `WorkManager` 周期性任务，由系统调度
- 保活检测使用 `AlarmManager` 每 30 分钟检查服务存活

### 3.3 后台保活

| 策略 | 实现 |
|------|------|
| 前台服务 | FOREGROUND_SERVICE_SPECIAL_USE + 静音通知 |
| 定时检测 | AlarmManager 每 30 分钟检查服务存活 |
| 开机自启 | BootReceiver + 延迟到解锁后启动 |
| 电池白名单 | 引导用户手动设置 |
| 自启动管理 | 引导用户在小米安全中心开启 |

### 3.4 本地存储

Room 数据库 `events` 表，未上报事件标记 `isUploaded=false`，上报成功后置为 `true`。
自动清理超过 3 天的已上报数据。

### 3.5 上报引擎

- 触发条件：每 5 秒 或 每 10 条事件（先到为准）
- 批量最大 50 条
- 失败重试：指数退避（1s → 2s → 4s → 8s → 16s），最多 5 次
- 离线缓存：Room 持久化，网络恢复后补传

### 3.6 已知坑点（澎湃 OS 3 + Android 16）

| 坑点 | 应对 |
|------|------|
| 无障碍服务被 HyperOS 自动关闭 | 定时检测 + 通知引导重新开启 |
| 前台服务启动后 30 秒内必须 startForeground | Service.onCreate 后立即调用 |
| BOOT_COMPLETED 需要解锁后接收 | 延迟到 `ACTION_USER_PRESENT` 后启动 |
| WiFi 扫描不再需要位置权限 | 使用 `NEARBY_WIFI_DEVICES` |
| 所有广播接收器必须声明 exported | 动态注册时加 ReciverFlag |

## 5. 开发与交付流程

```
代码开发 → 真机测试 → 修复 → 测试通过 → Release 签名打包 → 交付 APK
```

- 用户只收 APK，不碰代码
- 每次阶段交付一个 `app-release.apk`
- 使用自行生成的 keystore 签名，后续升级使用同一签名

```kotlin
buildConfigField("String", "SERVER_BASE_URL", "\"https://your-server.com/api/v1\"")
buildConfigField("int", "UPLOAD_INTERVAL_MS", "5000")
buildConfigField("int", "BATCH_MAX_SIZE", "50")
buildConfigField("int", "CACHE_MAX_DAYS", "3")
buildConfigField("int", "RETRY_MAX_ATTEMPTS", "5")
buildConfigField("boolean", "NOTIFICATION_CONTENT_ENABLED", "true")
```
