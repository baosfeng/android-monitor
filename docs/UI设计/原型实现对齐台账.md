# 原型 → 实现 对齐台账

> 何时读：新增或修改一屏之前；原型与实现「看起来不一样」需要定位原因时。

## 一句话结论

两端自由度不对称：原型能写任意 px，实现受 token 门禁约束；差额靠人工翻译，翻译损耗就是返工轮次。本台账把差额量化，并指明每处默认补 token 还是改原型档位。

## 三条损耗（2026-11 实测基线）

| 族 | 原型 | 实现 | 结论 |
|---|---|---|---|
| 间距 | `--space-1..12` = 4/8/12/16/20/24/32/48 | `space1..12` 同值 | 主档一致；原型另有 2px×29、6px×25 等 **63 处孤儿值**无档位 |
| 圆角 | `--radius-sm/md/lg` × 8 主题 | `radiusSm/Md/Lg/Pill` 随主题 | 主档一致；原型 7/3/2/48px 等 **9 处孤儿值** |
| 字号 | `--text-xs..4xl` × 8 主题 | `monitorTypography` 单一套 | **唯一系统性偏差**：换主题只换色不换字 |
| 颜色 | screens/ 裸色值 0 | token | 一致 |

## 工具

```bash
node scripts/check-prototype-rules.mjs           # 新增孤儿值即 exit 1（存量走基线）
node scripts/check-prototype-rules.mjs --warn    # 只报不红（排查用）
node scripts/check-prototype-rules.mjs --update  # 接受当前值为基线；修掉存量后缩基线
```

基线只存 `rule:value`、只许变短；判据覆盖 `src/screens/` 与 `styles/20-base.html`，含 `var()`/`calc()`/`%`/`em` 的值不判定。

## 每处孤儿值默认二选一

1. **补 token**：同一值出现 ≥3 次，或跨主题需要不同值 → 进 `src/styles/10-tokens.html`，重跑 `node tools/gen-design-tokens.mjs`（生成器有变量数自检，改数量同步改常量）。
2. **改原型档位**：一次性微调（±1px 不改观感）→ 改原型本体，实现侧不折算。

## 改一屏的默认动作

1. 改完原型跑 `check-prototype-rules.mjs --warn`，新增孤儿值先处理；
2. `node scripts/assemble-prototype.mjs` 生成产物；
3. 实现侧优先 `LocalDesignTokens.current` 的 `space*` / `radius*` / `text*`；
4. 提交前 `check-docs` / `check-anchors` / `checkUiStyle` 三条都过。

## 已知口径差（暂不改，需设计确认后再动）

- **字号不随主题**：`monitorTypography` 是固定值，原型 notion / stripe 主题的 `--text-base` 更小。跟随 token 会让 8 套主题行高与换行同时变化，需一次 8 主题真机截图对比。
- **历史别名**：`MonitorSpacing`（19 处，全在 autobook）、`MonitorRadius`（6 处）仍是旧代码引用；新代码用 token。

## 一模一样：可测判据与当前基线

判据：**P0 = 0**（原型可见锚点在实现里全部存在）+ 几何每边 ≤3dp + 字号一致 + 文案去空白后双向包含。

```bash
bash scripts/export-proto-spec.sh                                    # 原型真值（28 屏）
./gradlew :app:testDebugUnitTest --tests '*S01OverviewParityTest*' \
  --tests '*S04FinanceParityTest*'                                   # 实现真值 → app/build/parity/
node scripts/parity-native.mjs --proto .open-design/parity/proto-screens.json \
  --impl app/build/parity/impl-s01.json --screen s01
```

- 视口固定 **393dp 宽**（= 原型 `--screen-w:393px`），长页高度开到 6000dp 一次组合完；实现侧必须 `@GraphicsMode(NATIVE)`。
- 锚点口径：`-content` 只判存在；`-pane-*` / `s04-list` 跳过高度（原型挂整块 pane，实现挂标题行）；y 差超一屏时只比 x/w/h。
- 已知口径差走白名单 `scripts/parity-known-diffs.tsv`（屏/锚点/类型/原因），脚本会打印「已知跳过 N 条」，不静默吞掉。

## 行盒：CJK 撑高与「固定盒 + unbounded」解法

原型高度来自 CSS `line-height`（h1 1.05 / h3 1.3 / .row-title 1.25 / body 1.47）；Compose 单行 `Text` 的高度是字体行盒，中文 1.47 倍——17sp 得 25dp、28sp 得 41.3dp，比原型高 2–12dp。`lineHeight` / `LineHeightStyle.Trim` / `includeFontPadding=false` 实测都压不动。

可行解法（已用于 6 处）：外层 `Box(Modifier.height(原型行盒))` + `Text(Modifier.wrapContentHeight(Alignment.Top, unbounded = true))`——布局按原型取值、字形完整溢出绘制；直接给 `Text` 设 `height` 会裁掉字形下半（截图实测）。

已应用：`OverviewHead` 30、`FinanceScreenHead` 29.4、`CardHead` 22、`TransactionRow` 21.3/18.2、日期头 18.2、`OverviewKpiCard` value 30.8。

## 已知残差与边界

- 中文 12px 字宽：Badge「按设备活动推算」实现 91 / 原型 96（-5px）。
- 原型卡高含 1px 边框、Compose border 不占位：自绘卡补 `.padding(1.dp)`（s01-recent 已补）。
- 平台排版差异（字体 metric、系统 inset、动态字号）不会因 token 化消失；目标是把偏差压到可测阈值内，而不是像素全等。
