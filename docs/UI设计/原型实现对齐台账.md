# 原型 → 实现 对齐台账

> 何时读：新增或修改一屏之前；原型与实现「看起来不一样」需要定位原因时。

## 一句话结论

两端自由度不对称：原型在浏览器里能写任意 px，实现受 token 门禁约束。差额由人工翻译，翻译损耗就是返工轮次。本台账把差额量化，并指明每一处默认补 token 还是改原型档位。

## 三条损耗（2026-11 实测基线）

| 族 | 原型 | 实现 | 结论 |
|---|---|---|---|
| 间距 | `--space-1..12` = 4/8/12/16/20/24/32/48（8 档） | `space1..12` 同值，屏内 992 处消费 | 主档一致；原型另有 2px×29、6px×25 等 **63 处孤儿值**无档位可用 |
| 圆角 | `--radius-sm/md/lg` × 8 主题（0–36） | `radiusSm/Md/Lg/Pill` 随主题，屏内 173 处消费 | 主档一致；原型 7/3/2/48px 等 **9 处孤儿值** |
| 字号 | `--text-xs..4xl` × 8 主题（11–96） | `monitorTypography` 单一套，屏内 503 处消费 vs token 10 处 | **唯一系统性偏差**：换主题只换色不换字 |
| 颜色 | screens/ 裸色值 0 | token | 一致 |

裸间距 92 处、裸圆角 11 处、裸字号 4 处；孤儿值合计 83 处（占违规 107 处的 78%）。

传导证据：实现侧裸 dp 里 `2.dp` 34 处、`3.dp` 12、`6.dp` 9、`10.dp` 5（合计 60），与原型孤儿值的量级吻合 —— 原型没有档位的值，最终以裸字面量落在实现里。

## 工具

```bash
node scripts/check-prototype-rules.mjs           # 新增孤儿值即 exit 1（存量走基线）
node scripts/check-prototype-rules.mjs --warn    # 只报不红（排查用）
node scripts/check-prototype-rules.mjs --update  # 接受当前值为基线；修掉存量后也跑一次缩基线
```

基线在 `scripts/prototype-rules-baseline.json`（只存 `rule:value`，不存次数，只许变短）。判据只覆盖 `.open-design/src/screens/` 与 `styles/20-base.html`；外壳 / splash / devbar 不进实现，不检查。输出五类命中 + 孤儿值清单（值 × 次数 + 例证 `file:line`）。含 `var()` / `calc()` / `%` / `em` 的值不判定（已 token 化或与字号联动）。

## 每处孤儿值默认二选一

1. **补 token**：同一值出现 ≥3 次，或跨主题需要不同值 → 进 `src/styles/10-tokens.html`，重跑 `node tools/gen-design-tokens.mjs`。
2. **改原型档位**：一次性微调（±1px 不改观感）→ 改原型本体，实现侧不折算。

实现侧写裸 `2.dp` / `6.dp` 并加注释豁免，是损耗的常见入口，优先走上面两条。

## 项目自有风格（Open Design）

原型默认用项目风格，不再用内置 apple：包在 `.open-design/design-system/`（manifest + DESIGN.md + tokens.css），取值与实现 `DesignTokenTable` 同源。

- 改：只动 `tokens.css` 与 `DESIGN.md`，改完跑 `odops style-check .open-design/design-system`；
- 同步：`odops style-install .open-design/design-system --force --yes`（快照拷贝，改完必须重装），`odops style-current` 应显示 `user:android-monitor`；
- 用：`odops sketch <模版> --style .open-design/design-system` 生成的速稿逐字带上 56 个官方槽位与项目 C-extension；
- 边界：8 套运行时主题不复制进包，包只锁 apple 基线与结构 token，跨主题只换色。

## 改一屏的默认动作

1. 改完原型跑 `check-prototype-rules.mjs --warn`，新增孤儿值先处理；
2. `node scripts/assemble-prototype.mjs` 生成产物；
3. 实现侧优先 `LocalDesignTokens.current` 的 `space*` / `radius*` / `text*`；
4. 提交前 `check-docs` / `check-anchors` / `checkUiStyle` 三条都过。

## 已知口径差（暂不改，需设计确认后再动）

- **字号不随主题**：`Theme.kt` 里 `typography = monitorTypography` 是固定值，原型 notion / stripe 等主题的 `--text-base` 更小。改成跟随 token 会让 8 套主题的行高与换行同时变化，需一次 8 主题真机截图对比。
- **历史别名**：`MonitorSpacing`（19 处，全在 autobook）、`MonitorRadius`（6 处）仍有旧代码引用；新代码用 token，别名保留给旧代码编译。
- **几何字面量 248 处不是违规**：它们是下一层「几何契约」的导出对象（按锚点导出 w/h/font-size，供实现侧断言），本阶段只记账。

## 一模一样：可测判据与当前基线

判据：**P0 = 0**（原型可见锚点在实现里全部存在）+ 几何每边 ≤3dp + 字号/圆角/文案一致。

```bash
bash scripts/export-proto-spec.sh                                   # 原型真值（28 屏）
./gradlew :app:testDebugUnitTest --tests '*ImplSpecExport*'         # 实现真值 → app/build/parity/
node scripts/parity-native.mjs --proto .open-design/parity/proto-screens.json \
  --impl app/build/parity/impl-screens.json --screen s12
```

- 视口固定 **393dp 宽**（= 原型 `--screen-w:393px`；`00-brief.md` 的 390 是历史声明值）；长页把高度开到 6000dp 一次组合完，避免 LazyColumn 回收让导出忽有忽无（实测 844/4200/6000 三档：缺块 5 → 1 → 0）。
- 实现侧必须 `@GraphicsMode(NATIVE)`（否则字体度量是假的一律 1px/字符）；y 差超过一屏时按滚动视口降级，只比 x/w/h。

当前基线：s12 结构 15/15、P0 = 0；s01 结构 23/25、P0 = 2（缺的两个是行程卡内部锚点，trip fake 数据不全）。s01 的 P1 里数据驱动锚点（ring / recent / trip）的差异来自假数据没复刻原型，不是布局缺陷——这类锚点默认只判存在与宽度。已有导出口：s01（S01OverviewParityTest）、s07（S07DailyAvgParityTest）、s12（ImplSpecExportTest）；其余屏待加 fake 状态。

## 边界

- 平台排版差异（字体 metric、系统 inset、动态字号）不会因 token 化消失；目标是偏差可测、有阈值，不是像素全等。
- 原型新增的视觉效果若落不进 token 档位，优先在台账登记为「待设计确认」，不要先在实现里写死再做对齐。
