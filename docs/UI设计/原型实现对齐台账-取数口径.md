# 原型 ↔ 实现 对照的取数口径

> 何时读：跑 `scripts/parity-native.mjs` 之前；某一屏的 P0/P1 数字与肉眼不符、或怀疑「脚本量错了」时。判据本身与当前基线见[原型实现对齐台账](原型实现对齐台账.md)。

## 两个取数文件只改「怎么量」，不放松判据

| 文件 | 用途 |
|---|---|
| `scripts/parity-compose.tsv` | 同屏多页拼接表。**s09 原型是一张长页（高 3016）、实现拆成一级页 + 10 个二级页**：逐页登记「屏 / 实现文件 / 对齐锚点」，脚本按锚点算 dy、整体平移后按 id 合并（先到先得）再比；**屏级 P0/P1 以合并后计**。两端原点不同（原型 appbar 由外壳生成 vs 实现自绘导航栏占 47–70dp，如 s19 与 s22–s27）也走这张表。不登记的屏严格按原坐标比，没有隐式平移 |
| `scripts/parity-known-diffs.tsv` | 已知口径差白名单（屏 / 锚点 / 类型 / 原因），命中打印「已知跳过 N 条」，不静默吞掉；能修的一律不登记 |

## 原型侧孤儿值

基线只存 `rule:value`、只许变短（`check-prototype-rules.mjs` 新增孤儿值即 exit 1）。孤儿值二选一：**补 token**（同值 ≥3 次或跨主题需不同值 → `10-tokens.html` + `tools/gen-design-tokens.mjs`）或**改原型档位**；链路 = `check-prototype-rules --warn` → `assemble-prototype.mjs` → `LocalDesignTokens.current` → 三道门禁。

## 复跑命令

```bash
bash scripts/export-proto-spec.sh                                    # 原型真值（28 屏）
./gradlew :app:testDebugUnitTest --tests '*S01OverviewParityTest*'   # 实现真值 → app/build/parity/
node scripts/parity-native.mjs --proto .open-design/parity/proto-screens.json \
  --impl app/build/parity/impl-s01.json --screen s01
```

- 视口固定 **393dp 宽**（= 原型 `--screen-w:393px`），长页高 6000dp 一次组合完；实现侧必须 `@GraphicsMode(NATIVE)`。
- 脚本内置锚点口径：`-content`/`-body`/`-timeline` 是滚动容器只判存在；`-pane-*`/`s04-list`/`-records`/`-rules`/`-list`/`-summary`/`-legend` 只跳 h；`sNN-g09` 类小时组卡只跳 h；y 差超一屏只比 x/w/h。

## 锚点落点必须与原型同节点

原型锚点大多挂在 `.row` 本体（卡内 16 缩进之后），实现把 `testTag` 写在 `padding` 之前会连内边距一起量进去 —— 表现为成片的 `x −17 / w +34`。解法是给行组件加 `innerModifier`，挂在 padding 之内的那一层节点上（`TokenRow` / `TotpAccountRow` 已支持）。同理 `AppCard` 的 `border` 只绘制不占位，不补 `padding(1.dp)`（补了会让 `S07DailyAvgParityTest` 的卡内容宽断言变红）。
