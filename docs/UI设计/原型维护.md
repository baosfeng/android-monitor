# 交互原型维护

> ⚠️ **何时阅读：** 修改 `.open-design/` 下的交互原型（加屏、改屏、调样式）前先读本文。搞错「改分片还是改产物」会让人白改一轮。

## 一句话结论

原型**源码按屏拆成 16 个分片**（每屏一个文件），**产物仍是单文件**（`08-prototype.html`，GitHub Pages 与 README 截图的唯一输入）。改完分片跑一次组装脚本即可。

## 为什么产物不能拆成多个 HTML

`08-prototype.html` 是**交互**原型，不是静态页面集：

- 屏切换靠同页 DOM 切换（`App.go()` / 返回栈 / 过渡动画），拆成独立 HTML 后 `App.go`、`App.back()`、底部 Tab 全部失效；
- GitHub Pages 部署（`.github/workflows/pages.yml`）、README 截图（`docs/assets/readme/`）、`odops verify/spec` 都只吃这一个文件；
- Open Design 官方模版本身就是「shell + partial 组装成单文件」的形态，产物单文件是契约，不是妥协。

所以拆分发生在**源码层**，产物层保持单文件。

## 操作意图 → 文件

| 操作意图 | 对应文件 |
|---------|---------|
| 改某一屏的界面 / 文案 | `.open-design/src/screens/<屏>-<标题>.html` |
| 改全局 token（颜色 / 圆角 / 间距 / 字体） | `.open-design/src/styles/10-tokens.html` |
| 改公共组件样式（卡片 / 行 / 按钮 / 图表 / 浮层） | `.open-design/src/styles/20-base.html` |
| 改设备框、状态栏、底部 Tab、`.content` 滚动区 | `.open-design/src/00-shell.html` |
| 改开屏动画 / logo | `.open-design/src/10-splash.html` |
| 改屏切换、返回栈、toast、图表渲染逻辑 | `.open-design/src/99-app.js` |
| 改调试条（主题切换 / 状态演示入口） | `.open-design/src/90-devbar.html` |
| 重新生成产物 | `node scripts/assemble-prototype.mjs` |
| 校验产物与分片是否同步 | `node scripts/assemble-prototype.mjs --check` |
| 本地预览（改完自动刷新） | `odops preview .open-design/08-prototype.html` |

## 分片文件格式

每个 `screens/*.html` 固定三段，由三行**独占一行**的标记分隔：

```html
<!--@od:style-->
<style data-for="s07">…本屏样式…</style>
<!--@od:section-->
<section class="screen" data-screen="s07" data-title="统计分析" data-od-id="screen-s07">…本屏结构…</section>
<!--@od:end-->
```

- `<style data-for>` 段 → 组装进 `<head>`（所有屏的样式按屏号顺序集中）；
- `<section>` 段 → 组装进 `<body>` 的 `#screenHost`（按屏号顺序）；
- 标记必须独占一行，写在注释里提到标记名不影响解析。

`s14` / `s14b` 只有样式段（`<!-- 仅样式方案：无结构段落 -->`），它们是历史方案（一屏版 / 内联展开版）的样式保留，当前采用的是 `s14a`。

## 组装与校验

```bash
node scripts/assemble-prototype.mjs              # 生成 .open-design/08-prototype.html
node scripts/assemble-prototype.mjs --check      # 只校验，不一致退出码 1（CI 用）
node scripts/assemble-prototype.mjs --out x.html # 指定输出路径
```

组装器做的事：读 `00-shell.html`，把六个占位替换成对应内容后写出产物。

| 占位 | 注入内容 |
|------|---------|
| `<!--@od:base-styles-->` | `styles/10-tokens.html` + `styles/20-base.html` |
| `<!--@od:styles-->` | 所有屏的 `<style data-for>` 段（按屏号） |
| `<!--@od:screens-->` | 所有屏的 `<section>` 段（按屏号） |
| `<!--@od:splash-->` | `10-splash.html` |
| `<!--@od:devbar-->` | `90-devbar.html` |
| `<!--@od:scripts-->` | `<script>` 包裹的 `99-app.js` |

产物**入库**（Pages 与 README 直接用它），CI 里跑 `--check` 防止「只改分片忘组装」的产物漂移。

## 改完怎么验证

```bash
node scripts/assemble-prototype.mjs
odops verify .open-design/08-prototype.html --platform mobile   # 产物自测
odops preview .open-design/08-prototype.html                    # 浏览器实时预览
```

需要证明「拆分前后渲染完全一致」时，用 `odops spec` 对比渲染指纹：

```bash
odops spec <旧产物.html> --out /tmp/spec-old.json --yes
odops spec <新产物.html> --out /tmp/spec-new.json --yes
# 比对 anchors / tokens / tokenValues / states 四个键，source 与 url 是文件路径差异
```

本次拆分即以此验证：14 屏、308 个 `data-od-id` 锚点的几何与计算样式与拆分前**逐项一致**，首屏截图字节相同，`odops verify` 输出逐行相同。

## 与截图 / 发布的关系

- README 的界面预览图（`docs/assets/readme/*.png`）由原型渲染生成，改原型后需要重新截图并更新（截图前隐藏调试条、替换真实 Wi-Fi 名与设备型号）；
- 本机真实截图、取证素材**不入库**，规则见 `AGENTS.md` 与本文档「素材与生成物」约定。
