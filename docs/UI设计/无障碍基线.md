# 无障碍基线

> 新增或修改**任何**可交互元素前读本页：四条红线 + 三层落地（静态门禁 / 运行时审计 / 锚点账本）。

## 四条红线

每条都是「读屏能读到、自动化能点到」的最低要求，缺一条即视为该元素不可达。

### 1 可读名

- 推荐：可见文本；纯图标控件写 `contentDescription = "返回"`。
- 反例：`IconButton(...) { Icon(Icons.Filled.Close, contentDescription = null) }`。
- 后果：读屏只念「按钮」，用户不知道点了会发生什么。

### 2 可达标识

- 推荐：`Modifier.testTag("s22-send")`，锚点优先取 [锚点账本](../交互设计/锚点账本.md) 里的 `sXX-*` 命名；通用组件用 `组件名.用途`（`chip.option`），登记在 [组件级锚点登记](../交互设计/s12a-组件级锚点登记.md)。
- 反例：只在视觉上有位置、代码里没有任何稳定标识的 `Modifier.clickable`。
- 后果：运行时审计报不出问题元素，自动化与回归脚本无法定位，改版后无人知道少了谁。

### 3 可触达

- 推荐：触达区 ≥ `t.tapMin`（44dp，`ui/theme/GeneratedTokens.kt:93`，原型 `--tap-min`）；纯图标按钮优先 48dp（Material 默认只给 40dp，用 `minimumInteractiveComponentSize()` 兜住）。
- 判定线与 token 同源：审计/门禁都按 44dp 判。曾按 48 判，把照规范做的 44dp 控件一律误报成缺口。
- 反例：`.size(20.dp).clickable { ... }` 靠视觉间距凑点击域。
- 后果：手指点不准，边缘点击落到相邻控件上。

### 4 状态可读

- 推荐：`Modifier.toggleable` / `selectable`（自带 checked/selected 语义），或 `stateDescription`。
- 反例：自绘开关只换轨道颜色 + 滑块位移，语义树里只有「可点」。
- 后果：读屏念不出开或关，色弱用户同样分辨不出。

## 三层落地

| 层 | 入口 | 何时生效 |
|---|---|---|
| 静态门禁 | `scripts/check-a11y.sh`（构建内任务 `checkA11y`，见 `app/build.gradle.kts`） | 提交前 / CI；ERROR 阻断，WARN 只报 |
| 运行时审计 | `scripts/debug-cli.sh ui audit [tag]` → `files/dsh-ui/a11y-<tag>.json` | 真机跑通新页面后；有缺口时退出码 1 |
| 锚点 | `testTag("sXX-*")`，见 [锚点账本](../交互设计/锚点账本.md) | 写交互元素时 |

档位：**ERROR 1 项**（IconButton 家族内 `contentDescription = null`）、**WARN 4 项**（clickable 无 testTag / 触达区 <48dp / switch 类无 toggleable / 可点图标无可读名兜底）。
ERROR 必须为 0 且**没有豁免清单**：命中就是真缺口，改代码。WARN 只打印数量与前 20 条，不阻断构建。
「clickable 内有无名图标」原定 ERROR，因函数级判定命中 20 处全部合规（19 处行内有文本 + 装饰 chevron、1 处用 `.semantics` 给了标签），降级为 WARN 4 并收窄口径，理由写在脚本头。

## 可豁免

| 场景 | 允许 | 要求 |
|---|---|---|
| 纯装饰 Icon（不可点，旁边的文本已说明含义） | `contentDescription = null` | 加 `Modifier.clearAndSetSemantics {}`，或紧邻一行 `// decorative` 注释 |
| 纯文本展示（标题、金额、说明） | 不写 testTag | 读屏直接读文本，无需额外语义 |
| 不可交互元素（分隔线、骨架、进度条） | 不适用四条红线 | 进度类若要被读屏播报，仍按红线 4 给 `stateDescription` |

判据只有一条：**这个元素用户能不能点**。能点就四条全占，不能点就走上面三行。

## 存量缺口

| 档 | 实数 | 说明 |
|---|---|---|
| ERROR | 0 处 | 无豁免。`FinanceIconButton` 的内容 lambda 收到 `contentDescription` 并落到图标上，5 条调用点全部合规 |
| WARN | 2 处 | 仅剩 `widget/WidgetStyle.kt` 的 `WidgetCard` / `SolidTile`：Glance 只提供 `semantics { testTag = ... }` 属性形式，没有 `testTag(...)` 函数，按「函数调用」判定的正则扫不到（标识已加，属门禁盲区）。触达区 <48dp、switch 类无 toggleable、可点图标无可读名兜底三项均为 **0 处** |

脚本里没有豁免清单：修一处就是少一处，不允许加白名单。
