# UI 设计规范

> 版本：1.0.0 | 最后更新：2026-10-15（追加：图表色彩三角色 / 扇形图 / 分类与应用图标 / 开屏动效时序）
> 
> 本文档定义 android-monitor 应用的 UI 设计体系，所有 UI 开发必须遵循。
> 代码实现在 `app/src/main/java/com/bsfeng/monitor/ui/theme/` 下。

---

## 1. 设计哲学

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| **清晰** | 信息层级分明，一目了然 |
| **一致** | 颜色、字号、间距、组件风格统一 |
| **高效** | 减少视觉噪音，操作路径最短 |
| **平台亲和** | 以 Material 3 为基础，色彩调性偏向 iOS 风格 |

### 1.2 设计语言

- **基础框架：** Material 3（Google 官方）
- **视觉倾向：** iOS 风格（圆角分组卡片、扁平导航、柔和色彩）
- **字体系统：** SF 字体层级映射（通过 Typography 实现）
- **图标库：** Material Icons Extended（`material-icons-extended`）

## 2. 色彩体系

> **现行 token 入口（以原型为唯一权威）：** 颜色 / 尺寸 token 由原型生成 →
> `ui/theme/DesignTokenTable.kt`（生成物）+ `GeneratedTokens.kt`（`chartSeq` / `chart1..16` 等访问器）
> + `DesignTokenCatalog.kt`（派生：分类色板、热力阶、事件类型色、半透明覆盖）。屏内推荐统一通过
> `LocalDesignTokens.current` 读取。下文 §2.1 / §2.2 的 `IOSColors` / `MaterialTheme.colorScheme`
> 是历史入口，其同名值已登记在 `GeneratedTokens.kt` 的 LEGACY-TOKEN-MAP 中（新增代码优先走 token）。

### 2.2 Material 3 ColorScheme

**浅色模式：** `iOSLightColorScheme` — 使用 iOS 系统色板映射到 Material 3 语义色。

| Token | 颜色 | 用途 |
|-------|------|------|
| `primary` | `#007AFF` | 主按钮、Tab 选中态 |

| `error` | `#FF3B30` | 错误提示 |
| `onSurfaceVariant` | `#49454F` | 辅助文字 |

**深色模式：** `iOSDarkColorScheme` — 自动跟随系统切换。

> **使用规则：** 禁止在代码中直接引用 `IOSColors.blue` 或 `Color(0xFF...)` 作为前景色。所有前景色应通过 `MaterialTheme.colorScheme.xxx` 引用。

### 2.3 事件类型色

通过 `RecordType.toEventColor()` 扩展函数获取，用于事件时间线中的颜色标记：

```

CHARGING/BATTERY → #FF9500    WIFI → #007AFF
AUDIO → #AF52DE     PACKAGE → #FF2D55
POWER_SAVE → #8E8E93   AIRPLANE → #5856D6
PHONE_STATE → #30B0C7   LOCATION → #4CD964
```

### 2.4 财务分类色

记账分类默认走**分类色板** `chart1..16`（跨主题固定）：按分类在 `finance_categories` 的
`sort_order` 取 `index % 16`，相邻分类自然不同色，取色入口为 `DesignTokens.categoryDot(i)`
（派生层 `ui/theme/DesignTokenCatalog.kt`），完整三角色说明见 §7.4。

财务专用语义色优先使用**语义对**（与金额文字同色）：
- 支出 = `danger`（红）
- 收入 = `success`（绿）
- 预算进度 = `accent`（蓝）

（`Color.kt` 中的 `IOSColors` / `FinanceColors` / 15 色 `categoryPalette` 为历史名，
新代码优先直接使用 token。）

## 3. 字体体系

### 3.1 层级映射

定义在 `Type.kt` 的 `monitorTypography` 中，直接映射 iOS SF 字体层级。

```kotlin
MaterialTheme.typography.xxx  // 所有页面通过此引用
```

> 字阶对齐原型 token（`--text-xs 12 / --text-sm 14 / --text-base 17 / --text-xl 28`，见 `.open-design/parts/00-tokens.css:100-107`）。

| Token | 字号 | 字重 | 原型 | 用途 |
|-------|------|------|------|------|
| `headlineLarge` | 34sp | Bold | — | 大标题、记账金额 |
| `headlineMedium` | 28sp | Bold | `.h1` | 页大标题 |
| `headlineSmall` | 21sp | SemiBold | `.h2` | 区块标题 |
| `titleLarge` | 17sp | SemiBold | iOS Headline | 导航栏标题 |
| `titleMedium` | 17sp | SemiBold | `.h3` / `.st-title` | 卡片头、空态标题 |
| `titleSmall` | 17sp | Medium | `.row-title` | 列表行主标题 |
| `bodyLarge` | 17sp | Normal | `.tl-title` | 正文 |
| `bodyMedium` | 16sp | Normal | — | 按钮、输入框 |
| `bodySmall` | 14sp | Normal | `.meta` / `.st-desc` | 辅助说明 |
| `labelMedium` | 14sp | Medium | `.row-sub` | 列表副标题、分组标签 |
| `labelSmall` | 12sp | Medium | `.fine` | 时间戳、极小说明 |

**等宽数字族**（原型 `.kpi-value` = `--font-mono` + `tabular-nums`，见 `Type.kt` 的 `monitorMono*`）：

| 样式 | 字号 | 原型 | 用途 |
|------|------|------|------|
| `monitorMonoNumber` | 28sp Bold | `.kpi-value` | KPI 主数值、大额金额 |
| `monitorMonoKpi` | 21sp Bold | `.s07-kv` | 统计页 KPI 瓦片 |
| `monitorMonoBadge` | 11sp SemiBold | `.badge` | 角标（等宽） |
| `monitorMonoMeta` | 14sp Normal | `.tl-time` / `.legend-num` | 时间列、图例数值 |

控件文字继续用 `MaterialTheme.typography.labelLarge`（M3 默认 14sp/500 = 原型 `--text-sm`）。

### 3.2 使用规则

1. **禁止直接写 `fontSize = X.sp`** — 必须从 `MaterialTheme.typography.xxx` 引用
2. **例外：** `fontSize = 9.sp` 用于极小类型标签（如事件卡片的类型角标），已封装为 `labelSmall.copy(fontSize = 9.sp)`
3. **字重规则：**
   - 标题：`FontWeight.Bold`
   - 列表项标题：`FontWeight.Medium`
   - 正文：默认（`FontWeight.Normal`）

## 5. 组件规范

### 5.1 组件列表

所有 iOS 风格组件定义在 `Components.kt` 中。

| 组件 | 功能 | 替代对象 |
|------|------|---------|
| `InsetGroupedCard` | iOS 风格圆角分组卡片 | Cupertino `section(InsetGrouped)` |
| `InsetGroupedSection` | 带标题/尾注的分组卡片 | Cupertino section 带 header |
| `IOSRow` | iOS 风格列表行（标题+尾随） | 自定义 Row |
| `SettingsRow` | 设置项行（标题+副标题+尾随） | Cupertino 设置项 |
| `IOSNavigationBar` | iOS 风格导航栏 | CupertinoNavigationBar |
| `CategoryDot` | 分类首字圆点 | iOSStyle CategoryDot |
| `IOSDivider` | 带缩进的分割线 | HorizontalDivider |

### 5.2 导航栏

使用 `IOSNavigationBar` 统一样式：

```kotlin
IOSNavigationBar(
    title = "页面标题",
    onBack = { /* 返回操作 */ },
    actions = { /* 右侧按钮 */ }
)
```

所有页面顶部导航栏必须使用此组件，禁止手动拼接 `Row` + `Text`。

### 5.3 分组列表

替代 Cupertino 的 `section(SectionStyle.InsetGrouped)`：

```kotlin
// 纯内容卡片
InsetGroupedCard {
    IOSRow(title = "行1")
    IOSDivider()
    IOSRow(title = "行2")
}

// 带标题和尾注
InsetGroupedSection(header = "标题", footer = "说明") {
    SettingsRow(title = "设置1", subtitle = "说明", trailing = { Switch(...) })
}
```

### 5.4 原型基元层（`ui/components/`）

`ui/components/` 是与原型一一对应的基元层（token 驱动，不被 M3 默认几何接管），新页面优先复用：

| 基元 | 对齐原型 | 说明 |
|------|---------|------|
| `StateContainer` / `EmptyState` / `ErrorState` / `EdgeState` / `StateSkeleton` / `SkeletonRow` | `.st-*` · `.sk` | 五态：骨架细行 shimmer（12/20px、宽 40~100%、radius-sm）；空/错态居中列（44dp 图标 + 17sp 标题 + 14sp 描述 + 可选 CTA） |
| `AppDialog` / `ConfirmDialog` | `.scrim > .dialog` | 底 `--surface-warm` + `--elev-3` + pop 入场；**替代 M3 `AlertDialog`** |
| `BottomSheet` | `.sheet` | 底 `--surface-warm` + `--elev-3` + grip |
| `AppCard` / `GlassCard` | `.card` / `.card.glass` | 描边 + 可选 `--elev-1`；玻璃卡含顶部 1px 高光内描边 |
| `Chip` / `SegmentedControl` | `.chip` / `.segmented` | 选中态中性（fg 7% 底 / fg 24% 描边）；分段控件 pill + 描边 + 选中 `--elev-1` |
| `Badge` | `.badge` | 底 fg 9%、无描边、等宽 11sp、高 20 |
| `Modifier.tokenShadow(level, shape)` | `--elev-1/2/3` | 层级阴影（Compose `shadow` 近似 CSS box-shadow） |
| `Modifier.fgFade(p)` / `Modifier.accentFade(p)` | `color-mix(fg/accent p%, transparent)` | 半透明覆盖色（chip/badge/骨架/热力/Tab 胶囊共用） |

### 5.5 图标基元（分类图标 / 应用图标）

| 基元 | 对齐原型 | 规格 |
|------|---------|------|
| `CategoryIcon(name, color, size = 34.dp)` | `.cat-icon` | 分类色 12% 淡底 + 圆角 `radiusMd` 方块；图标 20dp 线描（24×24 viewBox、`strokeWidth 1.7`、`fill=none`），描边色 = 分类色混 22% 前景色（`lerp(color, t.fg, 0.22f)`，即原型 `color-mix(k 78%, fg)`） |
| `CategoryIcons.keyOf(name)` / `drawableOf(key)` | 原型 s05 的 22 个分类线描 SVG | 分类名 → `res/drawable/ic_cat_<key>.xml`；收入类分类原型尚未绘制图标，默认回落该分类色的实心圆点 |
| `AppIcon(packageName, appName, size = 30.dp)` | `.app-icon` | 优先显示应用自身图标（`PackageManager.getApplicationIcon` → Bitmap，`ContentScale.Crop`，圆角 `radiusSm`）；取不到时回落「品牌色底 + 应用首字」——这就是原型 `background: var(--app, var(--fg-2))` 的兜底语义 |
| `AppIconCache` | —— | `LruCache`（96 项，取图边长 144px）缓存应用图标；取图固定发生在 `Dispatchers.IO`，`peek()` 供 Composable 首帧同步命中缓存，避免先渲染兜底再跳成真图标 |
| `AppBrandColors.colorOf(pkg)` | 品牌色表（与原型同源） | 表内应用用品牌色兜底；表外应用默认用中性色 `fg2` |

**取图判断规则**（原型 s02 的规律）：行标题里**应用名在前**时用 `AppIcon`（应用事件，如「微信 · 前台 12 分钟」）；
系统事件（屏幕点亮 / Wi-Fi 连接 / 充电中 …）默认保留 `TypeIconDot`。
该分流默认在唯一的事件行实现里统一完成 —— `app/src/main/java/com/bsfeng/monitor/ui/live/LiveCards.kt` 的
`LiveEventRow`（s01 最近事件 / s02 时间线共用，按记录类型 + `detail["package_name"]` 分流）。

## 6. 动效规范

### 6.1 弹性动画（Spring）

Compose 原生 `spring()` 动画用于交互反馈，模拟 iOS 弹性效果：

```kotlin
// 标准弹性参数
animationSpec = spring(
    dampingRatio = Spring.DampingRatioMediumBouncy,  // 0.5
    stiffness = Spring.StiffnessLow                  // 200f
)
```

**使用场景：**
- 按钮按下缩放（scaleX/scaleY 0.85~0.95 → 1.0）
- 列表项出现动画
- Tab 切换颜色过渡

### 6.2 页面转场

使用 Compose Animation 实现：

```kotlin
// 从右侧滑入（覆盖层页面）
AnimatedVisibility(
    visible = showPage,
    enter = slideInHorizontally() + fadeIn(),
    exit = slideOutHorizontally() + fadeOut()
)
```

**页面层级关系：**
- Tab 切换：无动画（直接切换）
- 覆盖层页面（SkipRule、Whitelist）：`slideInHorizontally` + `fadeIn`
- 列表项出现：`fadeIn` + `slideInVertically`

### 6.3 数字动画

金额/计数变化使用 `animateIntAsState` / `animateFloatAsState`：

```kotlin
val animatedValue by animateFloatAsState(
    targetValue = newValue,
    animationSpec = tween(durationMillis = 600)
)
```

### 6.4 开屏动效时序（`BrandSplash`）

开屏默认由 `app/src/main/java/com/bsfeng/monitor/ui/components/BrandSplash.kt` 的**单一时钟**驱动：
整条时间轴用一个 `Animatable` 时钟推进，各元素按 `segment(ms, delay, dur, easing)` 取切片，
与原型 CSS 的 `animation-delay + animation-timing-function + fill:both` 一一对应。
新增开屏元素时推荐沿用这一「单时钟 + 切片」写法；缓动默认取 `LocalDesignTokens.current` 的
`easeStandard` / `easeOut` / `easeSpring` / `easeIn`，时长优先复用 `durOverlayIn` 等既有动效 token。

**默认时序（ms，出处：原型 `.open-design/08-prototype.html` §8 开屏，CSS 1599-1631 / JS 6028-6037）**

| 起始 | 元素 | 动画 | 时长 | 缓动 | 关键帧 |
|---|---|---|---|---|---|
| 0 | 整层 `.splash` | od-fade | 220（`durOverlayIn`） | `easeStandard` | opacity 0→1 |
| 60 | mark 环 | od-draw | 720 | `easeOut` | 自 3 点钟起顺时针描出（`drawArc` sweep 0→360×p） |
| 300 | 进度条 | od-splash-bar | 1100 | `easeStandard` | scaleX 0→1（transform-origin left） |
| 420 | mark 珠 | od-pop | 420 | `easeSpring` | opacity 0→1、scale .94→1 |
| 520 | 字标 | od-rise | 420 | `easeOut` | opacity 0→1、translateY 10px→0 |
| 620 | 副标 | od-rise | 420 | `easeOut` | 同上 |
| 1600 | 整层 `.is-done` | 淡出 | 240 | `easeIn` | opacity→0 |
| 1900 | 整层 | 回调 `onFinished` | — | — | 移除开屏 |

**品牌标内部默认配方**（原型占位 mark 无柱，取自品牌资产）：三根强度柱各 380ms、
缓动 `cubic-bezier(.22,.85,.3,1)`、起始延迟 200 / 100 / 280，落位 660ms —— 仍在原型 mark 窗口
（环 780ms / 珠 840ms）之内（出处：`.open-design/brand/splash-motion.html`）。

**减弱动效（系统关闭动画时）默认行为**：元素直接落终态 → 400ms 起收起 → 700ms 结束，
与原型 `prefers-reduced-motion` + JS reduce 分支同构（Compose 侧读
`rememberMotionEnabled()`，即系统 `ANIMATOR_DURATION_SCALE`）。

**几何（默认值）**：`.brand-mark` 96×96；`.splash-inner` 间距 `space3` + 内边距 `space6`、纵向居中；
字标 `headlineMedium`（28/700，lineHeight = `textXl` × `leadingBody`）；副标 `bodySmall` 色 `muted`；
进度条 120×3 + `margin-top space4`、轨道底 `fg` 10%、进度色 `fg2`、圆角 `radiusPill`。

> 完整取证（原型逐帧截图清单、浏览器 `getComputedStyle` 实测、Compose `segment()` 与浏览器逐点对照，
> 最大偏差 5.1e-5）见 `.open-design/impl-notes/负责人-r2/splash-motion-parity.md`。

## 7. 图表与动效实现方式

> 选型原则：在「零第三方业务依赖」前提下，图形绘制默认用 Compose Canvas 自绘，动效优先用 Compose BOM 内置能力；当出现自绘难以覆盖的需求时，优先选用成熟的 Compose 图表库。

### 7.1 图形绘制：默认 Compose Canvas 自绘

| 项 | 说明 |
|----|------|
| 默认实现方式 | `androidx.compose.foundation.Canvas` + `DrawScope` 系列 API（`drawArc` / `drawPath` / `drawLine` / `drawRect`） |
| 既有同源实现 | 记账统计环形图 `DonutChart`，位于 `app/src/main/java/com/bsfeng/monitor/finance/ui/FinanceStatsScreen.kt` |
| 依赖代价 | 0（Canvas 随 `androidx.compose.foundation` 提供，无需新增依赖） |
| 设计一致性 | 优先继承设计 token：颜色取 `MaterialTheme.colorScheme`（定义在 `app/src/main/java/com/bsfeng/monitor/ui/theme/Color.kt`），间距取 `MonitorSpacing`（定义在 `app/src/main/java/com/bsfeng/monitor/ui/theme/Dimens.kt`） |
| 动效一致性 | 入场与过渡时长沿用第 6 节动效规范，与全应用观感一致 |

### 7.2 动效：优先使用 BOM 内置 androidx.compose.animation

数字滚动、弹簧过渡、错落入场三类需求由 Compose BOM 内置的 `androidx.compose.animation` 覆盖：

| 需求 | 推荐 API |
|------|---------|
| 金额 / 计数滚动（count-up） | `animateIntAsState` / `animateFloatAsState` / `Animatable` |
| 弹簧过渡 | `animate*AsState` 搭配 `spring()` |
| 错落入场（stagger） | 按索引叠加固定 delay，配合 `AnimatedVisibility` / `animateItem` |

BOM 版本见 [编译配置 → 当前依赖](../开发指南/编译配置.md#当前依赖)，动效参数见本文第 6 节。

### 7.3 触发条件：何时选用成熟的 Compose 图表库

出现下列自绘难以覆盖的需求时，优先选用成熟的 Compose 图表库：

| 触发条件 | 说明 |
|---------|------|
| 交互式图表 | 需要缩放 / 平移 / 十字准线 / 点选联动等交互，自绘的手势与命中测试成本高 |
| 大数据量实时渲染 | 数据点数量级与刷新频率超出 Canvas 每帧重绘的可接受范围 |
| 图表类型成片扩张 | 单屏需同时呈现多种图表类型，且与既有自绘基线复用率低 |

选用时的准入要求（评估阶段逐项取证）：
1. **覆盖率**：先列需求清单，核对库的原生覆盖项与「引入后仍需自绘」的项数；
2. **体积**：实测引入前后 `./gradlew assembleDebug` 的 APK 体积差值；
3. **版本面**：核对库对 Compose BOM / Material3 / Kotlin 的版本要求，评估对 `app/build.gradle.kts` 中 BOM 锁定的影响；
4. **回归面**：依赖变更后被抬升的 UI 组件做整体回归；
5. **落库**：取证齐备后，实现方式变更记入 [编译配置](../开发指南/编译配置.md)，并同步更新本节。

### 7.4 图表色彩三角色（互不混用）

图表体系里有三个色彩角色（序列色 / 分类色板 / 强度阶），另有一组收支**语义对**；取值统一来自 token 层
（`ui/theme/DesignTokenTable.kt` → `GeneratedTokens.kt` → `DesignTokenCatalog.kt` 派生）：

| 角色 | Token | 默认用途 | 取值策略 |
|------|-------|---------|---------|
| 序列色 | `chartSeq`（`--chart-seq` = `--accent`） | 柱状 / 折线 / 面积 / 仪表 / 迷你走势 | 跟随主题强调色；同一图表内所有数据点**同色** |
| 分类色板 | `chart1..chart16`（`--chart-1..16`） | 扇形图分片 / 分类圆点 / 分类图例 / 分类网格 | **跨主题固定**：同一分类在 8 套主题下保持同色 |
| 强度阶 | `heatRamp`（原型 `.h0..h5`） | 热力条 | 序列色的透明阶梯 8 / 20 / 36 / 54 / 72 / 90%；0 值格默认取最低档 8%（卡片上几乎不可见） |
| 语义对 | `danger` / `success` | 收支双系列 | 与金额文字同色（支出红 / 收入绿），优先于分类色 |

使用要点：

1. **柱状图推荐单色**：同一图表内所有柱子取序列色 `chartSeq`，让「高度」单独承载数值信息
   （逐柱循环取色会画成「彩虹柱」，原型早期版本即为反例）。
2. **折线 / 圆环 / 仪表推荐只描边不填充**（`drawStyle = Stroke`）：原型曾因 `.s1{fill}` 覆盖
   `.chart-arc{fill:none}` 把环图填成实心饼；Compose 侧用 `drawArc` + `Stroke` 天然规避。
3. **分类身份色跨主题不变**：分类分片 / 分类圆点只取 `chart1..16`；切主题时只有序列色
   （趋势图主色）跟随变化。
4. **取色入口**：屏内推荐只读 `LocalDesignTokens.current`（`t.chartSeq` / `t.categoryDot(i)` /
   `t.heatCell(i)`），色值字面量集中在 `ui/theme/` 内维护，checkUiStyle 会在构建期核对。
5. **分类色分配**：按分类在 `finance_categories` 的 `sort_order` 取 `index % 16`
   （`DesignTokens.categoryDot(i)`），相邻分类默认不同色。

### 7.5 扇形图与趋势图形的分工

用户已在方案对比页逐套对比后选定：**占比用扇形图，趋势用柱状 / 面积 + 数值直标**。

**占比 → 扇形图 `PieChart`（`ui/components/Charts.kt`）**

| 项 | 规范 |
|----|------|
| 形态 | 实心扇形（`useCenter = true` + `Fill`），无中心文字；数值放在外部图例里 |
| 角度 | 自 -90°（12 点方向）起算、顺时针累加：`sweep = 360 × value / total` |
| 分片缝隙 | 每片用卡片底色（`surface`）描 2dp 边（`PIE_SEAM`），相邻分片不糊成一团 |
| 取色 | 默认分类色板 `chart1..16`（跨主题固定） |
| 尺寸 / 动效 | 默认 128dp（与 `RingChart` 的 `--ring-size` 一致）；入场按分片错峰扫出（`durChart`） |
| 图例 | 推荐「色点 + 名称 + 数值 + 百分比」四段式 |

**趋势 → 柱状 / 面积 + 数值直标**

- `BarChart(showValues = true)`（默认开）：柱顶直标数值，顶部留白 22dp 容纳文字；数值文本在
  `drawWithCache` + `rememberTextMeasurer` 中一次测量，绘制期只 `drawText`（滚动不掉帧）。
- `AreaChart(markPeak = true)`（默认开）：峰值点上方标注「峰值 N」。
- 单值进度环 `RingProgress(fraction)` 保留给预算使用率这类场景（轨道 + 单弧 + 中心标签）；
  多段占比优先 `PieChart`，需要环形容器 + 中心数值时用 `RingChart`。
- **同一图形内只用一种角色**：占比图取分类色板、趋势图取序列色，两套色彩不在同一个图形里混用。

## 8. 触觉反馈（震动）

### 8.1 系统提供

通过 `LocalHapticFeedback` 或 `View.performHapticFeedback` 使用系统触觉反馈，零第三方依赖。

### 8.2 标准震动类型

| 类型 | Compose API | 触发场景 |
|------|-------------|---------|
| 轻触（Light） | `HapticFeedbackConstants.CONFIRM` | 开关切换、列表点击 |
| 中触（Medium） | `HapticFeedbackConstants.KEYBOARD_TAP` | Tab 切换 |
| 重触（Heavy） | `HapticFeedbackConstants.LONG_PRESS` | 长按操作 |

### 8.3 用法

```kotlin
val view = LocalView.current

// 开关操作（通用）
Switch(
    checked = value,
    onCheckedChange = {
        newValue = it
        view.performHapticFeedback(HapticFeedbackConstants.CONFIRM)
    }
)

// Tab 切换
onClick = {
    selectedTab = index
    view.performHapticFeedback(HapticFeedbackConstants.KEYBOARD_TAP)
}
```

### 8.4 使用规则

1. **开关、按钮点击：** 必须附带触觉反馈
2. **列表项点击：** 建议附带触觉反馈
3. **页面转场、滚动：** 不附带触觉反馈
4. **禁止滥用：** 同一操作不应触发多次震动

## 9. 布局规范

### 9.1 页面层级

```
MonitorTheme (顶层主题) ─── 定义 ColorScheme + Typography + Shapes
  └─ Scaffold ─── 提供导航栏 + 安全区域
       ├─ NavigationBar ─── 底部 Tab 导航
       └─ 页面内容 ─── 各 Screen 组件
```

### 9.2 编码约定

1. **命名：** Screen 层函数命名 `XxxScreen`，私有组件命名 `XxxItem` / `XxxRow`
2. **参数：** Screen 函数第一个参数为数据/回调，最后一个参数为 `modifier: Modifier`
3. **主题引用：** 颜色 → `MaterialTheme.colorScheme`，字号 → `MaterialTheme.typography`，间距 → `MonitorSpacing`
4. **ViewModel：** 在 Screen 入口通过 `viewModel()` 默认参数获取，下层组件通过参数传入

### 9.3 屏幕适配

- 使用 `Modifier.fillMaxSize()` / `fillMaxWidth()` 自适应
- 避免固定宽高（有特殊布局意图的除外，如 52.dp 时间列宽）
- 底部留白：使用 `WindowInsets.navigationBars` + `Spacer(Modifier.height(96.dp))`（为 FAB 预留空间）

## 10. 主题代码结构

```
ui/theme/
├── Color.kt       — 所有颜色定义 + ColorScheme 生成
├── Type.kt        — Typography 定义 + 对照表
├── Dimens.kt      — Spacing / Radius / IconSize
├── Theme.kt       — MonitorTheme 入口 + 便捷访问对象
└── Components.kt  — 复用组件（7 个）
```

> **修改原则：** 修改颜色/字号/间距时，先在 `ui/theme/` 中改定义，所有页面自动生效。禁止在各 Screen 文件中直接定义颜色或字号常量。
