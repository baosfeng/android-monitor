> 改动画 / 震动 / 转场 / 按压手感时先查下面的表。**为什么这么设计、视觉口径**见 [设计规范](设计规范.md) §6 动效、§8 触觉；帧预算与排查口径见 [滚动性能](../开发指南/滚动性能.md)。

## 动效分档

`foundation/MotionTier.kt`：`enum class MotionTier { FULL, NORMAL, REDUCED }`，`MotionTier.scale` = 1f / 0.75f / 0f。全局单例 `MotionConfig.get()` 暴露三个 StateFlow——`userTier`（用户选择，设置页选中态读它）、`tier`（生效值，动效基元订阅它）、`autoDowngraded`（自动降档标记），热路径同步读用 `current()` / `tierScale()`。默认 `FULL`；系统「动画时长缩放 = 0」由 `effectiveMotionTier()` 压到 `REDUCED`，用户选择保留、系统恢复后自动还原。

推荐：档位一律经 `components/Motion.kt` 的 `rememberMotionTier()` 取，时长与缓动一律经 `MotionTier.scaleDuration(ms)` 或 `t.springOf(MotionToken.Xxx)`（`MotionToken` 同在该文件）取——`spring(dampingRatio = 0.5f, stiffness = 200f)` 这类魔数会让同一手感被拆成几份。`scaleDuration` 在 `REDUCED` 档返回 0，此时调用点走「直接落终态」分支，而不是播一段 0ms 动画。

## 卡顿自动降档

`foundation/JankMonitor.kt` 用 `Choreographer` 采样，判决口径唯一实现是纯函数 `isJankyWindow()`：`JANK_WINDOW_FRAMES`（120）帧窗口内样本 ≥ `JANK_MIN_SAMPLES`（30）、超标帧（`JANK_FRAME_FACTOR` = 2× 刷新间隔）占比 > `JANK_RATIO_THRESHOLD`（0.15）且超标帧 ≥ 2 帧 → `MotionConfig.autoDowngradeToNormal()`，只降不升、落盘一次。两帧间隔 > `JANK_IDLE_GAP_MS`（1000.0）视为切后台 / 锁屏，这段样本直接丢弃。已挂在 `MainActivity`（`app/src/main/java/com/bsfeng/monitor/MainActivity.kt`）的 `onResume` / `onPause`，新增页面默认不必自己挂。

## 数字滚动与入场

`components/Motion.kt` 里 `animatedCount` / `animatedAmount` 是按 `durChart` + `easeOut` 滚到目标的值层 API；`AnimatedNumber` 是配套文本层（`prefix` / `suffix` / `style` / `color` 同 `Text`）。`Modifier.staggerEnterAt(index)` 已是「进度 → alpha + 上浮 `STAGGER_RISE`」的一步式封装，内含减弱动效兜底；`maxSteps` 默认取 `staggerStepsFor(tier)`，`NORMAL` / `REDUCED` 下步数为 0（全部同时入场），`FULL` 档上限 `FULL_STAGGER_MAX_STEPS`（12，`components/Motion.kt` 以 `STAGGER_MAX_STEPS` 转出）。长列表的现有写法是 `if (index < STAGGER_MAX_STEPS) Modifier.staggerEnterAt(index) else Modifier`，见 `ui/AdScreen.kt` / `ui/WhitelistScreen.kt`。

## 按压反馈

`foundation/PressFeedback.kt`：按下缩到 `PRESS_SCALE_TARGET`（0.96f），走 `graphicsLayer` 绘制期缩放（不进 measure/layout），spec 取 `t.springOf(MotionToken.Press)`。默认 `Modifier.pressFeedback(interaction)`；只要数值时 `rememberPressScale(interaction)`，纯函数 `pressScaleTargetFor()` 便于单测。`interaction` 必须与触发点击的 `clickable` / `combinedClickable` 共用同一实例，否则收不到 Press 事件（表现为「怎么按都不缩」）；禁用态传 `enabled = false`。

`components/Controls.kt` 的 `AppFab` / `Chip` / `AppSwitch` **内部已接** `pressFeedback` + `rememberHaptic()`。调用点只传 `modifier`：外层再叠 `graphicsLayer` 缩放会与内部 0.96 相乘（外层 0.88 × 0.96 ≈ 0.845，按得比设计值重），`pointerInput` 会抢掉内部 Press 事件，且绕过档位让精简档仍然缩放。

## 触觉

`foundation/Haptics.kt` 是唯一出口。六档 `HapticTone`：`LIGHT`（开关、Chip）、`MEDIUM`（Tab、FAB）、`HEAVY`（长按）、`SUCCESS`（保存完成）、`WARNING`、`REJECT`（校验失败）。`View.performHaptic(tone)` 内部过三重闸门（系统 `systemHapticEnabled`、`View.isHapticFeedbackEnabled`、应用内 `HapticConfig.isEnabled`）并做强度换算（`HapticStrength.toneFor`），调用点不自判版本与系统开关。`HapticConfig` 提供 `setEnabled` / `setStrength` / `resetToDefault`，热路径读 `isEnabled` / `currentStrength`。

`components/Haptics.kt` 的 `performConfirmHaptic()` 已 `@Deprecated`，等价 `performHaptic(HapticTone.SUCCESS)`；新代码直接写 `HapticTone`。

## 转场

`foundation/Transitions.kt` 分四层：纯函数 `transitionSpecFor(role, motionEnabled, tokens)` → `TransitionSpec`（可 JVM 单测）、`toEnterTransition` / `toExitTransition`、`@Composable` 一步入口（上文八个基元）、`AnimatedScreenOverlay`（`AnimatedVisibility` + `BackHandler`）。角色由 `TransitionRole` 决定参数：整屏水平位移、抽屉垂直、弹窗只 fade + scale（自 `DIALOG_SCALE_FROM` = 0.94f）、折叠展开垂直；时长取 `durOverlayIn/Out` / `durPage`，缓动进场 `ease-out`、退场 `ease-in`，减弱动效档返回 `None`。Tab 切换默认无动画。

## 绘制期性能

前提：动画值只影响绘制、不影响布局。

- 位移 / 透明度：`foundation/GpuMotion.kt` 的 lambda 版 `gpuSlideX { value }` 把取值放进 layer 块，动画推进不触发重组。
- `Path` / `Brush`：`foundation/DrawCache.kt` 的 `rememberDrawCache()`，在 `drawWithCache` 的 build 块内先 `onSize(size)` 再 `path(key)` / `brush(key)`，绘制 lambda 内只读；key 取少量常量或颜色值，尺寸变化由 `onSize` 触发清空。
- 底衬与系统栏：`Modifier.pageBackdrop()` 是页面底衬的唯一实现（构造见 `foundation/Backdrop.kt`），叠遮罩用 `ImmersiveScrim`，系统栏适配用 `MonitorEdgeToEdge`。

4 项检查各自期望 0 处命中，本地与 CI 同一条命令，命中即失败。

| # | 检查内容 | 推荐改法 |
|---|---|---|
| 1 | `*Screen.kt` 自画底衬渐变（`Brush.verticalGradient(listOf(t.backdropA`） | `Modifier.pageBackdrop()` |
| 2 | `onDrawBehind` / `onDrawWithContent` 体内 `Path()` / `Brush.` 构造 | 对象移进 `drawWithCache` 的 build 块 + `DrawCache` |
| 3 | `Modifier.offset(...)` 引用 `animate*AsState` 的值 | `Modifier.gpuSlideX/Y`（绘制期位移） |
| 4 | `AnimatedVisibility` 参数块内裸 `slideInHorizontally()` / `slideOutHorizontally()` / `slideInVertically()` / `slideOutVertically()` / `fadeIn()` / `fadeOut()`（不带 `animationSpec`） | `foundation/Transitions.kt` 基元或 `AnimatedScreenOverlay` |

脚本按行判定，已知局限：字符串 / 注释里的花括号会干扰块结束位置，跨行书写的 `offset(x = 变量)` 不在判定范围——这两类写法在仓库中不出现，保持即可。
