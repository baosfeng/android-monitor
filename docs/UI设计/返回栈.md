# 返回栈（返回键 / 返回手势）

> ⚠️ **何时阅读：** 新增整屏覆盖层、页面内子页、或任何"按返回键应该退一层"的界面之前必读。

## 一句话结论

返回键与左滑返回**只有一个分发入口** [`BackRouter`](../../app/src/main/java/com/bsfeng/monitor/ui/foundation/BackRouter.kt)：每层界面用 `BackLayerRegistration` 把自己登记进栈，根 `BackHandler` 只调 `backRouter.pop()`，一次返回退一层。

## 为什么不再各处写 BackHandler

各处自行注册 `BackHandler` 时，**谁先收到返回由组合顺序决定**，而组合顺序会随重组与页面进出变化。曾经的现场：设置 → 功能开关 → 广告跳过细则 → 规则管理，在规则页按返回，画面留在规则页，但实际把下面的「广告跳过细则」关掉了（回归 probe 日志：`overlay back tag=settingsSub`），再按一次才退规则页 —— 用户看到的是"退了两层"。

## 层级

`BackLayer.priority` 决定谁先退，数字大的在上；同层按打开顺序，后开的先退。

| 层级 | 用途 | 典型 |
|---|---|---|
| `INNER` 50 | 同一覆盖层内部的子路由 | 验证器详情 / 扫码 |
| `OVERLAY` 40 | 与 Tab 同级、铺满全屏的覆盖层 | 规则管理 / 白名单 / 额度设置 / 验证器 / 行程 / 外观 |
| `PAGE_SUB` 30 | 设置页二级 / 三级子页 | 功能开关 → 广告跳过细则 |
| `PAGE_ROUTE` 20 | Tab 内部的页面路由 | 记账新增 / 编辑 / 统计 / 预算 / 导入 |
| `PAGE_TAB` 10 | Tab 内的二级视图 | 记账「统计汇总」子 Tab |

## 新增一层时怎么做

1. 能让 `AnimatedScreenOverlay` 承载的，直接用它的 `backLayer` 参数，不用额外写代码。
2. 页面内部的子路由（同一容器里的下一屏）在容器处登记一次即可：`BackLayerRegistration` 里的 `onBack` 每次重组都会换成最新闭包，**不需要**每层各登记一条。
3. 登记 key 要稳定（同一屏用同一个 key）；同一 key 重复登记是替换，不是叠加。

## 根返回键的接管条件

`BackHandler(enabled = backRouter.canGoBack)`：栈为空时不接管，返回键/手势交还系统（退桌面）。不要在页面里再加"兜底 BackHandler"，否则会绕过层级重新变成组合顺序决定。

## 边界

- 浏览器式的"前进"不在此范围：本项目只有后退语义。
- 弹窗（Dialog / BottomSheet）仍用各自的 `BackHandler`：它们是模态覆盖，优先级高于页面栈，且生命周期随可见性收敛。
- 未装配 `BackRouter` 的场景（Compose 预览、单测）由 `AnimatedScreenOverlay` 自带的 `BackHandler` 兜底，行为与改造前一致。
