# 桌面小组件 · 预览图与小米入口

> 「安卓小部件」列表里这 6 个组件曾经是空白样张；本文说清样张怎么来的，以及小米用户到底该从哪个入口添加。

## 结论

- 6 个组件都挂了 `android:previewImage`，样张由单测从**同构镜像**渲染，不含任何真实账目与账号。
- 小米 / HyperOS 把标准 AppWidget 统一收进「安卓小部件」分类；进「小部件中心」必须走小米小部件开放平台审核，个人包拿不到，本项目不做。
- 应用内引导（设置页「桌面小组件」的手动路径提示）与样张是同一件事的两半：让用户在那一层分类里找得到、认得出。

## 预览图怎么来的

| 步骤 | 位置 |
|---|---|
| 改视觉 | `widget/WidgetStyle.kt` |
| 同步镜像 | `test/.../widget/WidgetPreviewSkin.kt`（皮）+ `WidgetPreviewScenes.kt`（6 块内容） |
| 重出图 | `./gradlew :app:testDebugUnitTest --tests "*WidgetPreviewImageTest*"` |
| 落盘 | `res/drawable-nodpi/widget_*_preview.png` |
| 引用 | 6 个 `res/xml/widget_*_info.xml` 的 `android:previewImage` |

画布尺寸：4×2 → 350×190dp（Wide 档「顶栏 + 40sp 金额 + 进度条 + 底栏两块」实测要 189dp，按 170dp 画会把底栏数值裁掉）、2×1 → 170×110dp、1×1 → 110×110dp。

按 xhdpi（2x）出图，圆角外挖透明（否则深色壁纸上是一圈浅灰方角）。

⚠️ 真机实测（小米 14 / HyperOS，density 3.0）：4×2 是 **347×177dp**，推算 2×1 只有 **~170×84dp** —— 比上面画布小。compact 档在 84dp 高下必然溢出（顶行 26 + 8 + 读数 45 = 79dp，加 32dp 内边距共 111dp）。预览图先按设计基准出，真机适配是独立一轮（改档位阈值 + 内边距，需要设计确认）。

## 为什么必须单测出图

Glance 的 composition 只在真机 launcher 上出 RemoteViews，单测渲染不了；而预览图会随 APK 公开，不能拿真机截图（含真实金额）。所以用 Compose 把 `WidgetStyle` 的同一套常量复刻一遍：

- 圆角、内边距、字号、图标块比例**全部取自** `CARD_RADIUS` 与 `WidgetPalette`，不复制字面量；
- 同源约束：改皮肤必须同步镜像，否则预览图与桌面上的真实组件不符 —— 比没有预览图更糟（用户按图去找、找不到）。

## 小米上的入口

- 桌面双指捏合 / 长按空白 → 添加小部件 → 底部「**安卓小部件**」→ 搜「监控」。
- 设置页的「添加」按钮走 `requestPinAppWidget`；小米桌面不弹确认框也不回调，失败时提示同一句手动路径。
- 想进「小部件中心」：企业开发者账号 + 应用商店上架 + 邮件 `miui-widget@xiaomi.com` 开通上传入口 + 平台送审上线，见 [小米官方 FAQ](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1591)。
- ⚠️ 只给 receiver 加 `<meta-data android:name="miuiWidget" android:value="true" />` 而不送审：组件会从「安卓小部件」里消失，又进不了小部件中心 —— 两边都找不到。
