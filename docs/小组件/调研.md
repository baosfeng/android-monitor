# 桌面小组件（App Widget）调研

> 调研时间 2026-10。目标：判断这个 App 能做什么样的小组件、用什么技术栈、代价多大。结论可直接作为首批 widget 的选型依据。

## 结论

- **能做的**：信息型 + 快捷入口型小组件（数字/进度/一行文案 + 点击跳转），**不能**做动画、自定义绘制、水平滑动、复杂表单。
- **技术默认选 Jetpack Glance 1.2.0**：与现有 Compose 风格一致，响应式尺寸/深浅色/预览/状态管理都是白送的。代价是引入 `androidx.work` 与 `androidx.datastore`（项目已移除 WorkManager），实测依赖树见下。
- **刷新靠已有链路**：AlarmReceiver 60 秒心跳兜底 + 记账 `FinanceMutationSignal` / 额度 `QuotaScheduler` 推送，不新增唤醒源、不加权限。
- **范围（2026-10 决定）**：6 个全做；**不做**最近事件明细（桌面可见，撞隐私红线）与更新红点（联网成本高、无持久态）。

## 两条技术路线

| | RemoteViews + AppWidgetProvider | Jetpack Glance 1.2.0 |
|---|---|---|
| 写法 | XML 布局 + PendingIntent + onUpdate | `@Composable`，编译成 RemoteViews |
| 版本状态 | 系统 API，长期稳定 | 2026-08-26 发布 1.2.0 稳定版（1.3.0-alpha02 在途，要求 AGP ≥ 9.2 且积累 alpha 风险，不追） |
| 依赖 | 0 | glance + glance-appwidget；实测带入 `work-runtime 2.7.1`、`datastore 1.0.0`（alias 已配，`./gradlew :app:dependencies` 可解析） |
| 响应式尺寸 | 手动监听 `onAppWidgetOptionsChanged` 切布局 | `SizeMode.Responsive/Exact` + `LocalSize` |
| 深浅色 | 自建 `-night` 资源 | `ColorProvider(day/night)` |
| 状态 | 自己存 | `updateAppWidgetState` + DataStore |
| 测试 | RemoteViews 难断言 | `glance-appwidget-testing` 可单测 |
| 体感 | 老项目多、代码碎 | 新项目主流；Glance 的 update 走 WorkManager session |

**选择依据**：项目已是 Compose + 零 XML 布局（`res` 下无 layout），Glance 复用同一心智；RemoteViews 要从零补布局、颜色、点击、状态。仅当「不能新增 WorkManager 依赖」是硬约束时才退回 RemoteViews。

## 系统能力与硬限制

- **手势**：只有触摸和垂直滑动。水平滑动被桌面占用，滚动列表是唯一例外（且条目有限）。
- **控件白名单**：文本/图片/按钮/进度条/复选框/单选/开关/LazyColumn 等；不能自定义 View、Canvas、动画。
- **刷新**：`updatePeriodMillis` 最小间隔 30 分钟；实时性靠自己触发 `AppWidgetManager.updateAppWidget`（本项目有 60 秒心跳可用）。
- **回调预算**：`onUpdate` 里只有约 10 秒，超时 ANR；异步必须 `goAsync()`；**禁止**从 `onReceive`/`onUpdate` 起前台服务（后台触发会抛 `ForegroundServiceStartNotAllowedException`）。
- **点击**：`PendingIntent` 跳 Activity / 发广播 / 起服务；可直接复用现有 `EXTRA_START_TAB` 深链。
- **Android 12+**：圆角、尺寸断点（2×2 / 4×2 / 4×4…）、动态配色、`targetCellWidth/Height`。
- **Android 12+ 预览**：`providePreview` + `setWidgetPreview`，小组件选择器里显示真图；Android 15+ 的生成式预览推送限流约 2 次/小时，别频繁刷。
- **锁屏小组件**：Android 16 起 Pixel 支持，国内 ROM 是否开放由厂商决定，**不作依赖**。
- **targetSdk 37 强制内存上限**：Android 17 行为变更，RemoteViews 图片数据总量超过 `6 × 宽 × 高` 字节会**抛 IllegalArgumentException 直接更新失败**（API 36 及以下只告警）。→ 我们以文字/图标为主，不要塞大图。
- **进程关系**：widget 更新由 App 进程执行，进程活着可以读内存态；进程死了只能读持久化数据（SQLite / SharedPreferences）。

## 国产 ROM 现实（小米/红米 HyperOS）

- `requestPinAppWidget` 在小米上**不弹确认框**、空间不足自动开新页；添加成功回调不可靠 → 用 `getAppWidgetIds()` 前后对比判断。
- 同一小组件在不同机型的占格不同（4×2 可能变 5×3），必须按尺寸桶适配。
- 系统字体放大后容易遮挡/裁切，布局不要写死高度。

## 本项目数据可得性

| 数据 | 来源（文件:方法） | 状态 |
|---|---|---|
| 今日事件数 / 跳过数 / 活跃分钟 | `OverviewViewModel.buildSnapshot()`：`RecordStore.queryByDate` | SQLite，按天有界查询 |
| 记账月收支 / 预算进度 | `FinanceManager.getMonthlyStats()` / `getMonthlyBudget()` | SQLite；写路径有 `FinanceMutationSignal` 信号 |
| 额度快照 | `QuotaSnapshotStore`（SharedPreferences JSON） | 已落盘，widget 直接读，**禁止在 widget 内联网** |
| 监控健康 | `MonitorAccessibilityService.isRunning` + `HeartbeatWatchdog` 心跳时间 | 内存态 + SharedPreferences |
| 广告跳过累计 | `SkipRuleHits.loadSkipHits`（无时间下界，成本随表增长） | SQLite 派生 |
| 传送状态 | `TransferEngine.running / devices` | 纯内存态，进程回收即丢 |

## 刷新架构（建议）

| 触发 | 作用范围 | 说明 |
|---|---|---|
| `AlarmReceiver` 60s 心跳（已有） | 全部 widget | `onReceive` 里加一行 `WidgetRefresher.refresh()`；不新增唤醒源 |
| `FinanceMutationSignal`（已有） | 记账 widget | 写交易后立即刷；进程内信号，冷启动丢失 |
| `QuotaScheduler`（已有） | 额度 widget | 跟随 1/3/6 小时刷新 |
| Glance `update()` 自带 | — | 走 WorkManager session，天然节流；不要在 `onUpdate` 里做 IO 超过几秒 |

## 待验证 / 风险

1. **Glance 带入 WorkManager**（已拍板）：接受传递依赖 —— 它只服务 widget 更新会话，不启动其它后台任务；退回 RemoteViews 会丢掉响应式与预览能力，不划算。
2. **APK 增量**：本次只验证了依赖可解析，没做真实构建对比（未引用代码会被 R8 裁掉，体积要等首个 widget 落地后量）。
3. **HyperOS 真机**：pin 行为、占格、字体缩放需真机验证。
4. **测试**：widget 渲染无法用现有 Robolectric 覆盖，逻辑抽纯函数单测 + 真机截图取证。
