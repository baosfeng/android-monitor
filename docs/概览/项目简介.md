# 手机行为监控系统 —— 项目概述

## 1. 项目目标

开发一款 Android 端行为监控 App，记录用户在手机上的所有操作行为（打开什么应用、何时锁屏/解锁、何时充电等），通过无障碍服务实时采集，并通过 HTTP API 实时上报到自建后端服务器。用户可在后端自行分析自己的行为数据。

**核心设计理念：静默、无感、省电、精简。** 安装后用户完全感知不到它的存在——通知栏永远不出现，无图标、无声音、无弹窗。只在遇到故障时主动通知用户。

## 2. 核心能力

- 实时监听前台 App 切换（包名 + Activity 级）
- 监听屏幕亮/灭、解锁成功/失败
- 监听充电状态、WiFi 连接、耳机插拔
- 监听 App 安装/卸载、通知到达、电池状态
- 所有事件通过统一结构化 JSON 实时上报
- 支持离线缓存，网络恢复后补传

## 3. 设计哲学

| 原则 | 说明 |
|------|------|
| **静默无感** | 无启动动画、无默认通知、无弹窗，只在故障时通知用户 |
| **省电优先** | 避免轮询、减少唤醒、合并网络请求、不在后台做冗余计算 |
| **内存精简** | 不引入 Hilt/Dagger 等重型框架，手动依赖注入，APK 体积目标 ≤ 2MB |
| **仅事故通知** | 通知栏仅在服务异常（如被系统杀死、网络长时间中断）时显示，正常运行完全无感 |
| **开发者测试完成** | 每次改动经过真机测试验证后，由开发者打包 APK 交付给用户侧载安装 |

## 4. 系统架构

```
┌──────────────────────────┐      HTTP REST API       ┌──────────────────┐
│    Android 手机端          │ ──────────────────────→  │   自建后端服务器    │
│                          │     实时上报事件           │   （用户自建）     │
│  ┌──────────────────┐   │                           │                  │
│  │ AccessibilityService │  ← 系统回调                 │  ┌────────────┐  │
│  │  监听窗口变化/通知   │   │                           │  │ 数据库      │  │
│  └────────┬─────────┘   │                           │  └────────────┘  │
│           │             │                           └──────────────────┘
│  ┌────────▼─────────┐   │
│  │ 事件处理器 (Event) │   │
│  │  → 格式化 JSON   │   │
│  └────────┬─────────┘   │
│           │             │
│  ┌────────▼─────────┐   │
│  │ 上报引擎 (Reporter) │   │
│  │  → 实时 HTTP 发送 │   │
│  │  → 失败本地缓存   │   │
│  └──────────────────┘   │
└──────────────────────────┘
```

### 4.1 组件说明

| 组件 | 职责 |
|------|------|
| **AccessibilityService** | 系统级回调入口，监听窗口变化、通知等 |
| **BroadcastReceiver** | 监听屏幕亮/灭、充电、WiFi、耳机等系统广播 |
| **EventCollector** | 统一接收各类事件源，标准化为 Event 模型 |
| **EventReporter** | 负责上报（实时 + 重试 + 缓存） |
| **LocalCache** | 网络不可用时的本地 Fallback 存储（SQLite） |
| **Backend API** | 用户自建的服务端接收端 |

## 5. 技术栈

| 层级 | 技术 |
|------|------|
| Android 开发语言 | Kotlin |
| UI 框架 | Jetpack Compose |
| 导航 | Navigation Compose |
| 本地存储 | Room (SQLite) |
| 网络请求 | OkHttp + Retrofit |
| JSON 序列化 | Kotlinx Serialization |
| 后台调度 | WorkManager + AlarmManager |
| 依赖注入 | 手动（不引入 Hilt/Dagger） |
| 异步 | Kotlin Coroutines + Flow |
| 核心监听 | AccessibilityService + BroadcastReceiver |
| 目标 API | Android 16 (API 36) |
| 包名 | com.bsfeng.monitor |

## 6. 非功能性需求

| 需求 | 目标 | 实现方式 |
|------|------|---------|
| **电池消耗** | 日耗电 ≤ 5%（基于 5000mAh 日常 12h） | 非轮询架构、批量上报、无冗余计算 |
| **APK 体积** | ≤ 2MB | 不使用重型库、代码混淆、仅含必要资源 |
| **内存占用** | 常驻内存 ≤ 30MB | 精简事件模型、及时释放、无缓存泄漏 |
| **上报延迟** | 事件发生后 ≤ 2 秒触发上报 | 实时回调 → 立即入队 → 批量合并发送 |
| **离线容错** | 本地缓存 ≥ 3 天数据 | Room 持久化，网络恢复后自动补传 |
| **用户感知** | 正常运行时完全无感 | 无前台服务、无通知栏图标、无声音/震动/弹窗 |
| **故障通知** | 服务异常时仅通知 1 次 | 被系统杀死、网络长时间中断时触发通知 |
