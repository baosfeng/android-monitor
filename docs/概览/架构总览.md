## 架构分层

| 层级 | 说明 | 核心组件 |
|------|------|---------|
| **事件源层** | 产生事件的入口，实现 `EventSource` 接口 | `MonitorAccessibilityService`, `ReceiverRegistrar` (通过 BroadcastReceiver) |
| **采集层** | 接收 EventSource 原始数据，组装 RawEvent（含导航上下文 + 设备状态） | `RawEventCollector`, `NavigationContextTracker`, `RawEvent`, `NavigationTracker`, `AppSessionManager` |
| **管道层** | 将 RawEvent 扇出给所有已注册 Handler，独立协程互不阻塞 | `EventPipeline`, `EventHandler`, `EventPipelineImpl` |
| **执行层** | 每个 Handler 只做一件事：持久化/上传/日志 | `DatabaseHandler`, `UploadHandler`, `LogHandler` (可按需扩展) |
| **UI 层** | 用户界面（调试/管理） | `MainActivity`, `MainScreen`, `StatsScreen`, `SettingsScreen`, `MainViewModel` |
| **工具层** | 公共工具和配置 | `AppConfig`, `AppUtils`, `MonitorApp` |

## 数据流

```
系统事件 → AccessibilityService (实现 EventSource)
    → RawEventCollector.emit(source) → 组装 RawEvent（含导航上下文）
        → EventPipeline.dispatch(rawEvent)  →  fork 扇出
            ├─ DatabaseHandler → EventEntity → SQLite
            ├─ UploadHandler  → 入队列 → EventReporter → HTTP POST
            └─ LogHandler     → Logcat 调试日志
```

- 事件源实现 `EventSource.collectRaw()` 提供原始数据，`RawEventCollector` 负责组装成 `RawEvent`（自动填充 `deviceId`、`timestampMs`、导航上下文、设备快照）
- `EventPipeline` 将 `RawEvent` 扇出给所有 Handler，每个 Handler 运行在独立协程中，互不阻塞
- 新增处理逻辑只需实现 `EventHandler` 接口并在 `MonitorApp.initPipeline()` 中注册
- 旧的 `EventCollector` 已移除，被 `RawEventCollector + EventPipeline` 取代

## 依赖注入策略

**手动依赖注入**（不引入 Hilt/Dagger）：
- 通过 `MonitorApp.instance` 静态实例获取 Application Context
- 各组件单例通过 `getInstance()` 懒加载模式
- 手动创建依赖链：`Activity → ViewModel → Repository/Reporter`

## 技术栈

| 层级 | 技术 |
|------|------|
| 开发语言 | Kotlin |
| UI | Jetpack Compose (Material 3) + Compose BOM 2024.12.01 |
| 导航 | Navigation Compose 2.8.5 |
| 本地存储 | **SQLiteOpenHelper**（系统内置，无 Room 依赖） |
| 网络 | **HttpURLConnection**（系统内置，无 OkHttp/Retrofit 依赖） |
| JSON | **org.json.JSONObject**（系统内置，无 Kotlinx Serialization 依赖） |
| 后台调度 | **AlarmManager**（系统内置，无 WorkManager 依赖） |
| 异步 | Kotlin Coroutines + Flow |
| 构建系统 | Gradle (Kotlin DSL) + AGP |
