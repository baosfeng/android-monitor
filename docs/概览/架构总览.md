## 架构分层

| 层级 | 说明 | 核心组件 |
|------|------|---------|
| **事件源层** | 产生事件的入口 | `MonitorAccessibilityService`, `BroadcastReceiver`(s) |
| **事件处理层** | 统一接收、标准化、去重、富化 | `EventCollector`, `ScreenClassifier` |
| **上报层** | 批量打包、HTTP 上报、失败重试 | `EventReporter`, `ApiService` |
| **持久化层** | 本地数据库缓存 | `AppDatabase`, `EventDao`, `EventEntity` |
| **UI 层** | 用户界面（调试/管理） | `MainActivity`, `MainScreen`, `StatsScreen`, `SettingsScreen`, `MainViewModel` |
| **工具层** | 公共工具和配置 | `AppConfig`, `AppUtils`, `MonitorApp` |

## 数据流

```
系统事件 → BroadcastReceiver / AccessibilityService
    → EventCollector.emit() → 写入 Room
        → EventReporter.uploadBatch() → ApiService.uploadEvents()
            → HTTP POST /api/v1/events (批量)
```

- 事件源通过 `EventCollector.emit()` 异步写入 Room 数据库
- `EventReporter` 定时从数据库拉取未上报事件，批量打包后通过 Retrofit 发送
- 上报成功则标记已上传，失败则保留重试
- 上报引擎支持动态配置（间隔、批量大小、重试次数）

## 依赖注入策略

**手动依赖注入**（不引入 Hilt/Dagger）：
- 通过 `MonitorApp.instance` 静态实例获取 Application Context
- 各组件单例通过 `getInstance()` 懒加载模式
- 手动创建依赖链：`Activity → ViewModel → Repository/Reporter`
