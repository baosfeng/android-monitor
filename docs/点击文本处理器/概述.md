# 点击文本处理器

> **包路径：** `com.bsfeng.monitor.click`

App 专用的点击文本处理器模块。某些 App（如微信、企业微信）的点击事件文本提取需要针对其特有视图结构进行优化，本模块提供扩展点。

---

## 模块职责

当用户在 App 内点击元素时，`MonitorAccessibilityService` 通过 `TYPE_VIEW_CLICKED` 事件捕获点击行为。默认情况下，点击文本从 `AccessibilityEvent.text` 或 `contentDescription` 中提取。但在某些 App 中，这个默认文本可能没有意义——例如微信聊天列表中，点击某个聊天项时提取到的文本可能是时间戳（如"21:16"），而非群聊名称。

点击文本处理器模块解决这个问题：允许为特定 App 注册专用处理器，在默认提取结果不理想时提供更合适的替代文本。

## 接口定义

### AppClickHandler

**文件：** `app/src/main/java/com/bsfeng/monitor/click/AppClickHandler.kt`

```kotlin
interface AppClickHandler {
    /** 该处理器适用的包名 */
    val packageName: String

    /**
     * 获取比默认 clickText 更合适的点击显示文本。
     * @param event 原始 AccessibilityEvent
     * @param clickText 默认文本提取结果（可能为 null 或短字符串）
     * @return 更合适的显示文本，返回 null 表示使用默认逻辑
     */
    fun resolveClickDisplayText(event: AccessibilityEvent, clickText: String?): String?
}
```

实现此接口的类通过 `packageName` 声明自己负责哪个 App 的点击文本处理。

## 注册表

### AppClickHandlerRegistry

**文件：** `app/src/main/java/com/bsfeng/monitor/click/AppClickHandlerRegistry.kt`

```kotlin
object AppClickHandlerRegistry {
    fun getHandler(packageName: String): AppClickHandler?
    fun register(handler: AppClickHandler)
}
```

- `getHandler(packageName)` — 查找指定包名的专用处理器，找不到返回 null
- `register(handler)` — 动态注册自定义处理器（供扩展使用）

当前内置注册：

|------|--------|

## 微信实现

### WeChatClickHandler

**文件：** `app/src/main/java/com/bsfeng/monitor/click/WeChatClickHandler.kt`

#### 解决的问题

在微信聊天列表（LauncherUI）中，点击某聊天项时 `AccessibilityEvent.text` 可能只包含时间戳（如"21:16"），而非群聊名称。这是因为微信的列表项中，时间戳视图是直接可点击的 TextView，而群聊名称在父容器中。

#### 解决思路

从被点击的 View 沿祖先链向上爬，最多 10 层。在每层遍历所有子 View：

1. 只在 `TextView` / `EditText` 类型的子节点中搜索有意义的长文本（长度 ≥ 4 且不是点击文本本身）
2. 非文本节点但有直接长文本的也纳入考虑
3. 从所有找到的文本中选取最长的一个作为结果

#### 使用场景示例

```
聊天列表项（根节点）
  ├── TextView: "产品设计组"    ← 群聊名称（被提取）
  ├── TextView: "好的，马上处理"
  └── TextView: "21:16"        ← 被点击的 View（默认提取为时间戳）
```

## 调用链路

```
MonitorAccessibilityService.handleViewClick(event)
    │
    ├─ 默认提取 clickText (从 event.text / contentDescription)
    │
    ├─ AppClickHandlerRegistry.getHandler(packageName)
    │   │
    │   ├─ 找到处理器 → WeChatClickHandler.resolveClickDisplayText(event, clickText)
    │   │                 └→ 返回更合适的文本（或 null 表示不需要替换）
    │   │
    │   └─ 未找到处理器 → 使用默认 clickText
    │
    └─ 最终 displayText = handlerResolved ?: clickText
```

## 如何为新的 App 添加处理器

```kotlin
class MyAppClickHandler : AppClickHandler {
    override val packageName = "com.example.myapp"

    override fun resolveClickDisplayText(
        event: AccessibilityEvent,
        clickText: String?
    ): String? {
        // 默认文本已有意义时不需要处理
        if (clickText != null && clickText.length > 5) return null

        // 自定义提取逻辑
        val source = event.source ?: return null
        // ... 视图树遍历逻辑 ...
        source.recycle()
        return resolvedText
    }
}

// 在 AppClickHandlerRegistry 中注册
AppClickHandlerRegistry.register(MyAppClickHandler())
```
