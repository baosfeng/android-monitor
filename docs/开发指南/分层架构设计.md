# 分层架构设计

> 关联：[架构总览](../概览/架构总览.md) · [代码规范](代码规范.md)。

## 一、目标与判据

| 目标 | 衡量标准 |
|---|---|
| 层间单向依赖 | 下层不依赖上层，同层可依赖但避免循环 |
| 面向接口编程 | 跨层调用走接口，实现类对上层不可见 |
| 消除上帝类 | 每个类 ≤300 行，单类单职 |
| 构造器注入 | 消除 `MonitorApp.instance` 与 `object` 全局单例 |
| 可测试性 | 模块可独立测试，无需启动 Android 框架 |

## 二、分层与依赖方向

```
Presentation (Compose UI / Screen / ViewModel)  com.bsfeng.monitor.ui, .finance.ui
Domain       (纯 Kotlin：模型 / usecase / repository 接口)  .domain.model, .domain.usecase, .domain.repository
Data         (Repository 实现 / DataSource / Mapper)  .data.repository, .data.datasource, .data.entity
Infrastructure (Pipeline / Network / Persistence / DI / Core)  .pipeline, .network, .data.database, .core, .di
```

依赖方向：`Presentation → Domain ←→ Data → Infrastructure`。

| 层 | 可依赖 | 不可依赖 |
|---|---|---|
| Presentation | Domain、Infrastructure 的 Core/DI | Data、Network、Pipeline |
| Domain | 仅 Kotlin 标准库 | Android 框架、Infrastructure |
| Data | Domain（接口）、Infrastructure | Presentation |
| Infrastructure | Domain（模型） | Presentation、Data |

> ⚠️ 核心约束：**Domain 层无任何 Android 依赖**（Context、Handler、Looper 都不行），领域逻辑可在纯 JVM 单测运行，不需要 Robolectric。

## 三、各层设计要点

**Infrastructure**：框架级能力。`core/MonitorApp.kt` 只初始化 DI；`core/di/ServiceContainer.kt` 为手动 DI 容器（替代 `MonitorApp.instance`），`by lazy` 缓存 `appConfig` / `databaseHelper` / `eventRepository` / `navigationTracker` / `appSessionManager` / `skipRuleManager` / `skipRuleEngine` 等；使用方通过构造器拿到 `ServiceContainer`。`pipeline`、`network`、`util` 保持，`data/database` 迁入。`service/` 只做编排（见 §四）。`EventPipeline`/`EventSource` 属框架能力，归此层。`UploadHandler` 批处理修复：事件入队 → 检查阈值（`batchThreshold = 20`）→ 定时（`batchIntervalMs = 30_000`）刷出。

**Data**：实现 Domain 的 Repository 接口，封装本地 DB 与网络。`data/repository/*RepositoryImpl`、`data/datasource/{LocalEventDataSource, RemoteEventDataSource, PreferenceDataSource}`、`data/mapper/{EventMapper, RuleMapper}`。数据源只暴露最小方法集（如 `getUnsentEvents(limit)` / `markUploaded(ids)` / `insert(entity)` / `cleanOldEvents(before)`；`uploadEvents(batch)` / `registerDevice(request)`）。

**Domain**：纯 Kotlin 模块，架构核心。`domain.model`（Event、NavigationNode、SessionRecord、SkipRule、AppInfo）、`domain.repository`（★ 仅接口）、`domain.usecase`（ProcessWindowChange、ProcessClick、ExecuteSkipRule、ManageNavigation）。UseCase 不依赖 Android 框架，可在 JVM 单测直接测。`NavigationTracker`、`AppSessionManager` 从 `object` 改为 `class`，从而可构造器注入、每个测试用独立实例、不共享状态。

**Presentation**：Compose UI + ViewModel，只做展示与交互。ViewModel 通过构造器接收 UseCase，而不是直接依赖 Repository/DatabaseHelper/EventReporter。

## 四、上帝类拆分

`MonitorAccessibilityService`（当时 ~1000 行）→ 入口（~80 行）+ 5 个协作者 + `EventEmitter`：

```
MonitorAccessibilityService
├── WindowChangeHandler     窗口变化
├── ClickHandler            点击事件
├── NavigationOrchestrator  导航追踪
├── SessionOrchestrator     会话保存 / 恢复
├── SkipAdOrchestrator      开屏跳过集成
└── EventEmitter            发射事件到 Pipeline
```

`onAccessibilityEvent` 只按 `eventType` 分派（WINDOW_STATE_CHANGED → windowHandler，VIEW_CLICKED → clickHandler）。

`SkipRuleEngine`（当时 29KB）→ 拆出 `RuleMatcher`（选择器匹配）与 `MonitorScanner`（屏幕扫描）。
