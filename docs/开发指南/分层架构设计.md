# 分层架构设计

> 关联：[架构总览](../概览/架构总览.md) · [代码规范](代码规范.md)。

## 一、四层与依赖方向

| 层 | 位置 | 内容 |
|---|---|---|
| 表现层 | `MainActivity.kt`、`MainContent.kt`、`MainTabContent.kt`、`ui/`、`finance/ui/`、`transfer/ui/` | Compose 页面与 ViewModel |
| 领域层 | `domain/src/main/kotlin/com/bsfeng/monitor/domain/` | `model`、`repository`（仅接口）、`quota`、`totp`、`transfer`、`trip` |
| 数据层 | `data/DatabaseHelper.kt`、`data/repository/`、`record/` | SQLite 建表迁移、记录与规则读写 |
| 基础设施 | `service/`、`network/`、`core/di/`、`util/`、`skip/`、`autobook/` | 系统服务接入、HTTP、DI、公共工具 |

依赖方向：`表现层 → 领域层接口 ← 数据层实现`；基础设施可被三层依赖。

> ⚠️ 核心约束：`domain` 用 `org.jetbrains.kotlin.jvm`，**零 `import android.*`**（实测 0 处）。领域逻辑放这里才能在纯 JVM 单测里跑，不必拉起 Robolectric。

## 二、判定规则

| 场景 | 做法 |
|---|---|
| 新增业务逻辑 | 先问能否放进 `domain`（纯函数 / 状态机 / 规则）；能放就放，放不了再下沉到 `record/`、`skip/` |
| 表现层取数据 | 走 `domain/repository` 接口，实现类在 `data/repository/*Impl`；不在 `ui/` 里 new 数据源 |
| 需要 Context / 系统 API | 只能写在 `app` 模块；`domain` 用纯数据模型接收结果 |
| 跨模块共享模型 | 放 `domain/model`，`app` 侧只做映射 |

## 三、当前例外（别当成违规去"修"）

- `ui/` 实测 **0 处** import `data/` 或 `network/`，这条已守住。
- `finance/ui/FinanceViewModel` 直接依赖 `finance/FinanceManager`：记账是垂直切片，`FinanceManager` 同时充当仓储与业务层，未抽 `domain` 接口。
- 广播接收器与 `object` 工具（`RecordReceiver`、`AlarmReceiver`、`HealthChecker`）没有构造入口，仍读 `MonitorApp.instance.container`；`ServiceContainer` 覆盖其余场景。

## 四、DI 现状

`MonitorApp.onCreate()` → `ServiceContainer(app)`，全部依赖 `by lazy`；使用方 `MonitorApp.instance.container.xxx`（30 处）或构造器注入。新代码**优先构造器注入**，容器只负责装配。

## 五、别按这些"目标目录"找代码

`data/entity`、`data/datasource`、`data/mapper`、`domain/usecase`、`domain/click`、`pipeline/` 全部**不存在**。曾计划把网络层拆成 Remote/Local 两个 DataSource、把状态型单例改成可构造 class，均未落地——按需 grep 现状，别照愿景改。
