## 一、设计目标

| # | 目标 | 衡量标准 |
|---|------|---------|
| 1 | **层间单向依赖** | 下层绝不依赖上层，同层可依赖但避免循环 |
| 2 | **面向接口编程** | 跨层调用必须通过接口，实现类对上层不可见 |
| 3 | **消除上帝类** | 每个类 ≤300 行，单类单职 |
| 4 | **构造器注入** | 消除 `MonitorApp.instance` 和各 `object` 全局单例 |
| 5 | **可测试性** | 每个模块可独立测试，无需启动 Android 框架 |

### 依赖方向（严格单向）

```
Presentation → Domain ←→ Data → Infrastructure
                    ↓              ↑
                    └──────────────┘
```

| 层 | 可依赖 | 不可依赖 |
|----|--------|---------|
| **Presentation** | Domain, Infrastructure 中的 Core/DI | Data、Network、Pipeline |
| **Domain** | 仅 Kotlin 标准库 | Android 框架、Infrastructure 各模块 |
| **Data** | Domain（接口）、Infrastructure | Presentation |
| **Infrastructure** | Domain（模型） | Presentation、Data |

> ⚠️ **核心约束：Domain 层不能有任何 Android 依赖**（Context、Handler、Looper 等都不允许）。这使得领域逻辑可以在 JVM 单元测试中运行，无需 Robolectric。

## 三、各层详细设计

### 3.1 Infrastructure（基础设施层）

**职责：** 提供框架级能力，是所有上层的基础。

```
📁 com.bsfeng.monitor.core
   ├── MonitorApp.kt              # Application 入口（仅初始化 DI 容器）
   ├── AppConfig.kt               # 配置读取（从 BuildConfig）
   └── di/
       └── ServiceContainer.kt    # 手动 DI 容器（取代 MonitorApp.instance）

📁 com.bsfeng.monitor.pipeline          # 事件管道（已有，保持）
📁 com.bsfeng.monitor.network           # 网络通信（已有，保持）
📁 com.bsfeng.monitor.data.database     # SQLite 封装（从 data/ 移入）
📁 com.bsfeng.monitor.util              # 工具类（已有，保持）

📁 com.bsfeng.monitor.service           # Android 服务层
   ├── MonitorAccessibilityService.kt   # 无障碍服务（仅编排，业务委派）
   ├── AlarmReceiver.kt                 # 定时保活
   └── HealthChecker.kt                 # 健康检查
```

#### 关键变更：DI 容器

用 `ServiceContainer` 替代 `MonitorApp.instance`：

```kotlin
// com.bsfeng.monitor.core.di.ServiceContainer
class ServiceContainer(private val app: Application) {
    // 单例缓存
    val appConfig: AppConfig get() = AppConfig()
    val databaseHelper: DatabaseHelper by lazy { DatabaseHelper(app) }
    val eventRepository: EventRepository by lazy { EventRepositoryImpl(databaseHelper) }
    val navigationTracker: NavigationTracker by lazy { NavigationTracker() }
    val appSessionManager: AppSessionManager by lazy { AppSessionManager() }
    val skipRuleManager: SkipRuleManager by lazy { SkipRuleManager(app) }
    val skipRuleEngine: SkipRuleEngine by lazy { SkipRuleEngine(skipRuleManager) }
    // ... 更多依赖
}

// MonitorApp 简化为：
class MonitorApp : Application() {
    lateinit var container: ServiceContainer
        private set

    override fun onCreate() {
        super.onCreate()
        container = ServiceContainer(this)
    }
}
```

使用方通过构造器注入获得 `ServiceContainer`，而不是直接 `MonitorApp.instance.getXxx()`。

#### 关键变更：Pipeline 层改造

`EventPipeline` 和 `EventSource` 移至 infrastructure 层，因为它们属于框架级能力。

```kotlin
// 保持现有接口定义
interface EventHandler { val id: String; suspend fun handle(event: RawEvent) }
interface EventPipeline { fun register(handler: EventHandler); fun dispatch(event: RawEvent) }
```

**UploadHandler 批处理修复：**

```kotlin
class UploadHandler(
    private val uploadQueue: UploadQueue,
    private val reporter: EventReporter,
    private val batchIntervalMs: Long = 30_000L,  // 30 秒定时刷出
    private val batchThreshold: Int = 20           // 或满 20 条触发
) : EventHandler {
    // 改为：事件入队 → 检查阈值 → 达到时触发上传
    // 同时启动定时协程，间隔到期自动刷出
}
```

## 四、上帝类拆分方案

### 4.1 MonitorAccessibilityService 拆分

当前（~1000行）→ 拆分为 1 个编排者 + 5 个协作者：

```
MonitorAccessibilityService (服务入口，~80行)
├── delegates to → WindowChangeHandler    处理窗口变化逻辑
├── delegates to → ClickHandler           处理点击事件逻辑
├── delegates to → NavigationOrchestrator 导航追踪编排
├── delegates to → SessionOrchestrator    会话保存/恢复
├── delegates to → SkipAdOrchestrator     开屏跳过集成
└── uses → EventEmitter                   发射事件到 Pipeline
```

```kotlin
class MonitorAccessibilityService : AccessibilityService() {
    // 5-8 个委派对象，通过构造器或 lazy 注入
    private lateinit var windowHandler: WindowChangeHandler
    private lateinit var clickHandler: ClickHandler
    private lateinit var navOrchestrator: NavigationOrchestrator
    private lateinit var sessionOrchestrator: SessionOrchestrator
    private lateinit var skipAdOrchestrator: SkipAdOrchestrator
    private lateinit var eventEmitter: EventEmitter

    override fun onCreate() {
        super.onCreate()
        val container = (application as MonitorApp).container
        // 从 DI 容器获取依赖
        windowHandler = WindowChangeHandler(container.navigationTracker, ...)
        // ...
    }

    override fun onAccessibilityEvent(event: AccessibilityEvent) {
        when (event.eventType) {
            TYPE_WINDOW_STATE_CHANGED -> windowHandler.handle(event)
            TYPE_VIEW_CLICKED -> clickHandler.handle(event)
        }
    }
}
```

## 六、实施路线图

```
阶段 1: 搭底子（不动业务逻辑）
├── 创建 domain/ 包结构，提取纯模型
├── NavigationTracker、AppSessionManager 从 object → class
├── 设计 ServiceContainer DI 容器
├── MonitorApp 简化，委托给 ServiceContainer
└── 更新所有引用方（编译通过）

阶段 2: 拆上帝类
├── MonitorAccessibilityService → 5 个委派类
├── SkipRuleEngine → RuleMatcher + MonitorScanner
├── UploadHandler 批处理修复
└── 删除 ReceiverRegistrar 等死代码

阶段 3: 建 Repository 层
├── 定义 Domain 层 Repository 接口
├── 实现 Data 层 RepositoryImpl
├── 引入 DataSource 模式拆分网络/本地数据源
└── 补充 Mapper 层

阶段 4: 引入 UseCase
├── 将 Service 中的业务逻辑提取到 UseCase
├── ViewModel 改为依赖 UseCase（而非直接依赖 Data 层）
└── UseCase 可独立测试

阶段 5: 补测试
├── UseCase 单元测试（纯 JVM，无需 Android）
├── Repository 测试（可 mock DataSource）
├── Pipeline 测试（用 TestDispatcher 替换 Thread.sleep）
└── 核心业务逻辑全覆盖
```
