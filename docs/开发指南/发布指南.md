# 发布指南

## 打包签名

Release APK 需要配置签名信息。在 `app/build.gradle.kts` 的 `android` 块中配置：

```kotlin
android {
    signingConfigs {
        create("release") {
            storeFile = file("keystore.jks")
            storePassword = "xxx"
            keyAlias = "xxx"
            keyPassword = "xxx"
        }
    }
    buildTypes {
        release {
            signingConfig = signingConfigs.getByName("release")
        }
    }
}
```

## 构建 Release APK

```bash
./gradlew assembleRelease
```

APK 输出路径：`app/build/outputs/apk/release/app-release.apk`

## 版本号管理

- **versionCode:** 整数，每次发布递增
- **versionName:** `主版本.次版本.修订号`，遵循语义化版本
- 当前版本：`1.0.0`（versionCode = 1）

## 每次改动交付物

> 本项目采用「每次改动即打包 APK」的交付模式。用户不接触代码和开发工具，每次交付的只有一个 APK 文件。

每次编译通过后，Debug APK 生成在：

```
app/build/outputs/apk/debug/app-debug.apk
```

### 安装到手机

```bash
# 覆盖安装（保留数据）
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

用户侧载安装时：
1. 将 APK 文件传给用户（微信/QQ/网盘等）
2. 用户在手机上点击 APK 文件 → 允许安装未知来源应用 → 安装完成
3. 使用同一签名文件，后续升级直接覆盖安装，不丢失数据

## 发布流程

1. 确认所有功能通过真机测试
2. 更新 `versionCode` 和 `versionName`
3. 配置签名信息
4. 运行 `./gradlew assembleRelease`
5. 验证生成的 APK
6. 分发 APK 文件给用户侧载安装

## 升级策略

- 使用同一签名文件，确保覆盖安装不丢失数据
- 用户侧载安装新版本 APK 即可自动覆盖旧版本
