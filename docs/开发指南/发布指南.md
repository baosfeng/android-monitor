# 发布指南

> ⚠️ **何时阅读：** 发版、配置签名、修改版本号或更新发布流程时先读本文档。

## 版本号管理

版本号维护在仓库根目录 `version.properties`：

```properties
versionCode=1
versionName=1.0.0
```

- `versionCode`：整数，每次发版单调递增（脚本自动 +1）；
- `versionName`：语义化版本 `主.次.修订`；
- 构建时由 `app/build.gradle.kts` 读取并注入 `BuildConfig`，App 设置页显示 `versionName`。

## 签名配置

Release 签名文件**不入库**，通过以下渠道注入：

| 渠道 | 用途 |
|------|------|
| `local.properties` | 本地构建：`releaseStoreFile`、`releaseStorePassword`、`releaseKeyAlias`、`releaseKeyPassword` |
| 环境变量 | CI：`RELEASE_STORE_FILE`、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD` |
| GitHub Secrets | Release workflow：`RELEASE_KEYSTORE_BASE64`、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD` |

当前 release keystore 默认放在：

```
~/keystores/android-monitor-release.jks
```

> ⚠️ **务必自行备份 keystore 与密码**：丢失后无法再发布可覆盖升级的版本，只能让用户卸载重装。
> 仓库、文档、CI 日志中都不得出现 keystore 内容或密码。

## 本地构建

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@21
./gradlew assembleDebug        # Debug APK
./gradlew assembleRelease      # Release APK（读取 local.properties 中的签名）
```

产物：

```
app/build/outputs/apk/debug/app-debug.apk
app/build/outputs/apk/release/app-release.apk
```

## 发版流程（推荐：tag 触发 CI）

1. 确认 `main` 分支工作区干净、CI 全绿；
2. 执行发布脚本：

   ```bash
   scripts/release.sh 1.1.0
   ```

   脚本会：递增 `version.properties` → 提交 → 打 tag `v1.1.0` → 推送到 GitHub；
3. GitHub Actions `Release` workflow 自动：
   - 用 Secrets 解码 keystore 并构建签名 APK；
   - 计算 SHA-256 并生成 `updates/version.json`；
   - 创建 GitHub Release 并上传 APK 与清单；
   - 把最新清单回写 `main`（供 jsDelivr / 镜像读取）；
4. 发布完成后，App 的「检查更新」即可发现新版本。

> 首次发版前需在 GitHub 仓库 Settings → Secrets and variables → Actions 添加上述 4 个 Secrets。

## 私有版更新源（自建服务器）

服务器地址只用于**私有构建**，不得进入公开仓库或公开 APK：

1. 本地 `local.properties` 配置：

   ```properties
   updateBaseUrl=http://<你的服务器>/updates
   updateServerHost=<你的服务器>
   updateServerUser=root
   updateServerKey=/path/to/ssh-key.pem
   updateServerPath=/var/www/updates
   ```

2. 把 APK 与清单同步到服务器：

   ```bash
   scripts/sync-to-server.sh app/build/outputs/apk/release/app-release.apk updates/version.json
   ```

3. 私有构建（本地 `assembleRelease`）会优先从该服务器检查更新与下载，公开构建则自动跳过。

> 服务器只服务你自己的私有版，公开版不携带该地址，也不会产生盗刷流量。

## 安全要求

- 服务器 IP、keystore、密码不得出现在仓库、文档、Issue、CI 日志或公开 APK 中；
- 公开 Release 用 CI 的干净环境构建（无 `local.properties`），确保 `UPDATE_BASE_URL` 与真实后端地址为空；
- 发布前确认 `git status` 干净，且没有把本机截图、日志等过程产物加入提交。

## 回滚

- 在 GitHub Release 中把旧版本标记为 latest；
- 把旧版 `version.json` 重新提交到 `main`（或恢复对应提交）；
- 若要强制回退安装包，客户端仍以 `versionCode` 比较，需发布一个更高的 `versionCode` 才能触发更新。
