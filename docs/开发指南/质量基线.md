# 质量基线

> 本文档定义项目的质量硬性标准。所有代码变更（新增、修改、重构）必须满足以下基线，否则视为未完成。

## 一、代码质量

| 项 | 标准 | 说明 |
|----|------|------|
| 编译 | 零编译错误 | `./gradlew assembleDebug` 必须 BUILD SUCCESSFUL |
| Lint | 零 error + 零 warning | IDE 与 Gradle lint 均不得有未处理警告 |
| 弃用 API | 不引入新的弃用 API 调用 | 已存在的 deprecated 使用需注明原因 |
| 硬编码 | UI 不得硬编码颜色/字号/间距/震动 | 必须使用 [UI 设计规范](UI设计/设计规范.md) 的 Token，见 [审查清单](UI设计/审查清单.md) |

## 二、测试

| 项 | 标准 |
|----|------|
| 新增代码 | 每新增一个类/方法/功能必须同时添加单元测试（纯文档/配置改动除外） |
| 测试通过 | 提交前 `./gradlew test` 必须全绿，失败必须修复（不推诿新旧问题） |
| 覆盖重点 | 规则引擎、节点匹配器、选择器解析、事件合并、统计计算等核心逻辑必须有测试 |
| 测试并行 | 测试任务应并行执行以加快反馈 |

## 三、提交

| 项 | 标准 |
|----|------|
| 提交信息 | `<type>: <中文描述>`，type 英文小写（feat/fix/docs/refactor/test/chore） |
| 提交粒度 | 每功能一提交，原子可回滚 |
| 提交前 | 必须通过全部测试 + 打包 Debug APK + 安装到手机验证 |

## 四、文档

| 项 | 标准 |
|----|------|
| 文档同步 | 代码变更后相关文档必须同步，禁止文档与代码不一致 |
| 文档先行 | 功能开发前先编写设计文档或接口说明 |
| 索引 | 新增文档必须同步更新 [索引](索引.md) |

## 五、运行时质量

| 项 | 标准 |
|----|------|
| 异常 | 不得静默吞异常；协程取消必须向上传播；错误必须记录日志 |
| 资源 | 数据库游标/连接、无障碍节点、网络连接必须关闭/回收 |
| 生命周期 | Handler 回调、广播、静态引用必须随组件销毁清理 |
| 主线程 | 不得在主线程执行 IO/DB/网络操作 |
