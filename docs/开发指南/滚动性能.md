# 滚动性能：帧预算与排查口径

> 结论先行：滑动卡顿先看 **UI 线程**是否超帧预算。`Pipeline=Skia (OpenGL)` 本身就是硬件加速，GPU 帧时间常年 3–7ms，优先怀疑主线程而不是显卡。

## 三个数字决定体感

- 真机（小米 14，1200×2670）是 120Hz 屏：每帧预算 **8.33ms**。
- debug 包实测：UI 线程 50th **9ms**、90th 32ms、99th 117ms，Janky 26.5% —— 常态压线掉帧 + 偶发长帧。
- 同机 GPU：50th 3ms、90th 5ms、99th 7ms —— 显卡有余量。

所以「优化滑动」= 压 Compose 主线程的组合 / 布局 / 绘制工作量，不是找硬件加速开关。

## 怎么测

```bash
# 帧统计（仅 debuggable 包输出，release 包没有这段）
adb shell dumpsys gfxinfo com.bsfeng.monitor | head -20

# 主线程在干什么：preview 一次滑动，抓 main 线程的 slice
adb shell atrace -b 20000 -a com.bsfeng.monitor -t 8 gfx view wm sched freq > /tmp/at.txt
```

读 atrace 时盯这几个 slice：`Recomposer:recompose`、`AndroidOwner:measureAndLayout`、
`Record View#draw()`、`animation`、`checkForSemanticsChanges`、`sendAccessibilitySemanticsStructureChangeEvents`。
`postAndWait` 是等 GPU，模拟器上恒偏大，别把它当 CPU 成本。

## 变体：日常装 perf，调试才装 debug

`debug` 变体是 `debuggable=true`（ART 解释执行 + 不 AOT），Compose 各阶段比 release 高 3–5 倍；
同页面同操作实测 `Record View#draw()` 1.02ms vs 0.24ms。

```bash
# perf：release 的编译优化 + debug 签名，可覆盖安装（数据库与无障碍授权都保留）
./gradlew :app:assemblePerf && ~/android-platform-tools/adb install -r app/build/outputs/apk/perf/app-perf.apk
```

日常自用与性能验证装 perf；需要断点、调试入口时才装 debug。

## 绘制期优先

能交给绘制期的不放布局期：`graphicsLayer` 的 translation / alpha 在合成阶段生效，只让 layer 失效、不触发 measure / layout；`Modifier.offset` 用动画值则每帧重新测量布局。

- 位移 / 透明度动画走 [GpuMotion.kt](../../app/src/main/java/com/bsfeng/monitor/ui/foundation/GpuMotion.kt)：`gpuSlideX { state.value }` 把取值放进 layer 块，动画推进不触发重组。
- 绘制对象进 `drawWithCache` 的 build 块；尺寸不变时用 [DrawCache.kt](../../app/src/main/java/com/bsfeng/monitor/ui/foundation/DrawCache.kt) 的 `path(key)` / `brush(key)` 复用同一 Path / Brush 实例。
- 透明度随进度变的渐变优先 `drawPath(..., alpha = p)`，绘制期不再重建带 alpha 的 Brush。
- 门禁 `bash scripts/check-ui-rules.sh`（CI 同一条命令）拦三类回归：页面自画底衬渐变、`onDrawBehind` / `onDrawWithContent` 内 new Path / Brush、动画值走 `Modifier.offset`。
- 真实模糊（blur / RenderEffect）不进方案：全项目 0 处，实时采样换静态观感是负收益。

## 滚动热路径的已落地收缩

| 机制 | 位置 |
|---|---|
| 入场动画只在进屏后 600ms 内挂载的行播，滚动新挂载一律落终态 | [MainScreen.kt](../../app/src/main/java/com/bsfeng/monitor/ui/MainScreen.kt) |
| 行 key 只用主键（带组内下标会让整日 key 抖动 → 丢状态 + 重播动画） | [FinanceMainScreen.kt](../../app/src/main/java/com/bsfeng/monitor/finance/ui/FinanceMainScreen.kt) |
| 行描边用 `drawWithCache` 缓存 outline/Stroke，不再每帧重建 | 同上 |
| 数据没变时 StateFlow 不再 emit（页头时间拆独立 StateFlow） | [MainViewModel.kt](../../app/src/main/java/com/bsfeng/monitor/ui/MainViewModel.kt) |
| `rememberMotionEnabled()` 进程级缓存，省每行一次 `Settings.Global` IPC | [Motion.kt](../../app/src/main/java/com/bsfeng/monitor/ui/components/Motion.kt) |
| 全屏底衬只保留根一层，`drawWithCache` 缓存 Brush | [Surfaces.kt](../../app/src/main/java/com/bsfeng/monitor/ui/components/Surfaces.kt) |
| 分类色板按主题缓存，不再每次访问 new 16 色 list | [DesignTokenCatalog.kt](../../app/src/main/java/com/bsfeng/monitor/ui/theme/DesignTokenCatalog.kt) |
| 开关滑块位移走绘制期（`offset(x = 动画值)` 会每帧 measure/layout） | [GpuMotion.kt](../../app/src/main/java/com/bsfeng/monitor/ui/foundation/GpuMotion.kt) |
| 面积 / sparkline 的 Path、面积渐变 Brush 跨帧复用 | [DrawCache.kt](../../app/src/main/java/com/bsfeng/monitor/ui/foundation/DrawCache.kt) |

## 复测口径

改动前后都用同一变体、同一页面、同一滑动路径比：`50th/90th/99th` + `Slow UI thread`。
模拟器 GPU 是瓶颈（`postAndWait` 30–40ms），只适合看相对变化；结论以真机为准。
