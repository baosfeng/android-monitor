# 数据备份与还原

> 结论：App 把两张库 + 设置 + 规则快照打成 zip 放到本机 Downloads；设置页可立即备份、按天/周自动备份，也可从 zip 还原（还原前自动留一份 pre-restore 包）。

## 备份内容

归档根 = 应用私有数据目录 `dataDir`，包内保持相对路径：

- `databases/finance.db`（账目）、`databases/monitor.db`（记录）
- 同目录的 `-wal` / `-shm`（存在才加；打包前先 `wal_checkpoint(TRUNCATE)` 尽量并入主库）
- `shared_prefs/*.xml`（全部设置）
- `files/skip_rules_v1_backup.json`、`files/profileInstalled`（存在才加）
- `manifest.json`：schemaVersion、appVersionName、createdAt、每个文件的 size + sha256、两张库的表行数

备份包不含账号凭据与设备外部存储上的文件；包本身是明文数据，拷出后请自行保管。

## 存放位置

- `Downloads/行为记录备份/monitor-backup-yyyyMMdd-HHmmss.zip`：MediaStore 公共目录，卸载不丢，用户可直接拷走。
- `Android/data/<包名>/files/backups/`：还原入口与「共 N 份」的快速列表来源（扫描快，随卸载清除）。
- 两处各最多保留 5 份，超额删最旧；pre-restore 包使用同一前缀，一起计入配额。

## 频率

- 关闭 / 每天 / 每周，默认每周（5 份配额约覆盖一个月，够回滚「上周改错账目」）。
- 用 AlarmManager `setInexactRepeating`（requestCode 7301，与保活心跳的 0 分开），不引入 WorkManager；开机后由 `AlarmReceiver` 心跳调 `ensureScheduled` 补排，已在跑时不重置触发时间。
- 系统省电策略会推迟触发时间（inexact 语义属正常）；关键节点（换签名、重装前）优先手动「立即备份」。

## 还原路径

设置页 →「数据与备份」→「从备份还原」→ SAF 选 zip，顺序固定：

1. 校验 manifest（结构版本、文件清单、非法路径）与每个文件的 size + sha256；
2. 自动把当前数据备份成 pre-restore 包（这一步失败即中止，现有数据不动）；
3. `close()` 两个数据库单例句柄，替换数据文件并清掉旧 `-wal`/`-shm`/`-journal`；
4. 结束进程（`Process.killProcess(Process.myPid())`），用户重新打开 App 时连接按新文件重建。

Android 10+ 对「从后台拉起自身界面」有限制，这里不强行 startActivity，重启后从桌面点开即可。

## 还原失败怎么办

- 文件替换中途中断，库打不开：从 `Downloads/行为记录备份/` 找最新的 pre-restore 包再还原一次。
- 包损坏 / 校验不过：同一次备份在本机存了两份（Downloads + `files/backups`），互相替补。
- 还原后数据不是预期版本：换正确的 zip 重来；pre-restore 包在最近 5 份里。

## 数据库连接要求

- 备份只读计数 + checkpoint，不改数据；还原必须先 `close()` 单例 helper 再替换文件。
- 兜底口径：句柄关不掉时按「替换文件后立即结束进程」处理——代价是关闭瞬间的内存缓冲未落盘，可能丢最后一次写入，用 pre-restore 包恢复。

## 测试与验收

- `./gradlew :app:testDebugUnitTest --tests "*Backup*"`：打包 / 解包 / manifest 校验 / 保留策略，18 例。
- `bash scripts/check-ui-rules.sh`：设置页沿用现有 `AppCard` / `TokenRow` / `ChipRow`，无新增自绘底衬。
