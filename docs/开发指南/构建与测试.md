# 构建与测试

## 环境

JDK 25（`brew install openjdk@25`，`export JAVA_HOME=/opt/homebrew/opt/openjdk@25`；JDK 21 仍可回退）、Android SDK API 37（`platforms;android-37.0`）、`ANDROID_HOME` 指向项目根 `android-sdk/`。

### 版本清单

| 项 | 版本 | 备注 |
|---|---|---|
| compileSdk / targetSdk | 37 / 37 | minSdk 29；`compileSdk` 对应 `platforms;android-37.0` 包 |
| AGP | 9.4.1 | 低于 9.4 装不了 compileSdk 37 依赖 |
| Gradle | 9.8.2 | 用项目 wrapper；支持 JVM 17–27，JDK 25 在矩阵内 |
| Kotlin / compose 插件 | 2.4.21 | 与 AGP 同批升 |
| Compose BOM | 2026.09.00 | 跨大版本升级，API 变更已适配 |
| Robolectric | 4.17 | 首次跑测试会下载 ~230 MB `android-all-instrumented:17-*` jar 到 `~/.m2` |
| Coroutines | 1.11.0 | |

> ⚠️ `platforms;android-37` 不存在，包名是 `platforms;android-37.0`；`sdkmanager --list` 只列到 android-36 说明 cmdline-tools 太旧。Robolectric 改 API 37 后需 `--add-exports=java.base/jdk.internal.access=ALL-UNNAMED` + `--add-opens=java.base/java.io=ALL-UNNAMED`（已写进 `app/build.gradle.kts` 的 `tasks.withType<Test>`）。

```bash
./gradlew build              # 首次完整构建
./gradlew assembleDebug      # Debug APK
./gradlew assembleRelease    # Release（需签名）
./gradlew clean
```

## 测试

```bash
./gradlew test                                  # 全部
./gradlew :app:test                             # app 模块
./gradlew :app:test --tests "*EventCollectorTest*"
./gradlew :app:createDebugUnitTestCoverageReport
```

并行：`app/build.gradle.kts` 配 `maxParallelForks = max(CPU/2, 2)`（10 核 → 5 fork），每个 fork 独立 JVM，Robolectric 沙箱缓存与静态单例互不干扰，全量约 15~25 秒。日志只打印失败用例（含堆栈）。

覆盖率：HTML `app/build/reports/coverage/test/debug/index.html`，exec `app/build/outputs/unit_test_code_coverage/debugUnitTest/testDebugUnitTest.exec`；开关 `buildTypes.debug.enableUnitTestCoverage = true`（仅测试期插桩，不进 APK）。

> ⚠️ **Robolectric 用例的覆盖不计入报告**：它用自带沙箱 ClassLoader 加载被测类，绕过 JaCoCo 在线插桩，exec 里只有纯 JVM 用例触碰的类。`FinanceDao` / `FinanceManager` / `PandaImporter` 等显示 0% 不代表没测试 —— 验收证据是「用例断言 + 反向验证」：临时回滚修复，对应用例必须变红（示例在 `app/src/test/java/com/bsfeng/monitor/finance/`）。

### 规则

- 提交前运行全部测试，全部通过。
- **测试失败必须修复**，不论是否本次改动引入；排查到具体代码并实施修复，遗留问题至少记入 `docs/踩坑/`，修复后重跑确认无回归。
- **新增代码必须加测试**：每个新类/方法/功能覆盖正常路径、边界与异常；不以「改动太小」跳过。纯文档/注释/配置改动可不加。

## 锚点对账

```bash
node scripts/check-anchors.mjs            # 锚点账本第一列 ↔ 代码 testTag 的两向差集
node scripts/check-anchors.mjs --strict   # 缺失也要求为 0（作废页清理完再启用）
node scripts/check-anchors.mjs --json     # 机器可读
```

锚点源：[锚点账本](../交互设计/锚点账本.md) + [组件级锚点登记](../交互设计/s12a-组件级锚点登记.md)。
自增（代码有、账本无）非 0 时 exit 1：锚点集合必须逐字对账，不允许代码自造锚点。
缺失默认只报告不失败——s17 / s20a / s20b 等作废页的锚点按设计就不实现。
testTag 参数是复杂表达式时无法静态求值，会落进缺失；实现侧应写成字面量或映射表常量。

## 交付包体积：17,609,287 B 才对

增量打包会在 APK 里留下**僵尸空洞**：旧 dex 数据块未回收，新 dex 写在它后面，中间留一段死字节。体积虚涨，包内容一字未变。

| 观测 | 体积 | 空洞 |
|---|---|---|
| 干净包（`--rerun-tasks`） | 17,609,287 B | 0（仅 4096 B 对齐） |
| 跑过 test 后增量打包 | 21,402,223 B | 3,792,936 B ≈ classes2.dex |
| 改源码后再增量打包 | 30,509,595 B | 12,900,308 B ≈ classes.dex |

判据（**不是插桩**，别按插桩处理）：解压后条目与大小完全一致（1231 项 / 18,024,094 B）；`classes*.dex` 的 `jacocoInit` 命中 0、方法数两包相同（63,564 / 13,298）；空洞 = `文件体积 − 17,609,287`。

```bash
stat -f%z app/build/outputs/apk/debug/app-debug.apk   # 期望 17609287
./gradlew assembleDebug --rerun-tasks                  # 体积异常一律靠它重出
```

增量包只用于装机自测；交付包一律 `--rerun-tasks` 出。

## 每次改动必须出 APK

```bash
./gradlew test && ./gradlew assembleDebug \
  && ~/android-platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
```

产物 `app/build/outputs/apk/debug/app-debug.apk`；`-r` 覆盖安装保留数据；多设备用 `adb -s <序列号> install -r …`。ADB 用全路径（见 [ADB 调试指南](ADB调试指南.md)）。

## 逐提交编译验证（历史整理 / bisect）

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@25
git tag backup/pre-squash-$(date +%Y%m%d) HEAD           # 会重写历史，先备份
git rebase -i --exec './gradlew :app:compileDebugKotlin -q' <base-sha>
git diff --stat ORIG_HEAD HEAD                            # 必须为空

# 或不重写历史：独立 worktree 取证
git worktree add --detach /tmp/am-wt <base-sha>
ln -sfn "$PWD/android-sdk" /tmp/am-wt/android-sdk
cp local.properties /tmp/am-wt/ && mkdir -p /tmp/am-wt/app && cp app/debug.keystore /tmp/am-wt/app/
```

> ⚠️ worktree 编译失败首要原因：`local.properties` 的 `sdk.dir=android-sdk` 是**相对路径**，而 `android-sdk/` 未被 git 跟踪 → 报 `SDK location not found`。软链到主仓库 SDK 或写绝对路径；`app/debug.keystore` 同样需拷贝，否则打包缺签名。

## R8 与体积

Debug / Release 都启用 R8 缩减；规则文件 `app/proguard-rules.pro` + `getDefaultProguardFile('proguard-android-optimize.txt')`。Debug 因 `debuggable = true` 关闭混淆与部分优化，但 shrinking 仍生效。Debug 产物体积见上文交付包口径；Release 需签名后实测。

| 优化项 | 操作 | 节省量 |
|---|---|---|
| Room → SQLiteOpenHelper / Retrofit → HttpURLConnection | 改用系统 API | ~3 MB |
| kotlinx.serialization → org.json | `JSONObject` | ~0.5 MB |
| material-icons-extended → core（~900 图标） | 换核心图标库 | ~10 MB |
| 启用 R8 裁剪 / 删除未使用依赖 | `isMinifyEnabled = true` | ~20-30 MB |

原则：**零第三方业务依赖**（Compose UI 框架除外），所有功能用系统内置 API。
