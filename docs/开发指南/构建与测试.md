# 构建与测试

## 环境要求

> ⚠️ **JDK 必须使用 21 版本。** JDK 25 与 AGP 9.x 存在 jlink 兼容问题，无法正常编译。

- **JDK:** 21（推荐通过 Homebrew 安装：`brew install openjdk@21`）
- **JAVA_HOME 设置：** `export JAVA_HOME=/opt/homebrew/opt/openjdk@21`
- **Gradle:** 9.5.0（使用项目自带的 Gradle Wrapper）
- **Android SDK:** API 36（Android 16）
- **ANDROID_HOME:** 指向项目根目录下的 `android-sdk/`

## 构建命令

```bash
# 首次完整构建
./gradlew build

# 编译 Debug APK
./gradlew assembleDebug

# 编译 Release APK（需配置签名）
./gradlew assembleRelease

# 清理构建产物
./gradlew clean
```

## 测试命令

```bash
# 运行所有测试
./gradlew test

# 运行指定模块测试
./gradlew :app:test

# 运行特定测试类
./gradlew :app:test --tests "*EventCollectorTest*"
```

## 测试执行要求

> **提交前必须运行全部测试，修复所有失败的测试用例，确保全部通过。**

- 每次提交前都应当运行项目对应的测试命令
- 如果存在测试失败，必须修复后才能提交

### 测试失败必须修复

> **不管失败是否是本次改动导致的，都要排查修复，不推诿不放过。**

1. **不推诿**：测试失败就是问题，不论根源是本次修改还是已有代码，都需要修复
2. **排查到底**：分析失败原因，定位到具体代码位置，给出修复方案并实施
3. **现存问题也要修**：如果失败是已有代码遗留的问题（不在本次改动范围内），同样要修复，或者至少记录到 `docs/踩坑/` 中
4. **修复后验证**：修复后重新运行测试，确保问题真正解决且不引入新问题

### 新增代码必须添加测试

**每次新增完代码之后，都必须添加对应的测试用例**，具体要求：

1. 每新增一个类/方法/功能，必须同时添加对应的单元测试
2. 测试应覆盖正常路径、边界条件和异常场景
3. 不得以"改动太小"或"来不及"为由跳过测试编写

**例外：** 纯文档/注释/配置文件修改（无逻辑变化）可不加测试。

## 每次改动必须打包 APK

> **每次代码改动编译通过后，必须立即打包为 Debug APK，并确保 APK 可正常安装到手机上。**

这是项目的硬性要求——因为用户不接触代码和开发工具，每次交付物就是一个 `.apk` 文件。

### 编译 Debug APK

```bash
./gradlew assembleDebug
```

APK 输出路径：`app/build/outputs/apk/debug/app-debug.apk`

### 安装到手机（覆盖安装）

> ⚠️ **ADB 路径：** 当前环境 ADB 安装在 `~/android-platform-tools/adb`，请使用全路径（详见 [ADB 调试指南](ADB调试指南.md)）。

```bash
# 确保手机已连接并开启 USB 调试
~/android-platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`-r` 参数表示覆盖安装（保留原有数据）。如需同时保留所有已连接的设备，可用：

```bash
# 查看已连接的设备
~/android-platform-tools/adb devices

# 安装到指定设备
~/android-platform-tools/adb -s <设备序列号> install -r app/build/outputs/apk/debug/app-debug.apk
```

### 全流程命令

```bash
# 一行完成：测试 → 编译 → 安装
./gradlew test && ./gradlew assembleDebug \
  && ~/android-platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
```

> 💡 如果手机未连接，请跳过 adb 安装步骤。详见 [ADB 调试指南 → 未连接手机处理流程](ADB调试指南.md#未连接手机处理流程)。

## 逐提交编译验证（历史整理 / git bisect 时用）

> 需要证明「**每个提交都能编译**」时（例如把中间态提交压成一个自洽提交后回归验证），
> 用 `git rebase -i --exec` 或独立 worktree 逐提交跑 `compileDebugKotlin`。

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@21

# 方式一：rebase 过程中对每个提交执行（会重写历史，务必先打备份 tag）
git tag backup/pre-squash-$(date +%Y%m%d) HEAD
git rebase -i --exec './gradlew :app:compileDebugKotlin -q' <base-sha>
# 校验内容零差异（rebase 会设置 ORIG_HEAD）
git diff --stat ORIG_HEAD HEAD     # 必须为空

# 方式二：不重写历史，只在独立 worktree 里逐提交取证
git worktree add --detach /tmp/am-wt <base-sha>
ln -sfn "$PWD/android-sdk" /tmp/am-wt/android-sdk   # ⚠️ 见下
cp local.properties /tmp/am-wt/ && mkdir -p /tmp/am-wt/app && cp app/debug.keystore /tmp/am-wt/app/
```

### ⚠️ worktree 里编译失败的第一个原因：`sdk.dir` 是相对路径

本项目的 `local.properties` 里写的是 `sdk.dir=android-sdk`（**相对路径**），而 `android-sdk/` 目录未被 git 跟踪，
因此新建的 worktree 里 Gradle 会报：

```
Where: sdk.dir property in local.properties file. Problem: Directory does not exist
SDK location not found. Define a valid SDK location ...
```

**解决**：在 worktree 根目录软链到主仓库的 SDK（或在 worktree 的 `local.properties` 里写绝对路径）：

```bash
ln -sfn ~/android-monitor/android-sdk /tmp/am-wt/android-sdk
```

同理，未被跟踪的 `app/debug.keystore` 也要拷进 worktree，否则打包会缺签名。

## R8 代码缩减

Debug 和 Release 构建均启用 R8 进行代码缩减。规则文件：

- `app/proguard-rules.pro` — 自定义保留规则
- `getDefaultProguardFile('proguard-android-optimize.txt')` — Android 默认规则

> ⚠️ Debug 构建由于 `debuggable = true`，R8 的混淆和部分优化被禁用，但代码裁剪（shrinking）仍然生效。

## Gradle 配置

构建配置位于项目根目录：

| 文件 | 说明 |
|------|------|
| `build.gradle.kts` | 根构建文件（插件声明） |
| `app/build.gradle.kts` | App 模块构建配置 |
| `settings.gradle.kts` | 项目设置和依赖仓库 |
| `gradle.properties` | Gradle 属性配置 |
| `local.properties` | 本地 SDK 路径配置 |

## APK 体积优化

### 当前体积

| 构建类型 | 体积 | 说明 |
|----------|------|------|
| Debug (R8 裁剪) | ~5.1 MB | 日常开发测试用 |
| Release (R8 全量优化) | N/A | 需配置 release 签名 |

### 优化策略

| 优化项 | 操作 | 节省量 |
|--------|------|--------|
| Room → SQLiteOpenHelper | 移除 Room + KSP，使用 `android.database.sqlite` | ~1.5 MB |
| Retrofit/OkHttp → HttpURLConnection | 移除 Retrofit + OkHttp，使用 `java.net.HttpURLConnection` | ~1.5 MB |
| Kotlinx Serialization → org.json | 移除序列化库，使用 `org.json.JSONObject` | ~0.5 MB |
| material-icons-extended → material-icons-core | 全量图标库→核心图标库（~900 个） | ~10 MB |
| 启用 R8 代码裁剪 | debug 构建设置 `isMinifyEnabled = true` | ~20-30 MB |
| 移除未使用的依赖（WorkManager 等） | 删除无用依赖声明 | ~0.1 MB |

### 体积变化历程

```
58.2 MB  →  6.7 MB  →  5.1 MB  →  5.1 MB
 原始APK   图标库+R8   Room/网络    最终稳定
                       /序列化替换
```

### 原则

项目遵循 **零第三方业务依赖** 原则（Compose UI 框架除外），所有功能使用 Android 系统内置 API 实现。
