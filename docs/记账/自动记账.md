# 自动记账

> ⚠️ **何时阅读：** 修改 `com.bsfeng.monitor.autobook` 下任何代码、调整支付页识别规则、排查「支付后不弹窗 / 金额识别错 / 重复记账」之前必读。
> 关联文档：→ [记账模块概述](概述.md) · [业界调研与实现方案](自动记账调研.md)
> 状态：已实现并在真机验证通过（小米 14 / HyperOS，支付宝账单详情页，2026-10-16）

## 模块职责

在微信 / 支付宝的**支付结果页**上识别出一笔账，弹出确认浮窗，用户确认后写入记账账本。

**不做静默自动记账** —— 识别结果一律要用户点一次「记一笔」。原因见 [调研文档 §6.1](自动记账调研.md)：无障碍识别存在不确定性（金额可能取错、商户可能为空），静默落库会污染账本，而浮窗一次点击的成本远低于事后排查。

## 数据流

```
AccessibilityEvent（TYPE_WINDOW_STATE_CHANGED / CONTENT_CHANGED）
   ↓ 包名命中 AutoBookRules
   ↓ resolveTargetRoot()  按包名从 windows 里取窗口（不能用 rootInActiveWindow）
NodeTextCollector.collect()      节点 → (文本, 坐标)
   ↓
PageLines.toLines()              按 Y 分行、行内按 X 排序 → 「标签 值」视觉行
   ↓
AutoBookParser.parse()           纯函数：页面特征 → 金额/方向/商户/分类/账户/时间 → AutoBookDraft
   ↓
AutoBookOverlay.show()           WindowManager + ComposeView，跟随 App 主题
   ↓ 用户点「记一笔」
AutoBookEngine.persist()         幂等落库（source + sourceId 去重）→ finance.db
```

## 识别规则

### 页面判定

命中 [AutoBookRule.pageMarkers](file://~/android-monitor/app/src/main/java/com/bsfeng/monitor/autobook/AutoBookRule.kt) 里任意一个特征词才认为「这是交易结果页」：`交易成功` / `账单详情` / `支付成功` / `付款成功` / `转账成功` / `你有一笔` …

命中 `excludeMarkers`（`账单统计` / `收支分析` / `月账单` / `年度账单`）直接放弃。

> ⚠️ **排除词里不要加「全部账单」「账单管理」** —— 真机实测这两个词就出现在账单**详情页**上（右上角按钮 + 底部入口），加进去会导致详情页整页被排除。

### 字段提取

| 字段 | 取值方式 | 兜底 |
|------|---------|------|
| 金额 | 带方向前缀（`支出3元`）> 带 `¥` > 带 `元` > 裸两位小数（`-3.00`） | 取不到则不弹窗 |
| 方向 | 金额行自带方向词 > 收入词 > 支出词（**判定前先清洗品牌名**） | 默认支出 |
| 商户 | `收款方全称` / `商户全称` / `商户名称` … 标签的同行右侧内容 | 页面靠前的可用短文本；再取不到留空 |
| 分类 | 平台自带分类（`日用百货` → 日用）优先 | 商户关键词；再兜底「其他」 |
| 账户 | 固定取 App 账户体系（支付宝 / 微信钱包），保证记账能算进余额 | 规则里配置 |
| 支付方式 | `付款方式` / `支付方式` 标签值（余额宝 / 零钱） | 空则不展示 |
| 时间 | `支付时间` / `交易时间` 标签值，或全页首个日期时间串 | 空则不展示 |
| 幂等键 | 有订单号用订单号 | 渠道 + 方向 + 金额 + 商户 + 5 分钟时间桶 |

### 明确不记的情况

| 情况 | 原因 |
|------|------|
| 无金额 | 无法记账（「你有一笔交易，点此查看详情」这类） |
| 提现 / 充值（`提现到` / `充值成功` …） | 账户间转移，记了会让总身家凭空变化 |
| 未来时态（`将于` / `即将` / `待扣` / `续费提醒`） | 钱还没扣，不是已发生的交易 |
| 金额落在余额/额度/优惠/积分上下文 | 余额不是交易金额 |

## 真机调试

统一日志 tag：**`AutoBook`**

```bash
# 1) 看识别链路
~/android-platform-tools/adb logcat -s AutoBook

# 2) 复现：切到桌面再切回目标 App（触发 WINDOW_STATE_CHANGED）
~/android-platform-tools/adb shell input keyevent KEYCODE_HOME
~/android-platform-tools/adb shell monkey -p com.eg.android.AlipayGphone -c android.intent.category.LAUNCHER 1
```

日志会明确区分四种情况（这是排查「为什么没弹窗」的关键）：

| 日志 | 含义 |
|------|------|
| `未取到 <包名> 的窗口，当前窗口=[...]` | 页面没开，或被第三方悬浮窗顶掉了（看方括号里的窗口清单） |
| `未收集到页面文本` | 窗口在但树是空的 |
| `未识别到账单: <包名> 行数=N 文本=[...]` | 收到了页面但不认识 —— **看方括号里的实际文本**，据此加特征词或调正则 |
| `识别到账单 channel=... amount=... merchant=...` | 识别成功，随后弹窗 |
