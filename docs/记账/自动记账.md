> 状态：小米 14 / HyperOS 上支付宝 + 微信真机验证通过（2026-10-16~10-17）；浮窗 v2 已真机验证。

## 职责与硬约束

在微信 / 支付宝的**单笔账单页**识别一笔账 → 弹确认浮窗 → 用户确认后落库。

1. **不做静默自动记账**：识别结果必须用户点一次「记一笔」。无障碍识别有不确定性（金额可能取错、商户可能为空），静默落库污染账本，而浮窗一次点击成本远低于事后排查。
2. **只认账单页**：首页、消息列表、账单流水一律不识别。付款前页面（转账输入 / 收银台 / 指纹 / 确认付款）**不弹窗**，只做预采集，支付成功页到了再合并。

## 数据流

```
AccessibilityEvent（WINDOW_STATE_CHANGED / CONTENT_CHANGED）
 ↓ 包名命中 AutoBookRules；resolveTargetRoot() 按包名从 windows 取窗口（不用 rootInActiveWindow）
NodeTextCollector.collect() → PageLines.toLines()（按 Y 分行、行内按 X 排序 → 「标签 值」视觉行）
 ↓ AutoBookParser.parse() 成功页 → AutoBookDraft（门禁 + 字段 + 去重键）
 │  解析失败 → parsePrePayment() 只缓存 PrePaymentDraft（收款方 / 备注），不弹窗
AutoBookDraftMerger.merge()（成功页优先）→ AutoBookDedup.blockedReason()（安静期内不弹）
 ↓ AutoBookEngine.showOverlay() 检测到支付成功页立即展示
AutoBookOverlay.show()（全屏遮罩 + 实心确认卡，WindowManager + ComposeView，跟随主题）
 ↓ 记一笔 / 忽略 / 点遮罩 → persist() 幂等落库（source + sourceId 去重）→ finance.db
```

## 浮窗显示契约（v2）

真机反馈后重做：①玻璃拟态下面板半透明透出支付页；②浮层没盖住状态栏。

| 项 | 规格 |
|---|---|
| 出现时机 | 识别到支付成功页**立即展示**（不延迟、不做点复核）；付款前页面由 `PRE_PAY_WORDS` 拒绝 |
| 全屏遮罩 | 铺满整屏（`fitInsetsTypes = 0` + 挖孔区 `ALWAYS` + `FLAG_LAYOUT_IN_SCREEN`）；叠两层 ≈ **0.56**，盖住状态栏 / 挖孔 / 手势条；点遮罩 = 忽略 |
| 面板实心 | `opaquePanel` = surface-warm → surface → bg 合成 **100% 不透明**（玻璃主题为 `#f2f8ff`），不透出支付页 |
| 状态栏图标 | 遮罩深色，图标切浅色（`isAppearanceLightStatusBars = false`）；最终由 systemui 决定，ROM 可能有差异 |
| 动效 | 遮罩淡入 180ms + 卡片底部滑入 220ms；关闭即时卸载 |
| 分类区域 | 4 列图标网格（同「记一笔」），一屏 3 行 12 个分类全可见，更多可上下滑，选中项自动滚入可视区 |
| 备注行 | 预采集到用户备注才显示「备注 午饭」 |

遮罩加深是有意的：原型 `scrim` 0.34，浮层盖在别的 App 上太浅分不清可点层；叠两层 ≈0.56 与 `WindowOverlay` 同口径。面板实心是对玻璃主题的有意偏离（确认卡要读要点，不能透字），其余页面保留玻璃语言。

## 付款前预采集

收款方、付款方式、用户备注只出现在付款前页面；支付成功页往往是极简静态页（微信转账成功页只有「支付成功 + 金额 + 完成」）。

| 阶段 | 行为 |
|---|---|
| 付款前（微信转账输入 / 收银台 / 指纹 / 确认付款；支付宝转账输入 / 添加备注弹窗） | **不弹窗**；`parsePrePayment()` 预采集金额 / 收款方 / 付款方式 / 备注，按字段**累积**（输入页备注不被收银台冲掉） |
| 支付成功页 | 正常解析；`merge()` 用预采集补空白字段，**成功页有的优先** |
| 合并条件 | 同渠道 + 金额一致（±0.01）+ 预采集未过期（`PRE_DRAFT_TTL_MS = 120s`） |
| 清理 | 浮窗真正展示后清空；服务销毁时清空 |

单测见 `AutoBookPrePaymentTest`。

### 支付宝红包：没有结果页，回聊天页

真机实测（2026-10-17）：发红包确认页（`返回 | 发红包 | 0.01 | 示例留言…`）**不弹窗**，打「正在发红包」标记 + 预采集金额；收银台 / 指纹页标记保持，仍被 `PRE_PAY_WORDS` 拒绝；发出后回聊天页（`… ¥0.01 | 示例留言 | 支付宝红包 16:45`），`parseSentRedPacketChat()` 识别为支出，金额取预采集（缺失取气泡金额），商户取领取人 / 联系人。

关键点：
- 不能只凭「页面有红包」就弹：必须 ①刚走过红包付款前页面（`isRedPacketPrePayPage()` → `redPacketPaymentPending`）②流程已到指纹 / 密码页（`isRedPacketFingerprintPage()` → `redPacketFingerprintArmed`）；二者满足后，聊天页出现「支付宝红包」气泡且金额与预采集一致（±0.01）才算成功。
- 不对气泡时间做要求：同页气泡文案会变（`支付宝红包 16:45` / `支付宝红包 清风明月`），用 HH:mm 匹配会在 16:49 漏弹（已回退）。
- 对方已领取时有「红包已被领取 / 领取了你的红包」强信号，金额以预采集为准；未领取时靠气泡金额兜底。
- 预采集因服务重启丢失时，只要还处于「刚发红包」状态，仍可用气泡金额补记。

## 交易详情页补全（已记账笔）

支付成功页只有金额 / 商户 / 付款方式；交易详情页才有订单号、精确时间、商品说明、商户全称。

| 页面 | 判定 | 行为 |
|---|---|---|
| 详情页 + 已匹配 | `isDetailPage()`：标题命中详情页名单 + 强字段（支付时间 / 订单号 / 商品说明 / 商户全称 / 账单分类）；**结果页只有「交易方式」不算** | 不弹浮窗；`AutoBookDetailEnricher.enrich()` 把字段并进已有记录，真有变化才 Toast「详情信息已补全」 |
| 详情页 + 没匹配 | 同上 | 正常弹记账浮窗（含去重） |
| 支付成功页 / 聊天页 | 非详情页 | 原链路不变 |

匹配规则（`findMatch()`，宁可配不上也不能改错账）：**只按时间戳精确匹配**，不用「同一天 / 最近 31 天」猜法。
- 候选：只在自动记账记录（`source = auto_alipay/auto_wechat`），金额一致（±0.005）。
- 已补全过（`tradeTime`/`orderId` 非空）：只认 **±60 秒** —— 真机事故：16:49 与 16:51 两个 0.01 红包，16:49 详情的把已补全的 16:51 又匹配了一次。
- 未补全过：记录时间是「点记一笔」时刻，与支付时间差几十秒 → **±2 分钟**（`NEAR_WINDOW_MS`）。
- 窗口内两笔同样接近 → **放弃补全**（`AMBIGUITY_MS = 30 秒`）；详情页没给时间 → 不匹配。

补全规则：只补信息不改用户选择（类型 / 分类 / 金额 / 账户原样）；商户名只在详情页不更短时替换（`领取中/已领取/待领取` 已排除，详情页无商户保留原值）；商品说明 / 付款方式 / 订单号 / 平台分类非空且不同即更新；交易时间以详情页为最终口径（同时修正 `date`/`dateTime`/`tradeTime`）；备注原样保留、只追加缺失项；`sourceId` 升级为详情页稳定键；只有 `changed = true` 才写库 + Toast。

> ⚠️ 已知数据问题：修复前 id=15 的 0.01 红包商户被改成「领取中」、时间改成 16:49:41，需用户手动删除 / 重记（编辑表单不暴露商户字段）。

## 记住上次类型 / 分类（按商户）

匹配键为商户名精确匹配（`FinanceDao.findLastByMerchant()`），只查已确认落库的记录；默认值取上次 `type + categoryName`；商户空 / 无历史则保持解析器结果；历史类型非法只沿用分类，反之亦然；查询在 `showOverlay()` 前，查库失败按无历史处理，绝不影响弹窗。

## 账单页门禁

背景（真机事故）：支付宝**首页**「最近消息」卡片 `付款成功￥3.00` 与结果页文案一致被认成 3 元支出（商户「松开刷新」）；微信**首页会话列表**中「微信支付」命中特征词、预览 `收款方24小时内未接收你的转账，已过期` 被取成值、`微信支付 20:47` 把 20 取成 ¥20.00 —— 每划一次列表弹一次。

判定顺序即设计（`AutoBookParser.isBillPage()`）。**白名单原则：默认拒绝**，只认三种签名 —— 账单页排版只有几种，「不像账单页」的页面无穷，黑名单列不完。

| # | 签名 | 判定 |
|---|---|---|
| 1 | 独占结果页 | 整行状态锚点（`支付成功` / `付款成功￥3.00`）+ 收尾按钮（`完成` / `查看账单` / `查看详情`） |
| 2 | 账单 / 交易详情页 | 标题命中名单（`账单详情`/`交易详情`/`付款详情`/`转账详情`/`交易成功`/`支付成功`/`付款成功`/`转账成功`/`已支付`，允许带图标或菜单前缀）+ ≥1 个强字段取到值（支付时间/订单号/商品说明/商户全称/收款方全称/账单分类/交易状态/当前状态）+ 有金额 |
| 3 | 微信红包结果页 | 页面 **≤8 行** + 产品名「微信红包」整词 + 「微信支付」+ 带货币符号金额（`￥0.01`） |
| — | 支付宝红包聊天页 | 不走 `isBillPage`，由 `AutoBookEngine` 单独兜底 |

前置硬拒（结构性判据，不是文案排除）：①出现付款前特征（`请验证指纹`/`使用密码`/`立即支付`/`确认付款`）②一屏 ≥2 处付款方式标签或 ≥2 个不同金额（列表/流水，单笔页只描述一笔，阈值 `MULTI_TRANSACTION_THRESHOLD = 2`）。

实现位置：`isBillPage()`（总入口）、`hasMultipleTransactions()`、`isStandaloneResultPage()`（`STATUS_ANCHOR` + `RESULT_PAGE_ACTIONS`）、`isStrongBillDetailPage()`（`STRONG_DETAIL_LABELS` + `STRONG_DETAIL_MIN_LABELS` + `DETAIL_PAGE_TITLES`）、`isRedPacketResultPage()`（`RED_PACKET_PRE_PAY_WORDS` 挡住付款前输入/收银台/指纹页）。

### 字段级防护

| 防护 | 实现 | 真机依据 |
|---|---|---|
| 时间戳不当金额 | `extractAmount()` 先用 `CLOCK` 抹掉 `20:47` | `微信支付 20:47` 把 20 当 ¥20.00 |
| 通知 / 会话预览不当字段值 | `labelValue()` 跳过含 `未接收`/`已过期`/`请查收` 的值与纯时间值 | `收款方24小时内未接收…已过期` 被取成值 |
| 时间不当商户名 | `isUsableMerchant()` 拒绝纯时间 | 列表项 `20:36` |

### 门禁回归用例（改门禁前先跑 `AutoBookParserTest`）

支付宝首页消息摘要、支付宝支付消息列表、微信支付服务号会话、微信首页会话列表、会话预览「红包退款到账通知」+ 群消息「40元」、会话名 `微信支付 20:47`、会话预览通知文案 —— 均不得被识别成账单。

### 规则层

命中 `AutoBookRule.pageMarkers` 任一特征词（`交易成功`/`账单详情`/`支付成功`/`付款成功`/`转账成功`/`你有一笔`…）才进门禁；命中 `excludeMarkers`（`账单统计`/`收支分析`/`月账单`/`年度账单`）直接放弃。

> ⚠️ 排除词不加「全部账单」「账单管理」—— 真机实测这两个词就出现在账单详情页（右上角按钮 + 底部入口），加了会整页被排除。

## 字段提取

| 字段 | 取值 | 兜底 |
|---|---|---|
| 金额 | 带方向前缀（`支出3元`）> 带 `¥` > 带 `元` > 裸两位小数（`-3.00`） | 取不到不弹窗 |
| 方向 | 金额行自带方向词 > 收入词 > 支出词；判定前先清洗品牌名与方向标签（`收款方`/`付款方`/`待…确认收款` 只表达谁收谁付） | 默认支出 |
| 商户 | `收款方全称`/`商户全称`/`商户名称` 同行右侧 | 页面靠前的可用短文本；再取付款前「付款给…」；仍无则留空 |
| 备注 | 付款前「备注 / 转账说明」原文；「修改 / 添加备注」是入口文案不算 | 空则不展示 |
| 分类 | 平台分类（`日用百货` → 日用） | 商户关键词；再兜底「其他」 |
| 账户 | 固定 App 账户体系（支付宝 / 微信钱包），保证算进余额 | 规则配置 |
| 支付方式 | `付款方式`/`支付方式`/`交易方式` 标签值；微信「已选择零钱，更改」归一成「零钱」 | 空则不展示 |
| 时间 | `支付时间`/`交易时间`/`创建时间` 标签值，或全页首个日期时间串 | 空则不展示 |
| 订单号 | `订单号`/`业务交易号` 标签值（含行内标签） | 取不到留空 |

> ⚠️ 标签取值有前缀误命中防护（`labelValue()` + `isCjkIdeograph()`）：短标签会命中长标签取半截值 —— 真机「付款方」命中「付款方式」，商户被写成 `式 招商银行信用卡(8888)`。**标签后紧跟汉字即视为更长词片段跳过**（紧跟冒号 / 空格 / 字母数字放行）；`MERCHANT_LABELS` 不放「付款方」。

> ⚠️ 订单号常不单独一行：真机支付宝塞在别的值里（`商品说明 充值:阿里云服务购买,业务交易号:CFP000…`），`extractOrderId()` 除按标签取还会扫行内标签（`ORDER_LABEL_INLINE`）。

## 同一笔只弹一次（去重）

真机同一笔会被反复触发：账单页连抛多个 CONTENT_CHANGED，来回切页也重触发。三层挡住：

| 层 | 位置 | 作用 |
|---|---|---|
| 事件节流 | `AutoBookEventThrottle`（只节流 CONTENT_CHANGED 800ms，WINDOW_STATE_CHANGED 永远放行） | 挡连续内容变化；**页面切换不能被吃掉**（真机支付成功页在指纹页后 402ms 到达，旧实现直接丢弃） |
| 短期去重表 | `AutoBookDedup.kt` | 按指纹记住三种结局，各有安静期 |
| 落库查库 | `AutoBookEngine.isAlreadyBooked()` | 覆盖进程重启：已记账的永久不再弹 |

三种结局与安静期：`CONFIRMED`（点记一笔，先打标再落库）10 分钟；`DISMISSED`（点忽略）10 分钟 + **落盘 7 天**（`AutoBookIgnoreStore`，跨进程/跨天不再弹）；`SHOWN`（弹出未操作）30 秒精确指纹 / **5 秒**金额模糊指纹。

### 多条指纹（任一命中即视为刚处理过）

| 指纹 | 形态 | 安静期 |
|---|---|---|
| 订单号（精确） | `order:alipay:CFP000…` | 10 分钟 |
| 交易时间（精确） | `time:alipay:0:3.0:2026-10-15 23:14:43` | 10 分钟 |
| 金额兜底（模糊，`precise=false`） | `sum:alipay:0:3.0` | 只在「刚弹过」时 5 秒防抖，不参与已忽略 / 已记账 |

三个刻意决定：
1. **指纹不掺「当前时间」**：改造前用「渠道+方向+金额+商户+5 分钟时间桶」，跨桶即换键 → 同一笔反复弹的根因之一。交易时间是账单自带属性，跨时间稳定，可参与指纹。
2. **指纹不掺商户名**：同一笔在支付宝首页两次识别的商户名完全不同（「松开刷新」vs 一串 UI 文本），带商户就会算出两个键连弹两次。商户名只进落库键。
3. **模糊指纹不承担跨分钟记忆**：`sum:` 键区分不了「同一笔」与「另一笔同金额」—— 真机 2026-10-16 微信：忽略一笔 ¥0.01 后 11 秒发出 ¥0.01 红包，撞同一模糊键被静默吞掉。故模糊键只在 `SHOWN` 时写入；已记账侧由落库键 + 查库兜底。2026-10-17 再实测：16:15:40 弹过 ¥0.01，16:16:02 另一笔被剩余 8s 的 30 秒窗口吞掉 → 模糊键 SHOWN 防抖收紧到 **5 秒**。

### 落库键与去重指纹是两套

| 用途 | 键 | 策略 |
|---|---|---|
| 弹窗去重 | `buildDedupKeys()` 多指纹 | 精确键长安静期 + 模糊键短安静期 |
| 落库幂等 | `buildSourceId()` 单键 | 订单号 > 交易时间 > 「渠道+方向+金额+商户+5 分钟桶」 |

> ⚠️ 落库键最后一档故意保留时间桶：落库宁可重复也不能丢账；拿「渠道+方向+金额」当唯一键会把连着两笔 3 元合并成一笔。反复弹窗由去重指纹单独解决。

## 明确不记

无金额；提现 / 充值（`提现到`/`充值成功`，账户间转移会让总身家凭空变化）；未来时态（`将于`/`即将`/`待扣`/`续费提醒`）；金额落在余额/额度/优惠/积分上下文；**不是账单页**。

## 后续计划（做法已有源码依据，未实施）

| 项 | 做法 | 价值 |
|---|---|---|
| 通知通道 | `parseNotification()`（不做页面门禁，通知来源明确）；文本按 `TITLE → TEXT → BIG_TEXT → TEXT_LINES → SUB_TEXT → SUMMARY_TEXT → ticker` 合并并按包含关系去重 | 覆盖微信无障碍拿不到的场景，成本最低 |
