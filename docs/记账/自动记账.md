# 自动记账

## 职责与硬约束
在微信 / 支付宝的单笔账单页识别一笔账 → 弹确认浮窗 → 用户确认后落库。链路：事件 → 包名命中 `AutoBookRules` → 按包名取窗口（不用 `rootInActiveWindow`）→ 视觉行 → `parse()`（门禁 + 字段 + 去重键）→ 预采集合并 → 三道去重 → 浮窗 → `persist()` 幂等落库（`source` + `sourceId`）。

1. **不做静默自动记账**：识别结果一律要用户点一次「记一笔」；静默落库会污染账本。
2. **只认账单页**：首页、消息列表、账单流水不识别；付款前页面默认只预采集、不弹窗；无金额、提现 / 充值、未来时态（`待扣` / `续费提醒`）、金额落在余额 / 优惠 / 积分上下文的都不记。

## 浮窗关闭契约（2026-10-20 起）
**默认只有「记一笔」和「忽略」两个按钮能让浮窗消失**；点遮罩、切到任何 App（含本 App）都保持显示。判定集中在 `AutoBookDismissPolicy.effectOf(source)`，引擎与 UI 都只问它，不各自判断。

| 来源 | 卸载浮窗 | 短期去重 | 落盘 7 天忽略 |
|---|---|---|---|
| 点「记一笔」 | 是 | `CONFIRMED`（10 分钟） | 否 |
| 点「忽略」 | 是 | `DISMISSED`（10 分钟） | 是 |
| 点遮罩 | 否（轻震动 + 每笔一次 Toast 提示） | 不写 | 否 |
| 切 App / 回桌面 | 否 | 不写 | 否 |
| 服务销毁 `release()` | 是 | 清表 | 否 |

- 反例（用户 2026-10-20 真机事故）：准备点「记一笔」时先点到屏幕，浮窗立刻消失，同一笔之后 7 天不再弹 —— 旧实现把「点遮罩」等同「忽略」并落了盘。默认另一笔账单识别成功会替换当前浮窗（程序内部替换，不算用户关闭），同一 `sourceId` 不重建；遮罩与卡片空白处都吞掉点击，不传给底层 App（代价：浮窗弹出后须先选一个按钮，无法先切走再回来）。

## 说明字段（2026-10-20 起）
账本「说明」只来自用户输入：浮窗可编辑行预填付款前页面的备注（占位「写一下买了什么」），确认时落库编辑值，空串即不写。
- `AutoBookDraft.remark()` / `bookedRemark(edited)` 只返回说明（`trim` + 截断 80 字），不拼商户 / 商品说明 / 付款方式；这些各有独立字段，`AutoBookDetailEnricher.enrich()` 只补结构化字段、说明原样保留。反例：改造前 `remark()` 拼「商户·商品说明·付款方式」，账本列表一长串重复文字，用户写的那句被淹没。

## 浮窗输入法
浮窗默认 `FLAG_NOT_FOCUSABLE`（点遮罩不抢目标 App 输入），此时输入框拿不到焦点。点「说明」行由 `AutoBookOverlay.setImeFocusable(true)` 切到可聚焦：去掉 `FLAG_NOT_FOCUSABLE` / `FLAG_LAYOUT_NO_LIMITS`，`fitInsetsTypes = ime` 且 `SOFT_INPUT_ADJUST_RESIZE`；失焦 /「完成」/ 键盘 Done 后恢复。
- 拿不到焦点时退回不可编辑（`remarkFocus` 最多重试 3 次），不假装能输入；编辑期间目标 App 不接管输入。API 29 无 `fitInsetsTypes`，键盘可能挡住卡片。

## 识别规则：门禁与字段提取
`AutoBookParser.isBillPage()` 采用白名单：默认拒绝，只认三种签名；「不像账单页」的页面无穷，黑名单列不完。

| # | 签名 | 判定 |
|---|---|---|
| 1 | 独占结果页 | 整行状态锚点（`支付成功` / `付款成功￥3.00`）+ 收尾按钮（`完成` / `查看账单` / `查看详情`） |
| 2 | 账单 / 交易详情页 | 标题命中名单（`账单详情` / `交易详情` / `交易成功`…）+ ≥1 个强字段（支付时间 / 订单号 / 商品说明 / 商户全称 / 交易状态）+ 有金额 |
| 3 | 微信红包结果页 | ≤8 行 + 「微信红包」整词 + 「微信支付」+ 带货币符号金额 |

- 前置硬拒：出现付款前特征（`请验证指纹` / `使用密码` / `立即支付` / `确认付款`）或一屏 ≥2 处付款方式 / ≥2 个不同金额（`MULTI_TRANSACTION_THRESHOLD = 2`）。
- 字段级防护：金额前先抹时间戳（`微信支付 20:47` 不当 ¥20）；会话预览含 `未接收` / `已过期` 不当字段值；纯时间不当商户名；标签后紧跟汉字视为更长词片段（`付款方` 不命中 `付款方式`）。
- 回归用例（改门禁前先跑 `AutoBookParserTest`）：支付宝首页消息摘要、支付消息列表、微信服务号会话、会话预览「红包退款到账通知」+ 群消息「40元」、会话名 `微信支付 20:47` 均不识别。

| 字段 | 取值 | 兜底 |
|---|---|---|
| 金额 / 方向 | 方向前缀 > `¥` > `元` > 裸两位小数；方向词判定前先清品牌名 | 取不到不弹窗；方向默认支出 |
| 商户 | `收款方全称` / `商户全称` 同行右侧 | 页面靠前可用短文本；仍无则留空 |
| 分类 / 账户 | 平台分类 → 商户关键词 → 其他；账户固定支付宝 / 微信钱包 | 保证算进余额 |
| 支付方式 / 时间 / 订单号 | 对应标签值（微信「已选择零钱，更改」归一成「零钱」） | 空则不展示 |

- 订单号常塞在别的值里（`商品说明 充值:阿里云服务购买,业务交易号:CFP000…`），`extractOrderId()` 同时扫行内标签。

## 同一笔只弹一次
三层挡住重复弹窗：页面文本指纹（内容一变立即处理，同一文本不重复解析；50ms 只合并同帧渲染）→ 短期去重表（三结局多指纹）→ 落库查库（跨进程重启）。

- 精确指纹（订单号 / 交易时间）承接「已记账 / 已忽略」：`CONFIRMED` 10 分钟、`DISMISSED` 10 分钟 + 落盘 7 天、`SHOWN` 30 秒；模糊指纹（`sum:渠道:方向:金额`）只做 `SHOWN` 5 秒防抖 —— 忽略 ¥0.01 后 11 秒的 ¥0.01 红包不能被吞掉。
- 指纹不掺当前时间、不掺商户名（跨桶换键与商户名抖动是「同一笔反复弹」的两大根因）；落库键 `buildSourceId()` 与弹窗指纹是两套：订单号 > 交易时间 > 「渠道+方向+金额+商户+5 分钟桶」，落库宁可重复也不能丢账。

## 交易详情页补全
详情页字段更全：匹配到已记账笔时不弹浮窗，`AutoBookDetailEnricher.enrich()` 补结构化字段并 Toast「详情信息已补全」；没匹配到则正常弹窗。

- `findMatch()` 只按时间戳匹配：已补全记录 ±60 秒、未补全记录 ±2 分钟；窗口内两笔同样接近（`AMBIGUITY_MS = 30 秒`）直接放弃；详情页没给时间不匹配。只补信息不改用户选择（类型 / 分类 / 金额 / 账户 / 说明原样），交易时间以详情页为最终口径（同步修 `date` / `dateTime` / `tradeTime`）。

## 真机调试与验证状态
日志 tag `AutoBook`（`adb logcat -s AutoBook`）；关键日志：`识别到账单 channel=... amount=...`（识别成功）、`去重命中，本次不弹窗：<原因>` / `该笔已被用户忽略`（去重挡住）、`遮罩点击已吞掉（closeOverlay=false）`（新契约生效）、`窗口输入焦点切换: focusable=...`（说明行进入或退出编辑）。

- 已验证（真机）：支付宝账单详情页 / 微信支付页与收银台 / 红包识别、跨升级查库去重、浮窗 v2 全屏遮罩与实心面板、详情页补全不改用户选择。
- 待真机验证：说明行输入法（`FLAG_NOT_FOCUSABLE` 切换在 HyperOS 上的表现）、点遮罩吞点击后的按钮手感；未实现：通知通道（`parseNotification()` 入口已备好），事件收敛 / 字段锚点 / 小程序 OCR 见[业界调研](自动记账调研.md)。
