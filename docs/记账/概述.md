# 记账模块

> ⚠️ **何时阅读：** 修改记账相关的任何代码（交易、分类、账户、预算、统计图表、熊猫记账导入）之前必读。
>

## 模块职责

记账模块是一个**与监控模块完全解耦**的独立子系统：监控数据存 `monitor.db`，记账数据存 `finance.db`，两者不共享表、不共享 Repository。

提供的能力：

| 能力 | 说明 |
|------|------|
| 交易记账 | 支出 / 收入 / **转账**录入、编辑、删除，按日期分组展示（**一屏表单 + 全抽屉**，见 [记一笔（s14a）](#记一笔s14a定版实现)） |
| 分类与账户 | 18 个支出一级 + 8 个收入一级，二级可选（约 90 个，名称全局唯一）；两级同屏选择；统计/预算按一级汇总；3 个预设账户 |
| 月度预算 | 总预算 + 分类预算，进度条按**当月实际支出**实时计算 |
| 统计分析 | 月度收支卡片 + 分类支出环形图 + 占比明细 |
| 熊猫记账导入 | 读取熊猫记账导出的 sqlite 文件，单事务导入并去重 |

## 数据库

数据库文件：`finance.db`，由 `FinanceDatabaseHelper` 管理，**独立于监控模块的 monitor.db**。

| 表 | 关键字段 | 约束 |
|----|---------|------|
| `finance_transactions` | V1：id, type, category_name, amount, account_name, remark, tag, date, date_time, created_at, updated_at, source, source_id<br>V2 增：merchant, product_desc, pay_method, order_id, platform_category, trade_time<br>V3 增：to_account_name（转账的转入账户） | 无唯一约束，导入去重靠 `source + source_id` 查询 |
| `finance_categories` | id, name, type, icon_name, color, parent_id, sort_order | UNIQUE(name) |
| `finance_accounts` | id, name, type, balance, sort_order | UNIQUE(name) |
| `finance_budgets` | id, month, category_name, budget_amount, spent_amount | UNIQUE(month, category_name) |
| `finance_tags` | id, name, type | UNIQUE(name)（尚无 DAO 读写） |

### 金额语义

- `amount` 为金额绝对值，方向由 `type` 决定；
- **转账（`type = 2`）**：`accountName` 是**转出**账户、`toAccountName` 是**转入**账户，余额一进一出
  （见 `FinanceManager.applyTransactionEffect`）；转账**不计入**当月支出 / 收入（统计 SQL 按 type 过滤），
  列表里用中性色、不带正负号展示；
- **例外：退款。** 熊猫记账 `t_bill.type = 3` 的退款导入后是「`type = 0（支出）` + 负数 amount」，用于**抵扣**当月支出，而不是虚增支出；
- 展示金额用 `Transaction.displayAmount`（已取绝对值，不会出现 -¥-30.00）；判断"是否退款抵扣"用 `Transaction.isRefundEntry`；
- **交易时间**：`dateTime` 是用户在表单里选定的「日期 + 时:分:秒」（`yyyy-MM-dd HH:mm:ss`），
  **不是点保存的时刻** —— 自动记账用页面上的支付时间，手动记账用表单里的时间（2026-10 真机踩坑：
  页面写 18:32 的那笔被落库成 20:51）。

### 「说明」只存用户手写内容

- 「说明」= `Transaction.remark`（DB 列 `remark` 名不变，仅 UI 文案改名），内容**只有用户手写的那一句**；
- 自动采集的商户 / 商品说明 / 付款方式 / 交易时间 / 订单号 / 平台分类各存独立列（`merchant` / `product_desc` /
  `pay_method` / `trade_time` / `order_id` / `platform_category`），进表单「单据」卡（`RecordForm.receiptItems`）；
- 交易行副标题走 `RecordForm.subtitle(tx)`：说明为空时回退「商户 · 付款方式」，再退回商品说明 —— 自动记账那笔没写说明也认得出；
- 表单「说明」行占位是「写一下买了什么」，编辑页复用同一行；
- 历史数据：`ensureInitialized()` 启动时跑一次 `cleanLegacyAggregatedRemarks()`（幂等、只清 `auto_*` 记录里与旧拼接算法完全一致的说明；单段值 / 手写内容 / 预采集备注都不动），单据信息保留在独立字段。

## 数据流

```
Compose Screen ──> FinanceViewModel ──> FinanceManager ──> FinanceDao ──> finance.db
                                            ▲
熊猫记账 sqlite ──> PandaImporter ───────────┘（runInTransaction 单事务，失败整体回滚）
```

- 所有数据库访问都在 `Dispatchers.IO`（`FinanceManager` 内部 `withContext`）；
- 写操作（新增 / 编辑 / 删除 / 导入 / 预算）成功后 `FinanceManager` bump `changeVersion`，
  `FinanceViewModel` 订阅它重新加载**当前浏览月** —— 自动记账在无障碍服务里落库，切回记账 Tab 就能看到，不用等用户操作；
- 记账首页在 `entryKey` 变化（切 Tab / 子页返回）与 `ON_RESUME`（App 回前台）时也主动 `loadCurrentMonth()`；
- 加载只读、不 bump，所以「加载 → 版本变化 → 再加载」不会自激；连续触发由 `loadMonth` 的 job 取消 + 序号合并成一次结果；
- 种子数据（分类 + 账户）由 `FinanceManager.ensureInitialized()` 在 ViewModel 初始化协程里执行，**不在主线程建库**。

## 记一笔（s14a）定版实现

用户诉求原话：「我希望一屏就能操作，而不是和现在一样还得来回滑动」。定版原型
[`.open-design/26-a-quan-chouti.html`](../../.open-design/26-a-quan-chouti.html)（A/B 选版与决策留档见
[`26-variants.md`](../../.open-design/26-variants.md)），实现落在 `AddTransactionScreen.kt` +
`RecordSheets.kt` + `RecordForm.kt` 三个文件。

| 原型要点 | 实现位置 | 为什么这么做 |
|---------|---------|------------|
| 一屏不放滚、保存吸底 | `AddTransactionScreen` | 抽屉开合**不改变表单高度**（原 s05 的 21 格网格 + 大卡片行是滚动的主因） |
| 分类：4 列网格抽屉，一屏 20 个 | `CategorySheet` | 内联展开的 B 版实测 850 > 738，会把表单顶出屏幕 |
| 账户：带余额的列表抽屉 | `AccountSheet` | 原 s05 是 3 张大卡片行，与其它行不同构 |
| 分类 / 账户**选中即收起** | `onPick`：回写值 + 关抽屉 | 用户明确要求（选完不该再点一次关闭） |
| 点抽屉外空白关闭 | `FinanceScrim(onDismiss)` | 外壳只绑了关闭按钮，遮罩是另接的 |
| 抽屉贴底 | `Modifier.align(Alignment.BottomCenter)` | 依赖公共组件 `BottomSheet` 把 modifier 作用在根节点上；此前失效导致抽屉贴顶，见 [踩坑 9](../踩坑/自绘BottomSheet传align定位失效.md) |
| 时间：日期快捷 + 时 / 分滚轮 | `TimeSheet` + `WheelColumn` | 原来只能记「今天」，记不了「昨天 10 点」；秒沿用当前值，精度到秒 |
| 单据明细（6 项） | `ReceiptSheet` | 就是自动记账落库的 6 个结构化字段，一个不多一个不少 |

**与原型逐项对齐的口径**（每一条都对着原型 DOM 的 computedStyle 核过，不靠目测）：

| 元素 | 原型规格 | 备注 |
|------|---------|------|
| 卡片 | `padding:12px 16px`、`radius:18px`、`--surface` 底 + 1px `--border-soft` | 行分隔线在卡片内边距**之内**（缩进 16px），所以内边距给在行外面 |
| 字段行 | `min-height:44px`、`padding:0`、gap 12px、标签列 44px | 行自身零内边距：Compose 的 `heightIn` 约束的是内容区，加 padding 会多出一个 padding 的高度 |
| 金额 | `--text-3xl`(56px)/700、`letter-spacing:-.02em`、色 `--fg`；`¥` 用 `--text-xl`(28px)/600 | 金额不染色，方向由类型段表达 |
| 分段控件 | 高 54px（1px 边 + 4 padding + 44 项）、项 14px/600 | 公共 `SegmentedControl` 已一致 |
| 按钮 | `min-height:48px`、`radius:--radius-md`(12px)、字 17px/600 | 抽屉里的「关闭」用 `.btn-ghost` 次级样式 |
| 日期 chip | 高 44px、`min-width:48px`、`padding:0 12px`；选中 = 底 `fg 7%` + 边 `fg 24%` + `--fg` 字 600 | **不是**黑底白字 |
| 时刻滚轮 | `104×132`、每格 44px、数字 `--text-lg`(21px)、冒号 `--text-xl`(28px)、高亮带左右内缩 6px + `fg 8%` | 上下各留 44px 让首尾项也能滚到中间 |
| 账户列表 | 整组一个 `.group` 卡片（`--surface` 底 + 1px 边 + radius 18 + 左右 16）；行 `min-height:52px` + 上下 8px | `min-height` 要用 `defaultMinSize`（CSS 语义含 padding） |
| 分类网格 | 4 列、gap 12px、`max-height:46vh`、图标 44px、名称 12px | 高度按屏高比例算，不写死 |
| 单据 kv | 标签列 64px、字 14px | 标签 `--muted`、值 `--fg` |

> 上面这张表是**实测口径**，来源是两轮「原型 computedStyle ↔ 模拟器实测」的对表（共修 18 项，
> 2026-10）。对照图与意见属于过程取证，不入库。
> 后续改记账 UI 时，**先按这张表核一遍**再动手。

**与原型的两处有意偏离**（都是原型没覆盖、但实现上必须回答的问题）：

1. **转账多一行「转入」** —— 原型里账户只有一行，而转账要两个账户才能把余额算对（V3 加
   `to_account_name`）。所以转账时字段卡是「转出 / 转入 / 时间 / 备注」，且**不显示分类行**
   （转账没有分类，统计与预算本就不含转账）；
2. **「保存」用等高空白的可滚 Column**，而不是原型的 `position:sticky` —— 小屏 / 大字体的极端情况下
   宁可整页可滚，也不让「保存」被裁掉。

## 熊猫记账导入规则

| 熊猫表 | 目标表 | 规则 |
|--------|--------|------|
| `t_bill` | `finance_transactions` | type 0→支出、1→收入、3→退款（支出 + 负金额）；`card_name`→账户名；`id`→`source_id`，`source = "panda_import"` |
| `t_category` | `finance_categories` | 按名称去重（UNIQUE 冲突忽略） |
| `t_card` | `finance_accounts` | type 0→现金、1/2→银行卡、3→第三方支付；按名称去重 |
| `t_bbudget` | `finance_budgets` | `budget`→预算额，`pay`→历史已支出（展示时被实时值覆盖），映射为总预算 |

- 全部写入包在 `FinanceDao.runInTransaction` 中：任一步失败整体回滚，`ImportResult` 计数归零并带上错误原因；
- 重复导入同一文件：按 `source + source_id` 跳过已存在账单（计入 `skippedTransactions`）。

## 改动注意事项（血泪教训）

1. **记账首页 FAB 不要外包容器**：不要用 `windowInsetsBottomHeight(...)` 之类的高度容器包 FAB，
   否则 FAB 会溢出内容区被底部导航栏盖住，用户看不到也点不到（详见
   [踩坑：记账首页 FAB 被底部导航栏遮住](../踩坑/记账FAB被底部导航栏遮住导致无法新增交易.md)）；
2. **交易时间戳必须用 `LocalDateTime`/`LocalTime` 取时刻**：`LocalDate.format("HH:mm")` 会抛
   `UnsupportedTemporalTypeException` 直接崩溃，且现象会伪装成「点保存跳到了别的 App」（详见
   [踩坑：LocalDate 格式化 HH:mm 导致记账保存崩溃](../踩坑/LocalDate格式化HH-mm导致记账保存崩溃.md)）；
3. 记账首页「记账」Tab 图标本身就是蓝色圆形加号（`Icons.Filled.AddCircle`），真机排查 FAB 问题时
   别把它误认成 FAB —— 用截图像素统计或 uiautomator 的 `content-desc="添加"` 节点确认；
4. **「记一笔」分类必须留在抽屉里**：把 21 个分类改回表单内联网格，就会把表单顶出屏幕、
   直接推翻「一屏不放滚」这条需求（B 版原型失败的实测数据：展开后 850 > 738）。

## 已知限制

1. **标签（tag）没有输入入口**：`finance_tags` 表已建但无 DAO 读写，`Transaction.tag` 目前只在导入时被赋值；
2. **分类 / 账户没有管理界面**：目前只有默认种子数据 + 导入数据，不能增删改；
3. **标签（tag）与分类 / 账户**：均无管理界面（分类与账户只有种子数据 + 导入数据）；
4. **统计页导航栏会随列表滚动**：它是 `LazyColumn` 的第一个 item；
5. **退款在列表中显示为绿色「+¥」**，与收入同色，未单独标注「退款」字样；
6. **转账没有分类**：转账记录 `categoryName` 为空串，列表标题显示「转出账户 → 转入账户」；
7. **时间选择器到分**：日期与「时 / 分」可选，**秒不可选**（新增沿用当前秒、编辑沿用原记录秒），
   落库仍精确到秒（`RecordForm.timePartsOf`）。
