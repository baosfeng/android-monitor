# 分类体系：一级 + 二级

> 阅读时机：改分类种子 / 分类选择器 / 统计与预算口径 / 自动记账分类映射 / 历史分类迁移。
> 关联：[记账概述](概述.md) · [自动记账](自动记账.md) · [设计规范](../UI设计/设计规范.md)

## 目标与边界

一级分类覆盖日常 99% 消费场景，高频项独立成一级；二级只是细分，记账时可以只选一级。统计与预算**按一级汇总**，避免环形图与预算列表被上百个二级切碎。不做分类管理界面（新增/重命名/删除），分类由系统预置。

## 存量安装补齐（目录版本）

`CategoryCatalog.VERSION` 标记目录版本（首批 1 / 第二批 2），**增删分类时必须递增**。`MonitorApp.onCreate()` 启动即调用一次 `syncCatalogOnce()`（`ensureInitialized()` 播种之后也会调）：按 `catalog_sync_v<版本>` 前缀的落盘标记每版只跑一次，把目录里新增的一级/二级 INSERT-IF-ABSENT 进已有 finance.db，返回新增条数并在 >0 时通知 UI。只增不删——历史交易的 `category_name` 可能引用旧名，删掉会让分类名游离在表外。

## 数据模型

- `finance_categories.parent_id` 已存在：一级 `parent_id = -1`，二级指向一级 `id`；名称全局唯一（UNIQUE(name)），二级不能与一级同名。
- 交易 `category_name`：有二级时存二级名，只记一级时存一级名；列表标题显示二级名（无二级显示一级）。
- 预算 `category_name` 只存一级名。
- 统计/预算查询通过分类树把二级映射到一级；一级名直接使用。

## 历史迁移（一次性，标记 `category_tree_v1`）

事务内执行：清空分类表 → 插入一级/二级；旧交易 `category_name` 与旧预算 `category_name` 按映射归到新一级（用户已确认「只归一级」）。映射：餐饮/零食/水果→餐饮；购物/日用→购物；出行/打车/地铁火车→交通；汽车→汽车；水电/房租还贷/居家生活→居住；通讯/宽带话费→通讯；就医→医疗健康；休闲娱乐→娱乐休闲；住宿/旅游度假→旅游；教育→教育学习；衣物/美妆→服饰美妆；手机数码→数码电子；其他/未知→其他。迁移失败整体回滚，不破坏原数据。

## 自动记账分类映射

`AutoBookParser.mapCategory` 返回**二级名**；平台分类优先，其次商户关键词，最后兜底一级「其他」。高频映射：
淘宝/天猫/京东/拼多多/唯品会→购物·电商；美团/饿了么/外卖→餐饮·外卖；滴滴/T3/曹操→交通·打车；12306/铁路→交通·火车高铁；地铁/公交→交通·公交地铁；星巴克/瑞幸/咖啡奶茶→餐饮·咖啡奶茶；麦当劳/肯德基/餐厅/火锅→餐饮·正餐；中石化/中石油/加油→汽车·加油；停车→汽车·停车；电影/影院→娱乐休闲·电影；游戏→娱乐休闲·游戏；视频/音乐会员→娱乐休闲·会员订阅；医院/诊所→医疗健康·门诊；药房/药品→医疗健康·药品；话费/流量/联通/移动/电信→通讯·话费；水费/电费/燃气→居住·水电燃气；物业→居住·物业；保险→金融保险·保险；酒店/民宿→旅游·住宿。

落库前校验二级存在（种子保证）；未知二级回退一级，绝不让分类名游离在分类表外。

## UI

两级同屏选择器（浮窗与「记一笔」共用）：上方一级 chips 横向滚动，下方 6 列二级网格；二级含「不细分」项，直接选一级。浮窗分类区高度受限时二级区可滚动，按钮吸底。统计环形图与图例、预算列表都只展示一级；交易列表标题显示二级名。

## 测试

- 分类树：一级/二级父子关系、名称唯一、收入/支出隔离；
- 迁移：旧交易归一级、旧预算归一级、未知分类归「其他」、事务失败回滚；
- 统计/预算：二级支出按一级聚合、一级名直接统计、预算按一级进度；
- 识别映射：高频商户/平台分类命中预期二级，未命中回退「其他」；
- 选择器纯逻辑：一级切换、二级选择、不细分、默认选中识别二级。

## 非目标

自定义分类管理、二级预算、分类图标重做（复用 `CategoryIcon` / `categoryColorOf`）、熊猫记账导入分类结构重构（未知分类归「其他」并保留原始平台分类字段）。
