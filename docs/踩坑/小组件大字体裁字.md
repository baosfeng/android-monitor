# 小组件在系统大字体下裁字：正常字号看不出

**结论**：2×1 组件的「顶行 + 两列读数」在系统字体 ≥ 120% 时放不下，读数会被整段裁掉且不报错；按 `fontScale` 降级成一行摘要。

## 现象

- 正常字号：2×1 的「监控健康」显示「♥ ● 监控中 / 今日事件 8 / 跳过 0」，完整；
- 系统字体调到 130%（`adb shell settings put system font_scale 1.3`）：同一块组件只剩「今日事件 / 跳过」两个标签，**下面的数字整段消失**；
- 构建、单测、lint 全绿 —— 这条路径没有断言能覆盖。

## 原因

2×1 在 Pixel 上实测 177×98dp，减掉 32dp 内边距只剩 66dp。字体放大后一行内容要：
顶行 22dp + 间距 8dp + 标签 ≈20dp + 3dp + 值 ≈37dp = **90dp**，超出 34dp。

Glance 把超出的部分裁掉，不打日志、不报错 —— 桌面上就是「字没了」。

## 修法

`fontScale >= 1.2` 时切到一行摘要（`HealthWidget` / `AdSkipWidget` 各一处）：

```kotlin
val largeText = LocalContext.current.resources.configuration.fontScale >= LARGE_FONT_SCALE
if (largeText) HealthCompactOneLine(state, data) else { /* 原两列读数 */ }
```

一行只留「状态 + 今日事件」：145dp 可用宽塞不下两个计数，硬塞会把状态词挤成省略号。

## 验证

- 字体 130%：一行摘要完整，无裁切；
- 改回 100% 后**组件不会立刻恢复两列** —— 进程内 Resources 还持有旧 configuration，`am kill` 重启进程后才变回来（真机上改字体会触发系统重建，影响有限）；
