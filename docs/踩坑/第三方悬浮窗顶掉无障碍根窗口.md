# 第三方悬浮窗顶掉无障碍根窗口

> ⚠️ **何时阅读：** 无障碍读不到目标 App 的节点（`rootInActiveWindow` 拿到的不是目标 App），或排查「自动记账 / 开屏跳过读不到页面」时。

## 现象

自动记账在支付宝账单详情页上始终**识别不到**，日志只有：

```
AutoBook: 未识别到账单: com.eg.android.AlipayGphone 行数=9
文本=[取消 熊猫自动记账 保存 | 备注 阿里云 | 金额 3.00 | 日期 2026-10-15 23:14 | 类型 支出 | 分类 日用 | ...]
```

读到的 9 行文本**全是另一个 App（熊猫记账）的记账确认浮窗内容** —— 支付宝页面的字段一个都没有。

同一个时刻用 `uiautomator dump` 却能拿到支付宝页面完整的 95 个节点（含 `交易成功` `支出3元` `收款方全称`）。**uiautomator 能读、我们读不到**，一度怀疑是微信/支付宝的白名单校验。

## 根因

`AccessibilityService.rootInActiveWindow` 返回的是**「活动窗口」**，而不是「目标 App 的窗口」。只要有第三方悬浮窗（`TYPE_APPLICATION_OVERLAY` / 系统归类为 `TYPE_SYSTEM`）盖在支付页上，活动窗口就是那个浮窗：

```
窗口列表(1): type=3:com.uanmi.miaojiaccount     ← 只剩这一个窗口
```

浮窗消失后同一次事件读出的是：

```
窗口列表(3): type=3:com.miui.home, type=3:com.android.systemui, type=1:com.eg.android.AlipayGphone
识别到账单 channel=alipay amount=3.0 merchant=阿里云计算有限公司   ← 立刻正常
```

## 解决

不要用 `rootInActiveWindow`，改从 `AccessibilityService.windows` 里**按包名**挑窗口：

```kotlin
// app/src/main/java/com/bsfeng/monitor/autobook/AutoBookEngine.kt → resolveTargetRoot()
// 第一轮：优先 TYPE_APPLICATION 且包名匹配；第二轮：放宽到任意类型窗口只要包名匹配；
// 兜底：rootInActiveWindow 恰好就是目标包时使用
```

依赖无障碍配置里的 `flagRetrieveInteractiveWindows`（本项目 `app/src/main/res/xml/accessibility_service_config.xml` 已开启）。

## 教训

1. **`rootInActiveWindow` ≠ 目标 App 的窗口。** 只要设备上装了同类工具（记账、屏幕翻译、悬浮球、录屏），就可能被顶掉，且**用户完全无感**。
2. **诊断日志要打印「窗口清单 + 实际读到的文本」**，否则「读不到」和「读到了但不认识」无法区分 —— 这次正是靠打印实际文本才一眼看出读到的是别的 App。
3. **`uiautomator dump` 与 App 内无障碍服务的结果不一致时，优先怀疑「窗口选择」而不是「权限/白名单」**，前者几分钟能验证，后者会把人带偏。
4. 对于自动记账还有一层含义：**用户正在处理另一笔记账时，不该叠加弹窗**。当前实现按包名取窗口后天然规避了这种叠加。
