# 事件节流吞掉页面切换，支付成功后浮窗不弹

> 日期：2026-10-17 · 设备：小米 14 / HyperOS · 场景：自动记账（微信转账）
> 关联：[自动记账](../记账/自动记账.md) · [微信支付页识别调研](../记账/微信支付页识别调研.md)

## 现象

支付完成后确认浮窗**完全不出现**，而且 `adb logcat -s AutoBook` 里**看不到支付成功页的任何识别日志** ——
像是「支付成功页没被收到」，而不是「解析失败」。

## 真机日志（关键片段）

```
16:06:10.405 D/AutoBook: 未识别到账单: com.tencent.mm [非账单页,门禁拒绝] 行数=3
             文本=[付款给张三(***) | ￥0.01 | 微信支付]        <- 指纹页
16:06:10.807 D/MonitorService: onAccessibilityEvent: type=32, pkg=com.tencent.mm
                                                              <- 支付成功页的窗口切换
（此后没有任何 AutoBook 日志，页面也没有再抛事件）
```

## 根因

`AutoBookEngine.onAccessibilityEvent` 在解析前做 800ms 节流：

1. 指纹页在 `16:06:10.405` 被解析 → `lastRunAtMs = ...405`；
2. 支付成功页的 `TYPE_WINDOW_STATE_CHANGED` 在 `16:06:10.807` 到达，只隔 **402ms** → 被节流直接 `return`；
3. 支付成功页是**静态页**，之后不再抛 `CONTENT_CHANGED` —— 这一页永远不会再进解析器。

节流原本是为了挡 `CONTENT_CHANGED`（支付结果页会连续抛多个），却把**低频且关键的页面切换**一起挡了。

## 修复

新增纯逻辑 `AutoBookEventThrottle`：

| 事件 | 处理 |
|------|------|
| `TYPE_WINDOW_STATE_CHANGED`（页面切换） | **永远放行**，并重置节流窗口 |
| `TYPE_WINDOW_CONTENT_CHANGED`（内容变化） | 800ms 窗口节流 |

单测 `AutoBookEventThrottleTest` 用真机时间差复现：`402ms 后的页面切换必须放行`。

## 顺带修掉：付款前页面被当成账单页

同一段日志还暴露了更早的一个问题 —— **指纹页/收银台也被识别成账单**：

```
16:05:58.885 I/AutoBook: 识别到账单 channel=wechat ... amount=0.01 markers=[零钱]
16:06:08.466 I/AutoBook: 识别到账单 ...（指纹页）
```

这两页同样有「付款方式 + 零钱 + 金额」，旧门禁的`hasDetailStructure`会放行 —— 用户还没付完就可能弹窗
（这正是用户反馈「我当前还没完成支付就出现了」的来源）。现在 `isBillPage()` 开头先用
`PRE_PAY_WORDS`（`请验证指纹` / `使用密码` / `立即支付` / `确认付款` …）挡掉付款前页面。

## 同类风险

任何「页面切换后是静态页」的事件驱动链路都可能中招。**节流只能作用在高频事件上**；
把页面切换也塞进同一个时间窗口，等于在最关键的时刻丢事件。
