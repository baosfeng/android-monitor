# 桌面小组件尺寸与档位：三个连着的坑

**结论**：判档走 `AppWidgetOptions`，info 按「格数×70−30」，高度门槛放到 45dp —— 三处任一错，组件都只显示一半内容。

## 现象

模拟器（Pixel 4×2，实际 368×223dp）上：
- 记账 4×2 只显示「本月支出 + 金额」，进度条和底部两列都没有；
- 健康 / 传送 2×1 只显示状态行，第二行「今日 N 事件」不出现；
- 桌面把 2×1 组件摆成 2×2、1×1 摆成 2×2。

## 原因（三个独立问题叠在一起）

1. **Glance 的 `LocalSize` 不可信**：实测 4×2 时它返回 **110×110**，取的是 launcher 上报的最小值，
   而不是当前占格（`AppWidgetOptions` 里是 `minWidth=368, minHeight=124`）。
   用它判档，4×2 会落进 Tiny。
2. **info.xml 的 minWidth/minHeight 写大了**：之前按「1 格 = 110dp」写，
   而官方公式是 `格数 × 70 − 30`（1 格=40、2 格=110、4 格=250）。
   2×1 写成 110×110 → launcher 按 2×2 摆；1×1 写成 110×110 → 直接变 2×2。
3. **高度门槛 90dp 太高**：2×1 在真机上只有约 72dp（minHeight=40 + launcher 内边距），
   90dp 的阈值把所有 2×1 都判成 TINY。

## 修复

| 问题 | 改法 | 位置 |
|---|---|---|
| 尺寸来源 | `GlanceAppWidgetManager.getAppWidgetId()` → `AppWidgetManager.getAppWidgetOptions()` 读 `OPTION_APPWIDGET_MIN_WIDTH/HEIGHT` | `widget/WidgetSize.kt` |
| info 尺寸 | `minWidth = 列数×70−30`、`minHeight = 行数×70−30`，`minResize` 给 40dp | `res/xml/widget_*_info.xml` |
| 高度门槛 | `MIN_VIABLE_HEIGHT_DP = 45f`（低于才降 Tiny） | `widget/WidgetLayoutPolicy.kt` |

## 判定与取证

```bash
# 组件实际占格（min/max 是 launcher 上报值）
adb shell dumpsys appwidget | grep -A1 'com.bsfeng.monitor/widget'
# 桌面截图看档位（4×2 应有三行：头 / 大金额 / 底栏两列）
adb exec-out screencap -p > home.png
```

## 反例

- 照抄「1 格=110dp」：构建、单测、lint 全绿，桌面上组件却永远只有一半内容；
- 用 `LocalSize` 判档：在 Pixel 上永远 Tiny，换台设备（上报值不同）又可能变 Wide —— 比写死还难查。
