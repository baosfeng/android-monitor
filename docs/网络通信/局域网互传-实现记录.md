## 2. 协议关键点

- 端口：UDP 发现 `53318`（组播 `239.255.77.77` + 广播 `255.255.255.255`）；HTTP `53319`，占用顺延到 `53328`，**实际端口随公告上报**。
- 发现节奏：启动连发 3 次（间隔 500ms）→ 每 5s 心跳；收到 `discover` 单播 `offer`（同 IP 2s 内只回一次）；15s 未公告离线、60s 移除。
- Android 特有：必须持有 `WifiManager.MulticastLock` 且用完 release（`stop()` 与启动失败路径都 release，`setReferenceCounted(false)`）；模拟器上 MulticastSocket 走 IPv6 双栈，`ipv4` 表看不到、要看 `/proc/net/udp6`。
- 路由：`GET /info`、`POST /offer`、`GET /offer/status`、`PUT /upload`、`POST /cancel`，前缀 `/api/v1/`，响应 `{code, message, data}`。
- 错误码 `0/4001~4007`（常量在 `TransferErrorCode`），协议层非法报文/未知路由用 `ApiResponse.PROTOCOL_ERROR = -1` + HTTP 400/404/405。
- 鉴权分工：`X-Pair-Key` 只用于 `POST /offer`；`token` 只用于 `PUT /upload`。
- 落盘：`Downloads/局域网互传/`（`MediaStore.Downloads` + `RELATIVE_PATH`），64 KiB 流式、`.part` 续传、完成后 sha256 校验再改名、同名追加 ` (1)`。
- 音效默认：完成=开、失败=关、新设备=关；同一事件 500ms 去重。

## 4. 互操作约定

### 4.1 接收端生成 pairingKey → approved 下发 → 发送端持久化

```
Mac 发送：POST /offer（无 X-Pair-Key、无 pin）
接收端：生成 PIN=1234，state=pending，token 照常返回 data={sessionId, token, state:"pending", accepted:[]}
Mac 发送：POST /offer（pin:"1234"，可带 sessionId）
接收端：校验 PIN → settings.savePairingKey(senderDeviceId, key)（32 字节随机 hex，SecureRandom）
        → data={sessionId, token, state:"approved", accepted:[{fileId, offset}], pairingKey:"<64 hex>"}
Mac：按 deviceId 持久化 pairingKey，之后 POST /offer 带 X-Pair-Key → compare == settings.pairingKey → 直接 approved（免 PIN）
```

要点：`pairingKey` 只在新配对成立的 approved 响应里下发，pending/denied 不带；老客户端忽略该字段仍走 PIN。实现：`TransferEngine.offer()` / `TransferSettings.savePairingKey()` / `TransferEngine.sendFilesInternal()`；移除配对 `removePairing()`。

### 4.2 重提 PIN 的会话复用优先级（`offer()` 内）

1. body 带 `sessionId` 且 `sessions[sessionId].senderDeviceId == senderDeviceId` → 复用；
2. 否则 `senderDeviceId` 相同 + `files.sha256` 集合相同 + 会话非终态 → 复用（容忍对端不回传 sessionId）；
3. 否则新建会话（新 sessionId + 新 token，登记 RECV 任务）。

复用后 approve 把已存在的 `.part` 长度作为 `offset` 回填，重提 PIN 不会重传已收字节。

### 4.3 续传偏移的唯一来源：`.part` 实际大小

`TransferEngine.resumableOffset(incoming)` 是唯一偏移来源（不存在→0；≤声明大小→该值；超长→视脏数据删除后 0；已收满→size）。三处复用：`acceptedArray()`（`/offer` approved 与 `/offer/status`）、`approve()`（回填 `incoming.received`）、`upload()` 入口（严格校验，不匹配返回 4003）。与 Mac 端 `UploadPlanner.resumableOffset(partSize:expectedSize:)` 同源。

> 修复前用内存 `received`：接收端进程被回收重启后内存为 0、磁盘 `.part` 有 5 字节 → 应答 offset=0 → 从头传 → 4003 → 续传失效。

## 7. 功能落地（多轮迭代，只记结论与常量）

- **交互**：历史/已完成任务左右滑动删除（`SwipeToDismissBox`，仅 `TransferStatus.isTerminal` 可删，进行中回弹）；删除后有 5s 撤销（`UNDO_WINDOW_MS = 5_000L`），撤销时文件已删则提示「文件已删除，仅恢复记录」。
- **PIN 超时**：`CONFIRM_TIMEOUT_MS = 60_000L`，弹窗显示「Ns 后自动拒绝」，超时静默收起（不播失败音/不震），任务 4007。
- **设备别名**：offer `senderAlias` → 发现层同 `deviceId` 兜底 → 「未知设备」；系统名解析顺序 `Settings.Global.DEVICE_NAME` → `MANUFACTURER + MODEL` → `MODEL` → `Android`，未知对端不显示 deviceId。
- **Tab**：概览 / 实时 / 广告 / 记账 / 传送 / 设置；label `labelSmall` + `maxLines=1` + `softWrap=false`，图标 22dp。
- **免配对**：时间窗口（开关 + 5/10/30 分钟，持久化到期时刻）+ 体积阈值（0/10/50/100 MB，默认 0 关闭），二者 **OR**；命中直接 approved 并下发 pairingKey。
- **后台接收（默认关）**：`ServiceModePolicy` —— 关闭时只在 App 可见时运行（ON_START 启动 / ON_STOP `stopService`），不进前台不挂通知；开启才常驻 + 通知。**单一真值源 = `TransferEngine.running`**：App 打开不再自动启动服务，传送页「接收状态」区、开关、磁贴、设置页读写同一 Flow。
- **通知**：`IMPORTANCE_LOW` + `setSound(null)` + 无震动 + 无角标 + `lockscreenVisibility=SECRET`；一行「局域网互传 · N 台设备」；点击带 `EXTRA_START_TAB` 直达传送页；「暂停 5 分钟 / 恢复」action；传输进度复用同一 notification id。
- **暂停接收**：暂停期间 `POST /offer` 直接 `denied`（不建会话、不弹 PIN），到期自动恢复。
- **省电**：心跳有设备 5s，连续 60s 无设备降到 15s（`DiscoveryCadence`）；后台接收关闭且 App 不可见时停组播接收线程。
- **磁贴**：`TransferTileService` 点击 = 开关「后台接收 + 前台服务」，状态源 `running`（服务被杀自动 `INACTIVE`）；API 33+ 用 `StatusBarManager.requestAddTileService()` 引导，低版本给文案。
- **自动关闭接收**：关闭（默认）/ 5 / 10 / 30 分钟，服务启动成功后起算，到点 `stopForeground(REMOVE) + stopSelf`，磁贴回 `INACTIVE`；只持久化时长、不持久化计时起点。
- **任务持久化**：`DatabaseHelper` v3→v4 新增 `transfer_tasks`（索引 `created_at`），`TransferTaskStore` 读写/删除/裁剪；引擎在创建与进入终态时落库（进度推进不写库），`start()` 异步加载最近 100 条，崩溃残留的非终态按「上次未完成」失败展示。
- **超时收敛**：`enforceTimeouts()`（ticker 每轮 + `offerStatus` 每次查询）—— 待确认超时 / 传输中 60s 无字节进展统一 `failSession()` → `FAILED` + 4007。
- **落盘失败即时终态**：sha256 不符（4005）与落盘失败（4004）立即 `FAILED`，不挂到 4007。
- **接收目录**：设置页显示「占用 X / 共 N 个」+ 清理（二次确认，空时直接提示）；清 `Downloads/局域网互传/` 并移除接收+已完成历史行，失败/取消的 `.part` 保留。
- **小米互传已评估不采用**：无第三方开放 API，系统开关私有，联盟协议只有逆向实现，接入等于再写一套协议栈且仅覆盖联盟设备。
- **Mac 端扫码通道（跨端，Android 无需实现）**：`GET /scan?t=<token>` 上传页 + `POST /scan/upload?t=&name=` 裸字节落盘；token 16 字节随机、10 分钟有效、最多 5 并发、单文件上限 2 GiB（4008 / HTTP 413）。

## 8. 未做 / 遗留风险

1. **真机联调未做**（唯一功能级遗留）：协议 §10 端到端 5 项（互相发现、双向传文件、断网续传、PIN 二次免确认、8 主题切换）需 Android ↔ Mac 真机验证。仅做过 `adb install -r` 安装。
2. **任务列表持久化边界**：删除/撤销只保证进程内一致，撤销窗口外的快照由 UI 调 `commitDelete` 丢弃。
3. **系统深色模式不生效**：App 主题固定 8 套浅色 token，是否需要暗色需产品决策（涉及 8 套 token 全量新增）。
4. **模拟器设备名**：`DEVICE_NAME` 等于型号代号，四级回落只能得到「Google sdk_gphone64_arm64」；真机可拿到用户命名，已加「本机名称」入口兜底。
