# 局域网文件互传协议

> 状态：待实现｜版本：v1（2026-10-18）
> 跨仓库唯一真相：[desktop 仓库设计规格](~/desktop/docs/设计/局域网文件互传-设计规格.md)。本文档是它的 Android 侧落地契约，协议字段以本文档为准；改动协议先改 desktop 侧设计文档，再同步本文档。

## 1. 两端关系

- **Mac 端**：`desktop` 仓库的 NetworkMonitor 菜单栏 App（Swift），新加「传送」面板
- **Android 端**：本仓库（Kotlin），替换现有第 0 个「概览」占位 Tab 为「传送」
- 两端**对称**：都监听 HTTP 端口、都发 UDP 公告、都既能发也能收

## 2. 网络约定

| 用途 | 端口 | 说明 |
|------|------|------|
| UDP 发现 | `53318` | 组播组 `239.255.77.77` + 广播 `255.255.255.255` |
| HTTP 传输 | `53319` | 被占用时顺延 `53320`–`53328`，实际端口随公告上报 |

## 3. 发现协议

三个 `type`，字段集一致（`discover` 可只带 `v/type`）：

```json
{
  "v": 1,
  "type": "announce",
  "deviceId": "and-7f3a9c",
  "alias": "小米14",
  "deviceType": "android",
  "port": 53319,
  "proto": "http",
  "caps": ["send", "recv"],
  "appVersion": "1.0.0",
  "ts": 1760000000
}
```

- `type`：`announce` 周期公告 / `discover` 主动查询 / `offer` 对 `discover` 的单播应答
- 节奏：启动连发 3 次（间隔 500ms）→ 每 5s 心跳；收到 `discover` 立即单播 `offer`（同 IP 2s 内只回一次）
- 离线：15s 未收到公告标记离线，60s 未收到从列表移除
- 兜底顺序：组播 → 广播 → 对本机 `/24` 逐 IP 单播 `discover`（并发 128、单 IP 超时 300ms）

**Android 特有约束**：必须持有 `WifiManager.MulticastLock`，否则多数 ROM 上收不到组播；`MulticastLock` 用完必须 `release()`。

## 4. 传输协议

统一前缀 `http://<ip>:<port>/api/v1/`，响应体沿用本仓库既有约定 `{code, message, data}`。

| 路由 | 方法 | 用途 |
|------|------|------|
| `/info` | GET | 设备信息与能力 |
| `/offer` | POST | 提交文件清单，建立会话 |
| `/offer/status` | GET | 查询会话确认状态（`session` 参数） |
| `/upload` | PUT | 单文件二进制流上传（`session`、`file`、`offset` 参数） |
| `/cancel` | POST | 中止会话（`session` 参数） |

**`POST /offer` 请求体**

```json
{
  "senderDeviceId": "and-7f3a9c",
  "senderAlias": "小米14",
  "files": [
    { "fileId": "f1", "name": "照片.jpg", "size": 4123456, "sha256": "<hex>", "mime": "image/jpeg" }
  ]
}
```

**响应** `data = { sessionId, token, state, accepted[], pairingKey? }`
- `approved`：`accepted` 含每个文件的 `{fileId, offset}`（新文件 `offset=0`）
- `pending`：未配对，接收端已弹 PIN，`token` 照常返回、`accepted` 为空数组
- `denied`：用户拒绝
- `pairingKey`：**可选**，仅本次 offer 完成新配对（PIN 校验通过）时出现，32 字节小写 hex；由接收端生成，发送端按 `peerDeviceId` 持久化，后续请求带 `X-Pair-Key`

**`PUT /upload`**：请求头 `X-Transfer-Token`、`Content-Type: application/octet-stream`；请求体是从 `offset` 起的裸字节流（不包 multipart）；成功返回 `{fileId, received, sha256}`。

**鉴权分工**：`X-Pair-Key` 只用于 `POST /offer`（判断能否免确认）；`token` 只用于 `PUT /upload`（判断本次会话能否上传）。

### 4.1 错误码

| code | 含义 |
|------|------|
| 0 | 成功 |
| 4001 | token 缺失或不匹配 |
| 4002 | 会话不存在或已过期 |
| 4003 | offset 与已收字节不匹配 |
| 4004 | 接收端磁盘空间不足 |
| 4005 | sha256 校验失败 |
| 4006 | 用户拒绝 |
| 4007 | 确认超时（默认 60s） |

## 5. 配对

- 未配对时 `POST /offer`（无 `X-Pair-Key`）返回 `state=pending`，接收端展示 4 位 PIN；发送端输入 PIN 后**带 `pin` 与上次的 `sessionId` 重新 `POST /offer`**
- 接收端没收到 `sessionId` 时，按 `senderDeviceId + files 的 sha256 集合` 复用待确认会话
- **`pairingKey` 由接收端生成、经 `/offer` 的 approved 响应下发给发送端**，双方各自按 `deviceId` 持久化；此后带 `X-Pair-Key` 免确认
- 接收端展示的对方名称优先取 offer 的 `senderAlias`（如 `bsfeng 的 Mac`），字段缺失或空白时才回落「未知设备」
- 确认超时 60s：PIN 弹层显示「Ns 后自动拒绝」，超时自动收起（不发通知、不播失败音），会话置 `failed`（4007）
- PIN 由**接收方**生成显示、发送方输入

## 6. 落盘与续传

- 默认目录 `Downloads/局域网互传/`，用 `MediaStore.Downloads` + `RELATIVE_PATH` 写入（`minSdk 29` 原生支持）
- 传输中写 `<fileId>.part`，完成后校验 sha256 再改名；同名追加 ` (1)`
- 缓冲 64 KiB 流式落盘，内存占用与文件大小无关
- 60s 无字节进展判超时；断网重试 3 次（1s/2s/4s 退避），失败保留 `.part` 供下次续传

## 7. Android 侧动效与音效

动效全部复用已有 token（`DesignTokenTable` 的 `dur-*` / `ease-*`），不新增时长常量：

| 触发 | 动效 | 时长 / 曲线 |
|------|------|------------|
| 设备出现在列表 | 淡入 + 上移 10px，逐项延迟 | 340ms / ease-out，每项 +24ms |
| 任务卡新增 | 高度展开 + 淡入 | 340ms / ease-out |
| 进度推进 | 宽度插值，数字等宽 | 120ms / ease-standard |
| 传输完成 | 进度条填满 → 对勾弹入 → 转成功色 | 220ms / ease-spring |
| 传输失败 | 横向抖动 ±4px ×3 → 转错误色 | 300ms / ease-in |
| 配对弹层 | 淡入 + 缩放 0.96→1 | 220ms 进 / 150ms 出 |
| PIN 每位填入 | scale 0.9→1 | 120ms / ease-spring |
| 按钮按下 | scale 0.96 | 120ms |

系统动画缩放为 0 时全部直接到终态（复用 `rememberMotionEnabled`）。

音效（零依赖，不打包音频资源）：

| 事件 | 实现 | 默认 |
|------|------|------|
| 接收/发送完成 | `RingtoneManager` 系统通知音 + `HapticFeedbackConstants.CONFIRM` | 开 |
| 传输失败 | `ToneGenerator.TONE_PROP_NACK` + `HapticFeedbackConstants.REJECT` | 关 |
| 新设备出现 | 仅震动 `CONFIRM` | 关 |

同一事件 500ms 内去重。
