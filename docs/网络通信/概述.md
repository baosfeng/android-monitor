# 网络通信模块

## 职责

Android ↔ 后端的全部 HTTP 通信：设备注册、事件批量上报、心跳保活。两个核心类：`ApiService`（HTTP 封装 + 数据类）与 `EventReporter`（业务：拉未发事件 → 构建批次 → 上传 → 标记已上传 → 清理过期）。

零第三方依赖：只用系统内置 `java.net.HttpURLConnection` 与 `org.json.JSONObject`（不引 Retrofit / OkHttp / kotlinx.serialization）。

## 数据流

```
上层（定时调度 / ViewModel）
 → EventReporter.uploadBatch() / registerDevice()     包 network
 → ApiService（object）：uploadEvents / registerDevice / heartbeat / checkConnection
 → HttpURLConnection（每次新建连接，connect/read 超时各 10s，Authorization: Bearer <token>）
 → 后端
```

## 文件

| 文件 | 职责 |
|---|---|
| `network/ApiService.kt` | 请求封装、JSON 序列化/反序列化、数据类定义 |
| `network/EventReporter.kt` | 批量上传与设备注册的业务封装 |

## ApiService

| 方法 | HTTP | 路径 | 请求体 | 返回 |
|---|---|---|---|---|
| `uploadEvents(batch)` | POST | `events` | `EventsBatch.toJson()` | `Result<JsonResponse>` |
| `registerDevice(request)` | POST | `devices` | `DeviceRegisterRequest.toJson()` | `Result<JsonResponse>` |
| `heartbeat()` | GET | `heartbeat` | — | `Result<JsonResponse>` |
| `checkConnection()` | — | — | — | `Boolean` |

`data class JsonResponse(val code: Int, val json: JSONObject)`：`code` 是 HTTP 状态码，`json` 是已解析响应体。

配置：Base URL = `AppConfig.serverBaseUrl`（`BuildConfig.SERVER_BASE_URL`，末尾自动补 `/`）；`Content-Type: application/json`；连接/读取超时 10s；每次请求从 `AppUtils.getToken()` 取 Bearer Token 注入 `Authorization`；无状态 object，不管理实例。

解析函数：`parseUploadResponse` / `parseDeviceRegisterResponse` / `parseHeartbeatResponse`（`JsonResponse` → 类型化数据类）。

## 数据类

均为纯 Kotlin 数据类（无 `@Serializable`），提供 `toJson(): JSONObject`。

请求：`EventsBatch`（`events`、`batch_id`、`device_id`、`batch_created_at_ms`、`batch_size`）、`DeviceRegisterRequest`（`device_id`、`device_name`、`manufacturer`、`model`、`android_version`、`app_version`（`VERSION_NAME`）、`app_build`（`VERSION_CODE`））。

响应统一 `{ code, message, data }`：`UploadResponse(data: accepted_count / rejected_count / server_time_ms)`、`DeviceRegisterResponse(data: device_id / token / token_expires_at_ms / config)`、`HeartbeatResponse(data: server_time_ms / config)`。

`ServerConfig` 可覆盖本地 `AppConfig` 默认值：`upload_interval_ms 5000`、`batch_max_size 50`、`retry_max_attempts 5`、`retry_backoff_base_ms 1000`、`cache_max_days 3`、`enable_notification_content true`。字段级契约见 [API 接口定义](../API接口定义_后端需实现.md)。

## EventReporter

`class EventReporter(private val context: Context)`，内部用 `ApiService` 与 `DatabaseHelper` 单例。

`uploadBatch(): Result<Int>`（挂起，`Dispatchers.IO`）：

```
db.getUnsentEvents(batchMaxSize) → 空则返回 success(0)（不发请求）
构建 EventsBatch（batch UUID、device_id、时间戳）→ ApiService.uploadEvents()
成功（HTTP 200 且 code == 0）→ db.markUploaded(eventIds) → cleanOldEvents() → success(size)
```

`registerDevice(): Result<String>`：构建 `DeviceRegisterRequest`（`AppUtils` / `BuildConfig`）→ `ApiService.registerDevice()` → 成功则 `AppUtils.saveToken(token)` → 返回 token。

私有：`cleanOldEvents()` 删除 `now - cacheMaxDays` 之前的记录；`EventEntity.toUnifiedEvent()` 把 `extraJson` 反序列化为 `Map<String, String>`，失败返回空 Map。

## 边界与注意

1. **Token**：注册成功写 `SharedPreferences`；每次请求实时读取，无自动刷新 —— 过期需重新注册。
2. **线程**：`EventReporter` 公开方法都 `withContext(Dispatchers.IO)`；`ApiService` 无状态，线程安全。
3. **清理独立于上传**：上传失败也保留旧事件等下次重试；清理按 `cacheMaxDays`。
4. **空批次短路**：无未发送事件直接返回 `success(0)`，不发起 HTTP。
5. **动态配置**：注册与心跳可能带 `ServerConfig`，本模块不自动应用，由上层按需更新调度参数。
