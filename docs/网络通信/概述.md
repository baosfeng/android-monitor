# 网络通信模块

## 职责

Android ↔ 后端的全部 HTTP 通信，零第三方依赖（只用 `HttpURLConnection` + `org.json`）。**当前一个请求都不发**：`EventReporter.registerDevice()` 与 `ApiService.heartbeat()` 封装完整但**无调用方**（`ServiceContainer.eventReporter` 只 lazy 定义），`uploadBatch()` 是二期桩（恒返回 `Result.success(0)`）；`AlarmReceiver` 也因此不触发任何上报。

## 数据流

```
EventReporter.registerDevice()              包 network，已封装、当前无调用方
 → ApiService（object）：registerDevice / uploadEvents / heartbeat / checkConnection
 → ApiHttpTransport：post / get（每次新建连接，connect/read 超时各 10s，Authorization: Bearer <token>）
 → 后端 → ApiResponseParser 解析成类型化数据类
```

## 文件

| 文件 | 职责 |
|---|---|
| `network/ApiService.kt` | 动作入口：发哪个请求（上报 / 注册 / 心跳 / 连通性探测） |
| `network/ApiHttpTransport.kt` | `HttpURLConnection` 收发与连接释放，无业务语义 |
| `network/ApiDtos.kt` | 请求 / 响应数据类与 `toJson()` 编码 |
| `network/ApiResponseParser.kt` | `JsonResponse` → 类型化数据类 |
| `network/EventReporter.kt` | 业务封装；`registerDevice()` 有实现但无调用方，`uploadBatch()` 是二期桩 |

## ApiService

| 方法 | HTTP | 路径 | 请求体 | 返回 |
|---|---|---|---|---|
| `uploadEvents(batch)` | POST | `api/monitor/events` | `EventsBatch.toJson()` | `Result<JsonResponse>` |
| `registerDevice(request)` | POST | `api/monitor/devices` | `DeviceRegisterRequest.toJson()` | `Result<JsonResponse>` |
| `heartbeat()` | GET | `api/monitor/heartbeat` | — | `Result<JsonResponse>` |
| `checkConnection()` | GET | `api/monitor/heartbeat` | — | `Boolean`（收到任何响应即 true） |

`data class JsonResponse(val code: Int, val json: JSONObject)`：`code` 是 HTTP 状态码，`json` 是已解析响应体。

配置：Base URL = `AppConfig.serverBaseUrl`（`BuildConfig.SERVER_BASE_URL`，末尾自动补 `/`）；`Content-Type: application/json`；每次请求从 `AppUtils.getToken()` 取 Bearer Token；无状态 object。

## 数据类

纯 Kotlin 数据类（无 `@Serializable`），提供 `toJson(): JSONObject`。

- 请求：`EventsBatch`（`events` / `batch_id` / `device_id` / `batch_size` 等）、`DeviceRegisterRequest`（`device_id` / `device_name` / `manufacturer` / `model` / `android_version` / `app_version` / `app_build`）
- 响应统一 `{ code, message, data }`：`UploadResponse` / `DeviceRegisterResponse`（含 token）/ `HeartbeatResponse`
- `ServerConfig` 可覆盖本地默认值（`batch_max_size 50` / `retry_max_attempts 5` / `cache_max_days 3`），本模块不自动应用，由上层按需更新调度参数

`ApiDtos` 的 `LOCAL_ONLY_DETAIL_KEYS`（当前只有 `address`）保证定位地址永不随事件上传。字段级契约见 [API 接口定义](../API接口定义_后端需实现.md)。

## EventReporter

`class EventReporter(private val context: Context)`，公开方法都 `withContext(Dispatchers.IO)`。

`registerDevice(): Result<String>`：构建 `DeviceRegisterRequest`（`AppUtils` / `BuildConfig`）→ `ApiService.registerDevice()` → HTTP 2xx 且 `code == 0` 时 `AppUtils.saveToken(token)` → 返回 token。

`uploadBatch(): Result<Int>` 全文只有两行：

```
DiagnosticCounters.lastUploadResult = "上传暂不可用（二期实现）"
Result.success(0)
```

> 二期接上传必须一并补回：取未发事件 → 构建 `EventsBatch` → 成功才标记 → 按 `cacheMaxDays` 清理，以及 `AlarmReceiver` 里「有 token 才上传 + 失败指数退避」的调度。**别恢复成每 60 秒无条件上传**。

## 边界与注意

1. **凭据只有 token**：注册成功写 `monitor_prefs` 的 `auth_token`（Keystore AES-GCM 密文，`v1:` 前缀；解不开即视为未登录）；无自动刷新，过期需重新注册。当前无调用方，所以这个流程还没被真正跑过。
2. **没有上传队列**：库里没有「已上传」标记，也没有事件实体 / `getUnsentEvents` / `markUploaded`——别按旧文档找。
3. **`uploadBatch()` 恒成功**：调用方拿不到失败信号；接真实上传时要同时改调用方的重试语义。
