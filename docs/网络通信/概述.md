# 网络通信模块

## 职责概述

本模块负责 Android 端与后端服务器的所有 HTTP 通信，包括设备注册、事件批量上报和心跳保活。对外暴露两个核心类：`ApiService`（HTTP 请求封装 + 数据类定义）和 `EventReporter`（业务封装：从 SQLite 拉取事件 → 构建批次 → 上传 → 标记已上传 → 清理过期数据）。

> 本模块使用 `java.net.HttpURLConnection` 和 `org.json.JSONObject`（均为 Android 系统内置 API），**不依赖 Retrofit / OkHttp / Kotlinx Serialization 等第三方库**。

## ApiService — HTTP 请求封装

**文件：** `app/src/main/java/com/bsfeng/monitor/network/ApiService.kt`

### 公开方法

| 方法 | HTTP | 路径 | 请求体 | 返回类型 | 用途 |
|------|------|------|--------|----------|------|
| `uploadEvents(batch)` | POST | `events` | `EventsBatch.toJson()` | `Result<ApiService.JsonResponse>` | 批量上报事件 |
| `registerDevice(request)` | POST | `devices` | `DeviceRegisterRequest.toJson()` | `Result<ApiService.JsonResponse>` | 设备注册获取 Token |
| `heartbeat()` | GET | `heartbeat` | — | `Result<ApiService.JsonResponse>` | 心跳保活 + 同步服务端配置 |

### JsonResponse

```kotlin
data class JsonResponse(val code: Int, val json: JSONObject)
```

- `code` — HTTP 状态码
- `json` — 已解析的 `JSONObject`（来自服务端响应体 JSON）

### HTTP 客户端配置

| 配置项 | 值 |
|--------|-----|
| Base URL | `AppConfig.serverBaseUrl`（来自 `BuildConfig.SERVER_BASE_URL`，末尾自动补 `/`） |
| Content-Type | `application/json` |
| 超时 — 连接 | 10 秒 |
| 超时 — 读取 | 10 秒 |
| 认证 | 每次请求从 `AppUtils.getToken()` 读取 Bearer Token，注入 `Authorization` 请求头 |
| 实例管理 | 无状态 object（不需要单例管理） |

### 响应解析辅助方法

ApiService 提供 3 个解析函数，将 `JsonResponse` 转为对应的类型化数据类：

| 函数 | 输入 | 输出 |
|------|------|------|
| `parseUploadResponse(resp)` | `JsonResponse` | `UploadResponse` |
| `parseDeviceRegisterResponse(resp)` | `JsonResponse` | `DeviceRegisterResponse` |
| `parseHeartbeatResponse(resp)` | `JsonResponse` | `HeartbeatResponse` |

## 数据类定义

所有请求/响应模型均为纯 Kotlin 数据类（无 `@Serializable` 注解），提供 `toJson(): JSONObject` 方法。

#### 请求体

| 数据类 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `EventsBatch` | `events` | `List<UnifiedEvent>` | 事件列表 |
| | `batch_id` | `String` | 批次 UUID |
| | `device_id` | `String` | 设备标识 |
| | `batch_created_at_ms` | `Long` | 批次创建时间戳 |
| | `batch_size` | `Int` | 本批事件数 |
| `DeviceRegisterRequest` | `device_id` | `String` | 设备 ID |
| | `device_name` | `String` | 设备名称（如"小米14"） |
| | `manufacturer` | `String` | 制造商（如 Xiaomi） |
| | `model` | `String` | 型号（如 23127PN0CC） |
| | `android_version` | `String` | Android 版本号 |
| | `app_version` | `String` | App 版本名（`BuildConfig.VERSION_NAME`） |
| | `app_build` | `Int` | App 构建号（`BuildConfig.VERSION_CODE`） |

#### 响应体

所有响应体统一结构：`{ code: Int, message: String, data: T? }`。

| 数据类 | data 内部类 | 关键字段 |
|--------|-------------|----------|
| `UploadResponse` | `UploadData` | `accepted_count`, `rejected_count`, `server_time_ms` |
| `DeviceRegisterResponse` | `DeviceRegisterData` | `device_id`, `token`, `token_expires_at_ms`, `config: ServerConfig?` |
| `HeartbeatResponse` | `HeartbeatData` | `server_time_ms`, `config: ServerConfig?` |

`ServerConfig` 可动态覆盖本地 `AppConfig` 默认值：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `upload_interval_ms` | 5000 | 上传间隔（毫秒） |
| `batch_max_size` | 50 | 每批最大事件数 |
| `retry_max_attempts` | 5 | 失败最大重试次数 |
| `retry_backoff_base_ms` | 1000 | 退避基时（毫秒） |
| `cache_max_days` | 3 | 本地缓存保留天数 |
| `enable_notification_content` | true | 是否采集通知内容 |

## EventReporter — 业务封装

**文件：** `app/src/main/java/com/bsfeng/monitor/network/EventReporter.kt`

### 构造依赖

```kotlin
class EventReporter(private val context: Context)
```

- `context` — 用于初始化 `DatabaseHelper` 实例
- 内部持有 `ApiService`（无状态 object）和 `DatabaseHelper` 单例

### 公开方法

| 方法 | 返回类型 | 调用时机 | 说明 |
|------|----------|----------|------|
| `uploadBatch()` | `Result<Int>` | 定时器或触发式调度 | 从 DatabaseHelper 拉取未发送事件 → 构建 `EventsBatch` → POST → 标记已上传 → 清理过期 |
| `registerDevice()` | `Result<String>` | 应用首次启动或 Token 无效时 | 构建设备信息 → POST → 保存返回的 Token → 返回 Token 字符串 |

### uploadBatch() 流程

```
① db.getUnsentEvents(AppConfig.batchMaxSize)
   ↓ 空列表 → 返回 Result.success(0)
   ↓ 有数据
② 构建 EventsBatch（包含 batch UUID、device_id、时间戳）
   ↓
③ ApiService.uploadEvents(batch)
   ↓ 成功 (HTTP 200 且 code == 0)
④ db.markUploaded(events.map { it.eventId })
⑤ cleanOldEvents()  →  删除超过 cacheMaxDays 的旧事件
⑥ 返回 Result.success(events.size)
```

### registerDevice() 流程

```
① 构建 DeviceRegisterRequest（从 AppUtils / BuildConfig 读取设备与版本信息）
   ↓
② ApiService.registerDevice(request)
   ↓ 成功 (HTTP 200 且 code == 0)
③ AppUtils.saveToken(token)
④ 返回 Result.success(token)
```

### 私有方法

| 方法 | 说明 |
|------|------|
| `cleanOldEvents()` | 计算 `now - cacheMaxDays` 时间戳，调用 `db.cleanOldEvents(before)` 删除过期记录 |
| `EventEntity.toUnifiedEvent()` | 将 `EventEntity` 转为 `UnifiedEvent`，`extraJson` 通过 `JSONObject(extraJson)` 反序列化为 `Map<String, String>`，失败则返回空 Map |

## 注意事项

1. **Token 持久化：** `registerDevice()` 成功后通过 `AppUtils.saveToken(token)` 写入 `SharedPreferences`；`ApiService` 每次请求从 `AppUtils.getToken()` 读取，不支持自动刷新——Token 过期需重新注册。
2. **线程安全：** `EventReporter` 所有公开方法使用 `withContext(Dispatchers.IO)` 切换到 IO 线程；`ApiService` 为无状态 object，线程安全。
3. **旧事件清理：** `uploadBatch()` 成功后调用 `cleanOldEvents()`，以 `AppConfig.cacheMaxDays` 为保留期限。该清理独立于上传——即使上传失败，旧事件仍会留在数据库中等待下次重试。
4. **空批次短路：** 当数据库中无未发送事件时，`uploadBatch()` 立即返回 `Result.success(0)`，不会发起 HTTP 请求。
5. **服务端动态配置覆盖：** 注册和心跳响应中均可能携带 `ServerConfig`，调用方应根据其值动态更新本地调度参数（当前由上层业务自行处理，本模块不自动应用）。
