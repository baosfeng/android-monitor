# 交互契约口径（全项目统一）

> 21 份契约共用的一套口径。写契约前先读本文，避免每份各说一套。
> 依据优先级：项目源码实测 > 项目设计规范 > 原型 > 本文件默认值。

## 一、时长

| 项 | 取值 | 依据 |
|---|---|---|
| 按下态 | 120ms | `--dur-press` |
| 状态描边 / 底色变化 | 120ms | `--dur-state` |
| 浮层进入 | 220ms | `--dur-overlay-in` |
| 浮层退出 | 150ms | `--dur-overlay-out` |
| 页面转场 | 由 `Transitions.kt` 统一，不写进契约 | 设计规范 §6 |
| **Toast 停留** | **1600ms** | `ui/components/ToastHost.kt:35` `durationMs: Int = 1600` |
| 撤销窗口 | 5000ms | 交互惯例，全项目一致 |
| 搜索防抖 | 300ms | 无源码依据，取通用值 |

## 二、点击区与行高

| 项 | 取值 |
|---|---|
| 可点元素点击区 | ≥ 44×44 dp |
| 列表行高 | ≥ 52 dp |
| 相邻可点元素间距 | ≥ 8 dp |

## 三、触感

| 场景 | 强度 |
|---|---|
| 开关、行选中、普通按钮 | LIGHT |
| 主操作确认、完成对勾 | SUCCESS |
| 破坏性操作（删除 / 取消传输） | REJECT |

同一操作不重复震动。

## 四、多选与单选（易混点）

| 控件 | 语义 | 判定依据 |
|---|---|---|
| 抽屉里带「确定」按钮的 chip 组 | 按**标题与确认文案**判定：标题单数（「选择记录类型」）+ 确认 toast 单数 → **单选** | 文案即契约 |
| 无确认按钮、勾选即生效的 chip 组 | **多选** | 项目惯例 |

> 结论：`s12` 抽屉 chip 按**单选**写（标题「选择记录类型」、确认「已选择：前台切换」均是单数）。原型的脚本行为与文案冲突时，**以文案为准**——文案是用户看到的，脚本可以被改。

## 五、写契约时禁止出现的内容

| 禁止 | 原因 |
|---|---|
| 「现状是…」「改为…」「落点在 xxx.kt:行」 | 这是改进方案，不是契约 |
| 「用 BottomSheet 实现」「改 ViewModel」 | 这是实现方案，交开发定 |
| 「按设计稿」 | 设计稿不会变，契约会 |
| 空话：友好 / 合理 / 按需 / 视情况 / 有反馈 | 无法验收 |

## 六、锚点规则

- 锚点逐字沿用原型 `data-od-id`，**不改号、不新增、不删除**
- 一个锚点承载多个控件时（如卡片容器带 3 个按钮），在该锚点下用多行覆盖，并在「控件」列写清是哪个
- 确实需要拆分的，写进交付回报，由下一轮统一处理；**本轮不擅自改号**

## 七、待产品确认项怎么处理

拿不准的**按最保守口径写死**，并在文件末尾加一行：

```
> [待确认] <问题描述>｜当前按 <取值> 写
```

不要留空、不要写「待定」——契约必须可以直接照着做。
