## 内部矛盾（3 条）

### 1. s02 组头焦点：可聚焦 vs 不参与焦点顺序

- 冲突：`s02-g08` 边界列写「组头不参与焦点顺序」；`s02-loadwrap` 移除列写「按钮消失后焦点落到新出现的第一个组头」。
- 裁决：**组头可聚焦**（2dp 环），但 Tab 不逐个停在每个组头——「不参与焦点顺序」理解为「不占 Tab 停位」。
- 依据：加载完成后焦点必须有落点，组头不可聚焦则 `s02-loadwrap` 的承诺无法兑现。
- 实施：`LiveEventTimeline.kt` 的 `LiveHourGroupHead` 持有 `focusRequester`。

### 2. s06 空态卡位置：视觉首位 vs 焦点末位

- 冲突：`s06-empty` 边界列写「空态卡画在列表首位，下方分类行照常渲染」；`s06-content` 反馈列写「Tab 依次进入：上个月 → 下个月 → 总预算行 → 6 条分类行 → 空态 CTA」。
- 裁决：**视觉与焦点都按首位**，Tab 顺序为月份条 → 空态标题/CTA → 总预算行 → 分类行。
- 依据：焦点顺序跟随视觉顺序（审查清单口径）；否则键盘用户会先跳过首屏最大的卡片。
- 实施：`BudgetScreen.kt` 空态标题持 `emptyTitleFocus`，进入空态即获焦。

### 3. s12 抽屉 chip：多选 vs 单数文案

- 冲突：`s12-sheet` 类型 chip 行写「多选：每个 chip 独立切换，参与最终『确定』结果」；同组「确定」行的 toast 写「已选择：前台切换」（单数）。
- 裁决：**单选**。
- 依据：`契约口径.md` §四「标题与确认文案是单数 → 单选；原型脚本行为与文案冲突时以文案为准」。
- 实施：抽屉 chip 组单选，选中即替换。

## 已裁决的口径（实施时按此执行）

- **焦点环**：一律 2dp，仅键盘 / 遥控器操作时绘制；契约写 4px 的以 2dp 为准。
- **动画时长**：取 `MotionTokens`；契约里的近似数字（如 600ms 长按）不单独造 token。
- **按下缩放**：统一走共享基元的 0.96；契约写 0.94 / 0.965 / 0.985 的差值 ≤0.03，不逐页微调。
- **toast**：全项目 1.6s 停留（契约写 1.8s 的取 token）。
- **无数据源不编数**：DeepSeek 赠金 / 充值、s09 副标题计数、s01 环比等，锚点保留、条件渲染、登记待确认。
