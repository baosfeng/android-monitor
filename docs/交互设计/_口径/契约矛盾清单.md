## 四、已裁决口径

- **焦点环** 2dp，仅键盘/遥控器绘制；契约写 4px 的以 2dp 为准。
- **动画时长** 取 MotionTokens；近似数字不造 token。
- **按下缩放** 统一 0.96；0.94 / 0.965 / 0.985 差值 ≤0.03 不逐页微调。
- **行按压** 统一 0.96 缩放 + LIGHT；s12 契约写的「fg 5% 底色」并入统一基元。
- **toast** 1.6s 停留（契约写 1.8s 的取 token）。
- **无数据源不编数**：锚点保留、条件渲染、登记待确认。

## 六、契约把「演示态」写成了验收条件

同一类问题出现 4 次，处理方式统一：**改契约措辞，不改代码**。

- **s12 展厅三处 CTA**：结果列写「打开监控开关 / 重新发起加载 / 删除该条记录」，但展厅是纯演示容器，手里没有任何业务依赖。改为「只演示反馈，不改数据」，与同屏 s12-buttons 的既有写法一致。
- **s12 弹窗演示**：删除确认弹窗是共享组件的真实实例，确认后不删真实记录容易让人误解交付形态。改为在弹窗文案标注「演示用，不删真实记录」。
- **s09 / s11 / s13 五态行**：前置条件绑定在「状态切换器」上，而该切换器受 `rememberDemoVisible()` 三重闸控制，release 构建恒不渲染。契约需区分「演示态验收」与「真实数据态验收」，不能把演示件当作产品行为写死。
- **s13「重新应用」失败分支**：`ThemeRepository.setTheme` 对已知 id 恒返回 true，失败态不可达。契约应写明「本态由演示切换器进入」。

## 七、易误判项（已澄清，勿再按缺陷处理）

- **s19 opencode-go / opendesign「假能力」**：契约 s19:18/19 写「不可展开」，但源码四家都是真 provider（`ServiceContainer.kt:74-83`，各有单测，真发请求）。**以源码为准、行可展开**——本条见第三节既有裁决。按契约禁用等于把可用功能变成死功能。
- **s06 分类预算连带改总预算**：不是缺陷。契约 s06:39 明写「总预算＝分类预算之和」，`FinanceViewModel.setCategoryBudget` 求和回写是该口径的实现。
