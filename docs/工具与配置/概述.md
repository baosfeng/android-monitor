# 工具与配置

> 层级：工具层（见[架构总览](../概览/架构总览.md)）。包：`com.bsfeng.monitor` / `.util`。
> 提供全局配置参数、通用工具与调试诊断能力。

## 1. `AppConfig`（`AppConfig.kt`）

单例对象，从 `BuildConfig` 编译期常量暴露配置；值在 `app/build.gradle.kts` 中由 `buildConfigField` 定义（`local.properties` 可覆盖），构建时注入、打包后不可改。

| 属性 | 默认 | 说明 |
|---|---|---|
| `serverBaseUrl` | `https://your-server.example.com` | 后端基地址；`local.properties` 的 `serverBaseUrl` 注入，仓库内只留占位 |
| `uploadIntervalMs` | 5000 | 批量上报轮询间隔，决定入库到发出的最大延迟 |
| `batchMaxSize` | 50 | 单次批量最大事件数 |
| `cacheMaxDays` | 3 | SQLite 本地缓存保留天数，超期清理 |
| `retryMaxAttempts` | 5 | 单批最大重试次数，超出丢弃 |
| `notificationContentEnabled` | true | 是否采集通知正文；关闭后只留元信息 |

调整方式：改 `app/build.gradle.kts` 中对应的 `buildConfigField`（`SERVER_BASE_URL` / `UPLOAD_INTERVAL_MS` / `BATCH_MAX_SIZE` / `CACHE_MAX_DAYS` / `RETRY_MAX_ATTEMPTS` / `NOTIFICATION_CONTENT_ENABLED`）。

## 2. `AppUtils`（`util/AppUtils.kt`）

单例对象，设备与应用元信息工具。

| 方法 | 说明 |
|---|---|
| `getDeviceId()` | 持久化设备唯一标识：首次生成 UUID 写入 `monitor_prefs`，之后恒定 |
| `getAppName(packageName)` | 包名 → 显示名，查不到返回包名 |
| `getToken()` / `saveToken(token)` | 读写认证令牌 |
| `getDeviceName()` / `getManufacturer()` / `getAndroidVersion()` | `Build.MODEL` / `MANUFACTURER` / `VERSION.RELEASE` |

SharedPreferences 名 `monitor_prefs`，键 `device_id`、`auth_token`。卸载后设备标识不保留。

## 3. `DebugConfig`（`util/DebugConfig.kt`）

调试开关，开启后输出 `MonitorDebug` 日志，可在设置页实时切换。

`init()`（从 `monitor_prefs` 读状态与解锁标记）、`setEnabled(value)`（持久化并更新运行时标志）、`log(message)`（仅调试模式 `Log.d`）、`unlock()`（解锁隐藏调试入口）。持久化键：`debug_enabled`、`debug_unlocked`。

## 4. `DiagnosticCounters`（`util/DiagnosticCounters.kt`）

无 adb/logcat 时排查数据流用；字段均 `@Volatile`。按四组计数：

| 分组 | 字段 |
|---|---|
| 无障碍服务 | `accessibilityEventCount`、`lastAccessibilityEventType`、`lastAccessibilityPackage`、`accessibilityFilteredCount`（被系统 UI 过滤数） |
| EventCollector | `emitCalledCount`、`lastEmittedEventType`、`emitSuccessCount`、`emitFailCount`、`lastErrorMessage` |
| DatabaseHelper | `dbInsertCalledCount`、`dbInsertSuccessCount`、`dbInsertConflictCount`（rowId == -1）、`dbInsertFailCount`、`dbLastException` |
| 上传 | `uploadAttemptCount`、`uploadSuccessCount`、`uploadFailCount`、`lastUploadResult`、`lastUploadError`、`isTokenAvailable`、`uploadEventCount` |

`snapshot()` 生成分段诊断报告（`toString()` 同），`reset()` 清零，另有 `lastRefreshTimestamp`。

```kotlin
DiagnosticCounters.accessibilityEventCount++
Log.d("Diagnostics", DiagnosticCounters.snapshot())
DiagnosticCounters.reset()
```

## 5. `MonitorApp`（`MonitorApp.kt`）

`Application` 入口，`onCreate()` 顺序：

1. `instance = this`（`MonitorApp.instance` 供全局取 Context，无 Hilt/Dagger）。
2. `SkipConfig.init(this)` —— 必须在规则管理器创建前，内置规则时间闸门依赖它。
3. `AutoBookConfig.init(this)` —— 自动记账开关（默认开启），无障碍服务在支付结果页读取。
4. `container = ServiceContainer(this)` —— 手动 DI 容器（依赖注入统一走它）。
5. `registerRecordReceiver()` —— 注册 `RecordReceiver`（动态注册，两个 filter，`RECEIVER_EXPORTED`）。
6. `registerWifiNetworkCallback()` —— 用 `NetworkCallback` 而非 `WIFI_STATE_CHANGED_ACTION`（后者是硬件开关，在 HyperOS 上易误触发；首次同步回调要跳过，防 force-stop 后误记「连接 WiFi」）。
7. `scheduleAlarmCheck(this)` —— 每分钟保活检查 + 周期上报（设备注册/心跳）。
8. `checkSubscriptionUpdate()` —— 后台检查一次规则订阅更新（未订阅或未到周期立即返回）。

`AndroidManifest.xml` 中 `android:name=".MonitorApp"`。

## 6. 消费者

| 消费者 | 使用 | 用途 |
|---|---|---|
| `record/RecordCollector` | `AppUtils.getDeviceId()` | 事件富化附设备标识 |
| `network/EventReporter`、上传引擎 | `AppConfig.*` | 上报行为与清理策略 |
| `MonitorAccessibilityService` | `AppConfig.notificationContentEnabled`、`DiagnosticCounters.*` | 通知正文开关、数据流诊断 |
| 设备注册 / 认证 | `AppUtils.getToken()` / `saveToken()` | 维护认证状态 |
| 任意模块 | `MonitorApp.instance` | 取 Application Context |
| 设置页 | `DebugConfig.init()` / `setEnabled()` | 调试模式开关 |
