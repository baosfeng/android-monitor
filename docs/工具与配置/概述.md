# 工具与配置

> **所属层级：** 工具层（见[架构总览](../概览/架构总览.md)）
> **包名：** `com.bsfeng.monitor` / `com.bsfeng.monitor.util`

提供应用的全局配置参数、通用工具方法和调试诊断工具，支撑其他所有模块的运行时行为。

---

## 1. 应用配置 — `AppConfig`

**文件：** `app/src/main/java/com/bsfeng/monitor/AppConfig.kt`

单例对象，从 `BuildConfig` 编译期常量暴露配置属性。各配置项在 `app/build.gradle.kts` 中定义，构建时注入，打包后不可修改。

### 配置项一览

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `serverBaseUrl` | `String` | `"https://your-server.example.com"` | 后端 API 基地址，由 `local.properties` 的 `serverBaseUrl` 注入；仓库内只保留占位，本地构建时自行配置 |
| `uploadIntervalMs` | `Int` | `5000` | 批量上报轮询间隔（毫秒），决定事件从入库到发出的最大延迟 |
| `batchMaxSize` | `Int` | `50` | 单次批量上报的最大事件数，避免单包过大 |
| `cacheMaxDays` | `Int` | `3` | SQLite 本地缓存保留天数，超期事件会被清理 |
| `retryMaxAttempts` | `Int` | `5` | 单批事件上报的最大重试次数，超出后丢弃 |
| `notificationContentEnabled` | `Boolean` | `true` | 是否采集通知内容文本（无障碍服务读取），关闭后只采集通知元信息 |

### 使用示例

```kotlin
// 任意模块中通过 AppConfig 读取
val baseUrl = AppConfig.serverBaseUrl
val interval = AppConfig.uploadIntervalMs
```

### 操作意图对照表

| 目标 | 操作 |
|------|------|
| 修改服务器地址 | 修改 `app/src/main/java/com/bsfeng/monitor/AppConfig.kt` 中 `serverBaseUrl` 的硬编码值，重新构建 |
| 调整上报频率 | 修改 `app/build.gradle.kts` 中 `UPLOAD_INTERVAL_MS` 的 `buildConfigField` 值 |
| 调整批量大小 | 修改 `app/build.gradle.kts` 中 `BATCH_MAX_SIZE` 的 `buildConfigField` 值 |
| 调整缓存天数 | 修改 `app/build.gradle.kts` 中 `CACHE_MAX_DAYS` 的 `buildConfigField` 值 |
| 调整重试次数 | 修改 `app/build.gradle.kts` 中 `RETRY_MAX_ATTEMPTS` 的 `buildConfigField` 值 |
| 关闭通知内容采集 | 修改 `app/build.gradle.kts` 中 `NOTIFICATION_CONTENT_ENABLED` 为 `false` |

> **编译配置定义文件：** `app/build.gradle.kts` 第 16–21 行。

## 2. 工具方法 — `AppUtils`

**文件：** `app/src/main/java/com/bsfeng/monitor/util/AppUtils.kt`

单例对象，提供与设备和应用元信息相关的静态工具方法。依赖 `MonitorApp.instance` 获取 Application Context。

### 方法一览

| 方法 | 返回类型 | 说明 |
|------|---------|------|
| `getDeviceId()` | `String` | 获取持久化设备唯一标识。首次调用生成 UUID 并写入 `SharedPreferences`（`monitor_prefs`），后续始终返回同一值 |
| `getAppName(packageName)` | `String` | 根据包名查询应用的显示名称，查不到则返回包名本身 |
| `getToken()` | `String?` | 从 `SharedPreferences` 读取已保存的认证令牌，不存在返回 `null` |
| `saveToken(token)` | `Unit` | 将认证令牌写入 `SharedPreferences` |
| `getDeviceName()` | `String` | 获取设备型号（`Build.MODEL`），如 `"Xiaomi 14"` |
| `getManufacturer()` | `String` | 获取设备制造商（`Build.MANUFACTURER`），如 `"Xiaomi"` |
| `getAndroidVersion()` | `String` | 获取 Android 系统版本号（`Build.VERSION.RELEASE`），如 `"14"` |

### 持久化存储说明

- **SharedPreferences 文件名：** `monitor_prefs`
- **键值：**
  - `device_id` → UUID 字符串（首次生成后永久保留）
  - `auth_token` → 认证令牌字符串（由 `saveToken`/`getToken` 管理）
- **设备标识不会在应用卸载后保留**（`SharedPreferences` 随应用卸载清除）

### 使用示例

```kotlin
// 事件采集时获取设备标识
val deviceId = AppUtils.getDeviceId()

// 上报时附加设备信息
val eventExtra = mapOf(
    "device_name" to AppUtils.getDeviceName(),
    "manufacturer" to AppUtils.getManufacturer(),
    "android_version" to AppUtils.getAndroidVersion()
)
```

### 操作意图对照表

| 目标 | 操作 |
|------|------|
| 获取设备唯一 ID | 调用 `AppUtils.getDeviceId()` |
| 获取 App 显示名称 | 调用 `AppUtils.getAppName("com.example.app")` |
| 读取已保存的认证令牌 | 调用 `AppUtils.getToken()` |
| 保存认证令牌 | 调用 `AppUtils.saveToken("xxx-token")` |
| 获取设备型号 | 调用 `AppUtils.getDeviceName()` |
| 获取制造商 | 调用 `AppUtils.getManufacturer()` |
| 获取系统版本 | 调用 `AppUtils.getAndroidVersion()` |

## 3. 调试配置 — `DebugConfig`

**文件：** `app/src/main/java/com/bsfeng/monitor/util/DebugConfig.kt`

调试模式开关，开启后输出详细的 `MonitorDebug` 日志。可在设置界面中实时开关，无需修改代码。

### 方法一览

| 方法 | 说明 |
|------|------|
| `init()` | 初始化时从 SharedPreferences 读取开关状态 |
| `setEnabled(enabled)` | 持久化开关状态并更新运行时标志 |
| `log(message)` | 仅在调试模式下输出 `Log.d("MonitorDebug", message)` |

### 使用示例

```kotlin
// 在任意代码中输出调试日志
DebugConfig.log("WeChatClickHandler: climbing view hierarchy...")

// 设置界面中切换
DebugConfig.setEnabled(true)
```

### 数据持久化

- **SharedPreferences 文件名：** `monitor_prefs`
- **键值：** `debug_enabled` → Boolean，状态持久化，重启后保持

## 4. 诊断计数器 — `DiagnosticCounters`

**文件：** `app/src/main/java/com/bsfeng/monitor/util/DiagnosticCounters.kt`

应用内诊断计数器，用于在无 adb/logcat 环境下排查数据流问题。所有计数器使用 `@Volatile` 确保跨线程可见性。

### 计数器分组

| 分组 | 计数器 | 说明 |
|------|--------|------|
| **无障碍服务** | `accessibilityEventCount` | onAccessibilityEvent 被调用次数 |
| | `lastAccessibilityEventType` | 最后一次事件类型 |
| | `lastAccessibilityPackage` | 最后一次事件包名 |
| | `accessibilityFilteredCount` | 被 isSystemUi 过滤的次数 |
| **EventCollector** | `emitCalledCount` | emit 被调用次数 |
| | `lastEmittedEventType` | 最后一次发射的事件类型 |
| | `emitSuccessCount` | 写入成功次数 |
| | `emitFailCount` | 写入失败次数 |
| | `lastErrorMessage` | 最后一次异常信息 |
| **DatabaseHelper** | `dbInsertCalledCount` | insert 被调用次数 |
| | `dbInsertSuccessCount` | 写入成功次数 |
| | `dbInsertConflictCount` | 主键冲突次数 |
| | `dbInsertFailCount` | 写入失败次数 |
| | `dbLastException` | 最后一次异常信息 |
| **上传** | `uploadAttemptCount` | 上传尝试次数 |
| | `uploadSuccessCount` | 上传成功次数 |
| | `uploadFailCount` | 上传失败次数 |
| | `lastUploadResult` | 上次上传结果 |
| | `lastUploadError` | 上次上传异常 |
| | `isTokenAvailable` | 是否有 Token |
| | `uploadEventCount` | 上次上传事件数 |

### 使用方式

```kotlin
// 在无障碍服务中递增计数器
DiagnosticCounters.accessibilityEventCount++
DiagnosticCounters.lastAccessibilityEventType = event.eventType.toString()

// 获取诊断报告（用于 UI 显示或日志输出）
val report = DiagnosticCounters.snapshot()
Log.d("Diagnostics", report)

// 重置所有计数器
DiagnosticCounters.reset()
```

## 5. 应用入口 — `MonitorApp`

**文件：** `app/src/main/java/com/bsfeng/monitor/MonitorApp.kt`

继承 `Application`，是全局初始化的入口点。

### 职责

1. **保存 Application 实例** — 通过 `MonitorApp.instance` 对外暴露，供所有模块获取 Application Context（手动依赖注入的核心机制）。
2. **初始化调试配置** — 在 `onCreate()` 中调用 `DebugConfig.init()`，读取 SharedPreferences 中的调试开关状态。
3. **初始化三层管道** — 在 `initPipeline()` 中创建 SQLite 数据库、EventReporter 和 UploadQueue，并注册三个 Handler：DatabaseHandler（持久化）、UploadHandler（上报）、LogHandler（日志）。创建 `RawEventCollector` 和 `NavigationContextTracker` 供事件采集使用。

### 初始化流程

```kotlin
// MonitorApp.onCreate()
override fun onCreate() {
    super.onCreate()
    instance = this
    DebugConfig.init()        // 读取调试开关
    initPipeline()            // 初始化三层管道
}

fun initPipeline() {
    val db = DatabaseHelper.getInstance(this)
    val reporter = EventReporter(this)
    val uploadQueue = UploadQueue()

    navTracker = NavigationContextTracker()
    pipeline = EventPipelineImpl()

    pipeline.register(DatabaseHandler(db))
    pipeline.register(UploadHandler(uploadQueue, reporter))
    pipeline.register(LogHandler())

    collector = RawEventCollector(pipeline, navTracker)
}
```

### 使用说明

- `MonitorApp` 必须在 `AndroidManifest.xml` 中配置为 `android:name`：
  ```xml
  <application
      android:name=".MonitorApp"
      ... >
  ```
- 其他模块通过 `MonitorApp.instance` 获取 Context，无 Hilt/Dagger 依赖。

### 操作意图对照表

| 目标 | 操作 |
|------|------|
| 获取 Application Context | 引用 `MonitorApp.instance` |
| 获取事件采集器 | 调用 `MonitorApp.instance.getCollector()` |
| 注册/移除 Handler | 修改 `MonitorApp.initPipeline()` 中的 `pipeline.register(...)` 调用 |

| 设备注册/认证模块 | `AppUtils.getToken()`, `AppUtils.saveToken()` | 维护认证状态 |
| 点击文本处理器 | `DebugConfig.log()` | 输出调试日志 |
| UI 设置页面 | `DebugConfig.init()`, `DebugConfig.setEnabled()` | 调试模式开关 |
| 无障碍服务 | `DiagnosticCounters.*` | 数据流计数和诊断 |
