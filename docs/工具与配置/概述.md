# 工具与配置

> 包：`com.bsfeng.monitor`（`AppConfig`/`MonitorApp`）与 `.util`。分层见[架构总览](../概览/架构总览.md)。

## 1. `AppConfig`（`AppConfig.kt`）

从 `BuildConfig` 暴露编译期常量：值由 `app/build.gradle.kts` 的 `buildConfigField` 定义（`local.properties` 的 `serverBaseUrl` 可覆盖），打包后不可改。

| 属性 | 默认 | 现状 |
|---|---|---|
| `serverBaseUrl` | `https://your-server.example.com` | 仓库内只留占位；消费方只有 `network/ApiHttpTransport` 与 `ApiService.checkConnection()` |
| `uploadIntervalMs` | 5000 | **无消费方**（二期上报用），当前不上报 |
| `batchMaxSize` | 50 | 二期上报用，当前无消费方 |
| `cacheMaxDays` | 3 | 二期清理用，当前无消费方 |
| `retryMaxAttempts` | 5 | 二期重试用，当前无消费方 |
| `notificationContentEnabled` | true | **无消费方**：通知采集未实现（`RecordType` 无通知类型） |

> 改字段只需改 `app/build.gradle.kts` 的 `buildConfigField`（`SERVER_BASE_URL` / `UPLOAD_INTERVAL_MS` / `BATCH_MAX_SIZE` / `CACHE_MAX_DAYS` / `RETRY_MAX_ATTEMPTS` / `NOTIFICATION_CONTENT_ENABLED`）。

## 2. `AppUtils`（`util/AppUtils.kt`）

设备与应用元信息工具。SharedPreferences 名 `monitor_prefs`，键 `device_id`、`auth_token`；卸载不保留设备标识。

| 方法 | 说明 |
|---|---|
| `getDeviceId()` | 首次生成 UUID 落 `monitor_prefs`，之后恒定 |
| `getAppName(pkg)` / `invalidateAppName(pkg)` | 包名 → 显示名（带 LRU）；改名 / 卸载后失效缓存 |
| `getToken()` / `saveToken(token)` | 读写 `auth_token`（**明文**，故备份包显式排除 `monitor_prefs`） |
| `getDeviceName()` / `getManufacturer()` / `getAndroidVersion()` | `Build.MODEL` / `MANUFACTURER` / `VERSION.RELEASE` |

## 3. `DebugConfig`（`util/DebugConfig.kt`）

调试开关：开启后输出 `MonitorDebug` 日志，设置页可实时切换。`init()` 读 `monitor_prefs`，`setEnabled(value)` 持久化并更新标志，`log(msg)` 仅调试模式 `Log.d`，`unlock()` 解锁隐藏入口。键：`debug_enabled`、`debug_unlocked`。

## 4. `DiagnosticCounters`（`util/DiagnosticCounters.kt`）

无 adb/logcat 时排查数据流用；字段均 `@Volatile`。

| 分组 | 字段 |
|---|---|
| 无障碍服务 | `accessibilityEventCount`、`lastAccessibilityEventType`、`lastAccessibilityPackage`、`accessibilityFilteredCount` |
| RecordCollector | `emitCalledCount`、`lastEmittedEventType`、`emitSuccessCount`、`emitFailCount`、`lastErrorMessage` |
| DatabaseHelper | `dbInsertCalledCount`、`dbInsertSuccessCount`、`dbInsertConflictCount`（rowId == -1）、`dbInsertFailCount`、`dbLastException` |
| 上报 | `uploadAttemptCount`、`uploadSuccessCount`、`uploadFailCount`、`lastUploadResult`（二期桩写「上传暂不可用」） |

`snapshot()` 生成分段报告（`toString()` 同），`reset()` 清零。

## 5. `MonitorApp`（`MonitorApp.kt`）

`onCreate()` 顺序（顺序有意义，别重排）：

1. `instance = this` —— 全局取 Context（无 Hilt/Dagger）。
2. `healInterruptedRestore()` —— 上次还原中断则先回滚，**必须在打开任何数据库句柄之前**。
3. `SkipConfig.init(this)` —— 内置规则时间闸门依赖它，须先于规则管理器创建。
4. `AutoBookConfig.init(this)`、`container = ServiceContainer(this)`。
5. `registerRecordReceiver()` —— 动态注册（两个 filter，`RECEIVER_EXPORTED`）。
6. `registerWifiNetworkCallback()` —— 用 `NetworkCallback` 而非 `WIFI_STATE_CHANGED_ACTION`（后者是硬件开关，HyperOS 易误触发；首个同步回调要跳过）。
7. `scheduleAlarmCheck(this)` / `QuotaScheduler.reschedule(this)`。
8. `checkSubscriptionUpdate()` —— 未订阅或未到周期直接返回。
