## 3. AccessibilityService 实现方案

### 3.1 核心配置

**res/xml/accessibility_service_config.xml:**

```xml
<?xml version="1.0" encoding="utf-8"?>
<accessibility-service
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:accessibilityEventTypes="typeWindowStateChanged|typeNotificationStateChanged|typeWindowContentChanged"
    android:accessibilityFeedbackType="feedbackGeneric"
    android:accessibilityFlags="flagReportViewIds|flagRetrieveInteractiveWindows"
    android:canRetrieveWindowContent="true"
    android:canRetrieveWindowContent="true"
    android:notificationTimeout="100"
    android:canTakeScreenshot="false"
    android:canPerformGestures="false" />
```

### 3.2 关键事件监听

```kotlin
class MonitorAccessibilityService : AccessibilityService() {

    override fun onAccessibilityEvent(event: AccessibilityEvent) {
        when (event.eventType) {
            AccessibilityEvent.TYPE_WINDOW_STATE_CHANGED -> {
                // 前台 App / Activity 切换
                handleWindowChange(event)
            }
            AccessibilityEvent.TYPE_NOTIFICATION_STATE_CHANGED -> {
                // 通知到达
                handleNotification(event)
            }
        }
    }

    override fun onInterrupt() {
        // 无障碍服务被系统中断
    }
}
```

### 3.3 前台 App 切换识别逻辑

`TYPE_WINDOW_STATE_CHANGED` 事件的 `packageName` 即为当前前台 App 的包名，`className` 为当前 Activity 的全名。

```kotlin
private var lastPackageName: String? = null
private var lastActivityClass: String? = null
private var lastSwitchTimeMs: Long = 0L

fun handleWindowChange(event: AccessibilityEvent) {
    val packageName = event.packageName?.toString() ?: return
    val className = event.className?.toString() ?: ""

    // 过滤系统界面（可选）
    if (isSystemUi(packageName)) return

    val now = System.currentTimeMillis()
    val duration = if (lastPackageName != null) now - lastSwitchTimeMs else 0L

    // 发出 app_foreground 事件
    EventCollector.emit(
        AppForegroundEvent(
            packageName = packageName,
            appName = getAppNameByPackage(packageName),
            activityName = className.substringAfterLast('.'),
            activityClass = className,
            fromPackage = lastPackageName,
            fromActivity = lastActivityClass,
            foregroundDurationMs = duration
        )
    )

    // 判断是否同一 App 内 Activity 切换
    if (packageName == lastPackageName && className != lastActivityClass) {
        EventCollector.emit(
            ActivityChangeEvent(
                packageName = packageName,
                appName = getAppNameByPackage(packageName),
                fromActivity = lastActivityClass,
                toActivity = className,
                // ...
            )
        )
    }

    lastPackageName = packageName
    lastActivityClass = className
    lastSwitchTimeMs = now
}
```

### 3.4 通知监听

```kotlin
fun handleNotification(event: AccessibilityEvent) {
    val packageName = event.packageName?.toString() ?: return
    val notificationText = event.text?.joinToString("") ?: ""

    EventCollector.emit(
        NotificationReceivedEvent(
            packageName = packageName,
            appName = getAppNameByPackage(packageName),
            category = findNotificationCategory(event),
            priority = event.priority,
            // 内容摘要默认不传
        )
    )
}
```

### 3.5 小米 HyperOS 适配要点

| 问题 | 解决方案 |
|------|---------|
| 无障碍服务可能被系统自动关闭 | 前台服务 + 定时检测服务存活 |
| 电池优化策略激进 | 引导用户加入电池白名单 |
| 自启动限制 | 引导用户在安全中心→自启动管理 中开启 |
| 通知无法监听某些第三方 App | 无解，这是 App 自身限制，不影响核心监控 |
| `TYPE_WINDOW_STATE_CHANGED` 在分身空间/双开 App 中失效 | 记录此限制，V1 不处理 |

## 4. BroadcastReceiver 事件源

```kotlin
class ScreenStateReceiver : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        when (intent.action) {
            Intent.ACTION_SCREEN_ON -> {
                // 屏幕亮起（含锁屏界面）
                // 此时无法直接判断解锁成功
            }
            Intent.ACTION_SCREEN_OFF -> {
                // 屏幕熄灭
            }
            Intent.ACTION_USER_PRESENT -> {
                // 解锁成功（用户已进入主界面）
            }
        }
    }
}
```

### 4.2 充电状态

IntentFilter().apply {

## 5. 静默运行策略（核心设计）

本 App 的设计理念是**正常运行时用户完全无感知**。所有策略围绕这一目标展开。

### 5.1 通知栏策略

Android 16 强制前台服务必须显示通知。为做到最低打扰，采用以下手段：

| 手段 | 实现 | 效果 |
|------|------|------|
| **最低优先级** | `NotificationCompat.PRIORITY_MIN` | 不在锁屏显示、不弹 heads-up |
| **静音通知通道** | 创建 `IMPORTANCE_NONE` 的通知通道 | 无声音、无振动、无指示灯 |
| **无文字内容** | 通知标题设为空字符串"·"，不写"正在监控"等字样，降低视觉存在感 | 用户扫一眼看不到敏感信息 |
| **极简图标** | 使用 1x1 像素透明图标，或极小几何图标 | 状态栏图标几乎不可见 |
| **仅在故障时通知** | 正常运行不主动通知；只有服务被系统杀掉、网络长时间中断等异常才发真实通知 | 用户只在出问题时才知道这个 App 的存在 |

### 前台服务通知实现

```kotlin
// 创建静音通知通道（仅在 App 启动时创建一次）
val channel = NotificationChannel(
    FOREGROUND_CHANNEL_ID,
    "·",  // 通道名用极简符号
    NotificationManager.IMPORTANCE_NONE  // 无声音/无振动/无打扰
).apply {
    description = ""
    setShowBadge(false)
    lockscreenVisibility = NotificationCompat.VISIBILITY_SECRET
}
notificationManager.createNotificationChannel(channel)

// 前台通知
val notification = NotificationCompat.Builder(this, FOREGROUND_CHANNEL_ID)
    .setContentTitle("·")  // 极简占位
    .setContentText("")
    .setSmallIcon(R.drawable.ic_silent)  // 透明/极小图标
    .setOngoing(true)
    .setPriority(NotificationCompat.PRIORITY_MIN)
    .setSilent(true)
    .build()

startForeground(NOTIFICATION_ID, notification)
```

### 5.2 故障通知机制

只有在以下情况才弹真实通知：

| 故障类型 | 检测方式 | 通知行为 |
|---------|---------|---------|
| 无障碍服务被系统关闭 | 定时检测 `isServiceRunning()` | 弹通知：「监控服务已停止，请重新开启」 |
| 网络中断 > 30 分钟 | 在 `EventReporter` 中累计离线时间 | 弹通知：「网络连接异常，数据将在恢复后上传」 |
| 事件队列积压 > 1000 条 | 检查 Room 中未上报事件数 | 弹通知：「事件积压过多，请检查网络或联系开发者」 |
| 系统低电量（< 15%） | 电量广播 | 不弹通知，自动降低上报频率 |

### 5.3 后台保活策略

Android 16 + 澎湃 OS 3 对后台限制非常严格：

| 策略 | 实现方式 | 重要性 |
|------|---------|--------|
| **前台服务** | `FOREGROUND_SERVICE_SPECIAL_USE` 类型 + 静音通知 | 必选 |
| **无障碍服务本身保活** | 系统对无障碍服务有一定优先级保护 | 辅助 |
| **电池优化白名单** | 引导用户将 App 设为"无限制" | 关键（必做） |
| **自启动管理** | 引导用户在安全中心 → 自启动管理 中开启 | 关键（必做） |
| **定时检测** | AlarmManager 每 30 分钟检测 `isServiceRunning()`，不在前台则重新启动 | 兜底 |
| **Boot Receiver** | 监听 `BOOT_COMPLETED`（设备解锁后延迟启动） | 基础 |
| **最近任务锁定** | 引导用户在最近任务列表中下拉锁定 App | 辅助 |

### 上报逻辑

```kotlin
class EventReporter(private val api: ApiService, private val db: AppDatabase) {

    // 定时批量上报
    fun uploadBatch() {
        val unsentEvents = db.eventDao().getUnsentEvents(limit = 50)
        if (unsentEvents.isEmpty()) return

        val batch = unsentEvents.map { it.toEvent() }
        val response = api.uploadEvents(EventsBatch(batch))

        if (response.isSuccessful) {
            db.eventDao().markUploaded(unsentEvents.map { it.eventId })
        } // 否则保留，下次重试
    }
}
```

## 8. 已知限制与风险

| 限制 | 说明 |
|------|------|
| **小米澎湃 OS 3 无障碍服务可能关闭** | HyperOS 可能自动关闭长时间运行的无障碍服务，需前台服务+定时检测恢复 |
| **无法监控锁屏界面 Enter 的密码** | 无障碍服务无法读取密码输入框内容 |
| **通知内容全部上报** | 根据用户配置，所有通知内容（含摘要）均上报。如需关闭需修改编译配置 |
| **电量消耗** | 无障碍服务 + 网络上报，目标日耗电 ≤ 5% |
| **Activity 切换的误报** | 某些 App 同一页面也会触发 `TYPE_WINDOW_STATE_CHANGED`（如 WebView 加载），需去重 |
| **多开/分身应用** | 分身空间中的 Activity 切换无障碍服务无法感知 |
| **系统桌面 Launcher** | 包名 `com.miui.home`，这是有效的 App 切换事件，不应过滤 |
| **Android 16 `FOREGROUND_SERVICE_SPECIAL_USE`** | 前台服务启动后必须在 30 秒内调用 `startForeground()`，否则 ANR |

### 8.1 澎湃 OS 3 专项适配

| 问题 | 用户体验 | 方案 |
|------|---------|------|
| 无障碍服务自动关闭 | 监控中断 | 定时检测+通知引导重新开启 |
| 电池优化白名单 | App 被系统杀死 | App 启动时自动引导用户设置 |
| 自启动限制 | 重启后不自动启动 | 主动引导用户开启 |
| 通知通道被系统隐藏 | 前台服务通知无法显示 | 走系统预置通道 Fallback |
| 省电策略杀进程 | 事件丢失 | 事件持久化 Room，不丢失 |
