# 更新检测

> ⚠️ **何时阅读：** 修改更新检测、版本清单（`updates/version.json`）或发布流程时先读本文档。

## 目标

App 内检查 GitHub Release 是否有新版本，支持应用内下载 APK 并拉起系统安装器；在 GitHub 访问受限的网络下自动切换镜像。

## 更新源策略

更新源按顺序尝试，任意一个解析成功即返回：

| 顺序 | 源 | 说明 |
|------|-----|------|
| 1 | 自建服务器 `updateBaseUrl/version.json` | 仅私有构建注入（`local.properties`），**公开构建为空** |
| 2 | jsDelivr | `https://cdn.jsdelivr.net/gh/<owner>/<repo>@main/updates/version.json` |
| 3 | GitHub 镜像 | `gh-proxy.com` / `ghfast.top` / `ghproxy.net` 前缀 + GitHub raw 地址 |
| 4 | GitHub 直连 | `https://raw.githubusercontent.com/<owner>/<repo>/main/updates/version.json` |

APK 下载源：

| 顺序 | 源 | 说明 |
|------|-----|------|
| 1 | `updateBaseUrl/app-release.apk` | 仅私有构建（服务器地址保密，不进入公开 APK） |
| 2 | 镜像前缀 + GitHub Release 资源地址 | 逐前缀尝试，适合国内网络 |
| 3 | GitHub Release 直连 | 兜底 |

> **IP 保密：** 服务器地址只通过 `local.properties` 注入私有构建；公开 Release 的 APK 不含任何自建地址（`UPDATE_BASE_URL` 为空），避免解包泄露源站 IP。

## 版本清单格式

`updates/version.json`（由 `.github/workflows/release.yml` 在发版时生成并回写 main）：

```json
{
  "versionCode": 2,
  "versionName": "1.1.0",
  "apkUrl": "https://github.com/baosfeng/android-monitor/releases/download/v1.1.0/app-release.apk",
  "apkSha256": "……",
  "changelog": "- 修复……",
  "publishedAt": "2026-10-19T00:00:00Z"
}
```

- `versionCode` 必须大于当前安装版本才会提示更新；
- `apkSha256` 用于下载完成后校验，为空时跳过校验；
- `changelog` 展示在更新对话框。

## 代码路径

| 职责 | 文件 |
|------|------|
| 清单解析与字段校验 | `app/src/main/java/com/bsfeng/monitor/update/UpdateManifest.kt` |
| 多源检查与下载源生成 | `app/src/main/java/com/bsfeng/monitor/update/UpdateChecker.kt` |

## 配置项

| 配置 | 来源 | 说明 |
|------|------|------|
| `UPDATE_BASE_URL` | `local.properties` 的 `updateBaseUrl` | 私有构建的自建更新源；公开构建为空 |
| `UPDATE_REPO` | `app/build.gradle.kts` | 仓库全名，用于拼 jsDelivr 与 raw 地址 |
| 镜像前缀 | `UpdateConfig.mirrorPrefixes` | 失效后按需替换 |

## 交互流程

1. 设置 → 关于 → 检查更新；
2. 检查中显示加载状态，失败 Toast 提示「检查更新失败」；
3. 有新版本时弹出对话框展示版本号与更新说明；
4. 下载显示进度与百分比，完成后校验 SHA-256；
5. 点击安装会先检查「安装未知来源应用」权限，再通过 FileProvider 拉起系统安装器。

## 测试

```bash
./gradlew :app:testDebugUnitTest --tests "com.bsfeng.monitor.update.*"
```

覆盖：清单解析、非法 JSON、版本比较、全部源失败、下载源包含镜像且以 GitHub 直连兜底。

## 常见问题

- **jsDelivr 缓存延迟**：`@main` 分支的 CDN 缓存可能滞后数分钟，发版后立即检查可能仍返回旧清单，稍后重试即可；
- **镜像失效**：`UpdateConfig.mirrorPrefixes` 按实测可用性排序（当前 `gh-proxy.com` 优先），失效前缀会自然跳过；镜像域名可随时替换；
- **服务器地址泄露**：公开构建不要配置 `updateBaseUrl`，发布到 GitHub 的 APK 用干净环境构建（CI 默认如此）。
