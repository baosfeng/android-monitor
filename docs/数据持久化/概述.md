# 数据持久化模块

> 包 `com.bsfeng.monitor.data`，单文件 `data/DatabaseHelper.kt`（系统内置 `SQLiteOpenHelper`，零第三方 ORM）。

## 数据库

| 项 | 值 |
|---|---|
| 文件名 | `monitor.db` |
| 版本 | 4 |
| 单例 | `DatabaseHelper.getInstance(context)`（双重检查锁） |
| 表 | `records`（行为记录）、`transfer_tasks`（互传任务历史） |

记账数据另有独立库（`finance.db`，由 finance 模块的 helper 管理），不放 `monitor.db`。

### `records`

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | 记录 UUID |
| `type` | TEXT | NOT NULL | RecordType 名（`SCREEN` / `APP_USAGE` …） |
| `action` | TEXT | NOT NULL | 动作（`ON` / `CLOSED` …） |
| `timestamp` | INTEGER | NOT NULL | 事件时间（ms） |
| `duration` | INTEGER | — | 持续时长（ms），仅成对类型使用 |
| `label` | TEXT | NOT NULL | 人类可读摘要 |
| `detail` | TEXT | — | JSON 字符串（`Map<String,String>`） |
| `owner` | TEXT | 默认 `''` | 预留多人场景 |

索引：`timestamp`、`type`。

### `transfer_tasks`

互传任务历史（v3→v4 迁移新建，幂等建表 + 迁移补建，索引 `created_at`），字段与读写由 `transfer/TransferTaskStore` 负责；仅保留最近 100 条，崩溃残留的非终态按「上次未完成」展示。

## 访问方式

业务不直接碰 SQL：记录经 `record/RecordStore`（`insert` / `insertOrMerge` / `queryByDate` / `queryByType` / `getDailySummary` / `getAppUsageRank` / `delete*`），互传经 `transfer/TransferTaskStore`。`DatabaseHelper` 只负责建表、迁移与底层 CRUD。

**所有方法同步阻塞**，调用方放在 `Dispatchers.IO`。

## 操作意图 → 文件

| 想做什么 | 位置 |
|---|---|
| 改表结构 / 迁移 | `data/DatabaseHelper.kt`（升 `DATABASE_VERSION`，写幂等迁移） |
| 改记录读写与统计 | `record/RecordStore.kt` |
| 改互传任务历史 | `transfer/TransferTaskStore.kt` + `TABLE_TRANSFER_TASKS` |
| 改记录模型 | `domain/.../model/Record.kt`（字段改动需同步表与序列化） |

## 边界

- 迁移必须幂等（`CREATE TABLE IF NOT EXISTS` + 迁移补建），老版本升级不丢数据。
- `detail` 序列化失败按空 Map 处理，不阻塞写入。
- 清理按时间范围 / 动作删除（`deleteBefore` / `deleteByRange` / `deleteByAction`），不再有「已上传」标记（上报通道记录的是事件快照，见[网络通信](../网络通信/概述.md)）。
