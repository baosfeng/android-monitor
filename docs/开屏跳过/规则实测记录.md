## 1. 实测规模与命中率（诚实数据）

2026-10-13 用快照工具一次性抓取 **30 份页面快照**，覆盖 15 个 App：

| 结果 | 数量 | 说明 |
|------|------|------|
| 抓到**真正的开屏广告页** | **1** | `com.qq.reader` / `com.qq.reader.activity.launch.DefaultAliasSplashActivity` |
| 抓到 App 首页/主界面 | 29 | 导出时机晚于开屏页（固定 5 秒延时的固有缺陷，见 §2.2） |

**开屏页捕获率 ≈ 3%** —— 这就是「逐 App 补规则」无法靠人工耐性硬堆的根因：
广告本身有频次控制，再叠加导出时机不稳，覆盖 20 个 App 需要几十次冷启动且成功率不可控。

## 2. 由此发现并修复的两个缺陷（本任务的真实价值）

### 2.1 `activityIds` 规则会被 Toast 静默搞失效

**真机证据**：30 份快照里 **12 份** 把 `className` 记成了 `android.widget.TextView` / `android.widget.FrameLayout`，
而当时 App 明明停在主界面（对照同一 App 其它快照记到的是真实 Activity）。

**根因**：Toast、弹窗、输入法也发 `TYPE_WINDOW_STATE_CHANGED`，其 `event.className` 是 **widget 类名**；
`MonitorAccessibilityService` 与 `SkipRuleEngine` 都直接采信 → 「当前 Activity」被冲掉。

**后果**（两个都很难被发现，因为日志只表现为「未命中任何规则」）：
1. 写了 `activityIds` 的规则（内置 `bilibili_splash`、新增的 QQ阅读规则）在该次启动里**静默不再命中**；
2. 页面快照记下错误的 Activity，写规则的人照着错的界面名写，规则永远不生效。

**修复**：新增 `app/src/main/java/com/bsfeng/monitor/util/ActivityNames.kt`
（`isActivityClass` / `resolveActivityClass`）——widget 类名不覆盖已知 Activity，跨 App 时清空；
引擎（`SkipRuleEngine.onWindowChanged`）与服务（`handleWindowChange` 的 `lastActivityClass`）共用同一判定。

**验证**：
- `app/src/test/java/com/bsfeng/monitor/util/ActivityNamesTest.kt`（9 例，含 widget/系统 UI/输入法/`pkg/cls` 形式）
- `app/src/test/java/com/bsfeng/monitor/skip/SkipRuleEngineTest.kt` 新增 2 例回归（Toast 之后 `activityIds` 规则仍命中晚到的广告）
- 真机复测：新导出的快照 `className = com.lianjia.activity.MainActivity`（修复前常见 `android.widget.TextView`）

### 2.2 快照工具抓不到开屏页 → 改为「切到目标 App 后自动导出」

**旧行为**：`SnapshotRequest.request()` 固定 5 秒延时（从点「导出」那一刻起算）。
人还没切到目标 App 就已经在倒计时，切过去后往往导到首页。

**新行为**：`SnapshotRequest.requestOnAppSwitch(originPackage)` + 服务轮询调用
`SnapshotRequest.onForegroundPackage(pkg, now)` —— **等离开发起请求的 App 之后**再等 `SWITCH_SETTLE_MS`（2.5 秒）导出。
2.5 秒的取值依据：开屏广告页在「切过去 2~3 秒」时通常正显示跳过按钮（唯一成功的 QQ阅读 抓取也落在这个区间）。

**验证**：真机点「导出」→ 冷启动链家 → 日志 `MonitorService: 页面快照导出: .../1791907888496.json`，
快照 `className = com.lianjia.activity.MainActivity`（时机与 Activity 都正确）。

## 3. 唯一抓到的真实开屏页（QQ阅读）与新增规则

快照：`files/snapshots/1791906264682.json`（Activity `com.qq.reader.activity.launch.DefaultAliasSplashActivity`，17 个节点）

```
RelativeLayout[vid=splash_root]               1200x2670  不可点
├── FrameLayout[vid=splash_container]         1200x2670  不可点
│   └── RelativeLayout[vid=ywad_gdt_splash_container]     ← 优量汇(GDT)广告容器，整屏、不可点
└── TextView[text="跳过5"]                    189x84  clickable=true  childCount=0   ← 真正的跳过按钮
```

**新增规则**（`app/src/main/java/com/bsfeng/monitor/skip/BuiltInRules.kt`，`BUILT_IN_VERSION` 8 → 9）：

```kotlin
appRule(id = "qq_reader_splash", app = "com.qq.reader", name = "QQ阅读", groups = listOf(
    splashGroup(
        matchTimeMs = matchTimeMs,
        activityIds = listOf("com.qq.reader.activity.launch.DefaultAliasSplashActivity"),
        rules = listOf(rule(0, "splash_root 内的跳过文本",
            "[vid=\"splash_root\"] > TextView[text^=\"跳过\"][text.length<10][visibleToUser=true]"))
    )
))
```

- 广告容器**绝不能点**（整屏、不可点；即使误命中，`RuleNodeFinder.isOversized` 面积守卫也会丢弃）
- 与全局规则的关系：全局文本规则本就能跳过 QQ阅读（真机日志 4 次 `✅ 跳过成功（已确认广告消失）`）；
  该规则的价值是把命中**限定在开屏 Activity 的 `splash_root` 内**，进一步降低在阅读页误点的概率。
  App 规则优先匹配，但全局规则仍是兜底，**不会降低覆盖率**。
- ⚠️ **未取得的证据**：新规则*由它自己命中*的真机日志（广告受频次控制，本轮没再复现）。
  判定方法：日志里 `←` 后的选择器若是 `[vid="splash_root"] > TextView[...]` 即说明是它命中的。

## 4. 为什么暂停逐 App 广度调优

1. **用户指示**：不用每个软件都测。
2. **技术依据**：单次抓取命中率 ≈3%（§1）；而要覆盖 20 个 App 意味着几十次不可控的冷启动。
3. **边际收益低**：本次实测里能跳过的 App（B站 / 链家 / 12306 / QQ阅读 / 九方智投）**全部由内置全局文本规则命中**，
   加 App 规则只是把范围收窄、降低误点概率，并不提升「能不能跳过」。
4. **真正的短板不在这里**：无文本、无稳定 ID 的页面（[兜底方案调研](兜底方案调研.md) §1 的 C/D 类）**加规则无解**，
   属于 P2-3 的产品决策范围。

**改为按需触发**：谁反馈某个 App 跳不过，再用改进后的快照工具抓那一页（单个 App 约 3 分钟），
而不是预先盲目扫全量。

## 5. 复现步骤（后续接手用）

```bash
A=~/android-platform-tools/adb
# 1) 打开 App → 设置 → 开屏广告跳过 → 管理 → 点「页面快照」的「导出」
# 2) 立刻冷启动目标 App（不要用 force-stop！）
$A shell am kill <包名> && $A shell monkey -p <包名> -c android.intent.category.LAUNCHER 1
# 3) 等 3~4 秒：切走后 2.5 秒会自动导出
$A logcat -d | grep 页面快照导出
# 4) 取回快照并分析跳过按钮候选（层级路径 + 尺寸 + 可点击性）
$A exec-out run-as com.bsfeng.monitor cat files/snapshots/<文件名>.json > /tmp/snap.json
python3 /tmp/analyze-snaps.py        # 临时脚本：遍历快照打印候选节点路径（未入库）
```
