## 1. 问题界定

机制：Android 无障碍树 = View 层级 + `AccessibilityNodeProvider` 虚拟节点；渲染到独立绘制表面（Surface / GL / Vulkan）的内容不产生子 View，自然无可读节点。虚拟视图须由 provider 主动 populate。

| 框架/形态 | 树里到底有什么 | 结论 |
|---|---|---|
| Flutter | 语义树由引擎 `AccessibilityBridge` 控制，开关即系统无障碍开关（关闭时事件直接 return）；`setClassName("android.view.View")`、`setViewIdResourceName(identifier)`（App 自给，多为 null） | ⚠️「Flutter 一定拿不到文本」是错误前提：带语义标注的控件能读到；真正读不到的是 ①`ExcludeSemantics`/自绘控件 ②原生广告 SDK 图片 View ③Flutter 页几乎没有稳定资源 ID（这点确定） |
| Unity | 6.3 Accessibility 模块默认启用，节点映射到 `AccessibilityNodeInfo`，但需开发者建元数据 | 广告 SDK 渲染的开屏通常不给「跳过」建 a11y 元数据 → 无文本（推断，未采样） |
| WebView | Chrome/WebView 无障碍「off by default and enabled automatically on-demand」 | 开启后会建树；`<img>`/canvas/背景图无 alt 则读不到，文本节点能读到 → 必须按页面实测，不能整体归为「读不到」 |
| 纯图片按钮（原生） | `ImageView`/`ImageButton` 无 `contentDescription` 时节点存在但 text/desc 皆空；点击由外层容器处理时只有几何特征 | 只有几何特征可用 |
| 游戏引擎/自绘 | 整页只有 `SurfaceView`/`TextureView`/`GLSurfaceView` 单节点 | 无子节点 |

佐证「业界主要靠文本」：内置全局规则选择器为「文本含跳过 + 短文本 + 可见叶子」+ 少量固定 ID（`skip/BuiltInRules.kt` 的 `TEXT_SKIP`/`DESC_SKIP`/`VIEW_ID_SKIP`），唯一确认的广告 SDK 命名特征是字节系 `tt_splash_skip_btn`。

### 1.1 可复现的判定方法

1. **确认跳不过**：开调试模式，冷启动目标 App，`~/android-platform-tools/adb logcat -s SkipRuleEngine SkipAction MonitorDebug MonitorTimeline`；出现 `SkipEngine: 未命中任何规则 <包名> / <Activity>` 进入下一步。
2. **采集快照**：规则页「页面快照」延迟 5 秒导出当时前台页面的无障碍树 → `files/snapshots/<时间戳>.json`。字段（`skip/SnapshotExporter.kt`）：`id/vid/name/text/desc/clickable/longClickable/focusable/checkable/checked/editable/visibleToUser/left/top/right/bottom/width/height/childCount/index/depth`，字符串为空则省略。
3. **按判定表分类**（阈值是建议初值，属推断，需真实样本校正）：

| 类别 | 快照特征 | 现有引擎 | 兜底方向 |
|---|---|---|---|
| A 有文本 | `text`/`desc` 含「跳过/skip」且 `childCount=0`、`visibleToUser=true` | 能 | 无需兜底（P2-1 规则调优） |
| B 无文本有稳定 ID | `vid`/`id` 形如 `*skip*`、`*count*down*`、`tt_splash_skip_btn` | 能 | 补 ID 规则 |
| C 弱信号可判 | 无文本无 ID，但有「小块 + clickable + 右上角」节点；或全页可见节点 < 5 | 不能 | §2.1 弱信号 / §2.3 坐标候选 |
| D 像素渲染 | 根节点 childCount 1~3，子节点为 Surface/Texture/GLSurfaceView/`android.view.View`，或整页近全屏 ImageView | 不能 | §2.2 截图启发式 / §3 OCR |
| E 广告独立 window | `getWindows()` 出现额外应用 window（引擎只看 `rootInActiveWindow`） | 不能 | 多窗口枚举 |

建议初值（推断）：「小块」= 节点面积 < 根节点 1/9；「右上角」= `left > 0.6×屏宽 && top < 0.2×屏高`；「节点极少」= ≤5。已有可复用几何判据：面积守卫（命中面积 ×3 > 根节点面积即丢弃，`skip/RuleNodeFinder.kt` 的 `isOversized`）。

### 1.2 可用弱信号（引擎已支持，规则即可用，求值见 `skip/ExpressionEvaluator.kt`）

| 信号 | 写法示例 | 误点风险 |
|---|---|---|
| 控件类名 | `[name="android.widget.ImageView"]` | 低（判定用） |
| 子节点数 | `[childCount=0]`、`[childCount<2]` | 低 |
| 可点击 | `[clickable=true]` | 中（需配面积/尺寸约束） |
| 屏幕坐标 | `[left>648][top<216]`（绝对像素，需按分辨率维护） | 中~高（分辨率/DPI/横竖屏失效） |
| 尺寸 | `[width<500&&height<300]` | 低（内置规则在用） |
| 层级 | `[depth<3]`、`[index=0]` | 低 |
| 可见/可用 | `[visibleToUser=true][enabled=true]` | 低 |
| 资源 ID | `[vid*="skip"]`、`[id$="tt_splash_skip_btn"]` | 低 |
| 文本/描述 | `[text*="跳过"]`、`[desc*="跳过"]` | 低（现状主路径） |
| 父子关系 | `[parent.getChild(0).childCount=0]` | 低 |
| 包名 | `[package="com.xxx"]` | 低 |

改内置规则 → `skip/BuiltInRules.kt`（改内容需递增 `BUILT_IN_VERSION`，当前 8）；用户规则 → 规则页 `ui/SkipRuleScreen.kt`。

## 2. 零依赖增强（不破「零第三方业务依赖」）

「零依赖」≠「零成本」：成本是自研工程量、维护腐烂与实测调参。

### 2.1 纯无障碍弱信号启发式

| # | 启发式 | 落地 | 代价 / 风险 |
|---|---|---|---|
| 1 | 小块可点击 + 右上角：`[clickable=true][childCount=0][visibleToUser=true][left>0.6W][top<0.2H][width<500&&height<300]` | 直接写内置规则 | 中：右上角可能有正常控件 → 配 `matchTime` + 只执行一次 + 点击后确认 |
| 2 | 广告容器页判定：可见节点 ≤5 且近全屏 ImageView / 子节点极少 | 改引擎（需「页面结构摘要」，可复用 `NodeMatcher.diagnosePageStructure`、`SnapshotExporter.summarize`） | 中；判据随广告改版失效 |
| 3 | 像素渲染页识别：子节点 name ∈ {SurfaceView, TextureView, GLSurfaceView} 或 `android.view.View` 且无 text/desc/vid | 改引擎（只决定是否启用兜底层，不直接点） | 小；是判定手段不是跳过手段 |
| 4 | 多窗口枚举：`getWindows()` 枚举交互窗口 | 改引擎（配置已含 `flagRetrieveInteractiveWindows`） | 中；可能重复命中 |
| 5 | 包名/Activity 先验（仅排除）：`excludeActivityIds`/`excludeMatches` | 直接写规则 | 低 |
| 6 | 广告 SDK 命名特征 `vid*="skip"`、`tt_splash_skip_btn` | 已在用，扩充需先采样 | 低，随 SDK 改版腐烂 |

1/2/6 都是经验特征，会随 App 改版腐烂，需持续采样（主流 App 的跳过按钮基本没有稳定 id/vid）。

### 2.2 `AccessibilityService.takeScreenshot`

| 项 | 事实 |
|---|---|
| 元数据 | `android:canTakeScreenshot`，since API 30（本项目当前 `false`） |
| 全屏截图 | `takeScreenshot(displayId, Executor, TakeScreenshotCallback)`，since API 30 |
| 单窗口截图 | `takeScreenshotOfWindow(windowId, ...)`，since API 34；官方推荐用于「目标窗口被无障碍悬浮窗遮挡」与「ML 视觉理解」 |
| 结果 | `ScreenshotResult`（HardwareBuffer + ColorSpace + 时间戳）→ `Bitmap.wrapHardwareBuffer`，**无需第三方图像库** |
| 能力校验 | 无 capability 抛 `SecurityException`（`AccessibilitySecurityPolicy.canTakeScreenshotLocked` = 检查 `CAPABILITY_CAN_TAKE_SCREENSHOT`） |
| **系统节流** | `ACCESSIBILITY_TAKE_SCREENSHOT_REQUEST_INTERVAL_TIMES_MS = 333`（@hide @TestApi），间隔 ≤333ms 返回 `ERROR_TAKE_SCREENSHOT_INTERVAL_TIME_SHORT` → **上限约 3 张/秒** |
| 其它失败码 | `INTERNAL_ERROR(1)` / `NO_ACCESSIBILITY_ACCESS(2)` / `INTERVAL_TIME_SHORT(3)` / `INVALID_DISPLAY(4)` / `INVALID_WINDOW(5)` / `SECURE_WINDOW(6, Android 14+)` |
| 不可截 | `TYPE_VIRTUAL + FLAG_PRIVATE` 显示（返回 `INVALID_DISPLAY`）；含 `FLAG_SECURE` 的窗口（Android 14+ 返回 `SECURE_WINDOW`，推断） |
| 现状 | `canTakeScreenshot="false"`、`canPerformGestures="true"`、`minSdk=29`（低于 API 30） |

- **minSdk 29 后果**：截图 API 与属性均 API 30+，Android 10 不可用，代码需 `SDK_INT >= 30` 守卫，UI 需区分「本机不支持」。
- **权限提示**：AOSP 无额外确认流程（`attrs.xml` 只有布尔属性，运行时只检查 capability）；用户只能在系统「无障碍 → 该服务」看到服务信息。HyperOS 是否额外提示/静默降级：未知；Google Play 无障碍政策要求：本次未取到，未知。
- **隐私**：截图是整屏位图（含聊天、通讯录、表单、他人信息），仅 `FLAG_SECURE` 除外。本项目现有约定是屏幕内容本地处理、不上传；截屏仍全本地，但把可见范围从「树里的文本」扩大到「整屏像素」→ 是否需要隐私告知/默认开关属产品决策。若实施：只在「开屏窗口内 + 已判定像素渲染页 + 用户显式开启」时截图，立即回收 Bitmap，不落盘不入库，**不与快照功能混用同一路径**。
- **性能（算术推算）**：1080×2400×4 ≈ 9.9 MiB/帧；3 帧/秒 ≈ 30 MiB/s 像素拷贝 → 内存带宽、GC、发热有压力。缓解（需实测）：按需单帧、降采样 1/4、复用与及时 `recycle()`、帧间差分限制在窗口内且 ≤N 帧。真实帧率/内存/耗电未知。
- **不引第三方库的像素启发式**（`Bitmap` + `getPixels` 手写，不需 OpenCV）：A 右上角高对比小块（取 W×0.35/H×0.12 → 灰度二值化 → 连通域找面积达标块；深色/浅色主题、视频广告会干扰）；B 倒计时区域帧间差分（变化周期 ≈1 秒；受 333ms 节流约 1 秒 3 帧；视频广告整屏全变会失效）；C 全屏变化块定位；D 先降 1/4 再跑 A/B（小字号倒计时可能被抹掉）。命中率/误点率均未实测。

### 2.3 现有 `ActionExecutor` 坐标手势 + 命中后确认

已有能力：`clickAt(x,y)`、归一化坐标（`normalizedPoint`/`ClickPosition`）、节点中心手势（`performGestureClick`/`clickNodeOrCenter`，含异步回调）、点击后确认（`SkipRuleEngine.VERIFY_DELAYS = [400, 600]`，`confirmed=true/false/null` 落 `AD_SKIPPED.detail.confirmed`）、面积守卫。

**关键落差**：现有复核是「用命中的同一选择器重新匹配」，坐标点击没有选择器 → 必须新增复核判据（页面结构指纹变化 / 是否离开广告 Activity / 候选区域消失）。这是真实工程量，不能按「复用」估算。

坐标先验：GKD 生态与内置规则都按右上角思路；`zfdang/Android-Touch-Helper`（MIT）走「按 App 配置屏幕区域」，简单可靠但坐标需人工维护、换分辨率即失效。**本项目 `AD_SKIPPED` 无坐标字段**，用历史命中坐标做先验需先加埋点。

## 4. 方案对比

| 维度 | A 不引第三方（弱信号 + 截图启发式 + 坐标） | B 仅宽松许可端侧 OCR | C 更强模型（ML Kit / YOLO / 云） |
|---|---|---|---|
| 破零依赖 | 否 | 是 | 是（且可能闭源 / AGPL / 云） |
| 许可风险 | 无 | 低（Apache/MIT/BSD） | 中~高（ML Kit 闭源 / AGPL / 数据出境） |
| 包体增量 | 0 | Tesseract ≈2.35 MiB（native 未知）~ PP-OCRv5 20.7 MB / ORT 26.6 MiB | ML Kit +4 MB/脚本/架构；YOLO ≈5 MB；ncnn 20~31 MiB |
| 精度 | 未知（无实测） | 未知（通用 OCR 指标不可外推） | 二手 19/20（未复现） |
| 离线 | 完全离线 | 完全离线 | ML Kit 捆绑 / YOLO 离线；云不在线不可用 |
| 维护成本 | 自研图像处理；阈值坐标腐烂 | 运行时 + native 构建 + 模型更新 | 托管最低 ↔ 自训最高 |
| 覆盖率上限（推断） | 中（只覆盖规律性强的按钮） | 高（页面上有文字就能读） | 最高（纯图形/倒计时圆环） |
| 误点风险 | 中（坐标/像素误判） | 中（OCR 误读跳过/关闭/×） | 中~低 |
| 决定性前提 | 接受开截图 + 自研图像处理 + 长期调参 | 允许新库 + 包体 +N MB + native 维护 | GMS / AGPL 或授权 / 数据出境 |

取舍（不含推荐）：
- **A**：①需开 `canTakeScreenshot`（扩大服务能力）②图像处理自研、阈值调参长期 ③对纯图形 + 无规律位置的广告存在覆盖率天花板。适用：产品接受部分 App 仍跳不过。
- **B**：覆盖「有文字但树里读不到」；代价是破零依赖、包体 +2.35 MiB~20.7 MB、需 native 构建或额外运行时、精度需真机标定集。适用：有包体预算、能承担 native 维护。
- **C**：能解纯图形按钮/倒计时圆环（业界唯一高命中路线）；代价是 ML Kit 需 GMS 且闭源、YOLO AGPL、云端冲突隐私、自训需数据管线。适用：法务/产品先给许可与隐私结论。

## 6. 最小可行落地路径（若选择「引入」）

阈值均为建议初值（推断），由产品按 §5 决定。

- **阶段 0 判定与埋点（零风险，先做）**：按 §1.1 把跳不过的 App 分成 A/B/C/D/E 得到真实基线。只加采集（快照 `SnapshotExporter`/`SnapshotRequest`）与埋点（`util/DiagnosticCounters.kt`、`skip/SkipEventRecorder.kt`），不改跳过逻辑。验收：目标 App 有分类结论、埋点能区分「未命中规则」/「命中但复核失败」、快照能看到 D 类特征。**退出条件：若 D 类占比极低，兜底层不必做，回到 P2-1 规则调优。**
- **阶段 1 弱信号启发式（零依赖，不改引擎）**：覆盖 C 类「小块可点击 + 右上角 + 叶子」。改 `BuiltInRules.kt`（递增 `BUILT_IN_VERSION`）。验收：`AD_SKIPPED` 的 `selector` 非空可读、`confirmed=true` 比例、正常页零误点。**退出条件：正常页出现误点立即回滚该规则。**
- **阶段 2 截图启发式（零依赖，需开能力）**：覆盖 D 类中「右上角固定位置有跳过/倒计时按钮」。改 `accessibility_service_config.xml`（`canTakeScreenshot="true"` + UI 开关），新增截图调度与像素分析（**新文件**，不要塞进 `SkipRuleEngine.kt`，注意与 300ms 扫描节奏、`VERIFY_DELAYS` 交互），点击复用 `ActionExecutor.clickAt`。必须实测：候选定位命中率、误点率、单帧往返耗时、连续截图内存峰值与 GC、耗电（系统电池统计前后对比）、API 29 降级行为。**退出条件：误点率超 Q5 → 收紧区域/帧数，仍超则关闭该层（保留开关默认关）。**
- **阶段 3 OCR（须先过 Q1/Q3/Q4）**：覆盖「有文字但树里读不到」。按技术栈加依赖（`app/build.gradle.kts`）+ 推理封装，建议只对候选小图 OCR。验收：候选区域 OCR 命中率（自建小标定集）、单次耗时、包体增量实测、隐私告知上线。**退出条件：包体/耗时超上限 → 降级小模型或回退阶段 2。**

埋点字段：`layer`（`l1_node`/`l2_weak_signal`/`l3_screenshot`/`l4_ocr`）、`pageClass`（A~E）、`candidateRect`（屏幕坐标 + 归一化，坐标先验唯一来源）、`shotMs`/`analysisMs`/`ocrMs`、`confirmed`（已有）、`frameCount`。

## 9. 未做、风险与遗留

**未做**（原因均为任务约束：不跑 gradle、不用 adb、不装 APK、不改源码）：OCR/模型/截图的真机实测（命中率/耗时/内存/耗电）；Flutter/Unity/WebView 真实快照采样；带 ML Kit/ORT/PP-OCR 的 APK 包体实测；本机 GMS 验证；`developer.android.com` 逐字核对（改用本地 SDK 元数据 + AOSP 镜像，证据等级不降）。

**风险**：
1. 预设前提被证伪：「Flutter/Unity/WebView 一定无文本」不成立，按错前提上 OCR 会白投成本 → 必须先做阶段 0。
2. 截图合规与用户信任：扩大可见范围，需告知与开关（Q2/Q3）。
3. 包体与 native 构建：OCR/推理框架带来 native 构建、ABI 裁剪、模型分发新维护面；Tesseract 不在 Maven Central，集成路径更长。
4. 许可：Ultralytics AGPL-3.0 是明确法律风险；ML Kit 闭源禁逆向。
5. 精度不可外推：PaddleOCR 81.29%、ad-skipper 19/20 是各自场景指标，不能作本项目预期。
6. 规则/坐标长期腐烂：需持续采样维护，是持续成本。
7. 系统节流是硬上限：333ms（≈3 帧/秒）意味着流式视频分析在无障碍截图路径不可行。
8. API 29 降级：需明确「老设备不支持兜底层」。

**遗留**：阶段 0 采集与分类未开始（需真机 + 目标 App 清单）；坐标点击的复核判据未设计；埋点字段未落地。
