# 开屏跳过模块设计

> 包：`com.bsfeng.monitor.skip`。状态：v2 已实现（GKD 语义重构完成）。
> 改代码 / 规则前先读[业界调研与改进方案](业界调研与改进方案.md)；兜底路径见[兜底方案调研](兜底方案调研.md)。

模块 = 无障碍服务 + GKD 兼容选择器 + 订阅规则，自动跳过开屏广告。

## 1. 架构

```
MonitorAccessibilityService（WINDOW_STATE_CHANGED / WINDOW_CONTENT_CHANGED）
 → SkipRuleEngine（匹配窗口 + 防误触闸门 + 调度）
 → SkipRuleManager（内置 / 自定义 / GKD 订阅）→ SelectorCache → SelectorParser（字符串 → AST）
 → NodeMatcher → SelectorEvaluator（从右往左求值；快速查询 byViewId / byText）
 → ActionExecutor.perform(node, action)（clickNode / clickCenter / back / longClick）
 → SkipEventRecorder → RecordCollector（AD_SKIPPED，含命中的 selector）
```

### 匹配窗口模型

以「App 切换时刻」为锚点开窗（默认 10 秒，设置页可选 5/10/15 秒，`SkipConfig.kt`）；弱网下窗口到点且页面仍在渲染时最多顺延 4 秒（§4.3）。

| 事件 | 行为 |
|---|---|
| 前台 App 变化 | 重置计数/冷却 → 开窗 → 立即扫描 |
| 同 App 内 Activity 变化 | 更新 className（影响 `activityIds` 过滤与 ACTIVITY 级重置）→ 立即扫描 |
| WINDOW_CONTENT_CHANGED | 100ms 节流后立即扫描（广告渲染完成第一时间命中） |
| 兜底轮询 | 每 300ms，防事件丢失 |
| 根节点为 null | 不放弃，下轮重试（旧实现会整次启动漏检） |
| 命中并执行 | 进入点击后确认（§4.2），期间不再执行任何规则 |
| 到点且页面仍在渲染 | 弱网顺延（§4.3）：截止 +2 秒，最多 2 次（合计 +4 秒）；页面静止则结束 |
| 窗口结束 | 停止扫描 |

## 2. 选择器语法（GKD 子集）

实现 `SelectorParser.kt`，AST 在 `domain/.../model/Selector.kt`。**求值方向从右往左**：`A > B` 先找 B 再判断 A 是否其父；目标节点为 `@` 标记段（缺省最右段）。

| 元素 | 写法 | 说明 |
|---|---|---|
| 类名简写 | `TextView` | 等价 `[name='TextView'\|\|name$='.TextView']` |
| 任意类名 | `*` | 不约束类名 |
| 属性表达式 | `[text*="跳过"]`、`[text.length<10]`、`[width<500&&height<300]` | 支持成员表达式与方法调用（`parent.getChild(0)`） |
| 逻辑 | `[a\|\|b]`、`[a&&b]`、`[!(vid="x")]`；并列 `[a][b]` ≡ `[a&&b]` | `&&` 优先于 `\|\|` |
| 目标标记 | `@[vid="close"]`、`@LinearLayout > TextView` | 决定点击哪个节点 |
| 关系算子 | `A > B`（祖先，`>1`=父）、`A B`（任意祖先）、`A <n B`（直接子）、`A <<n B`（子孙）、`A + B`/`A - B`（前置/后置兄弟） | 可带表达式：`>n`、`<<2`、`+(1,2,3)`、`>(-n+4)` |
| 比较符 | `= != > >= < <= ^= !^= *= !*= $= !$= ~= !~=` | 除 `=`/`!=` 外任一侧 null 结果为 false；字符串大小写敏感 |
| 逻辑组合链 | `(A > B) \|\| (M > N)` | 多链组合必须加括号 |

不支持：关系算子 `->`（解析期报错，避免静默误匹配）、CSS 伪类 `:has/:not`（用 `parent.getChild(0)`、`index` 等价表达）。

### 快速查询（性能）

整树深度遍历在开屏场景每次几十毫秒，会阻塞无障碍主线程。规则（`SelectorParser.hintOf` + `SelectorEvaluator.fastQueryCandidates`）：

| 属性段 | 是否走原生 API |
|---|---|
| `[text=]`/`[text*=]`/`[text^=]`/`[text$=]`（长度 ≥2） | ✅ `findAccessibilityNodeInfosByText`（包含匹配，结果是超集） |
| `[id=]`/`[vid=]`（长度 ≥2） | ✅ `findAccessibilityNodeInfosByViewId`（`vid` 自动补 `包名:id/`） |
| `[id$=]`/`[vid*=]` 等非精确 ID | ❌ 走遍历（防漏匹配） |
| `!(...)` 内部 | ❌ 不走快速查询 |
| `\|\|` 混合分支 | 仅当每个分支都能快速查询才启用（否则漏分支） |
| 规则字段 `fastQuery: false` | ❌ 清空 hint，强制深度优先（保证匹配顺序） |

解析结果由 `SelectorCache.kt` 进程内缓存（`fastQuery` 参与缓存键），规则更新后调 `SelectorCache.clear()`。

## 3. 规则模型

领域模型 `domain/.../model/SkipRule.kt`（`SkipRule` / `RuleGroup` / `MatchRule` / `MatchAction` / `ResetMatch` / `ClickPosition`）。语义对齐 GKD：

| 字段 | 层级 | 语义 |
|---|---|---|
| `app` | 规则 | 包名；`"*"`（`SkipRule.GLOBAL_APP`）= 全局规则 |
| `activityIds` / `excludeActivityIds` | 组 | **前缀匹配**，`.` 开头自动补包名；exclude 优先；空 = 全部界面 |
| `excludedApps` | 规则 | 全局规则的按应用禁用名单（GKD `globalGroups[].apps[{id,enable:false}]`），命中则不生效 |
| `matchTime` | 组/规则 | 匹配时间窗口（ms，自 App 切换起算；0 = 不限） |
| `actionMaximum` + `resetMatch` | 组/规则 | 最大执行次数与重置时机（`APP`/`ACTIVITY`/`MATCH`） |
| `actionMaximumKey` | 规则 | 与同组同 key 规则**共享执行次数**（多条开屏规则只跳一次） |
| `actionCd` / `actionCdKey` | 组/规则 | 两次动作最小间隔；`actionCdKey` 与同组同 key 规则**共享冷却** |
| `preKeys` | 规则 | 要求同组同 key 规则刚刚执行过（多步流程顺序闸门，防误触） |
| `actionDelay` | 规则 | 命中后等待，**到期且再次命中**才执行 |
| `matches` | 规则 | 全部命中才执行，点击**最后一个**选择器的目标节点 |
| `anyMatches` | 规则 | 任一命中即点击该节点 |
| `excludeMatches` | 规则 | 任一命中则放弃（防误触） |
| `matchDelay` | 规则 | 首次命中的挂起时长，到期重新命中才执行（存到期时间戳，不被扫描取消） |
| `action` | 规则 | `click`/`clickNode`/`clickCenter`/`back`/`longClick`/`none` |
| `position` | 规则 | 归一化坐标（仅 `clickCenter`） |
| `fastQuery` | 规则 | 是否允许快速查询 |

序列化：`SkipRuleSerialization.kt`（org.json 往返 + GKD 订阅 JSON5 → 模型）。

## 4. 防误触闸门（依据见调研 §3.2）

1. **只点规则命中的节点**：坐标连点（16 点）与「返回键兜底」已删除 —— 旧实现把它们记为跳过成功，396 条 `AD_SKIPPED` 记录 `selector` 全空，含大量「返回键把用户踢出 App」的假成功。
2. **面积守卫**：命中节点面积 > 根节点 1/3 丢弃（整屏广告容器点中心会进落地页）。
3. **时间闸门**：`matchTime`（开屏 8~10 秒）+ `actionMaximum` + `resetMatch=APP`。
4. **熄屏不动作**：`PowerManager.isInteractive == false` 时丢弃事件并停止扫描。
5. **白名单**：`skip_whitelist`（`ui/WhitelistScreen.kt`）。
6. **全局规则排除名单**：`BuiltInRules.GLOBAL_EXCLUDED_PACKAGES`（系统 UI / 桌面 / 浏览器 / 输入法等）。
7. **activityIds 前缀过滤**：规则限定在开屏 Activity，避免正常页误点。
   微信小程序走这条而不是排除名单——`GLOBAL_EXCLUDED_PACKAGES` 只作用于全局规则，
   把 `com.tencent.mm` 加进去会让小程序规则一起失效；误触范围改由 `.plugin.appbrand.*` 圈定。

### 4.2 点击后确认

「动作执行成功」≠「广告消失」（点到装饰节点、点了没反应、广告换容器都会被记成功）。因此动作后进入复核：用**命中的同一选择器**在 400ms / +600ms 各复核一次（`SkipRuleEngine.verifyDelaysMs`），匹配不到才算已确认。

| 结果 | `SkipResult.confirmed` | 落库 / 展示 |
|---|---|---|
| 复核时已匹配不到 | `true` | 日志「跳过成功（已确认广告消失）」；弹幕「已跳过」；计入已确认 |
| 两次仍匹配到 | `false` | 日志「跳过未确认（点完广告仍在）」；弹幕「已点击跳过按钮（未确认）」 |
| 未复核（测试/关闭确认） | `null` | 不写 `detail.confirmed`，展示「已自动跳过开屏广告」 |

复核期间不执行任何规则（即使允许无限次），防同一条广告被点多次；复核由自身次数上限收敛，不受窗口到期影响；熄屏或切 App 会终止复核。落库字段 `AD_SKIPPED.detail.confirmed`，记录页显示「累计跳过 N 次（已确认 M 次）」。

### 4.3 弱网顺延边界

窗口到点时若页面仍在渲染（距最近 CONTENT_CHANGED < 1 秒）则顺延截止时间（`SkipConfig.kt`，判定在 `SkipRuleEngine.tryExtendWindow`）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `WINDOW_EXTEND_STEP_MS` | 2 秒 | 单次顺延 |
| `WINDOW_MAX_EXTENSIONS` | 2 次 | 最多顺延（合计 +4 秒，按「原截止 + 步长」累加） |
| `WINDOW_STILL_RENDERING_MS` | 1 秒 | 距最近 CONTENT_CHANGED 小于该值才算仍在渲染 |
| `WINDOW_EXTEND_MAX_SCAN_GAP_MS` | 1.5 秒 | 到点判定时距上次扫描超过该值则**不顺延**（排除进程冻结 / 时间跳变复活过期窗口） |

- **时间闸门联动**：规则闸门放宽为 `matchTime + 已顺延额度`；只延长扫描不放宽闸门会让内置规则（`matchTime` 等于监控窗口）在顺延期间扫到也不执行，增强变死代码。
- **不顺延 / 立即结束**：熄屏、切 App、命中（转复核）、`scanCount >= MAX_SCANS(80)`、页面静止、次数用尽 —— 护栏优先。
- **误触代价**：顺延期间正常页的「跳过 / 关闭」文本仍可能被命中（`actionMaximum=1` + `resetMatch=APP` 限次）；要更长覆盖应把窗口调到 15 秒，而不是无限顺延。
- 每次顺延写 `DebugConfig.log`（原因 + 新截止 + 顺延次数 / 累计额度）。

## 5. 规则来源与订阅

| 来源 | 存储 | 说明 |
|---|---|---|
| 内置规则 | `BuiltInRules.kt`（`BUILT_IN_VERSION`） | 1 条全局开屏规则 + 8 个 App 规则（自研，含微信小程序），闸门跟随监控窗口 |
| 自定义规则 | `files/skip_rules.json` | 规则页新增 / 修改 |
| 订阅规则 | `files/subscriptions/sub_<hash>.json`（每地址一文件） | GKD 订阅格式，`GkdSubscription` 拉取；清单存 `skip_rule_prefs.subscription_metas` |
| 启停状态 | `skip_rule_prefs → disabled_ids` | 只存被禁用 ID，内置规则升级不丢用户设置 |
| 监控窗口 | `skip_config → watch_window_ms` | 5/10/15 秒（默认 10），同时是内置规则的 `matchTime` |

迁移：v1 会把整份内置规则快照写进 `skip_rules.json` —— v2 启动时若该文件含 ≥20 条且 ID 全以 `_splash` 结尾，视为历史快照，备份为 `skip_rules_v1_backup.json` 后清空（`migrateLegacyRulesIfNeeded`）。早期单订阅文件 `skip_subscription.json` + `subscription_meta` 自动搬进 `files/subscriptions/`（`migrateSingleSubscriptionIfNeeded`）。

UI：`SkipRuleScreen` 顶部逐订阅源一行（地址 + 版本 + 条数，各带更新 / 删除）、「添加订阅」（多源，URI 键盘）、「页面快照」（**切到目标 App 后 2.5 秒**自动导出无障碍树 → `files/snapshots/<时间戳>.json`；固定延时模式命中率仅约 3%，见[规则实测记录](规则实测记录.md)）。规则卡片可展开查看每条匹配规则的选择器，排查「为什么跳不过」不必翻日志。

自动检查：`MonitorApp` 启动调用 `GkdSubscription.autoCheck`，逐个源检查，距上次超过 `CHECK_INTERVAL_MS`（1 天）才发请求（记录在 `subscription_check_at`）；单源失败只影响自己，保留旧规则。

订阅源可用性（真机实测）：jsdelivr 在真机下载不稳定（同地址 Mac 可下、手机失败）；推荐 npm 镜像（对话框已预填）：

| 地址 | 实测 |
|---|---|
| `https://registry.npmmirror.com/@gkd-kit/subscription/latest/files/dist/gkd.json5` | ✅ 2 秒内 611 条（version 186），全局开屏规则的 107 个禁用名单正确落到 `excludedApps` |
| `https://registry.npmmirror.com/@aisouler/gkd_subscription/latest/files/dist/Aisouler_gkd.json5` | ✅ 889 条（version 406） |
| `.../@aisouler/gkd_subscription/.../dist/gkd.json5` | ❌ 404（包内无此文件）—— URL 包内路径须与包内容一致 |

两源可同时添加（611 + 889 + 内置 8 = 1508 条），删一个只清自己的文件。踩坑见[GKD 订阅源在真机上的可用性](../踩坑/GKD订阅源在真机上的可用性.md)。

实现 `GkdSubscription.kt`（JSON5 解析 `json/Json5Parser.kt`）：两级订阅文件 `{id,version,updateUrl/checkUpdateUrl}` 探测 → 跟随（含相对路径）拉全量；本地版本 ≥ 订阅版本则跳过；安全边界为仅 https、响应体 ≤ 8MB、规则数 ≤ 3000、解析失败保留旧规则。**合规**：社区订阅仓库（AIsouler 12k★ / Lin-arm 5.9k★）均无 LICENSE，规则数据不可内置，只能由用户自行添加 URL；内置规则为自研。

## 7. 扩展点

- **新增 App 规则**：改 `BuiltInRules.appRules()`，先用 `SnapshotExporter` 导出真实页面树再写精确选择器，并递增 `BUILT_IN_VERSION`；`BuiltInRulesTest` 校验可解析。
- **接入社区规则**：让用户添加订阅 URL（不内置第三方规则数据），支持多源。
- **调监控窗口**：设置页 5/10/15 秒；窗口同时是内置规则的时间闸门，订阅 / 自定义规则保留各自的 `matchTime`。
- **强兜底**：无文本 / 无稳定 ID 场景的方案与代价见[兜底方案调研](兜底方案调研.md)；阶段 0 采样分类与弱信号启发式不破「零第三方业务依赖」，OCR / 小模型 / 云端 VLM 需产品决策。
