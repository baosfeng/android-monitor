# 开屏跳过模块设计

> 包：`com.bsfeng.monitor.skip`。状态：v2 已实现（GKD 语义重构 + 点击前判据）。
> 改代码 / 规则前先读[业界调研与改进方案](业界调研与改进方案.md)；兜底见[兜底方案调研](兜底方案调研.md)。

模块 = 无障碍服务 + GKD 兼容选择器 + 订阅规则，自动跳过开屏广告。

## 1. 架构与匹配窗口

```
MonitorAccessibilityService → SkipRuleEngine（窗口 + 闸门）
 → SkipRuleMatcher → RuleNodeFinder → SplashCandidateVerdict（点击前判据）→ ActionExecutor
 → SkipEventRecorder → RecordCollector（AD_SKIPPED / AD_SKIP_UNCONFIRMED）
```

窗口以「App 切换时刻」为锚点（默认 10 秒，可选 5/10/15 秒，`SkipConfig.kt`）：

| 事件 | 行为 |
|---|---|
| 前台 App 变化 | 重置计数/冷却 → 开窗 → 立即扫描 |
| 同 App 内 Activity 变化 | 更新 className（影响 `activityIds`）→ 立即扫描 |
| WINDOW_CONTENT_CHANGED | 100ms 节流后立即扫描 |
| 兜底轮询 / 根节点为 null | 每 300ms / 不放弃，下轮重试 |
| 命中并执行 | 进入点击后确认（§3.2），期间不再执行任何规则 |
| 到点且页面仍在渲染 | 弱网顺延（§3.3），最多 +4 秒 |

## 2. 选择器语法（GKD 子集）与规则模型

**求值从右往左**：`A > B` 先找 B 再判断 A 是否其父；`@` 段是点击目标（缺省最右段）。支持类名简写 `TextView`/`*`、
属性表达式 `[text*="跳过"]`、`[text.length<10]`，逻辑 `[a||b]`/`[a&&b]`/`[!(...)]`（并列 `[a][b]` ≡ `&&`），
关系算子 `> <n <<n + -`，比较符 `= != > >= < <= ^= !^= *= !*= $= !$= ~= !~=`（除 `=`/`!=` 外任一侧 null 为 false）。
`->` 解析期报错，`:has/:not` 用 `parent.getChild(0)` 等价表达。快速查询：文本类走 `ByText`、ID 类走 `ByViewId`，
`||` 混合分支与非精确 ID 走遍历；解析结果由 `SelectorCache` 缓存。

模型 `domain/.../model/SkipRule.kt` 对齐 GKD：`app`（`"*"` = 全局）、`activityIds`/`excludeActivityIds`（**前缀匹配**，`.` 开头补包名，exclude 优先）、
`matchTime`、`actionMaximum` + `resetMatch`、`actionMaximumKey`/`actionCdKey`（共享计数/冷却）、`preKeys`、`actionDelay`、`matchDelay`、`excludeMatches`、`fastQuery`。

## 3. 防误触闸门

1. **只点规则命中的节点**（坐标连点与返回键兜底已删除，旧实现记了 396 条 `selector` 全空的假成功）。
2. **面积守卫**：命中面积 > 根节点 1/3 丢弃（整屏广告容器点中心会进落地页）。
3. **时间闸门**：`matchTime` + `actionMaximum` + `resetMatch=APP`。
4. **熄屏不动作 / 白名单 / 全局规则排除名单**（系统 UI、桌面、浏览器、输入法）；**activityIds 前缀过滤**（微信小程序走这条而不是排除名单——整包排除会让小程序规则一起失效）。

### 3.1 点击前判据（默认拒绝）

时间闸门只限制「什么时候可以点」，拦不住「点的是不是开屏按钮」。`SplashGate` 在动作执行前取
（文案/描述/viewId/祖先 viewId 链/同屏广告标识/进入 App 后的毫秒数）判定：

| # | 条件 | 结果 |
|---|---|---|
| 1 | 有文案但不在 `SplashSkipWording` 白名单 | **拒绝**（跳过此步/跳过引导/跳过设置/跳过登录/跳过这一步） |
| 2 | 文案自带「广告」字样 | 接受 |
| 3 | 同屏存在广告标识文本（广告/推广/赞助/独立单词 AD） | 接受 |
| 4 | 自身或祖先 viewId 命中 `splash/gdt/ywad/ksad/advert/ad_container/tt_ad` | 接受 |
| 5 | 纯结构候选（无文案）且 viewId 带跳过语义（skip/跳过/跳過），在 `SPLASH_WORDING_GRACE_MS`（1.5 秒，**经验值未校准**）内 | 接受 |
| 6 | 纯文本候选在 `SPLASH_TEXT_ONLY_GRACE_MS`（0.8 秒，**经验值未校准**）内 | 接受 |
| 7 | 其余 | **拒绝** |

白名单**正向枚举**：跳过 / 跳過 / 跳过N / 跳过 N 秒 / 跳过广告 / 跳过广告N / 关闭广告 / Skip / Skip Ad / Skip N / 全角数字；超 16 字与三位数倒计时拒绝。**倒计时只是加分项**——「跳过 1」在多步骤向导里真实存在，纯倒计时文案仍走第 6 条短窗；**倒计时命名同理是弱证据**：`countdown/count_down` 是通用 UI 组件名（日历倒数日、番茄钟、抢购倒计时），无文案时既不算广告容器、也不给第 5 条宽限窗（真机 2026-11-05 日历 `countdown_container` 曾被放行），全局规则用它当选择器只是为捞「ID 带 count_down 的跳过按钮」。
拒绝写 `DebugConfig.log`（原因 + 规则名 + 选择器）；放行的判据结论与命中文案落进记录 `detail`（`matched_text` / `verdict_reason`，截断 32 字）—— 只有 `selector` 时无法回溯「点的是什么字」。
**误杀代价**：无广告证据且 0.8 秒后才出现的纯文本「跳过」会被拒，最可能是「慢机型冷启动首帧晚于 0.8 秒」与「广告 SDK 不暴露广告标识/容器的纯文本按钮」。
**恢复手段（未闭环）**：误杀时用户只看到「一条记录都没有」，拒绝原因仅在 `DebugConfig.log`；**设置页没有「拒绝原因」入口**，列为后续项。
**两个宽限窗都是经验值，未实测校准**：校准方法是抓「进入 App → 跳过按钮首次出现」的时刻分布取 P90。

### 3.2 点击后确认（`confirmed` 的语义边界）

动作后用**命中的同一选择器**在 400ms / +600ms 各复核一次，匹配不到才算已确认。

| 结果 | 落库 | 计数与提示 |
|---|---|---|
| `confirmed=true` | `AD_SKIPPED` | 计入已确认；弹幕「已跳过」 |
| `confirmed=null`（未复核） | `AD_SKIPPED` | 计入跳过成功 |
| `confirmed=false` | **`AD_SKIP_UNCONFIRMED`** | **不计入任何跳过成功**；弹幕「已点击（未确认）」 |

- **`confirmed=true` 不等于「广告已消失」**：它只表示该选择器不再匹配，点掉导航/引导节点同样匹配不到 → 判 true。误判防线在点击前的判据（§3.1），不在这个字段。
- **为什么未确认单独一个 action**：所有成功口径都按 `action='AD_SKIPPED'` 过滤，独立 action 让计数自动分离、不用改 UI 层；记录仍落库且在实时事件流可见，误判排查不丢证据。
- 复核期间不执行任何规则；由自身次数上限收敛，不受窗口到期影响；熄屏或切 App 会终止复核。

### 3.3 弱网顺延边界

到点时若页面仍在渲染（距最近 CONTENT_CHANGED < 1 秒）则顺延截止时间：

| 参数 | 默认 | 含义 |
|---|---|---|
| `WINDOW_EXTEND_STEP_MS` | 2 秒 | 单次顺延 |
| `WINDOW_MAX_EXTENSIONS` | 2 次 | 最多顺延（合计 +4 秒，按「原截止 + 步长」累加） |
| `WINDOW_STILL_RENDERING_MS` | 1 秒 | 距最近 CONTENT_CHANGED 小于它才算仍在渲染 |
| `WINDOW_EXTEND_MAX_SCAN_GAP_MS` | 1.5 秒 | 到点判定时距上次扫描超过它则**不顺延**（排除进程冻结/时间跳变） |

规则闸门同步放宽 `matchTime + 已顺延额度`。不顺延：熄屏、切 App、命中（转复核）、`scanCount >= 80`、页面静止、次数用尽。


## 4. 规则来源与订阅

| 来源 | 存储 |
|---|---|
| 内置规则 `BuiltInRules.kt`（`BUILT_IN_VERSION`） | 1 条全局开屏规则 + 8 个 App 规则（含微信小程序） |
| 自定义 / 订阅规则 | `files/skip_rules.json` / `files/subscriptions/sub_<hash>.json`（每地址一文件） |
| 启停状态 | `skip_rule_prefs → disabled_ids`（只存被禁用的 ID，内置升级不丢设置） |
| 监控窗口 | `skip_config → watch_window_ms`（同时是内置规则的 `matchTime`） |

订阅源实测：npm 镜像可用（`@gkd-kit/subscription` 611 条 / `@aisouler/gkd_subscription` 889 条），
jsdelivr 在真机不稳定。社区订阅**均无 LICENSE** → 规则数据不可内置，只能由用户自行添加 URL。
