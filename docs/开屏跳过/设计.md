# 开屏跳过模块设计

> 包路径：`com.bsfeng.monitor.skip`
> 状态：v2 已实现（GKD 语义重构完成）
> 关联文档：→ [业界调研与改进方案](业界调研与改进方案.md)（改代码/规则前必读） · [后续计划](后续计划.md)

本模块基于**无障碍服务 + GKD 兼容选择器 + 订阅规则**自动跳过开屏广告。

---

## 1. 架构总览

```
MonitorAccessibilityService            （事件源：WINDOW_STATE_CHANGED / WINDOW_CONTENT_CHANGED）
        │  onWindowChanged(pkg, cls) / onContentChanged(pkg)
        ▼
SkipRuleEngine                         （匹配窗口 + 防误触闸门 + 规则调度）
        │  取规则：SkipRuleManager.findRulesFor(pkg)
        ▼
SkipRuleManager                        （内置规则 / 用户自定义 / GKD 订阅）
        │  选择器字符串
        ▼
SelectorCache → SelectorParser         （字符串 → SelectorExpr AST，进程内缓存）
        ▼
NodeMatcher → SelectorEvaluator        （从右往左求值；快速查询 findAccessibilityNodeInfosByViewId/ByText）
        │  目标节点（@ 标记，缺省最右段）
        ▼
ActionExecutor.perform(node, action)   （clickNode / clickCenter / back / longClick）
        ▼
SkipEventRecorder → RecordCollector    （记录 AD_SKIPPED 事件，含命中的 selector）
```

### 匹配窗口模型（关键）

以「App 切换时刻」为锚点开窗（默认 [SkipRuleEngine.WATCH_WINDOW_MS] = 10 秒）：

| 事件 | 行为 |
|------|------|
| 前台 App 变化 | 重置计数/冷却 → 开窗 → 立即扫描一次 |
| 同 App 内 Activity 变化 | 更新 className（决定 `activityIds` 过滤与 ACTIVITY 级重置）→ 立即扫描 |
| WINDOW_CONTENT_CHANGED | 100ms 节流后立即扫描（广告渲染完成的第一时间命中） |
| 兜底轮询 | 每 300ms 一次，防止事件丢失 |
| 根节点为 null | **不放弃**，等下轮扫描重试（修复：旧实现整次启动漏检） |
| 窗口结束 / 命中成功 | 停止扫描 |

## 2. 选择器语法（GKD 子集）

实现：`app/src/main/java/com/bsfeng/monitor/skip/SelectorParser.kt`；AST 定义在
`domain/src/main/kotlin/com/bsfeng/monitor/domain/model/Selector.kt`。

### 2.1 求值方向

**从右往左**：`A > B` 先找到 B，再判断 A 是不是 B 的父节点。目标节点为 `@` 标记段
（缺省最右段）。

### 2.2 语法元素

| 元素 | 写法 | 说明 |
|------|------|------|
| 类名简写 | `TextView` | 等价 `[name='TextView'\|\|name$='.TextView']` |
| 任意类名 | `*` | 不约束类名 |
| 属性表达式 | `[text*="跳过"]`、`[text.length<10]`、`[width<500&&height<300]` | 支持成员表达式与方法调用（如 `parent.getChild(0)`） |
| 逻辑 | `[a\|\|b]`、`[a&&b]`、`[!(vid="x")]`；并列 `[a][b]` ≡ `[a&&b]` | `&&` 优先级高于 `\|\|` |
| 目标标记 | `@[vid="close"]`、`@LinearLayout > TextView` | 决定点击哪个节点 |
| 关系算子 | `A > B`（A 是 B 的祖先，`>1`=父节点）、`A B`（任意祖先）、`A <n B`（直接子节点）、`A <<n B`（子孙）、`A + B`/`A - B`（前置/后置兄弟） | 关系可带表达式：`>n`、`<<2`、`+(1,2,3)`、`>(-n+4)` |
| 比较符 | `= != > >= < <= ^= !^= *= !*= $= !$= ~= !~=` | 除 `=`/`!=` 外，任一侧为 null 结果为 false；字符串比较大小写敏感 |
| 逻辑组合链 | `(A > B) \|\| (M > N)` | 多个链做逻辑组合时必须用括号包裹 |

**不支持**：关系算子 `->`（解析期报错，避免静默误匹配）、`:has/:not` 等 CSS 伪类（用
`parent.getChild(0)`、`index` 等等价表达）。

### 2.3 快速查询（性能）

**为什么要做**：整树深度遍历判断 n 次节点，开屏场景下每次扫描几十毫秒，会阻塞无障碍主线程。

**规则**（`SelectorParser.hintOf` + `SelectorEvaluator.fastQueryCandidates`）：

| 属性段写法 | 是否走原生 API |
|-----------|---------------|
| `[text=]`/`[text*=]`/`[text^=]`/`[text$=]`（长度 ≥2） | ✅ `findAccessibilityNodeInfosByText`（包含匹配，结果一定是超集） |
| `[id=]` / `[vid=]`（长度 ≥2） | ✅ `findAccessibilityNodeInfosByViewId`（`vid` 自动补 `包名:id/`） |
| `[id$=]`/`[vid*=]` 等非精确 ID 匹配 | ❌ 走遍历（避免漏匹配） |
| `!(...)` 内部 | ❌ 一律不走快速查询 |
| `\|\|` 混合分支 | 仅当每个分支都能快速查询时才启用（否则会漏掉分支） |
| 规则字段 `fastQuery: false` | ❌ 清空 hint，强制深度优先（保证匹配顺序） |

解析结果由 `app/src/main/java/com/bsfeng/monitor/skip/SelectorCache.kt` 做进程内缓存
（`fastQuery` 作为缓存键的一部分），规则更新后调用 `SelectorCache.clear()`。

## 3. 规则模型

领域模型：`domain/src/main/kotlin/com/bsfeng/monitor/domain/model/SkipRule.kt`
（`SkipRule` / `RuleGroup` / `MatchRule` / `MatchAction` / `ResetMatch` / `ClickPosition`）。

| 字段 | 层级 | 语义（对齐 GKD） |
|------|------|-----------------|
| `app` | 规则 | 包名；`"*"`（`SkipRule.GLOBAL_APP`）表示全局规则 |
| `activityIds` / `excludeActivityIds` | 组 | **前缀匹配**，`.` 开头自动补包名；exclude 优先；空 = 全部界面 |
| `excludedApps` | 规则 | **全局规则**的按应用禁用名单（GKD `globalGroups[].apps[{id,enable:false}]`），命中则对该 App 不生效 |
| `matchTime` | 组/规则 | 参与匹配的时间窗口（毫秒，自 App 切换起算；0 = 不限） |
| `actionMaximum` + `resetMatch` | 组/规则 | 最大执行次数与重置时机（`APP`/`ACTIVITY`/`MATCH`） |
| `actionMaximumKey` | 规则 | 与同组内该 key 的规则**共享执行次数**（多条开屏规则只跳一次） |
| `actionCd` / `actionCdKey` | 组/规则 | 两次动作最小间隔；`actionCdKey` 表示与同组内该 key 的规则**共享冷却** |
| `preKeys` | 规则 | 要求同组内该 key 的规则**刚刚执行过**才允许触发（多步流程顺序闸门，防误触） |
| `actionDelay` | 规则 | 命中后先等待，**到期且再次命中**才真正执行动作（抗误触） |
| `matches` | 规则 | 全部命中才执行，点击**最后一个**选择器的目标节点 |
| `anyMatches` | 规则 | 任一命中即点击该节点 |
| `excludeMatches` | 规则 | 任一命中则放弃本规则（防误触） |
| `matchDelay` | 规则 | 首次命中后挂起，到期重新命中才执行（实现为到期时间戳，**不会被扫描取消**） |
| `action` | 规则 | `click`/`clickNode`/`clickCenter`/`back`/`longClick`/`none` |
| `position` | 规则 | 归一化坐标（仅 `clickCenter`） |
| `fastQuery` | 规则 | 是否允许快速查询 |

序列化：`app/src/main/java/com/bsfeng/monitor/skip/SkipRuleSerialization.kt`（org.json 往返 +
GKD 订阅 JSON5 → 模型）。

## 4. 防误触闸门（实测依据见调研文档 §3.2）

1. **只点规则命中的节点**：坐标连点（16 点）与"返回键兜底"已删除——旧实现把它们当作"跳过成功"，
   396 条 `AD_SKIPPED` 记录里 `selector` 全为空，其中包含大量"返回键把用户踢出 App"的假成功。
2. **面积守卫**：命中节点面积 > 根节点 1/3 时丢弃（整屏广告容器点中心会进落地页）。
3. **时间闸门**：`matchTime`（开屏 8~10 秒）+ `actionMaximum` + `resetMatch=APP`。
4. **熄屏不动作**：`PowerManager.isInteractive == false` 时丢弃事件并停止扫描。
5. **白名单**：`skip_whitelist`（`app/src/main/java/com/bsfeng/monitor/ui/WhitelistScreen.kt`）。
6. **全局规则排除名单**：`BuiltInRules.GLOBAL_EXCLUDED_PACKAGES`（系统 UI/桌面/浏览器/输入法等）。
7. **activityIds 前缀过滤**：把规则限定在开屏 Activity，避免在正常页误点。

## 5. 规则来源与订阅

| 来源 | 存储 | 说明 |
|------|------|------|
| 内置规则 | 代码 `BuiltInRules.kt`（`BUILT_IN_VERSION`） | 1 条全局开屏规则 + 7 个 App 规则（自研） |
| 自定义规则 | `files/skip_rules.json` | 用户在规则页新增/修改 |
| 订阅规则 | `files/skip_subscription.json` | GKD 订阅格式，由 `GkdSubscription` 拉取 |
| 启停状态 | `skip_rule_prefs` → `disabled_ids` | 只存被禁用的 ID，内置规则升级不丢用户设置 |

**升级迁移**：v1 会把整份内置规则快照写进 `files/skip_rules.json`；v2 启动时若该文件包含
≥20 条且 ID 全部以 `_splash` 结尾（v1 内置规则特征），视为历史快照 → 备份为
`files/skip_rules_v1_backup.json` 后清空（见 `SkipRuleManager.migrateLegacyRulesIfNeeded`）。

**UI 入口**：`SkipRuleScreen` 顶部「订阅规则」（添加/更新/清除订阅）与「页面快照」（延迟 5 秒
导出**当时前台页面**的无障碍树 → `files/snapshots/<时间戳>.json`）。

**自动检查**：`MonitorApp` 启动时调用 `GkdSubscription.autoCheck`，距上次检查超过
`CHECK_INTERVAL_MS`（1 天）才发起网络请求；检查时间存于 `skip_rule_prefs.subscription_check_at`。

**订阅源可用性（真机实测）**：jsdelivr（`fastly.jsdelivr.net`）在真机上下载不稳定（实测同样地址
Mac 可下、手机端失败）；推荐使用 npm 镜像
`https://registry.npmmirror.com/@gkd-kit/subscription/latest/files/dist/gkd.json5`
（实测 2 秒内拉取 611 条规则、版本 186，其中全局开屏规则的 107 个按应用禁用名单正确落到 `excludedApps`）。

订阅实现：`app/src/main/java/com/bsfeng/monitor/skip/GkdSubscription.kt`
（JSON5 解析：`app/src/main/java/com/bsfeng/monitor/skip/json/Json5Parser.kt`）

- 支持两级订阅文件：`{id,version,updateUrl/checkUpdateUrl}` 探测文件 → 跟随（含相对路径）拉全量
- 版本比对：本地版本 ≥ 订阅版本则跳过
- 安全：仅 https、响应体 ≤ 8MB、规则数 ≤ 3000、解析失败保留旧规则
- **合规**：社区订阅仓库（AIsouler 12k★ / Lin-arm 5.9k★）均**无 LICENSE**，其规则数据不可内置，
  只能由用户自行添加订阅 URL；内置规则为自研
