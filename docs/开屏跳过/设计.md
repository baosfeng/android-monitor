# 开屏跳过模块设计

> 包路径：`com.bsfeng.monitor.skip`
> 状态：设计阶段

本模块为应用添加**开屏广告自动跳过**功能，基于无障碍服务 + CSS 风格选择器 DSL + 规则引擎实现。

---

## 1. 架构总览

```
用户界面（规则管理）
    │
    ▼
SkipRuleManager ──→ 规则存储（本地 JSON 文件）
    │
    ▼
SelectParser  ←──  选择器 DSL 语法
    │
    ▼
NodeMatcher  ──→  无障碍树节点匹配
    │
    ▼
ActionExecutor  ──→  执行点击操作
    │
    ▼
SkipRuleEngine  ←──  MonitorAccessibilityService（WINDOW_STATE_CHANGED 事件）
```

### 核心流程

1. `MonitorAccessibilityService` 收到 `WINDOW_STATE_CHANGED` 事件（包名变化时）
2. 获取当前前台 `(packageName, className)`
3. `SkipRuleEngine.match(packageName, className)` 查找匹配规则
4. 对每条匹配规则，执行选择器在无障碍树中定位目标节点
5. 找到目标节点后执行点击操作
6. 记录跳过事件到事件管道
7. 未命中时启动持续监控（白屏→广告延迟加载场景）：
   - 以 `TYPE_WINDOW_CONTENT_CHANGED` 事件驱动扫描（100ms 节流）——广告加载完成后节点树必然变化，事件到达即扫描，响应快且省电
   - 500ms 兜底轮询防止事件丢失
   - 监控最长 5 秒，点击后进入验证阶段（连续 3 次未检测到广告即确认成功）

## 2. 选择器 DSL 设计

### 2.1 语法定义

借鉴 CSS 选择器语法，针对 Android 无障碍节点树优化：

```
selector = simple_selector (combinator selector)*

simple_selector = tag_selector? (attr_selector | pseudo_selector)*

tag_selector = NodeClassName       # e.g. TextView, Button, ImageView

attr_selector = [name operator? value?]

operator: 
  =   精确匹配   [text="跳过"]
  ^=  前缀匹配   [text^="跳过"]
  $=  后缀匹配   [text$="广告"]
  *=  包含匹配   [text*="广告"]
  ~=  正则匹配   [text~="^(跳过|关闭).*"]
  !=  不等于     [text!="确定"]

combinator:
  >   父子关系     A > B      A 的直接子节点 B
  +   紧邻兄弟     A + B      A 之后的直接兄弟节点 B
  (空格) 后代关系  A B        A 的任意后代节点 B

pseudo_selector:
  :has(selector)            父节点匹配
  :first-child              第一个子节点
  :last-child               最后一个子节点
  :nth-child(n)             第 n 个子节点
```

### 2.2 可用属性

| 属性名 | 来源 | 说明 | 示例 |
|--------|------|------|------|
| `text` | `node.text` | 节点文本 | `[text="跳过"]` |
| `desc` | `node.contentDescription` | 内容描述 | `[desc="关闭广告"]` |
| `id` | `node.viewIdResourceName` | 视图 ID | `[id="com.xxx:id/btn_skip"]` |
| `vid` | `node.viewIdResourceName` (短名) | 短 ID | `[vid="btn_skip"]` |
| `clickable` | `node.isClickable` | 可点击 | `[clickable=true]` |
| `longClickable` | `node.isLongClickable` | 可长按 | `[longClickable=true]` |
| `visible` | `node.isVisibleToUser` | 用户可见 | `[visible=true]` |
| `enabled` | `node.isEnabled` | 启用状态 | `[enabled=true]` |
| `checked` | `node.isChecked` | 选中状态 | `[checked=false]` |
| `focusable` | `node.isFocusable` | 可聚焦 | `[focusable=true]` |
| `selected` | `node.isSelected` | 选择状态 | `[selected=true]` |
| `className` | `node.className` | 类名 | `className="android.widget.Button"` |

### 2.3 匹配优先级

1. **ID 匹配**：`findAccessibilityNodeInfosByViewId()` 最快
2. **文本匹配**：`findAccessibilityNodeInfosByText()` 次快
3. **节点遍历匹配**：手动遍历无障碍树，最慢但最灵活

选择器解析器自动选择最优匹配路径：
- 包含 `[id=...]` → 优先按 ID 查找
- 包含 `[text=...]` → 优先按文本查找
- 其他 → 遍历匹配

## 3. 规则数据模型

### 3.1 JSON 规则格式

```json
{
  "version": 1,
  "rules": [
    {
      "id": "zhihu_splash",
      "app": "com.zhihu.android",
      "name": "知乎开屏广告",
      "enabled": true,
      "groups": [
        {
          "name": "开屏广告",
          "activityIds": ["com.zhihu.android.ui.activity.MainActivity"],
          "rules": [
            {
              "matchDelay": 500,
              "actionCd": 30000,
              "actionMaximum": 1,
              "matches": [
                "TextView[id=\"com.zhihu.android:id/btn_skip\"]",
                "[text*=\"跳过\"]",
                "[text*=\"广告\"] + [text*=\"关闭\"]"
              ],
              "action": "click"
            }
          ]
        }
      ]
    }
  ]
}
```

### 3.2 Kotlin 数据模型

```kotlin
// Selector 语法树
data class Selector(
    val tag: String? = null,              // 标签名（如 TextView）
    val attributes: List<AttrCondition> = emptyList(),
    val combinator: Combinator? = null,    // 组合器
    val right: Selector? = null            // 右侧选择器
)

data class AttrCondition(
    val name: String,          // 属性名
    val op: AttrOp,            // 操作符
    val value: String          // 值
)

enum class AttrOp { EQ, CONTAINS, STARTS_WITH, ENDS_WITH, REGEX, NOT_EQ }
enum class Combinator { CHILD, DESCENDANT, SIBLING }

// 规则模型
data class SkipRule(
    val id: String,
    val app: String,
    val name: String,
    val enabled: Boolean = true,
    val groups: List<RuleGroup> = emptyList()
)

data class RuleGroup(
    val name: String,
    val activityIds: List<String> = emptyList(),
    val rules: List<MatchRule> = emptyList()
)

data class MatchRule(
    val matchDelay: Long = 0,
    val actionCd: Long = 30000,
    val actionMaximum: Int = 1,
    val matches: List<String>,
    val action: String = "click"
)
```

## 4. 规则引擎设计

### 4.1 SkipRuleEngine

```kotlin
class SkipRuleEngine(
    private val ruleManager: SkipRuleManager
) {
    // 当前前台包名和 Activity
    private var currentPackageName: String? = null
    private var currentClassName: String? = null
    
    // 规则执行计数器（用于 actionMaximum）
    private val actionCounters = mutableMapOf<String, Int>()
    // 规则冷却时间
    private val actionCooldowns = mutableMapOf<String, Long>()
    
    /**
     * 处理窗口变化事件
     * @return true 表示已执行跳过操作
     */
    fun onWindowChanged(
        packageName: String,
        className: String,
        rootNode: AccessibilityNodeInfo?
    ): Boolean
    
    /**
     * 规则匹配
     */
    private fun matchRules(packageName: String, className: String): List<MatchRule>
    
    /**
     * 执行选择器匹配并点击
     */
    private fun executeRule(rule: MatchRule, rootNode: AccessibilityNodeInfo): Boolean
    
    /**
     * 重置应用的状态（包名变化时）
     */
    fun resetAppState(packageName: String)
}
```

### 4.2 执行流程

```
onWindowChanged(pkg, cls, root)
    │
    ├─ 过滤系统 UI（复用 isSystemUi）
    │
    ├─ 包名变化 → resetAppState()
    │
    ├─ 获取当前可用规则
    │   └─ matchRules(pkg, cls)
    │       ├─ 查找包名匹配的 SkipRule
    │       ├─ activityIds 过滤（如有）
    │       ├─ 检查冷却时间(actionCd)
    │       ├─ 检查最大执行次数(actionMaximum)
    │       └─ 返回可执行的 MatchRule 列表
    │
    ├─ 对每条规则：
    │   ├─ matchDelay 延迟等待
    │   ├─ 解析选择器（ParseSelector）
    │   ├─ 在无障碍树中定位节点（NodeMatcher）
    │   └─ 执行点击（ActionExecutor.performClick）
    │
    ├─ 成功 → 记录跳过事件 + 更新计数器/冷却
    │
    └─ 失败 → 启动持续监控（事件驱动 + 兜底轮询）
        ├─ TYPE_WINDOW_CONTENT_CHANGED 事件到达（100ms 节流）
        │   └─ 包名匹配且未超时 → 立即扫描无障碍树
        ├─ 500ms 兜底轮询（事件丢失时保障）
        ├─ 命中 → 点击 → 验证阶段（连续 3 次未检测到广告 = 成功）
        └─ 5 秒超时 → 停止监控
```

## 6. 与现有系统的集成

### 6.1 MonitorAccessibilityService

在 `handleWindowChange()` 中增加：

```kotlin
// ==== 开屏跳过 ====
if (skipEngine.onWindowChanged(packageName, className, rootInActiveWindow)) {
    // 已执行跳过，跳过后续导航追踪
    // 但保留状态更新
}
```

### 6.2 设置页面

在 `SettingsScreen` 增加"开屏跳过管理"入口：

```
"开屏广告跳过" → 跳转到 SkipRuleScreen
```

### 6.3 事件记录

跳过操作记录为 `VIEW_CLICKED` 事件，extra 中标记 `skip_ad: true`。

## 8. 防误触策略

| 机制 | 说明 | 默认值 |
|------|------|--------|
| `matchDelay` | 页面打开后延迟匹配 | 500ms |
| `actionCd` | 执行后冷却期 | 30s |
| `actionMaximum` | 规则生命周期内最大执行次数 | 1 |
| `activityIds` | 限定仅在指定 Activity 执行 | 空=不限 |
| 包名过滤 | 仅处理非系统 UI 的应用 | — |
| 节点可见性 | 仅匹配 `visibleToUser=true` 的节点 | — |
