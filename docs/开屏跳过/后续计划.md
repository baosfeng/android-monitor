## 已完成 ✅

### ✅ v2 重构：触发链路 + 假成功 + 选择器引擎（P0-1 ~ P0-4）

- **触发链路**：以「App 切换时刻」为锚点开窗（10 秒），窗口内 CONTENT_CHANGED 事件驱动扫描（100ms 节流）
  + 300ms 兜底轮询；根节点为 null 不再放弃（旧实现整次启动漏检）；熄屏丢弃事件与动作。
- **消灭假成功**：删除 `GlobalBackInterceptor`（按返回键即判成功）与 16 连点坐标兜底；
  只执行规则命中的节点动作；新增**面积守卫**（命中面积 > 根节点 1/3 视为整屏广告容器，丢弃）；
  跳过记录必须带命中的 selector。
- **规则不被饿死**：`matchDelay` 改为到期时间戳（旧实现每次扫描 cancel + 重投，CONTENT_CHANGED
  风暴下规则永不执行）。
- **选择器引擎**：GKD 选择器子集（逻辑表达式、成员表达式 `text.length`、`@` 目标、关系算子
  `> < << + -` 与空白祖先、14 个比较符、三种引号转义）；快速查询（`[vid=]/[id=]/[text*=]` 走
  `findAccessibilityNodeInfosByViewId/ByText`），解析结果进程内缓存。
- **规则模型**：`activityIds/excludeActivityIds` 前缀匹配、`matchTime/actionMaximum/resetMatch/actionCd/
  matchDelay/action`（click/clickNode/clickCenter/back/longClick/none）、`matches/anyMatches/excludeMatches`。
- **真机证据**：新版本 2 条 `AD_SKIPPED` 记录 selector 非空率 100%（旧版本全部为空）；
  日志 `✅ 跳过成功: tv.danmaku.bili ← [childCount=0][visibleToUser=true][text.length<10][text*="跳过"...]`。

### ✅ P0-1 全局规则为主的内置规则库

- `BuiltInRules.kt` 重写为「1 条全局开屏规则 + 7 个 App 规则」，全局规则带 `matchTime=8s` +
  `actionMaximum=1` + `resetMatch=APP` 时间闸门，并维护 `GLOBAL_EXCLUDED_PACKAGES`（系统 UI/桌面/浏览器/输入法）。
- `BuiltInRulesTest` 校验：选择器 100% 可解析、包名/ID 唯一、全局规则闸门齐备。

### ✅ P1-1 订阅机制（解析与落库完成，UI 入口待接）

- `GkdSubscription.kt`：https only、两级订阅文件（`updateUrl/checkUpdateUrl` 相对路径解析）、
  版本比对、响应体 8MB/规则 3000 条上限、失败保留旧规则。
- `json/Json5Parser.kt`：零依赖 JSON5 解析（注释/单引号/未引号键/尾随逗号/转义）。
- `SkipRuleSerialization.kt`：规则 ↔ JSON 往返 + GKD 订阅（`apps`/`globalGroups`）→ 模型。
- 合规：社区订阅无 LICENSE，**不内置**其规则数据，由用户自行添加订阅 URL。

### ✅ P1-2 快照工具（导出器完成，触发入口待接）

- `SnapshotExporter.kt`：无障碍树 → JSON（层级/属性/坐标），写 `filesDir/snapshots/<时间戳>.json`，
  并含 `summarize()` 结构摘要；用于编写精确选择器。
