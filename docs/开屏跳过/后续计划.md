## 背景（2025-08 调研结论）

对同类软件（GKD / 李跳跳 / 轻启动）调研后确认：本模块架构（无障碍服务 + CSS 风格选择器 + 规则引擎）对标 **GKD（gkd-kit）模式**，方向正确，但存在 4 个结构性短板：

| # | 短板 | 影响 |
|---|------|------|
| 1 | 内置规则是代码快照，无远程订阅更新 | App 发版改布局后规则永久失效，长期成功率衰减（李跳跳停更后"规则太旧"是前车之鉴） |
| 2 | 不监听 CONTENT_CHANGED 事件（已修复 ✅） | 跳过按钮延迟出现时只能靠轮询碰运气 |
| 3 | 非内置规则 App 的文本兜底被 canRunFullChain 锁死 | 长尾 App 基本跳不过 |
| 4 | 坐标盲点 16 连点 + isSplashPage 关键词判定宽松 | 误触风险（点到广告本体/摇一摇广告） |

调研细节（GKD 事件驱动机制、李跳跳逆向结论、各家识别策略对比）见本次会话记录，要点已落入下方各待办项。

## 已完成 ✅

### ✅ CONTENT_CHANGED 事件驱动监控（提交 `52a57a3`）

- **问题**：跳过按钮通常在广告加载完成后才出现，原实现只靠 5 秒 100ms 轮询碰运气，弱网场景易漏跳
- **方案**：监听 `TYPE_WINDOW_CONTENT_CHANGED`（节点树变化即按钮出现的信号），监控窗口内 100ms 节流立即扫描；原轮询降为 500ms 兜底（验证阶段保持 100ms）
- **涉及文件**：
  - `app/src/main/res/xml/accessibility_service_config.xml` — 监听事件类型增加 `typeWindowContentChanged`
  - `app/src/main/java/com/bsfeng/monitor/service/MonitorAccessibilityService.kt` — `handleContentChanged()` 转发（过滤系统 UI/桌面 + 日志降噪）
  - `app/src/main/java/com/bsfeng/monitor/skip/SkipRuleEngine.kt` — `onContentChanged()` + `currentTimeMillis` 时钟注入
- **测试**：`SkipRuleEngineTest` 新增 5 个用例（立即触发/非监控包名忽略/节流边界/超时停止/stopWatching 后忽略）
- **遗留注意**：改了无障碍事件配置，手机端需在无障碍设置中**关闭再开启**本服务才生效

## 待办清单（按优先级）

### P0-1 远程订阅规则（最重要，解决规则过期）

- **现状**：`app/src/main/java/com/bsfeng/monitor/skip/BuiltInRules.kt` 内置 88 个 App 规则，`BUILT_IN_VERSION = 6` 手动维护；App 更新改布局后规则失效只能等发版
- **目标**：支持从远程 URL 拉取规则订阅并自动更新（设计文档 §9.1 本就是预留项）
- **涉及文件**：
  - `app/src/main/java/com/bsfeng/monitor/skip/SkipRuleManager.kt`（现有 loadLocal，加 loadRemote + 缓存 + 版本比对）
  - `app/src/main/java/com/bsfeng/monitor/skip/BuiltInRules.kt`（作为首次安装的默认兜底）
  - `app/src/main/java/com/bsfeng/monitor/network/ApiService.kt` 或新增下载器（零第三方依赖：HttpURLConnection）
- **实现思路**（参考 GKD 订阅机制）：
  1. 规则 JSON 加 `checkUpdateUrl` / `version` 字段，定期（如每日）后台检查
  2. 订阅格式对齐 GKD 的 `apps[{id,name,groups[{key,activityIds,rules[{matches,actionMaximum,resetMatch}]}]}]`，便于复用社区规则
  3. 服务端可先挂 GitHub raw / Gitee 静态 JSON，无需自建后端
- **验收标准**：修改远程 JSON 版本号后，App 内自动拉取并生效（无需发版）；订阅失败静默降级到本地规则
- **注意**：远程规则安全校验（仅 https、JSON 结构校验、规则数量上限），防恶意订阅注入

### P1-1 快照工具（规则质量基础设施）

- **现状**：无。写选择器只能靠猜节点结构，内置规则 `[text*="跳过"]` 这类粗粒度匹配占 91 处，误触风险高
- **目标**：把当前前台页面的无障碍树序列化为 JSON，上传/导出后在网页可视化审查并编写精确选择器（GKD 的 snapshot 机制）
- **涉及文件**：
  - 新增 `app/src/main/java/com/bsfeng/monitor/skip/SnapshotExporter.kt`（无障碍树 → JSON）
  - `docs/开屏跳过/设计.md` §9.3 已有"规则快照（未来）"描述
- **验收标准**：一键导出当前页面无障碍树（节点层级/属性/坐标），可在网页查看；据此写出的选择器能命中目标节点

### P1-2 收紧坐标盲点（降低误触）

- **现状**：`SkipRuleEngine.tryCoordinateClick()` 一次连点 16 个盲点（右上 6 + 底部 5 + 中间靠右 5），且 `isSplashPage()` 只要 className 含"广告/AdActivity"即放行——应用内广告页也可能被盲点乱点，可能点到广告本体（跳应用市场）或触发"摇一摇"
- **目标**：
  1. 16 连点 → 只点右上角最常见的 2-3 个位置
  2. 坐标盲点仅在「有内置规则且首次匹配失败」时启用，无内置规则的 App 不允许
  3. 点击前用 `getActiveWindow`/屏幕截图判断是否仍为开屏（可选）
- **涉及文件**：`app/src/main/java/com/bsfeng/monitor/skip/SkipRuleEngine.kt`（`tryCoordinateClick`、`canRunFullChain` 判定）
- **验收标准**：应用内广告页不再触发盲点点击；日志中坐标点击执行频率显著下降

### P2-1 首次点击失败后的重试机会

- **现状**：`actionMaximum = 1` 且首次点击即消耗计数；验证失败进入重试时 `ExactRuleInterceptor` 已被计数挡住，对 `canRunFullChain=false` 的 App 只剩 4 条通用 ID，基本放弃
- **目标**：验证重试阶段允许重新执行精确规则（或引入"点击未命中不计入 actionMaximum"的语义：仅当验证确认广告消失才计数）
- **涉及文件**：`app/src/main/java/com/bsfeng/monitor/skip/SkipRuleEngine.kt`（`verifyRetryCount` 分支、`incrementCounter` 调用点）
- **验收标准**：广告延迟加载（首次点击时按钮未出现）场景下，重试能命中并跳过；正常页面不受影响

### P2-2 文本兜底解锁策略（需产品决策）

- **现状**：`canRunFullChain` 仅当 className 含 splash/AdActivity/开屏/广告 关键词或 activityIds 显式匹配时放行文本匹配/坐标点击；但内置 88 个 App 中**只有 4 个分组写了 activityIds**（知乎、B站、微信 LauncherUI、微信 appbrand），京东/淘宝等主 Activity（如 `MainFrameActivity`）不含关键词 → 文本兜底对它们实际被锁死，无内置规则的 App 更只有 4 条通用 ID 可用
- **选项**：
  - A（推荐）：为内置规则补齐 activityIds（需逐个 App 实测，工作量中）
  - B：放宽"无内置规则 App 的文本匹配"——仅匹配 `[clickable=true][text*="跳过"]` 且附加 `text.length` 约束（GKD 全局规则的常见写法），降低误触
  - C：维持现状（保守）
- **涉及文件**：`app/src/main/java/com/bsfeng/monitor/skip/BuiltInRules.kt`（补 activityIds）、`SkipRuleEngine.kt`（`canRunFullChain` 判定）
- **验收标准**：选定方案后，目标 App 开屏能跳过，正常页面零误触

### P2-3 监控窗口可配置（弱网适配）

- **现状**：`WATCH_TIMEOUT_MS = 5000` 硬编码；弱网下广告加载可能超过 5 秒，事件驱动虽加速响应但窗口到期即停
- **目标**：窗口时长与设置页联动（如 5s/8s/10s），或在监控超时前若检测到广告容器（如广告 SDK 根节点 ID）则自动延长窗口
- **涉及文件**：`SkipRuleEngine.kt`、`app/src/main/java/com/bsfeng/monitor/ui/SettingsScreen.kt`
- **验收标准**：弱网（飞行模式 + 单开数据）下开屏广告可跳过

### P3-1 内置规则质量维护

- **现状**：88 个 App 规则中纯文本匹配 91 处、活动页限定仅 4 处；`BUILT_IN_VERSION` 手动递增，无规则质量测试
- **目标**：
  1. 为高频 App（京东/淘宝/小红书/微博等）实测补齐 activityIds 与精确 ID 选择器
  2. 为 `BuiltInRules.kt` 增加结构校验测试（规则格式合法、matches 非空、包名唯一）
- **涉及文件**：`app/src/main/java/com/bsfeng/monitor/skip/BuiltInRules.kt`、新增 `BuiltInRulesTest.kt`
- **验收标准**：规则测试通过；高频 App 开屏实测可跳
