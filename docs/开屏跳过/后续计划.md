## 背景

对标 GKD（gkd-kit，43k★）后确认本模块架构方向正确，但 v1 存在三类结构性问题：
触发链路失效、假成功（返回键/盲点连点）、选择器能力不足。2026-10-13 完成真机取证与 v2 重构，
调研结论与逐条差距见 → [业界调研与改进方案](业界调研与改进方案.md)。

## 已完成 ✅

### ✅ v2 重构：触发链路 + 假成功 + 选择器引擎（P0-1 ~ P0-4）

- **触发链路**：以「App 切换时刻」为锚点开窗（10 秒），窗口内 CONTENT_CHANGED 事件驱动扫描（100ms 节流）
  + 300ms 兜底轮询；根节点为 null 不再放弃（旧实现整次启动漏检）；熄屏丢弃事件与动作。
- **消灭假成功**：删除 `GlobalBackInterceptor`（按返回键即判成功）与 16 连点坐标兜底；
  只执行规则命中的节点动作；新增**面积守卫**（命中面积 > 根节点 1/3 视为整屏广告容器，丢弃）；
  跳过记录必须带命中的 selector。
- **规则不被饿死**：`matchDelay` 改为到期时间戳（旧实现每次扫描 cancel + 重投，CONTENT_CHANGED
  风暴下规则永不执行）。
- **选择器引擎**：GKD 选择器子集（逻辑表达式、成员表达式 `text.length`、`@` 目标、关系算子
  `> < << + -` 与空白祖先、14 个比较符、三种引号转义）；快速查询（`[vid=]/[id=]/[text*=]` 走
  `findAccessibilityNodeInfosByViewId/ByText`），解析结果进程内缓存。
- **规则模型**：`activityIds/excludeActivityIds` 前缀匹配、`matchTime/actionMaximum/resetMatch/actionCd/
  matchDelay/action`（click/clickNode/clickCenter/back/longClick/none）、`matches/anyMatches/excludeMatches`。
- **真机证据**：新版本 2 条 `AD_SKIPPED` 记录 selector 非空率 100%（旧版本全部为空）；
  日志 `✅ 跳过成功: tv.danmaku.bili ← [childCount=0][visibleToUser=true][text.length<10][text*="跳过"...]`。

### ✅ P0-1 全局规则为主的内置规则库

- `BuiltInRules.kt` 重写为「1 条全局开屏规则 + 7 个 App 规则」，全局规则带 `matchTime=8s` +
  `actionMaximum=1` + `resetMatch=APP` 时间闸门，并维护 `GLOBAL_EXCLUDED_PACKAGES`（系统 UI/桌面/浏览器/输入法）。
- `BuiltInRulesTest` 校验：选择器 100% 可解析、包名/ID 唯一、全局规则闸门齐备。

### ✅ P1-1 订阅机制（解析与落库完成，UI 入口待接）

- `GkdSubscription.kt`：https only、两级订阅文件（`updateUrl/checkUpdateUrl` 相对路径解析）、
  版本比对、响应体 8MB/规则 3000 条上限、失败保留旧规则。
- `json/Json5Parser.kt`：零依赖 JSON5 解析（注释/单引号/未引号键/尾随逗号/转义）。
- `SkipRuleSerialization.kt`：规则 ↔ JSON 往返 + GKD 订阅（`apps`/`globalGroups`）→ 模型。
- 合规：社区订阅无 LICENSE，**不内置**其规则数据，由用户自行添加订阅 URL。

### ✅ P1-2 快照工具（导出器完成，触发入口待接）

- `SnapshotExporter.kt`：无障碍树 → JSON（层级/属性/坐标），写 `filesDir/snapshots/<时间戳>.json`，
  并含 `summarize()` 结构摘要；用于编写精确选择器。

  `I/MonitorService: 页面快照导出: …`；订阅区显示「未订阅：可添加 GKD 兼容订阅地址获取社区规则」。

  规则列表从 107 条回落为 8 条（1 条全局 + 7 条应用规则）。

### ✅ P1-4 订阅定时检查（已完成）

  未订阅/未到周期时零网络开销；检查时间持久化在 `skip_rule_prefs.subscription_check_at`。
- **真机验证（2026-10-13 22:51）**：注入订阅地址后重启 App → 日志
  `I/SkipRuleManager: 订阅已更新: https://registry.npmmirror.com/… version=186 规则=611`
  `I/GkdSubscription: 订阅自动检查: Updated(version=186, ruleCount=611)`；
  611 条规则落库，全局规则的 107 条按应用禁用名单正确进入 `excludedApps`，随后用规则页「清除」复原为 8 条。
- **注意**：jsdelivr 在真机上下载不稳定，文档里已改为推荐 npm 镜像地址（见 [设计 §5](设计.md)）。

### P1-5 订阅兼容性补齐（已完成 ✅，2026-10-13）

- 支持 GKD `globalGroups[].apps[{enable:false}]`（→ `SkipRule.excludedApps`，接入订阅后不会被
  全局开屏规则误点到系统 UI/浏览器/微信）
- 支持 `actionDelay`（命中后等待并复核才点击）、`actionCdKey`/`actionMaximumKey`（同组多规则共享冷却/次数）、
  `preKeys`（多步流程顺序闸门）
- 仍未支持（订阅规则里出现时按默认行为处理）：`position` 的表达式写法、`matchRoot`、
  `forcedTime`/`priorityTime`/`priorityActionMaximum`、`scopeKeys`、`swipeArg`、`categories`

### P1-6 设置页「无障碍服务」状态显示不准（发现待修）

- **现象（真机实测 2026-10-13 22:53）**：`dumpsys accessibility` 显示服务已绑定且引擎日志正常
  （`pollForegroundApp` 持续输出），但设置页显示「❌ 未开启」；同一台机器 22:15 曾显示「✅ 已开启」。
- **涉及文件**：`app/src/main/java/com/bsfeng/monitor/ui/MainViewModel.kt:238`（
  `getEnabledAccessibilityServiceList` 判定）、`app/src/main/java/com/bsfeng/monitor/ui/SettingsScreen.kt:56`
- **建议**：判定改为"设置项已勾选 **或** 服务实例已连接（`MonitorAccessibilityService.isRunning`）"，
  并在页面 onResume 时刷新。

### P2-1 规则实测调优（长期）

- **现状**：v2 内置规则为通用特征（文本/短文本/可见叶子节点 + 数量极少的 ID 特征），未逐 App 实测。
- **目标**：用快照工具抓真实开屏页，为高频 App（小红书/美团/淘宝系/地图类）补精确选择器与 `excludeMatches`。
- **验收标准**：高频 App 开屏实测命中率提升；正常页面零误触（`AD_SKIPPED` 记录逐条可追溯到 selector）。

### P2-2 监控窗口可配置（弱网适配）

- **现状**：`SkipRuleEngine.WATCH_WINDOW_MS = 10_000` 与全局规则 `matchTime = 8_000` 硬编码。
- **目标**：设置页可选 5s/10s/15s；弱网下自动延长（如窗口内检测到广告容器则顺延）。
- **涉及文件**：`SkipRuleEngine.kt`、`BuiltInRules.kt`、`app/src/main/java/com/bsfeng/monitor/ui/SettingsScreen.kt`。

### P2-3 硬骨头兜底（需产品决策，暂不做）

- Flutter/Unity/WebView/纯图按钮场景无障碍树里没有文本与稳定 ID，业界方案是 OCR / 小模型图像检测
