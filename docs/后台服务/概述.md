# 后台服务模块

> 包路径：`com.bsfeng.monitor.service`

本模块是应用的后台核心，负责事件采集的实时驱动、系统广播监听、服务健康保活以及开机自启恢复。所有数据源（无障碍事件、系统广播）通过本模块落入 `EventCollector`。

---

## 1. 文件清单

| 文件 | 职责 |
|------|------|
| `app/src/main/java/com/bsfeng/monitor/service/MonitorAccessibilityService.kt` | 无障碍服务——前台应用切换、Activity 跳转、界面内容识别、通知监听 |
| `app/src/main/java/com/bsfeng/monitor/service/ReceiverRegistrar.kt` | 统一注册所有 BroadcastReceiver（屏幕、电池、WiFi、蓝牙、耳机、应用包、飞行模式、省电模式、存储、USB、通话、音量、时区、语言） |
| `app/src/main/java/com/bsfeng/monitor/service/HealthChecker.kt` | 定时健康检查——检测 AccessibilityService 运行状态与事件积压，异常时推送通知（30 分钟冷却） |
| `app/src/main/java/com/bsfeng/monitor/service/BootReceiver.kt` | 开机广播接收——接收 `BOOT_COMPLETED` / `USER_PRESENT` 启动保活定时器 |
| `app/src/main/java/com/bsfeng/monitor/service/AlarmReceiver.kt` | 定时闹钟接收——每 30 分钟触发一次 `HealthChecker.checkAndRestore()` |

## 2. 核心流程

### 2.1 无障碍事件采集

```
系统界面变化
    │
    ▼
MonitorAccessibilityService.onAccessibilityEvent(event)
    │
    ├─ TYPE_WINDOW_STATE_CHANGED ──→ handleWindowChange()
    │   │
    │   ├─ 过滤系统 UI（com.android.systemui、com.miui.systemui、android）
    │   │
    │   ├─ packageName 变化 ──→ EventCollector.emit(APP_FOREGROUND)
    │   │
    │   ├─ 同一包、className 变化 ──→ EventCollector.emit(ACTIVITY_CHANGE)
    │   │
    │   └─ ScreenClassifier.classify() 成功 ──→ EventCollector.emit(SCREEN_CONTENT_DETECTED)
    │
    └─ TYPE_NOTIFICATION_STATE_CHANGED ──→ handleNotification()
        │
        └─ EventCollector.emit(NOTIFICATION_RECEIVED)
```

**状态跟踪：** 维护 `lastPackageName`、`lastActivityClass`、`lastSwitchTimeMs` 三个实例变量，用于计算前台驻留时长和判断 Activity 切换。

### 2.2 广播注册流程

```
ReceiverRegistrar(context).registerAll()
    │
    ├─ registerScreen()       → ACTION_SCREEN_ON / OFF / USER_PRESENT
    ├─ registerBattery()      → ACTION_POWER_CONNECTED / DISCONNECTED / BATTERY_CHANGED
    ├─ registerBluetooth()    → ACTION_ACL_CONNECTED / DISCONNECTED
    ├─ registerHeadset()      → ACTION_HEADSET_PLUG
    ├─ registerPackage()      → ACTION_PACKAGE_ADDED / REMOVED (data: package)
    ├─ registerAirplane()     → ACTION_AIRPLANE_MODE_CHANGED
    ├─ registerPowerSave()    → ACTION_POWER_SAVE_MODE_CHANGED
    ├─ registerStorage()      → ACTION_DEVICE_STORAGE_LOW / OK
    ├─ registerUsb()          → ACTION_USB_DEVICE_ATTACHED / DETACHED
    ├─ registerCall()         → PHONE_STATE
    ├─ volumeObserver.register()           → 音量 ContentObserver
    ├─ registerNetworkCallback()           → ConnectivityManager.NetworkCallback（WiFi / 移动数据 / VPN）
    ├─ registerHotspot()                   → WIFI_AP_STATE_CHANGED
    ├─ registerScreenshot()                → ScreenshotObserver
    ├─ registerRingerMode()  → RINGER_MODE_CHANGED_ACTION
    └─ registerLocale()      → ACTION_TIMEZONE_CHANGED / ACTION_LOCALE_CHANGED
```

所有广播注册兼容 Android 13+（`RECEIVER_EXPORTED`），蓝牙和通话注册可能因缺少权限抛出 `SecurityException`，注册时已 catch 静默处理。

### 2.3 健康检查与保活

```
AlarmManager（每 30 分钟）
    │
    ▼
AlarmReceiver.onReceive()
    │
    ▼
HealthChecker.checkAndRestore(context)
    │
    ├─ isAccessibilityServiceRunning()？── 否 ──→ 推送通知「监控服务已停止」
    │
    └─ countUnsent() > 1000？── 是 ──→ 推送通知「事件积压过多」
```

**通知冷却：** 同一种通知两次发送间隔至少 30 分钟（`NOTIFICATION_COOLDOWN_MS`），避免频繁打扰用户。

### 2.4 开机自启

```
系统启动完成
    │
    ▼
BootReceiver.onReceive()
    │
    ▼
scheduleAlarmCheck(context)
    │
    ▼
AlarmManager.setInexactRepeating() 启动 30 分钟周期闹钟
```

`BootReceiver` 同时响应 `ACTION_BOOT_COMPLETED` 和 `ACTION_USER_PRESENT`，后者在设备解锁后提供二次保活机会。

## 6. 常见问题

**Q：如何确认无障碍服务是否在运行？**
A：查看系统通知。如果 `HealthChecker` 检测到服务停止，会在 30 分钟冷却内推送一次通知。也可直接在 设置 → 无障碍 → 行为记录 中查看开关状态。

**Q：为什么某些广播（蓝牙、通话）可能收不到？**
A：`ReceiverRegistrar` 对蓝牙和通话广播的注册包裹了 `SecurityException` 捕获——如果应用缺少 `BLUETOOTH_CONNECT` 或 `READ_PHONE_STATE` 权限，注册会静默跳过。`AndroidManifest.xml` 中已声明相关权限，但用户可能在运行时拒绝授予。

**Q：事件积压阈值 1000 条是怎么来的？**
A：基于 30 分钟检查周期 × 平均事件产生速率估算。若应用长时间离线且产生大量事件，积压超过 1000 条会提醒用户检查网络。

**Q：系统 UI 过滤会不会漏掉重要事件？**
A：`isSystemUi()` 目前过滤 `com.android.systemui`、`com.miui.systemui` 和 `android`（锁屏界面），这些包的 Activity 切换与用户行为无关。如有新的系统 UI 包需要过滤，在 `isSystemUi()` 中添加即可。
