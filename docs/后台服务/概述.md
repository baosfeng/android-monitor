# 后台服务模块

> 包路径：`com.bsfeng.monitor.service`

本模块是应用的后台核心，负责事件采集的实时驱动、系统广播监听、服务健康保活以及自启恢复。所有数据源（无障碍事件、系统广播）通过本模块落入三层管道。

---

## 1. 文件清单

| 文件 | 职责 |
|------|------|
| `app/src/main/java/com/bsfeng/monitor/service/MonitorAccessibilityService.kt` | 无障碍服务——前台应用切换、Activity 跳转、导航栈追踪、点击事件捕捉、页面内容提取 |
| `app/src/main/java/com/bsfeng/monitor/service/ReceiverRegistrar.kt` | 统一注册所有 BroadcastReceiver（屏幕、电池、WiFi、蓝牙、耳机、应用包、飞行模式、省电模式、存储、USB、通话、音量、时区、语言） |
| `app/src/main/java/com/bsfeng/monitor/service/HealthChecker.kt` | 定时健康检查——检测 AccessibilityService 运行状态与事件积压，异常时推送通知（30 分钟冷却） |
| `app/src/main/java/com/bsfeng/monitor/service/AlarmReceiver.kt` | 定时闹钟接收——每 1 分钟触发一次保活检查，发现服务停止时自动唤醒进程 |

> **BootReceiver** 已移除（功能合并到 AlarmManager 定时检查 + MonitorApp.onCreate 启动保活定时器）。

## 2. 核心流程

### 2.1 无障碍事件采集

```
系统界面变化
    │
    ▼
MonitorAccessibilityService.onAccessibilityEvent(event)
    │
    ├─ TYPE_WINDOW_STATE_CHANGED ──→ handleWindowChange()
    │   │
    │   ├─ 过滤系统 UI（com.android.systemui、com.miui.systemui、android 等）
    │   │
    │   ├─ 检测桌面（Home）→ 保存当前 App 会话（AppSessionManager.saveSession）
    │   │
    │   ├─ packageName 变化 ──→ NavigationTracker.onAppSwitch()
    │   │                       └→ emit NAVIGATION_CHANGE
    │   │
    │   ├─ 同包名、className 变化 ──→ NavigationTracker.onActivityChange()
    │   │                             └→ emit NAVIGATION_CHANGE（无独立 ACTIVITY_CHANGE）
    │   │
    │   ├─ 从另一 App 回到之前到访过的 App ──→ AppSessionManager.restoreSession()
    │   │                                      └→ emit RETURN_TO_PAGE
    │   │
    │   └─ 更新 recentForegroundPackages 列表（最近 5 个前台包名）
    │
    ├─ TYPE_VIEW_CLICKED ──→ handleViewClick()
    │   │
    │   ├─ 检测 App 专用处理器（如 WeChatClickHandler）
    │   ├─ 提取点击文本 + 页面上下文文本
    │   └─ emit VIEW_CLICKED
    │
    └─ (其他事件类型忽略)
```

**状态跟踪：** 维护 `lastPackageName`、`lastActivityClass`、`lastSwitchTimeMs`、`lastPageTitle` 四个实例变量，用于判断界面变化和计算前台驻留时长。

**点击事件：** 监听 `TYPE_VIEW_CLICKED`，500ms 防抖 + 3 秒同文本过滤。优先使用 App 专用处理器（如 `WeChatClickHandler`）获取更有意义的点击文本。

**导航追踪：** 不再单独发射 `ACTIVITY_CHANGE` 事件，所有导航行为统一通过 `NAVIGATION_CHANGE` 事件呈现（包含面包屑路径）。

**时间线日志：** 通过 `Log.d("MonitorTimeline", ...)` 输出干净的操作时间线，使用 emoji 前缀（📍导航、👆点击）。

### 2.2 广播注册流程

```
ReceiverRegistrar(context).registerAll()
    │
    ├─ registerScreen()       → ACTION_SCREEN_ON / OFF / USER_PRESENT
    ├─ registerBattery()      → ACTION_POWER_CONNECTED / DISCONNECTED / BATTERY_CHANGED
    ├─ registerBluetooth()    → ACTION_ACL_CONNECTED / DISCONNECTED
    ├─ registerHeadset()      → ACTION_HEADSET_PLUG
    ├─ registerPackage()      → ACTION_PACKAGE_ADDED / REMOVED / RESTARTED (data: package)
    ├─ registerAirplane()     → ACTION_AIRPLANE_MODE_CHANGED
    ├─ registerPowerSave()    → ACTION_POWER_SAVE_MODE_CHANGED
    ├─ registerStorage()      → ACTION_DEVICE_STORAGE_LOW / OK
    ├─ registerUsb()          → ACTION_USB_DEVICE_ATTACHED / DETACHED
    ├─ registerCall()         → PHONE_STATE
    ├─ volumeObserver.register()           → 音量 ContentObserver
    ├─ registerNetworkCallback()           → ConnectivityManager.NetworkCallback（WiFi / 移动数据 / VPN）
    ├─ registerHotspot()                   → WIFI_AP_STATE_CHANGED
    ├─ registerScreenshot()                → ScreenshotObserver
    ├─ registerRingerMode()  → RINGER_MODE_CHANGED_ACTION
    └─ registerLocale()      → ACTION_TIMEZONE_CHANGED / ACTION_LOCALE_CHANGED
```

所有广播注册兼容 Android 13+（`RECEIVER_EXPORTED`），蓝牙和通话注册可能因缺少权限抛出 `SecurityException`，注册时已 catch 静默处理。

### 2.3 健康检查与保活

```
AlarmManager（每 1 分钟）
    │
    ▼
AlarmReceiver.onReceive()
    │
    ├─ HealthChecker.checkAndRestore(context)
    │   │
    │   ├─ isAccessibilityServiceRunning()？── 否 ──→ 推送通知「监控服务已停止」
    │   │
    │   └─ countUnsent() > 1000？── 是 ──→ 推送通知「事件积压过多」
    │
    ├─ isAccessibilityServiceRunning()？── 否 ──→ startActivity(MainActivity) 唤醒进程
    │                                             │
    │                                             ▼
    │                                       Application.onCreate() 重新初始化全部服务
    │
    └─ 每 1 分钟也触发一次数据上报（uploadBatch）
```

**保活机制：** AlarmReceiver 每 1 分钟触发一次，做三件事：
1. 调用 `HealthChecker.checkAndRestore()` 健康检查
2. 检测 AccessibilityService 是否存活，否则启动 MainActivity 唤醒进程
3. 触发 `EventReporter.uploadBatch()` 数据上报

**通知冷却：** 同一种通知两次发送间隔至少 30 分钟（`NOTIFICATION_COOLDOWN_MS`），避免频繁打扰用户。

**注册时机：** `scheduleAlarmCheck()` 目前只在 **一处** 调用：
- `MonitorApp.onCreate()` — 应用每次启动时（含从 launcher 点击图标、AlarmManager 唤醒等）

### 2.4 自启恢复

不再依赖 `BOOT_COMPLETED` 广播（BootReceiver 已移除）。设备重启后：
1. 用户主动打开 App → `MonitorApp.onCreate()` → `scheduleAlarmCheck()` → 启动 1 分钟周期闹钟
2. 系统可能自动启动 App（如被系统拉起）→ 同上流程

> 当前版本未实现开机自启动，需用户手动启动 App 至少一次才能启用后台保活。

## 6. 常见问题

**Q：如何确认无障碍服务是否在运行？**
A：查看 UI 界面的状态卡片——显示「✅ 无障碍已开启」或「❌ 无障碍未开启」。也可在 设置 → 无障碍 → 行为记录 中查看开关状态。

**Q：为什么某些广播（蓝牙、通话）可能收不到？**
A：`ReceiverRegistrar` 对蓝牙和通话广播的注册包裹了 `SecurityException` 捕获——如果应用缺少 `BLUETOOTH_CONNECT` 或 `READ_PHONE_STATE` 权限，注册会静默跳过。`AndroidManifest.xml` 中已声明相关权限，但用户可能在运行时拒绝授予。

**Q：事件积压阈值 1000 条是怎么来的？**
A：基于 1 分钟检查周期 × 平均事件产生速率估算。若应用长时间离线且产生大量事件，积压超过 1000 条会提醒用户检查网络。

**Q：系统 UI 过滤会不会漏掉重要事件？**
A：`isSystemUi()` 目前过滤 `com.android.systemui`、`com.miui.systemui`、`com.miui.personalassistant`、`com.sohu.inputmethod.sogou`（搜狗输入法）和 `android`（锁屏界面）。如有新的系统 UI 包需要过滤，在 `isSystemUi()` 中添加即可。

**Q：导航路径防抖 15 秒有什么作用？**
A：防止 App 内部瞬态中间 Activity（如闪屏过渡页、短暂加载页）产生重复或无意义的导航事件。同一路径在 15 秒内不会重复发射。
