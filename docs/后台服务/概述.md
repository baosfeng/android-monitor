# 后台服务模块

> 包：`com.bsfeng.monitor.service`（采集层在 `record`）。事件模型见[事件类型定义](../事件采集/事件类型定义.md)。

职责：无障碍事件采集与前台 App 轮询、系统广播接收、跳过弹幕、健康检查与保活自启。

## 文件

| 文件 | 职责 |
|---|---|
| `service/MonitorAccessibilityService.kt` | 无障碍服务：前台 App 轮询、窗口/内容变化、点击事件、跳过弹幕、kill 检测、开屏引擎与自动记账集成 |
| `service/HealthChecker.kt` | 健康检查：无障碍是否运行、事件积压，异常推通知（30 分钟冷却） |
| `service/AlarmReceiver.kt` | 1 分钟周期保活：健康检查 + 必要时把 App 拉到前台 + 触发上报 |
| `record/RecordReceiver.kt` | 动态注册的系统广播接收器（见下） |

## 采集流程

`MonitorAccessibilityService`（manifest 注册，`accessibility_service_config.xml` 配能力）核心：

- **前台轮询**：`pollForegroundApp()` 用主线程 `Handler` 每 **1000ms** 轮询前台包名（不依赖事件回调，避免漏事件），与 `WINDOW_STATE_CHANGED` 互补；`isHomeApp()` 判定桌面。
- **`onAccessibilityEvent`**：`WINDOW_STATE_CHANGED` → `handleWindowChange()`（过滤 `isSystemUi()`，更新 App/Activity、写 `MonitorTimeline` 时间线日志）；`WINDOW_CONTENT_CHANGED` → `handleContentChanged()`（驱动开屏跳过扫描；100ms 节流在引擎侧）。末尾独立 `try/catch` 调自动记账引擎，不互相影响。
- **跳过弹幕**：命中后显示 1200ms 弹幕（`showSkipDanmaku`，按 `confirmed` 区分「已跳过 / 已点击（未确认）」）。
- **kill 检测**：`updateKillDetectorTargets()` 维护待观测应用。
- **`onKeyEvent`**：返回键处理（业务相关）。
- 采集结果统一交给 `record/RecordCollector` → `RecordStore`（SQLite）。`record/UsageTracker` 负责 App 使用时长（OPENED/CLOSED 成对）。

## 广播接收（`RecordReceiver`）

`MonitorApp.registerRecordReceiver()` 用两个 `IntentFilter` 动态注册（`Context.RECEIVER_EXPORTED`），不在 manifest 静态声明。接收的 action：

- 屏幕/电源：`SCREEN_OFF`、`USER_PRESENT`、`POWER_CONNECTED`、`POWER_DISCONNECTED`
- 电量：`BATTERY_CHANGED`、`BATTERY_LOW`、`BATTERY_OKAY`
- 音频/电源/网络：`HEADSET_PLUG`、`POWER_SAVE_MODE_CHANGED`、`AIRPLANE_MODE_CHANGED`
- 通话：`PHONE_STATE_CHANGED`
- 包管理：`PACKAGE_ADDED`、`PACKAGE_REMOVED`（带 `data scheme=package`）

WiFi 不用广播：`MonitorApp` 用 `ConnectivityManager.NetworkCallback`（`WIFI_STATE_CHANGED_ACTION` 是硬件开关，HyperOS 上易误触发；首个同步回调跳过）。

## 保活

```
MonitorApp.onCreate → scheduleAlarmCheck()
AlarmManager.setInexactRepeating(RTC_WAKEUP, now+30s, 60s)
 → AlarmReceiver.onReceive
   ├─ HealthChecker.checkAndRestore()：无障碍未运行 → 通知；未上报事件 > 1000 → 通知「事件积压过多」
   ├─ 无障碍未运行 → bringToFrontIfBackground()（仅后台时，SINGLE_TOP 启动 MainActivity 唤醒进程）
   └─ 触发周期上报（设备注册 / 心跳）
```

| 参数 | 值 | 位置 |
|---|---|---|
| 保活周期 | 60 秒（首次 30 秒后） | `AlarmReceiver.scheduleAlarmCheck()` |
| 通知冷却 | 30 分钟（`NOTIFICATION_COOLDOWN_MS`） | `HealthChecker` |
| 事件积压阈值 | 1000 | `HealthChecker.checkAndRestore()` |

> 不用 `force-stop` 重启应用：会摘掉无障碍权限（见[踩坑](../踩坑/MIUI-force-stop导致无障碍服务被自动移除.md)）。

## 自启

不依赖 `BOOT_COMPLETED`（`BootReceiver` 已移除）。设备重启后需要用户主动打开 App（或系统拉起）→ `MonitorApp.onCreate()` → `scheduleAlarmCheck()` 才恢复保活。**未实现开机自启动**。

## 常见问题

- **怎么确认无障碍在跑**：设置页状态卡显示「无障碍已开启 / 未开启」；判定走 `util/AccessibilityStatus` 三重检查（设置项 / 服务列表 / 服务实例）。
- **蓝牙/通话广播收不到**：注册被 `SecurityException` 捕获后静默跳过，检查 `BLUETOOTH_CONNECT` / `READ_PHONE_STATE` 运行时授权。
- **积压阈值 1000 的由来**：按 1 分钟检查周期 × 平均事件产生速率估算，超限提醒用户检查网络。
- **系统 UI 过滤列表**：`isSystemUi()` 覆盖 `com.android.systemui`、`com.miui.systemui`、`com.miui.personalassistant`、输入法（搜狗）、`android`（锁屏）等，新增包名直接加进该方法。
