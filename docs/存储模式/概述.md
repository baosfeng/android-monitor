# 存储模式（本地 / 服务器）

> 结论：备份产物永远是同一份 zip + manifest；`StorageMode` 只决定它最终落点与计数来源——`LOCAL` 走现有私有目录、`SERVER` 走 HTTPS 上传；切换模式不迁移、不删除另一端的已有备份，恢复时一律先下载/选中再走现有还原流水线。

## 两种模式

| 模式 | 落点 | 计数与保留 | 联网要求 | 典型用途 |
|---|---|---|---|---|
| LOCAL（默认） | Android/data/<pkg>/files/backups/ 私有目录 | 本机最近 5 份（pre-restore 独立 2 份） | 不需要 | 隐私优先、离线设备 |
| SERVER | 配置的 Base URL /backups | 服务端最近 N 份（默认 10，可配置） | 需要 | 换机恢复、防卸载丢失 |

- 模式由 backup_prefs 中的 storageMode 持久化，不随备份内容同步；切换时只改变后续「立即备份 / 自动备份 / 列表」的目标。
- 本地备份在切换到 SERVER 后仍保留，供用户随时改回；服务器备份在切换回 LOCAL 后仍保留，供下次切回或手工下载。
- SERVER 模式下「导出到下载目录」先下载选中的服务器备份到缓存，再复用现有导出路径与确认闸门；永不用服务器 URL 直接暴露给系统下载器（避免绕过确认）。

## 不变量（两种模式都必须遵守）

- 产物字节完全相同：同一 manifest schema、同一 zip 结构、同一降精度规则；服务端只存不改。
- backupId（UUID，客户端生成）是两端的共同主键；重复提交同一 id 视为幂等重试，不能产生第二份。
- 列表展示的 createdAt / appVersionName / size / sha256 来自 manifest，而不是文件系统/服务端推断。
- 恢复永远要求：校验 manifest -> 下载/选定 -> sha256 校验 -> 走现有 BackupManager.restore() 流水线；服务端不参与解包。
- 自动备份失败不改变模式；LOCAL 失败只记 W，SERVER 失败走离线重试，失败也不回退成 LOCAL。

## 代码分工（建议）

- StorageMode（枚举）+ StorageModePrefs（backup_prefs 读写）
- BackupStorageProvider：list / put / get / delete / exists（纯接口，无 Android Context 依赖以外的运行时）
- LocalBackupStorageProvider：封装现有私有目录读写与保留策略
- ServerBackupStorageProvider：封装 HTTPS 传输，依赖 EventReporter 同款设备 Token
- BackupManager：只与 provider 交互，不感知模式字符串
