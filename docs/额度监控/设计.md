# 额度监控 · 设计

> 原型：`.open-design/src/screens/s18-额度.html` · `s19-额度设置.html`（预览 `node scripts/assemble-prototype.mjs` 后打开 `08-prototype.html`）。
> API 事实见 [API 调研](API调研.md) 与 [opencode-go/opendesign 接入调研](接入调研-opencode-opendesign.md)。

## 范围

一个底部「额度」Tab：聚合多家 AI 服务的余额、套餐额度与用量，按剩余比例阈值发系统通知。
接入 Ollama（余额 + 用量 + 按模型）、DeepSeek（余额 + 平台用量接口）、opencode-go（三窗口已用百分比，卡片三行百分比，「已用 → 剩余」的转换在 provider 内完成）与 opendesign（控制台内部接口，凭据是浏览器会话令牌、会过期）。
DeepSeek 用量凭据是**平台会话 token** 而非 `sk-` API Key：设置页分开填、过期提示重贴；必须带 User-Agent（缺了 WAF 429），错误恒为 HTTP 200 + body `code`，单次区间上限 31 天。

## 多账号：类型与实例

同一个 provider **可以挂多个账号**，每行独立刷新、独立预警、独立参与榜单。实现上拆开「类型」与「实例」：

| 键 | 取值 | 用在哪 |
|---|---|---|
| `providerTypeId` | 原 `QuotaProvider.id`（ollama / deepseek / opendesign / opencode-go） | 选实现、卡片排版、限流口径、UI 锚点 |
| `instanceId` | 第一实例 == 类型 id；新增才是 `"<类型>#2"` | 凭据、状态、快照、预警状态键、通知 ID、榜单行、选中态 |

- **零迁移**：默认第一个实例的 `instanceId` 直接等于 `providerTypeId`，历史凭据键 `"ollama:API_KEY"`、快照键 `snapshot:ollama`、`refresh_minutes:ollama` 天然命中。
- **清单落盘**：`quota_instances` 存一个 JSON 数组（instanceId + providerTypeId + label）。空清单按注册表合成默认单实例，不写盘也能工作；读取时按注册表顺序与组内序号规范化，丢掉未知类型与重复 id。
- **删账号**：清它自己的凭据 + 快照 + 状态 + 节流记录；其余账号 id **不重排**（重排会让凭据落到别的键上）。只剩一个账号时入口隐藏、数据层也拒绝。
- 刷新锁 / 节流 / 429 退避的键都是 `instanceId`（`QuotaRefreshBookkeeping`）：用类型 id 会让第二个账号被第一个的锁与退避拖死，表现是「加了账号但数字永远不动」。

## 入口与开关

- `Feature.QUOTA` 默认开：关闭后「额度」Tab 消失、后台刷新与预警评估一起停。
- `AppTab.QUOTA` 枚举**追加在 `SETTINGS` 之后**（通知深链 `EXTRA_START_TAB` 用枚举下标，插中间会让旧通知落错 Tab）；底部导航渲染顺序与枚举解耦。

## 页面

**额度页（Tab）**：顶部「聚合 / 单家」分段（默认聚合，选择持久化）→ 聚合：结论条 + 一实例一行榜单；单家：provider chip → 额度卡 → 用量卡（范围 / 指标 / 柱图 / 按模型 Top 3）。
榜单**一行 = 一个账号**，按剩余百分比升序。同类型多账号时行名带账号名（`DeepSeek · 账号 2`），单账号时就是类型名；**同值按 `instanceId` 字典序兜底**，否则两个账号比例相同时每次刷新会互换。只收能算出百分比的账号：纯余额型（金额且无总额）在末尾灰行标「不参与聚合」。排序与排除在 domain 的 `QuotaAggregator`，app 层只做 `ProviderState → 输入映射`；点行切回单家并选中该实例。

**额度设置（push 屏）**：每个 provider 类型一个分组，组内一行一个账号（标题账号名、副行连接状态），组尾「+ 添加账号」。展开 = 改名 → 凭据（保存 + 刷新间隔）→ 清除凭据 → 删除此账号（只剩一个时隐藏）。其后是预警开关与阈值、通知权限、后台刷新频率、Ollama 计费模式。

## 数据模型

```kotlin
data class QuotaInstance(
    val instanceId: String,      // 凭据 / 状态 / 快照 / 预警的唯一键
    val providerTypeId: String,  // 类型：选实现、排版、限流口径
    val label: String = "",      // 用户改的名字；空 = 退回默认名
)

data class QuotaSnapshot(
    val providerId: String,      // = instanceId
    val providerTypeId: String,  // 老快照缺这个字段时按 instanceId 回落
    val items: List<QuotaItem>, val usage: QuotaUsage?,
    val fetchedAt: Long, val stale: Boolean,
)
```

`QuotaItem` 把金额 / 百分比 / 次数归一成一个列表（`remaining` 恒为「剩余」）。解析必须容错：Ollama `included` 是 oneOf（USD 型 / 旧版百分比型 / 未知原样保留）；opencode-go 的 `percent` 是**已用**比例、归一化时转成剩余，并兼容 2026-08 前的旧字段名；DeepSeek 金额是字符串，用 `BigDecimal` 且不跨币种相加。

## 预警

- 阈值 `5 / 4 / 3 / 2 / 1 %`：取「不小于当前剩余值的最小阈值」，一次跨多档只命中最低档。
- 状态键 `instanceId.itemId`（`alertStateKey`），存周期标识 + 已提醒阈值；按实例隔离，同类型两账号各记各的。
- **通知 ID 按 instanceId 稳定派生**（`7301 + hash % 900`）：固定 7301 会让第二个账号的提醒覆盖第一条；标题带账号名。
- 余额型（无总额、无周期）走低余额单档：低于阈值提醒一次，充值回升后重新计数。
- 同一次刷新多个额度命中 → 合并一条；点通知进额度 Tab。总开关关闭 → 照常刷新、不评估。

## 刷新

| 场景 | 行为 |
|---|---|
| 进 Tab / 切账号 / 保存 Key | 立即刷新（余额与用量并行）；聚合模式刷全部账号（非 force） |
| 前台停留 / 手动刷新 | 按账号节流：Ollama 默认 60 秒（10 次/分钟且跨设备共享）、opencode-go 默认 5 分钟 |
| 后台 | AlarmManager 每小时 / 每 3 小时 / 每 6 小时 / 关闭 |
| 429 | 读 `Retry-After` + 抖动退避；无该头时退避至 60 秒 |

## 凭据

API Key 用 Android Keystore AES-GCM 加密后存 SharedPreferences，键 `"<instanceId>:<kind>"`；界面掩码输入、保存后立即清空明文；不写日志、不导出、不进备份包。
**清除凭据**：已配置的账号在保存按钮下方多一条 danger 按钮，二次确认后断开 = 清凭据 + 清快照 + 状态回落（不清快照会继续显示上次余额，像没断开）。加解密抽成 `QuotaSecretCipher`，生产只走 Keystore 实现，软件实现只在测试里。
