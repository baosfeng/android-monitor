# 额度监控 · 设计

> 原型：`.open-design/src/screens/s18-额度.html` · `s19-额度设置.html`（预览 `node scripts/assemble-prototype.mjs` 后打开 `08-prototype.html`）。
> API 事实见 [API 调研](API调研.md) 与 [opencode-go/opendesign 接入调研](接入调研-opencode-opendesign.md)。

## 范围

一个底部「额度」Tab：聚合多家 AI 服务的余额、套餐额度与用量，按剩余比例阈值发系统通知。
首版接入 Ollama（余额 + 用量 + 按模型）、DeepSeek（余额 + 平台用量接口：按模型、按小时的请求数 / token / 花费）、opencode-go（三窗口已用百分比，无用量明细，卡片是三行百分比，检测「已用 → 剩余」的转换在 provider 内完成）与 opendesign（控制台内部接口，凭据是浏览器会话令牌、会过期，与 API Key 分开填）。四家均已真实接入，无「待接入」占位通路。
DeepSeek 用量走平台内部接口（`/api/v0/usage/by_api_key/amount|cost`），凭据是**平台会话 token** 而非 `sk-` API Key：设置页分开填、过期提示重贴；必须带 User-Agent（缺了 WAF 429），错误恒为 HTTP 200 + body `code`，单次区间上限 31 天。

## 入口与开关

- 新增 `Feature.QUOTA`，默认开：关闭后「额度」Tab 消失、后台刷新与预警评估一起停。
- 新增 `AppTab.QUOTA`，**枚举追加在 `SETTINGS` 之后**（现有通知深链 `EXTRA_START_TAB` 用枚举下标，插中间会让旧通知落错 Tab）；底部导航显示顺序与枚举解耦，渲染为「… 记账 / 额度 / 设置」。
- 设置页「额度监控」分组：开关 + Provider 与 API Key + 预警通知 + 后台刷新；关闭时整组折叠成「开启后可用」。

## 页面

**额度页（Tab）**：顶部「聚合 / 单家」分段切换（默认聚合，选择持久化）→ 聚合时：结论条 + 一家一行榜单；单家时：provider 横向 chip → 额度卡（hero 金额或百分比、进度、周期与重置日、次级额度行）→ 用量卡（范围 24 小时 / 7 天 / 30 天、指标、柱图、按模型 Top 3 + 「其他」行）。

聚合榜单回答「谁最先见底」，**一家一行**、按剩余百分比升序。主指标取该家可量化项里剩余最少的那条（如 opencode-go 三窗口取最紧急的），其余窗口在行副文案并排。**只收能算出百分比的 provider**：纯余额型（金额且无总额，如 DeepSeek）没有分母，为排进榜单只能臆造总额、位次是假的，故不进排序，在末尾灰行标「不参与聚合」。排序与排除规则落在 domain 层纯函数（`QuotaAggregator`），app 层只做 `ProviderState → 输入的映射`。同值按 providerId 字典序兜底，否则相同比例的两行每次刷新都会互换，看起来像数据在跳。点行切回单家并选中该家。
Ollama 的计费模式**由用户手动选**（按百分比限额 / 按金额 USD），选择持久化；接口返回的结构与所选不一致时在卡片里提示，不静默改口径。

两种计划形态的差异必须落到 UI：USD 型显示金额与 token；**旧版计划只返回请求次数**，用量区只画「请求次数 + 时间分布」，不显示金额、token 与按模型明细。额度卡里的会话 / 每周按**剩余百分比**展示——接口不返回绝对次数就不编造次数，只在用量区用请求次数表达「用了多少」。柱状图不标柱顶数值，纵轴只留 0 与顶部刻度。状态齐四种：已配置有数据、旧版百分比计划、未配置 Key、查询失败（红条 + 重试 + 保留上次数据并标注时间）。

**额度设置（push 屏）**：provider 列表（已连接 / 未配置）、预警开关与阈值说明、低余额阈值（仅余额型）、通知权限状态、发送测试通知、后台刷新频率。

## 数据模型

```kotlin
data class QuotaItem(       // 一条额度：金额 / 百分比 / 次数统一成列表
    val id: String,         // included / purchased / session / weekly / balance:cny
    val title: String,
    val kind: QuotaKind,    // MONEY / PERCENT / COUNT
    val remaining: BigDecimal,  // 百分比统一为「剩余」0..100
    val total: BigDecimal?,     // 余额型为 null
    val unit: String,       // USD / CNY / %
    val resetsAt: Instant?,
    val primary: Boolean,
)

data class QuotaSnapshot(
    val providerId: String,
    val items: List<QuotaItem>,
    val usage: QuotaUsage?,     // 无用量接口时为 null，UI 显式说明
    val fetchedAt: Instant,
    val stale: Boolean,
)
```

解析必须容错：Ollama `included` 是 oneOf（USD 型 / 旧版百分比型 / 未知原样保留）；opencode-go 的 `percent` 是**已用**比例、归一化时转成剩余，并兼容 2026-08 前的旧字段名；DeepSeek 金额是字符串，用 `BigDecimal` 且不跨币种相加。

## 预警

- 阈值 `5 / 4 / 3 / 2 / 1 %`：取「不小于当前剩余值的最小阈值」，一次跨多档只命中最低档。
- 状态键 `providerId.itemId`，存周期标识（重置时间）+ 已提醒阈值；周期变化或余额回升到 5% 以上 → 清零。
- 余额型 provider（无总额、无周期）走低余额单档：低于阈值提醒一次，充值回升后重新计数。
- 同一次刷新多个额度命中 → 合并成一条通知；点通知进额度 Tab。
- 总开关关闭 → 照常刷新、不评估；后台刷新关闭 → 只在打开 App 时评估。

## 刷新

| 场景 | 行为 |
|---|---|
| 进 Tab / 切 provider / 保存 Key | 立即刷新（余额与用量并行）；聚合模式刷全部（`refreshAll`，非 force） |
| 前台停留 / 手动刷新 | Ollama 默认 60 秒节流（限流 10 次/分钟，跨设备共享）、opencode-go 默认 5 分钟；手动刷新再压到 ≥10 秒 |
| 后台 | AlarmManager 每小时 / 每 3 小时 / 每 6 小时 / 关闭 |
| 429 | 读 `Retry-After` + 抖动退避；无该头时指数退避至 60 秒 |
| 息屏 / 锁屏 | 不发起后台请求，解锁后不补跑 |

## 凭据

API Key 用 Android Keystore AES-GCM 加密后存 SharedPreferences；界面掩码输入、保存后立即清空明文；不写日志、不导出、不进备份包。

**清除凭据**：已配置的家在保存按钮下方多一条 danger 按钮，二次确认后断开 = 清凭据 + 清快照 + 状态回落（不清快照会继续显示上次余额，像没断开）。加解密抽成 `QuotaSecretCipher`（`quota/QuotaCredentialStore.kt`），生产只走 Keystore 实现，软件实现只在测试里——Robolectric 没有可用的 AndroidKeyStore provider。
