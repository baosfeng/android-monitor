# 事件采集

## 概述

事件采集模块负责监听、模型化、分类 Android 设备上的各类系统与应用事件。事件经过**三层管道架构**处理：

- **采集层** (`RawEventCollector`)：接收 `EventSource` 提供的原始数据，自动填充设备信息、导航上下文，组装成 `RawEvent`
- **管道层** (`EventPipeline`)：将 `RawEvent` 扇出给所有已注册的 `EventHandler`，每个 Handler 在独立协程中运行
- **执行层** (Handler)：各自完成单一职责——持久化(`DatabaseHandler`)、上传(`UploadHandler`)、日志(`LogHandler`)

同时提供 `ScreenClassifier` 协助对当前屏幕内容（包名/类名/节点文本）进行分类，产出 `ScreenContent` 识别结果。

> 旧版 `EventCollector` 单例已移除，被 `RawEventCollector + EventPipeline` 取代。

整体架构层次：

```
EventSource (AccessibilityService)
        │ collectRaw()
        ▼
  ┌─────────────────────────────────┐
  │     RawEventCollector           │  采集层入口
  │   填充 deviceId / 导航上下文     │
  │   组装成 RawEvent               │
  └──────────┬──────────────────────┘
             │ RawEvent
             ▼
  ┌─────────────────────────────────┐
  │     EventPipeline               │  管道层
  │    fork 给所有 Handler           │
  └────┬──────────┬──────────┬──────┘
       │          │          │
  ┌────▼──┐ ┌─────▼─────┐ ┌─▼───────┐
  │Database│ │Upload     │ │Log      │  执行层
  │Handler │ │Handler    │ │Handler  │
  │(SQLite)│ │(HTTP批量)  │ │(Logcat) │
  └────────┘ └───────────┘ └─────────┘
```

## 核心接口/类

| 名称 | 源文件 | 说明 |
|---|---|---|
| `EventType` | `EventType.kt` | 枚举，定义 37 种受支持的事件类型（前台切换、屏幕亮灭、充电、WiFi、通知等），每个值携带中文 `description`；提供 `fromString()` 反查。 |
| `EventSource` | `pipeline/EventSource.kt` | 接口，所有事件源实现 `collectRaw(): RawEventData` 提供原始数据 |
| `RawEventData` | `pipeline/RawEvent.kt` | 数据类，EventSource 返回的原始数据容器（不含 deviceId/时间等自动填充字段） |
| `RawEvent` | `pipeline/RawEvent.kt` | 数据类，自包含的完整信息包（含导航上下文、结构化数据、设备快照） |
| `RawEventCollector` | `pipeline/RawEventCollector.kt` | 采集层入口，接收 EventSource → 组装 RawEvent → 发往管道 |
| `NavigationContextTracker` | `pipeline/NavigationContextTracker.kt` | 导航上下文栈维护器，追踪"从哪来到哪去" |
| `EventHandler` | `pipeline/EventHandler.kt` | 接口，执行层 Handler 实现 `handle(event: RawEvent)` |
| `EventPipeline` | `pipeline/EventHandler.kt` | 接口，管道层 `register/unregister/dispatch` |
| `UnifiedEvent` | `EventModels.kt` | `@Serializable` 数据类，统一事件模型（用于旧版兼容和上报） |
| `EventEntity` | `data/EventEntity.kt` | Room `@Entity(tableName = "events")`，含 `fromRawEvent()` 工厂方法 |
| `ScreenContent` | `ScreenClassifier.kt` | 数据类，描述识别结果：`screenTitle`、`screenType`、`confidence` |
| `ScreenClassifier` | `ScreenClassifier.kt` | `object` 单例，基于包名/类名/节点文本进行屏幕分类 |

## 使用方式

```kotlin
// ========== 采集事件（新管道架构） ==========
// 方式一：实现 EventSource 接口（推荐，可携带完整上下文）
MonitorApp.instance.getCollector().emit(object : EventSource {
    override fun collectRaw() = RawEventData(
        eventType = EventType.APP_FOREGROUND,
        packageName = "com.example.app",
        className = ".MainActivity",
        summary = "前台应用: 示例App",
        rawExtra = mapOf("app" to "com.example.app")
    )
})

// 方式二：使用便捷方法（适合简单事件）
MonitorApp.instance.getCollector().emitSimple(
    EventType.UNLOCK_FAILED,
    summary = "解锁失败",
    extra = mapOf("attempts" to "3")
)

// 方式三：在 MonitorAccessibilityService 中已有完整迁移示例
// ========== 屏幕分类 ==========
// 在无障碍服务中调用
val result = ScreenClassifier.classify(
    packageName = "com.tencent.mm",
    className = "com.tencent.mm.ui.chatting.ChattingUI",
    windowText = listOf("聊天标题"),
    rootNode = rootInActiveWindow  // AccessibilityNodeInfo
)
// result.screenType == "chat", result.confidence == 0.85f

// 主动清理分类缓存
ScreenClassifier.cleanCache()
```

## 操作意图→文件映射

| 你想做什么 | 对应文件 | 关键 API |
|---|---|---|
| 新增/修改事件类型 | `EventType.kt` | 在枚举中追加新值，附带中文 `description` |
| 触发一个自定义事件 | `RawEventCollector.kt` + `EventSource.kt` | `collector.emit(source)` 或 `collector.emitSimple(type, summary, extra)` |
| 新增一种事件处理方式 | `handler/*.kt` | 实现 `EventHandler` 接口 → 在 `MonitorApp.initPipeline()` 中注册 |
| 修改导航上下文追踪逻辑 | `NavigationContextTracker.kt` | `onScreenChanged()` / `navigateBack()` / `getCurrentContext()` |
| 修改管道扇出行为 | `EventPipelineImpl.kt` | `register()` / `unregister()` / `dispatch()` |
| 查看/修改事件数据模型字段 | `RawEvent.kt` / `EventEntity.kt` | `RawEvent` 字段 + `EventEntity` 字段 + `fromRawEvent()` 工厂方法 |
| 识别当前屏幕是什么页面 | `ScreenClassifier.kt` | `ScreenClassifier.classify(pkg, cls, text, node)` |
| 修改屏幕分类规则 | `ScreenClassifier.kt` | `classifyByPackage()` 中的 `when` 分支逻辑 |
| 清理分类缓存 | `ScreenClassifier.kt` | `ScreenClassifier.cleanCache()` |
| 接入新的事件源 | `EventSource.kt` | 实现 `EventSource.collectRaw(): RawEventData` 接口 |
