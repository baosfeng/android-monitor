# 事件采集（Record 系统）

> 代码：`record/`（采集/存储）+ `domain/.../model/`（模型）。历史设计见[重构设计](../superpowers/specs/2026-07-02-record-system-redesign.md)。

## 数据模型

```kotlin
sealed interface RecordType  // SCREEN CHARGING APP_USAGE WIFI AUDIO BATTERY PACKAGE POWER_SAVE AIRPLANE PHONE_STATE LOCATION
data class Record(
    val id: String, val type: RecordType, val action: String, val timestamp: Long,
    val duration: Long? = null, val label: String,
    val detail: Map<String, String>? = null, val owner: String = ""
)
```

11 种类型、每种的 action 与 detail 键见[事件类型定义](事件类型定义.md)。新增类型 = 加一个 `data object` + 一个 `RecordHandler` + 注册（不改已有代码）。

## 采集链路

```
无障碍服务（前台轮询 1s + WINDOW/CONTENT 事件）/ RecordReceiver（系统广播）/ 开屏跳过命中
 → RecordCollector.onXxx(...)（统一 emit：type + action + ts + duration + detail）
 → RecordHandler 校验 + 生成 label（RecordHandlerRegistry 按 type 取策略）
 → RecordStore.insert / insertOrMerge → SQLite records 表
```

- `record/RecordCollector.kt` 入口：`onScreenChanged`、`onChargingChanged`、`onTick`（前台 App 轮询，驱动使用时长）、`onWifiChanged`、`onAudioChanged`、`onBatteryChanged` / `onBatteryLow` / `onBatteryOkay`、`onPackageChanged`、`onPowerSaveChanged`、`onAirplaneChanged`、`onPhoneStateChanged`、`onSkipAd`（写 AD_SKIPPED）。
- `record/UsageTracker.kt`：App 使用时长状态机。`tick(pkg, appName, ts)` 判断切换/停止，`flush(ts)` 收尾（息屏、服务结束），切换时写 `APP_USAGE/CLOSED + duration` 再写 `OPENED`；`getActiveSession()` 供查询。
- `record/RecordStore.kt`：`insert` / `insertOrMerge`（合并策略：同类的连续记录合并，返回是否合并）、`queryByDate` / `queryByType` / `queryByTypeAndAction`、`getDailySummary` / `getAppUsageRank`、`deleteBefore` / `deleteByRange` / `deleteByAction`；`computeScreenOnMillis()` 估算亮屏时长（无记录段按 5 分钟估计）。
- `record/RecordReceiver.kt`：动态注册的系统广播（屏幕、电量、耳机、省电、飞行、通话、包安装/卸载），由 `MonitorApp` 注册，详见[后台服务](../后台服务/概述.md)。
- `record/PageTracker.kt`：页面轨迹状态机（指纹 + 停留时长）。**页面标题**由 `PageTitle` 按「窗口标题 > 顶部可见文本 > 首个短文本」提取，≤30 字，写进 `PAGE` 的 `detail["page_title"]`；开关 `Feature.PAGE_TITLE` 默认开，关闭时既不提取也不写入。
- `record/LocationReverseGeocoder.kt`：逆地理编码。系统 Geocoder 优先，失败回落 Nominatim（免 key，只发量化坐标）；硬超时 3 秒、两次查询间隔 ≥2 秒、内存 LRU 缓存（键 = 量化经纬度），失败只累加诊断计数，`LOCATION` 记录照常落库并回落经纬度文案。

## 隐私口径

页面标题与地址**只存本地**：`page_title`（≤30 字）与 `address` 写进 `detail`，上报前由 `network/ApiDtos.kt` 的 `LOCAL_ONLY_DETAIL_KEYS` 剔除；标题不参与页面指纹，页面正文任何情况下都不落库。

## 存储

表 `records`：`id`(PK) / `type` / `action` / `timestamp` / `duration` / `label` / `detail`(JSON) / `owner`。索引 `timestamp`、`type`。`detail` 序列化为 JSON 字符串；`owner` 预留给后续多人场景。
