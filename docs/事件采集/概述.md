# 事件采集

## 概述

事件采集模块负责事件类型定义、导航追踪和 App 会话管理。事件处理经过**三层管道架构**：

- **采集层** (`RawEventCollector`)：接收 `EventSource` 提供的原始数据，自动填充设备信息、导航上下文，组装成 `RawEvent`
- **管道层** (`EventPipeline`)：将 `RawEvent` 扇出给所有已注册的 `EventHandler`，每个 Handler 在独立协程中运行
- **执行层** (Handler)：各自完成单一职责——持久化(`DatabaseHandler`)、上传(`UploadHandler`)、日志(`LogHandler`)

> 旧版 `EventCollector` 单例已移除，被 `RawEventCollector + EventPipeline` 取代。
> `ScreenClassifier` 也已移除，屏幕内容直接通过 `AccessibilityEvent.text` / `contentDescription` 提取。

整体架构层次：

```
EventSource (AccessibilityService)
        │ collectRaw()
        ▼
  ┌─────────────────────────────────┐
  │     RawEventCollector           │  采集层入口
  │   填充 deviceId / 导航上下文     │
  │   组装成 RawEvent               │
  └──────────┬──────────────────────┘
             │ RawEvent
             ▼
  ┌─────────────────────────────────┐
  │     EventPipeline               │  管道层
  │    fork 给所有 Handler           │
  └────┬──────────┬──────────┬──────┘
       │          │          │
  ┌────▼──┐ ┌─────▼─────┐ ┌─▼───────┐
  │Database│ │Upload     │ │Log      │  执行层
  │Handler │ │Handler    │ │Handler  │
  │(SQLite)│ │(HTTP批量)  │ │(Logcat) │
  └────────┘ └───────────┘ └─────────┘
```

## 事件类型（5 种）

当前 `EventType` 枚举仅保留以下 5 种事件类型：

| 事件类型 | 说明 | 触发场景 |
|---------|------|---------|
| `APP_FOREGROUND` | App 切换 | 用户从桌面或另一 App 切换到某个 App |
| `ACTIVITY_CHANGE` | 页面跳转 | 同 App 内 Activity 切换 |
| `VIEW_CLICKED` | 点击交互 | 用户在 App 内点击了某个可交互元素 |
| `NAVIGATION_CHANGE` | 导航路径变更 | App 内导航栈变化，包含完整面包屑路径 |
| `RETURN_TO_PAGE` | 回到之前浏览的页面 | 用户从另一 App 回到之前访问过的 App 页面 |

> 详见 [事件类型定义](事件类型定义.md)

## 核心接口/类

| 名称 | 源文件 | 说明 |

## 导航追踪

**包路径：** `com.bsfeng.monitor.event`

导航追踪系统由两个组件协同工作：

### NavigationTracker

为每个 App 维护独立的导航栈，追踪用户在 App 内的完整导航路径。

**文件：** `app/src/main/java/com/bsfeng/monitor/event/NavigationTracker.kt`

核心方法：

| 方法 | 说明 |
|------|------|
| `onAppSwitch(packageName, appName, className)` | App 切换时重置导航栈到根节点 |
| `onActivityChange(packageName, appName, className, pageTitle)` | 同 App 内 Activity 切换，更新导航栈 |
| `getCurrentPath(packageName)` | 获取指定 App 的当前导航路径 |
| `getPathAsString(packageName, separator)` | 获取面包屑格式路径，如「微信 > 发现 > 朋友圈」 |
| `saveState/restoreState(packageName, state)` | 保存/恢复导航栈状态 |
| `getCurrentDepth/LevelName` | 获取导航深度和指定层级名称 |

导航决策逻辑：
1. App 切换 → 重置栈为 `[app_name]`
2. 主页/首页类 Activity → 重置到根
3. 同 Activity 重复事件 → 去重忽略
4. 返回导航（栈中已存在 className）→ 退栈到该位置
5. 深层次导航 → 压入新节点

### AppSessionManager

保存用户离开某个 App 时的导航现场，30 分钟内回到同一 App 时恢复导航上下文。

**文件：** `app/src/main/java/com/bsfeng/monitor/event/AppSessionManager.kt`

| 方法 | 说明 |
|------|------|
| `saveSession(pkg, appName, navPath, pageTitle, activityClass)` | 离开 App 时保存现场 |
| `restoreSession(packageName)` | 回到 App 时恢复（30 分钟过期） |
| `clearSession/clearAll` | 清除会话 |

### 使用示例

```kotlin
// App 切换时调用
val navResult = NavigationTracker.onAppSwitch("com.tencent.mm", "微信", ".LauncherUI")
emitNavigationEvent(navResult, ...)

// 同 App 内 Activity 变化
val navResult = NavigationTracker.onActivityChange(
    "com.tencent.mm", "微信", ".ChattingUI", "群聊名称"
)

// 获取当前导航路径
val path = NavigationTracker.getPathAsString("com.tencent.mm")
// → "微信 > 聊天列表 > 群聊名称"

// 离开 App 时保存会话
saveCurrentSession()  // 内部调用 AppSessionManager.saveSession(...)

// 回到 App 时恢复
val session = AppSessionManager.restoreSession("com.tencent.mm")
if (session != null) {
    NavigationTracker.restoreState(pkg, session.navPath)
    // 发射 RETURN_TO_PAGE 事件
}
```

## 使用方式

```kotlin
// ========== 采集事件（新管道架构） ==========
// 方式一：实现 EventSource 接口（推荐，可携带完整上下文）
MonitorApp.instance.getCollector().emit(object : EventSource {
    override fun collectRaw() = RawEventData(
        eventType = EventType.APP_FOREGROUND,
        packageName = "com.example.app",
        className = ".MainActivity",
        summary = "前台应用: 示例App",
        rawExtra = mapOf("app" to "com.example.app")
    )
})

// 方式二：使用便捷方法（适合简单事件）
MonitorApp.instance.getCollector().emitSimple(
    EventType.NAVIGATION_CHANGE,
    summary = "导航到设置页面",
    extra = mapOf("nav_path" to "App > 设置")
)

// 方式三：在 MonitorAccessibilityService 中已有完整迁移示例
```
