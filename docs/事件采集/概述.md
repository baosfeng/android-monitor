# 事件采集

## 概述

事件采集模块负责监听、模型化、分类和持久化 Android 设备上的各类系统与应用事件。模块以 **`EventCollector`** 单例为入口，接收 `EventType` 枚举定义的 37 种事件，将其序列化为 `UnifiedEvent` 数据模型，并异步写入 Room 数据库（`events` 表）；同时提供 `ScreenClassifier` 协助对当前屏幕内容（包名/类名/节点文本）进行分类，产出 `ScreenContent` 识别结果，并以 `SCREEN_CONTENT_DETECTED` 事件回注到采集链路。

整体架构层次：

```
外部监听器 (BroadcastReceiver / Service)
        │ emit(eventType, extra)
        ▼
  ┌─────────────────────────────────┐
  │        EventCollector           │  入口单例
  │   创建 UnifiedEvent (kotlinx)    │
  │    转为 EventEntity (Room)       │
  └──────────┬──────────────────────┘
             │ scope.launch(IO)
             ▼
  ┌─────────────────────────────────┐
  │    AppDatabase.eventDao()       │  Room 持久化
  │    INSERT INTO events ...       │
  └─────────────────────────────────┘
             │
             ▼ (后续可被 UploadWorker 消费)
```

## 核心接口/类

| 名称 | 源文件 | 说明 |
|---|---|---|
| `EventType` | `EventType.kt` | 枚举，定义 37 种受支持的事件类型（前台切换、屏幕亮灭、充电、WiFi、通知等），每个值携带中文 `description`；提供 `fromString()` 反查。 |
| `UnifiedEvent` | `EventModels.kt` | `@Serializable` 数据类，统一事件模型：`eventId`（UUID）、`eventType`（String）、`timestamp`、`deviceId`、`extra`（Map）；附带 `toJson()` 序列化方法。 |
| `EventCollector` | `EventCollector.kt` | `object` 单例，唯一对外入口。`emit(eventType, extra)` 方法接收枚举事件与自定义附加参数，异步写入 Room。 |
| `EventEntity` | `data/EventEntity.kt` | Room `@Entity(tableName = "events")`，包含 `eventId` / `eventType` / `timestampMs` / `deviceId` / `extraJson` / `isUploaded` / `createdAt`。`isUploaded` 标记供上传模块轮询。 |
| `ScreenContent` | `ScreenClassifier.kt` | 数据类，描述识别结果：`screenTitle`（标题）、`screenType`（类型标签如 `chat`/`feed`/`article`）、`confidence`（置信度）。 |
| `ScreenClassifier` | `ScreenClassifier.kt` | `object` 单例，基于 `packageName`、`className`、`windowText` 和 `AccessibilityNodeInfo` 进行屏幕分类。内部维护 30 秒 TTL 缓存以避免重复计算。 |

## 使用方式

```kotlin
// ========== 采集事件 ==========
// 触发前台切换事件
EventCollector.emit(EventType.APP_FOREGROUND, mapOf("app" to "com.example.app"))

// 触发解锁失败事件，附加尝试次数
EventCollector.emit(EventType.UNLOCK_FAILED, mapOf("attempts" to "3"))

// 触发界面内容识别事件（通常由 ScreenClassifier 分类后调用）
EventCollector.emit(
    EventType.SCREEN_CONTENT_DETECTED,
    mapOf(
        "package_name" to "com.tencent.mm",
        "screen_type" to "chat",
        "title" to "张三"
    )
)

// ========== 屏幕分类 ==========
// 在无障碍服务中调用
val result = ScreenClassifier.classify(
    packageName = "com.tencent.mm",
    className = "com.tencent.mm.ui.chatting.ChattingUI",
    windowText = listOf("聊天标题"),
    rootNode = rootInActiveWindow  // AccessibilityNodeInfo
)
// result.screenType == "chat", result.confidence == 0.85f

// 主动清理分类缓存
ScreenClassifier.cleanCache()
```

## 关键源码文件（完整清单）

| 文件 | 相对路径 | 职责 |
|---|---|---|
| `EventType.kt` | `app/src/main/java/com/bsfeng/monitor/event/EventType.kt` | 事件类型枚举定义 |

## 操作意图→文件映射

| 你想做什么 | 对应文件 | 关键 API |
|---|---|---|
| 新增/修改事件类型 | `EventType.kt` | 在枚举中追加新值，附带中文 `description` |
| 触发一个自定义事件 | `EventCollector.kt` | `EventCollector.emit(EventType.XXX, extraMap)` |
| 查看/修改事件数据模型字段 | `EventModels.kt` / `EventEntity.kt` | `UnifiedEvent` 字段 + `EventEntity` 字段（两者需同步） |
| 识别当前屏幕是什么页面 | `ScreenClassifier.kt` | `ScreenClassifier.classify(pkg, cls, text, node)` |
| 修改屏幕分类规则 | `ScreenClassifier.kt` | `classifyByPackage()` 中的 `when` 分支逻辑 |
| 清理分类缓存 | `ScreenClassifier.kt` | `ScreenClassifier.cleanCache()` |
| 接入新的事件源（广播/服务） | `EventCollector.kt` | 在外部监听器中调用 `EventCollector.emit()` |
