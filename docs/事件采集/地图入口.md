# 地图入口（在地图中查看）

> 一句话：把轨迹点交给手机上**已装**的地图 App 打开，零 SDK、零 key、零费用、零条款。

## 为什么不是「内置地图」

Android 自身**没有**内置地图 App（AOSP / Pixel 只有浏览器）。「接系统内置地图」在本项目落地为
**系统 Intent 唤起已装地图**——这仍然全部走系统 API，不引入任何第三方依赖。

明确不做：不接高德 / 百度 / 腾讯 SDK，不申请 key，不接付费产品。

## 各家 scheme 与坐标系（差一个就偏 300~600 米）

| 目标 | scheme | 坐标系 | 备注 |
|---|---|---|---|
| 高德 | `androidamap://viewMap` | GCJ-02 | 必带 `sourceApplication`、`dev=0` |
| 腾讯 | `qqmap://map/marker` | GCJ-02 | 必带 `referer` |
| 百度 | `baidumap://map/marker` | **BD-09** | 必须显式 `coord_type=bd09ll`，否则按 gcj02 解释 |
| Google | `geo:lat,lng?q=` | WGS84 | 系统级，装了 Google Maps 才响应 |
| 浏览器 | `openstreetmap.org/?mlat=` | WGS84 | 兜底，见下 |

采集侧是 WGS84（GPS 原始坐标）。**WGS84 直接传给高德会偏 555 米、传给百度会偏 1380 米**（天安门实测），
所以纠偏层（`ui/maps/CoordTransform.kt`）不是可选项。

## 浏览器兜底为什么选 OpenStreetMap

OSM 原生就是 WGS84（不用纠偏）、免 key、无服务条款约束、不用登录。
高德 / 百度网页版吃 GCJ-02 且条款不明确，作为兜底反而增加不确定性。缺点是国内加载略慢，兜底场景够用。

## 三条交互路径（严格按顺序）

1. **恰好一个候选**（典型 = 只装了高德）→ 直接唤起，不弹任何东西；
2. **多个候选** → 弹「选择地图应用」列出高德 / 腾讯 / 百度 / Google，选中即打开；
3. **一个都没装** → 不弹选择器，直接开 OSM 网页并 toast「未安装地图应用，已改用浏览器」。

浏览器**只在完全没有地图 App 时**才成为候选——否则「只装高德」的用户每次都要多点一次选择器，
却得不到任何信息。

## 包可见性（Android 11+ 必做）

`AndroidManifest.xml` 的 `<queries>` 里按**包名精确**列出四家地图（`com.autonavi.minimap` 等）。
不声明时 `queryIntentActivities` / `resolveActivity` 一律看不到地图 App，功能会静默退化成「只有浏览器」。
不用 `<intent><data scheme="geo">` 通配：那会顺带看到任意能响应 https 的应用，白扩可见性面。
浏览器兜底走 https 隐式 Intent + 系统选择器，不需要声明。

## 打开哪个点

`MapEntryPoint.pick` 的口径：当天**最后一个**有效采样（「我现在在哪」）→ 第一个带坐标的停留点 → null（入口整块不渲染）。
非法坐标（NaN / 越界）直接跳过，不插值、不纠正。

## 失败怎么表现

打开 App 失败不崩，toast「打不开X地图，请检查该应用是否被冻结或已卸载」；
没有任何浏览器或坐标非法 → toast「没有可用的地图或浏览器应用」，不打开任何东西。

## 相关文件

- `ui/maps/GeoPoint.kt` 纯数据 + `CoordSystem` 枚举（坐标系口径只在这里表达一次）
- `ui/maps/CoordTransform.kt` WGS84 → GCJ-02 → BD-09；境外恒等（港澳台算境内，与高德/腾讯自身处理一致）
- `ui/maps/MapTarget.kt` 五个目标 + 各自包名与坐标系
- `ui/maps/MapUri.kt` URI 拼装（纯字符串，不用 Locale 敏感格式化）
- `ui/maps/MapLauncher.kt` 包可见性查询 + resolve 复核 + 静默降级
- `ui/maps/MapEntryPoint.kt` 打开哪个点的纯判定
- `ui/maps/MapEntryCard.kt` 入口行 + 选择弹窗（锚点 `s16-map-entry`）
