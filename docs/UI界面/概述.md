# UI 界面模块

## 模块职责

UI 界面模块负责向用户展示监控数据并提供交互控制。采用 Jetpack Compose (Material 3) 实现声明式 UI，通过 `MainViewModel` 统一管理界面状态，以三标签导航结构（实时/统计/设置）组织功能页面。

---

## 包路径

`com.bsfeng.monitor.ui`

| `app/src/main/java/com/bsfeng/monitor/ui/SettingsScreen.kt` | "设置"标签页面，展示服务状态和系统配置入口 |

## 数据模型

### MonitorState

定义在 `app/src/main/java/com/bsfeng/monitor/ui/MainViewModel.kt` (第 17-23 行)

```kotlin
data class MonitorState(
    val isMonitoring: Boolean = true,
    val recentEvents: List<EventEntity> = emptyList(),
    val unsentCount: Int = 0,
    val todayUnlockCount: Int = 0,
    val todayEventCount: Int = 0
)
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `isMonitoring` | `Boolean` | 是否正在监控（默认 true） |
| `recentEvents` | `List<EventEntity>` | 最近事件列表（最多 20 条） |
| `unsentCount` | `Int` | 尚未上报的事件数量 |
| `todayUnlockCount` | `Int` | 今日解锁成功次数 |
| `todayEventCount` | `Int` | 今日事件总数 |

## 页面详情

### 1. MainActivity — 导航入口

**文件:** `app/src/main/java/com/bsfeng/monitor/MainActivity.kt`

#### Screen 导航定义 (第 26-30 行)

```kotlin
sealed class Screen(val title: String, val icon: ImageVector) {
    data object Home : Screen("实时", Icons.Default.Home)
    data object Stats : Screen("统计", Icons.Default.Info)
    data object Settings : Screen("设置", Icons.Default.Settings)
}
```

#### MainActivity 生命周期 (第 32-89 行)

| 阶段 | 行为 |
|------|------|
| `onCreate` | ① 创建 `ReceiverRegistrar` 并调用 `registerAll()` 注册所有 BroadcastReceiver |
| | ② Android 13+ (API 33) 检查通知权限，未授权则请求 `POST_NOTIFICATIONS` |
| | ③ 调用 `scheduleAlarmCheck()` 启动 AlarmManager 定期保活检查 |
| | ④ 创建 `Scaffold` + `NavigationBar`，switching 三个页面 |
| 页面切换 | 通过 `remember { mutableStateOf<Screen>(Screen.Home) }` 管理当前页 |

## MainViewModel — 状态管理

**文件:** `app/src/main/java/com/bsfeng/monitor/ui/MainViewModel.kt`

### 构造函数依赖

| 依赖 | 获取方式 |
|------|---------|
| `AppDatabase` | `AppDatabase.getInstance(MonitorApp.instance)` |
| `EventReporter` | `EventReporter(MonitorApp.instance)` |

### 公开方法

| 方法 | 说明 | 调用者 |
|------|------|--------|
| `loadData()` | 从 Room 数据库加载最新数据：最近 20 条事件、未上报数、今日解锁数、今日事件总数 | Activity/页面 `LaunchedEffect`、`togglePause()` 恢复时 |
| `togglePause()` | 切换暂停/恢复状态；恢复时自动调用 `loadData()` 刷新 | `MainScreen` 暂停按钮、`SettingsScreen` 开关 |
| `uploadNow()` | 立即触发 `EventReporter.uploadBatch()` 上报，完成后刷新数据 | 预留（当前 UI 未直接暴露） |
| `getDeviceId()` | 返回设备唯一标识（通过 `AppUtils.getDeviceId()`） | `SettingsScreen` 关于信息 |

### 公开 StateFlow

| 属性 | 类型 | 说明 |
|------|------|------|
| `state` | `StateFlow<MonitorState>` | 监控数据状态 |
| `isPaused` | `StateFlow<Boolean>` | 是否处于暂停状态 |

## 注意事项

1. **ViewModel 单例共享：** `MainViewModel` 在 `MainActivity` 中通过 `viewModel()` 创建，三个页面共享同一实例，数据变更自动同步。
2. **LaunchedEffect 刷新：** `MainScreen` 和 `StatsScreen` 各自在首次组合时通过 `LaunchedEffect(Unit)` 调用 `loadData()`，确保页面可见时数据最新。
3. **暂停状态持久化：** 当前 `isPaused` 仅存在 ViewModel 内存中，App 重启后恢复默认（false），如需持久化需扩展。
4. **事件类型分布计算：** `StatsScreen` 在当前进程中直接通过 `groupBy { it.eventType }` 对 `recentEvents` 分组统计，数据受限于最近 20 条事件，如需全量统计需修改 `loadData()` 查询逻辑。
