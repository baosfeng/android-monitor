# UI 界面模块

## 模块职责

UI 界面模块负责向用户展示监控数据并提供交互控制。采用 Jetpack Compose (Material 3) 实现声明式 UI，通过 `MainViewModel` 统一管理界面状态，以三标签导航结构（实时/统计/设置）组织功能页面。

## 数据模型

### MonitorState

定义在 `app/src/main/java/com/bsfeng/monitor/ui/MainViewModel.kt`

```kotlin
data class MonitorState(
    val isMonitoring: Boolean = true,
    val recentEvents: List<EventEntity> = emptyList(),
    val todayEventCount: Int = 0,
    val accessibilityEnabled: Boolean = false
)
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `isMonitoring` | `Boolean` | 是否正在监控（默认 true） |
| `recentEvents` | `List<EventEntity>` | 最近事件列表（最多 20 条） |
| `todayEventCount` | `Int` | 今日事件总数 |
| `accessibilityEnabled` | `Boolean` | 无障碍服务是否已开启 |

## 页面详情

### 1. MainActivity — 导航入口

**文件:** `app/src/main/java/com/bsfeng/monitor/MainActivity.kt`

#### Screen 导航定义

```kotlin
sealed class Screen(val title: String, val icon: ImageVector) {
    data object Home : Screen("实时", Icons.Default.Home)
    data object Stats : Screen("统计", Icons.Default.Info)
    data object Settings : Screen("设置", Icons.Default.Settings)
}
```

#### MainActivity 生命周期

| 阶段 | 行为 |
|------|------|
| `onCreate` | ① 创建 `ReceiverRegistrar` 并调用 `registerAll()` 注册所有 BroadcastReceiver |
| | ② Android 13+ (API 33) 检查通知权限，未授权则请求 `POST_NOTIFICATIONS` |
| | ③ 调用 `scheduleAlarmCheck()` 启动 AlarmManager 定期保活检查 |
| | ④ 创建 `Scaffold` + `NavigationBar`，switching 三个页面 |
| 页面切换 | 通过 `remember { mutableStateOf<Screen>(Screen.Home) }` 管理当前页 |

### 2. MainScreen — 实时页面

**文件:** `app/src/main/java/com/bsfeng/monitor/ui/MainScreen.kt`

| 区域 | 内容 |
|------|------|
| 状态卡片 | 显示监控状态（⏸ 已暂停 / ⚫ 监控中）+ 暂停/恢复按钮 + 清空按钮 |
| 无障碍状态 | 显示「✅ 无障碍已开启」或「❌ 无障碍未开启」 |
| 摘要行 | 今日事件总数 |
| 事件列表 | `LazyColumn` 渲染 `EventCard`，支持展开详情 |

#### 事件卡片 EventCard (第 79-253 行)

每张卡片展示一条事件记录，包含：

| 内容 | 说明 |
|------|------|
| 时间 | `HH:mm:ss` 格式 |
| 事件类型 | 中文名称 + emoji 图标（📍导航、👆点击、📱App切换、🔙返回、🔄页面跳转） |
| 面包屑导航路径 | 最突出显示（加粗、主色调），如「微信 > 发现 > 朋友圈」 |
| 页面标题 | 当前页面标题或目标页面中文描述 |
| 页面关键文本 | 最多显示 3 行上下文内容文本 |
| 应用名 | 来源应用 |
| 来源提示 | 从哪一级页面来（`← 聊天列表`） |
| 停留时长 | 若为 App 切换事件，显示上一应用驻留时长 |
| 展开详情 | 点击卡片展开，显示完整的 extraJson 字段 |

EventCard 支持展开/折叠，折叠时展示摘要信息，展开时显示全部技术详情。

### 4. SettingsScreen — 设置页面

**文件:** `app/src/main/java/com/bsfeng/monitor/ui/SettingsScreen.kt`

| 卡片/区域 | 内容 | 操作 |
|-----------|------|------|
| 无障碍服务 | 显示「✅ 已开启」或「❌ 未开启」 | 点击按钮跳转 `Settings.ACTION_ACCESSIBILITY_SETTINGS` |
| 监控开关 | 显示「运行中」或「已暂停」 | 点击按钮切换 `togglePause()` |
| 电池优化 | 提示设为"无限制"防止被系统关闭 | 点击按钮跳转 `Settings.ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS` |
| **调试模式** | 显示「输出详细调试日志 (grep MonitorDebug)」或「已关闭」 | **Switch 开关**，实时切换，持久化保存 |
| 关于 | 版本号 (1.0.0)、设备 ID（截取前 8 位）、包名 | 无操作 |

> **调试模式** 是近期新增的功能：开启后输出详细的 `MonitorDebug` 日志（grep 标签 `MonitorDebug`），所有点击文本处理器的调试信息、视图树爬取过程等均可通过 logcat 查看。状态通过 SharedPreferences 持久化，重启后保持。

## MainViewModel — 状态管理

**文件:** `app/src/main/java/com/bsfeng/monitor/ui/MainViewModel.kt`

### 构造函数依赖

| 依赖 | 获取方式 |
|------|---------|
| `DatabaseHelper` | `DatabaseHelper.getInstance(MonitorApp.instance)` |

### 公开方法

| 方法 | 说明 | 调用者 |
|------|------|--------|
| `loadData()` | 从 SQLite 加载最新数据：最近 20 条事件 + 今日事件总数 + 无障碍服务状态 | `LaunchedEffect`、`togglePause()` 恢复时 |
| `togglePause()` | 切换暂停/恢复状态；恢复时自动调用 `loadData()` 刷新 | `MainScreen` 暂停按钮、`SettingsScreen` 开关 |
| `toggleDebug()` | 切换调试模式：更新 `debugEnabled` StateFlow + 持久化到 SharedPreferences | `SettingsScreen` 调试模式 Switch |
| `clearEvents()` | 一键清空所有事件记录 | `MainScreen` 清空按钮 |
| `getDeviceId()` | 返回设备唯一标识（通过 `AppUtils.getDeviceId()`） | `SettingsScreen` 关于信息 |

### 公开 StateFlow

| 属性 | 类型 | 说明 |
|------|------|------|
| `state` | `StateFlow<MonitorState>` | 监控数据状态（含事件列表、统计数据、无障碍状态） |
| `isPaused` | `StateFlow<Boolean>` | 是否处于暂停状态 |
| `debugEnabled` | `StateFlow<Boolean>` | 调试模式开关状态 |

### 自动刷新

ViewModel 初始化时启动一个协程，每 3 秒自动调用 `loadData()` 刷新界面数据。

## 注意事项

1. **ViewModel 单例共享：** `MainViewModel` 在 `MainActivity` 中通过 `viewModel()` 创建，三个页面共享同一实例，数据变更自动同步。
2. **LaunchedEffect 刷新：** `MainScreen` 和 `StatsScreen` 各自在首次组合时通过 `LaunchedEffect(Unit)` 调用 `loadData()`，同时 ViewModel 内部每 3 秒自动刷新。
3. **暂停状态持久化：** 当前 `isPaused` 仅存在 ViewModel 内存中，App 重启后恢复默认（false），如需持久化需扩展。
4. **事件类型分布计算：** `StatsScreen` 在当前进程中直接通过 `groupBy { it.eventType }` 对 `recentEvents` 分组统计，数据受限于最近 20 条事件。
5. **调试模式持久化：** `debugEnabled` 通过 `DebugConfig.setEnabled()` 持久化到 SharedPreferences（key: `debug_enabled`），重启后保持状态。
